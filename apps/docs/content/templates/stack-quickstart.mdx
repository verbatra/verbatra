By the end of this page your <StackText field="name" /> app shows a German string that verbatra translated from <StackText field="sourceFile" />, and a lock file makes every later run translate only what changed. You need Node.js `^22.18.0 || >=24`, a <StackText field="name" /> project, and about ten minutes. The first four steps need no account and no API key.

Already have locale files and a coding agent? Hand it the prompt on [Set up with an AI agent](/docs/start-with-ai) instead: it works around the files your project has and stops before it spends anything.

### Install the CLI

```npm
npm install --save-dev @verbatra/cli
```

verbatra is a development tool and never ships in your app. The commands below use `npx`; with pnpm, yarn, or bun, run `pnpm verbatra`, `yarn verbatra`, or `bun run verbatra` instead.

### Preview the run without a key

```bash

```


A dry run builds no provider, so it needs no key, spends nothing, and writes nothing.

### Translate

```bash
cp .env.example .env
```

```bash
npx @verbatra/cli translate
```

## What just happened

- `verbatra.lock.json` records a hash of each source string, so the next run sends only new and changed strings. See [The lock file](/docs/the-lock-file).
- A result that drops a placeholder is withheld, never written. See [Translation safety](/docs/translation-safety).

Commit the locale files, `verbatra.lock.json`, and `verbatra.provenance.json` together.

## Optional: connect your coding agent

<AvailableFrom version="0.12.0" />

```bash
npx @verbatra/cli init --agent
```

With the config in place, `init --agent` keeps it and adds only the agent files: the verbatra rules in `AGENTS.md` (or `CLAUDE.md`, when that is your only instruction file) and the verbatra MCP server, with spending off, in the project config of each coding agent it detects. Which files it writes for which agent, and `--client` to name the agents yourself, are in [Set up coding agents](/docs/cli/init#set-up-coding-agents). `--dry-run` shows the files without writing them.
