À la fin de cette page, ton app <StackText field="name" /> affiche un texte allemand que verbatra a traduit depuis <StackText field="sourceFile" />, et un fichier de verrouillage fait que chaque exécution suivante ne traduit que ce qui a changé. Il te faut Node.js `^22.18.0 || >=24`, un projet <StackText field="name" /> et une dizaine de minutes. Les quatre premières étapes ne demandent ni compte ni clé d'API.

Tu as déjà des fichiers de locale et un agent de code ? Donne-lui plutôt le prompt de [Configure verbatra avec un agent IA](/docs/start-with-ai) : il part des fichiers que ton projet a déjà et s'arrête avant de dépenser quoi que ce soit.

## Ce qui vient de se passer

- `verbatra.lock.json` enregistre un hash de chaque texte source, pour que l'exécution suivante n'envoie que les textes nouveaux ou modifiés. Voir [Le fichier de verrouillage](/docs/the-lock-file).
- Un résultat qui perd un placeholder est retenu, jamais écrit. Voir [Sûreté de la traduction](/docs/translation-safety).

Commite ensemble les fichiers de locale, `verbatra.lock.json` et `verbatra.provenance.json`.

## Optionnel : connecte ton agent de code

<AvailableFrom version="0.12.0" />

```bash
npx @verbatra/cli init --agent
```

Avec la configuration en place, `init --agent` la garde et ajoute seulement les fichiers pour l'agent : les règles verbatra dans `AGENTS.md` (ou `CLAUDE.md`, quand c'est ton seul fichier d'instructions) et le serveur MCP verbatra, sans les outils qui dépensent, dans la configuration de projet de chaque agent de code qu'il détecte. Quels fichiers il écrit pour quel agent, et comment choisir toi-même les agents avec `--client`, c'est dans [Préparer les agents de code](/docs/cli/init#préparer-les-agents-de-code). `--dry-run` montre les fichiers sans les écrire.

Ou, sans la CLI, ajoute seulement le serveur MCP à ton profil utilisateur VS Code ; utilise une seule voie, jamais les deux :
