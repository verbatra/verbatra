À la fin de cette page, ton app <StackText field="name" /> affiche un texte allemand que verbatra a traduit depuis <StackText field="sourceFile" />, et un fichier de verrouillage fait que chaque exécution suivante ne traduit que ce qui a changé. ## Étapes

<Steps>
<Step>

### Installe la CLI

```bash
npm install --save-dev @verbatra/cli
```

verbatra est un outil de développement et n'est jamais livré dans ton app. Dans un projet sans `package.json`, comme une app Flutter, npm en crée un ; ajoute `node_modules/` à son `.gitignore`. Les commandes ci-dessous utilisent `npx` ; avec pnpm, yarn ou bun, lance plutôt `pnpm verbatra`, `yarn verbatra` ou `bun run verbatra`.

### Connecte ton agent

<AvailableFrom version="0.12.0" />

```bash
npx verbatra init --agent
```

Passe cette étape si tu ne travailles pas avec un agent de code. Avec la configuration en place, `init --agent` la garde et ajoute seulement les fichiers pour l'agent : les règles verbatra dans `AGENTS.md` (ou `CLAUDE.md`, quand c'est ton seul fichier d'instructions) et le serveur MCP verbatra, sans les outils qui dépensent, dans la configuration de projet de chaque agent qu'il détecte : `.mcp.json` pour Claude Code, `.cursor/mcp.json` pour Cursor, `.vscode/mcp.json` pour VS Code. Avec `--client`, tu choisis toi-même les agents, et `--dry-run` montre les fichiers sans les écrire. Voir [Préparer les agents de code](/docs/cli/init#préparer-les-agents-de-code) et [Connecter un client MCP](/docs/connect-an-mcp-client).

</Step>

### Prévisualise l'exécution sans clé

```bash
npx verbatra translate --dry-run
```

Une exécution à blanc ne construit aucun fournisseur : elle n'a pas besoin de clé, ne dépense rien et n'écrit rien.

## Ce qui vient de se passer

- `verbatra.lock.json` enregistre un hash de chaque texte source, pour que l'exécution suivante n'envoie que les textes nouveaux ou modifiés. Voir [Le fichier de verrouillage](/docs/the-lock-file).
- Un résultat qui perd un placeholder est retenu, jamais écrit. Voir [Sûreté de la traduction](/docs/translation-safety).
- `npx verbatra check` se termine avec `1` dès qu'une locale n'est plus synchronisée : il peut donc protéger une pull request.

Commite ensemble les fichiers de locale, `verbatra.lock.json` et `verbatra.provenance.json`.
