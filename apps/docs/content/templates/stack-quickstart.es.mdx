```bash

```

verbatra es una herramienta de desarrollo y nunca llega a tu app. En un proyecto sin `package.json`, como una app de Flutter, npm crea uno; añade `node_modules/` a su `.gitignore`. Los comandos de abajo usan `npx`; con pnpm, yarn o bun, ejecuta `pnpm verbatra`, `yarn verbatra` o `bun run verbatra`.

<StackBlock name="init" />

`--format` <StackText field="format" /> es el formato de archivo de <StackText field="library" />. `init` encuentra tus archivos de locale, o escribe el patrón <StackText field="pattern" /> cuando aún no hay ninguno. `--yes` acepta lo que `init` detectó en lugar de preguntar. ### Conecta tu agente

<AvailableFrom version="0.12.0" />

```bash
npx verbatra init --agent
```

Sáltate este paso si no trabajas con un agente de programación. Con la configuración ya creada, `init --agent` la conserva y añade solo los archivos del agente: las reglas de verbatra en `AGENTS.md` (o `CLAUDE.md`, cuando es tu único archivo de instrucciones) y el servidor MCP de verbatra en `.mcp.json`, sin las herramientas que gastan. Consulta [`verbatra init`](/docs/cli/init) y [Conectar un cliente MCP](/docs/connect-an-mcp-client).

## Qué acaba de pasar

- `verbatra.lock.json` guarda un hash de cada texto de origen, para que la siguiente ejecución envíe solo textos nuevos y modificados. Consulta [El archivo de bloqueo](/docs/the-lock-file).
- Un resultado que pierde un marcador de posición se retiene y nunca se escribe. Consulta [Seguridad de la traducción](/docs/translation-safety).
- `npx verbatra check` termina con `1` en cuanto un locale deja de estar sincronizado, así que puede proteger un pull request.

Haz commit de los archivos de locale, `verbatra.lock.json` y `verbatra.provenance.json` juntos.
