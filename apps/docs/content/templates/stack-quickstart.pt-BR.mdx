Ao final desta página, seu app <StackText field="name" /> exibe uma string em alemão que o verbatra traduziu a partir de <StackText field="sourceFile" />, e um arquivo de lock faz com que cada execução seguinte traduza só o que mudou. Você precisa do Node.js `^22.22.0 || >=24`, de um projeto <StackText field="name" /> e de cerca de dez minutos. Os quatro primeiros passos não exigem conta nem chave de API.

Já tem arquivos de locale e um agente de programação? Em vez disso, entregue a ele o prompt de [Configurar o verbatra com um agente de IA](/pt-BR/docs/start-with-ai): ele se adapta aos arquivos que seu projeto já tem e para antes de gastar qualquer coisa.

## O que acabou de acontecer

- O `verbatra.lock.json` registra um hash de cada string de origem, então a próxima execução envia só as strings novas e alteradas. Veja [O arquivo de lock e a procedência](/pt-BR/docs/the-lock-file).
- Um resultado que perde um placeholder fica retido e nunca é gravado. Veja [Segurança da tradução](/pt-BR/docs/translation-safety).

Faça commit dos arquivos de locale, do `verbatra.lock.json` e do `verbatra.provenance.json` juntos.

## Opcional: conectar seu agente de programação

<AvailableFrom version="0.12.0" />

```bash
npx @verbatra/cli init --agent
```

Com a configuração já existente, o `init --agent` a mantém e adiciona só os arquivos de agente: as regras do verbatra em `AGENTS.md` (ou em `CLAUDE.md`, quando esse é seu único arquivo de instruções) e o servidor MCP do verbatra, com os gastos desativados, na configuração de projeto de cada agente de programação que ele detecta. Quais arquivos ele grava para cada agente, e como usar `--client` para nomear os agentes você mesmo, estão em [Configurar agentes de programação](/pt-BR/docs/cli/init#configurar-agentes-de-programação). `--dry-run` mostra os arquivos sem gravá-los.

Ou, sem a CLI, adicione só o servidor MCP ao seu perfil de usuário do VS Code; use um caminho só, nunca os dois:
