<DocsHomeSection title="すべての実行は差分であり、書き換えではない" lead="`verbatra translate` を実行すると何が起きるかを説明します。">

ソースロケールを 1 つ手作業で保守すると、ほかのすべてのロケールファイルがドリフトします。新しいキーがターゲットから欠落し、編集された文字列は古くなった訳文を残し、削除されたキーは孤立したキーとして残ります。verbatra は、コミットされたロックファイル `verbatra.lock.json` と各ターゲットを比較し、変更されたものだけを設定したプロバイダーに送ることで、この差を埋めます。翻訳するものがない 2 回目の実行では、プロバイダーをまったく呼び出しません。すべての結果は書き込む前にチェックされるため、壊れたプレースホルダーは保留されて再試行され、そのまま書き込まれることはありません。処理の流れ全体は[実行の仕組み](/ja/docs/how-it-works)を参照してください。

<DocsHomeSteps />

verbatra は、JSON や YAML から XLIFF、gettext、Android や Apple のカタログまで、一般的なロケールファイルのフォーマットを読み書きします。対応する LLM や機械翻訳のプロバイダーを 1 つのインターフェースの背後で使って翻訳します（プロバイダーなしで使う場合は[機械翻訳なしで実行する](/ja/docs/human-only-workflow)を参照）。同梱されていないフォーマットは、[カスタムフォーマットアダプターを書く](/ja/docs/custom-format-adapters)ことで追加できます。一覧は[フォーマット](/ja/docs/formats)と[プロバイダー](/ja/docs/providers)にあります。

</DocsHomeSection>
