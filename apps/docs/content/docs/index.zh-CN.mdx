<DocsHomeSection title="每次运行都是差异比对，而不是重写。" lead="运行 `verbatra translate` 时会发生什么。">

手动维护一个源语言环境，意味着其他每个语言文件都会漂移：新键在目标文件中缺失，编辑过的字符串留下过期的译文，删除的键则作为孤立的键留着。verbatra 把每个目标与已提交的锁文件 `verbatra.lock.json` 比对，只把已更改的内容发给你配置的提供商，从而消除这种差距；没有新内容可翻译时，再运行一次根本不会调用提供商。每条结果在写入之前都会经过检查，因此损坏的占位符会被搁置并重试，绝不会发布出去。完整流程见[运行的工作原理](/zh-CN/docs/how-it-works)。

<DocsHomeSteps />

verbatra 读写常见的语言文件格式，从 JSON 和 YAML 到 XLIFF、gettext，以及 Android 和 Apple 的消息目录，并通过统一的接口，使用任何受支持的 LLM 或机器翻译提供商进行翻译（也可以一个都不用，见[不用机器翻译运行](/zh-CN/docs/human-only-workflow)）；verbatra 未内置的格式，可以写成自定义适配器加入（见[编写自定义格式适配器](/zh-CN/docs/custom-format-adapters)）。完整的列表见[格式](/zh-CN/docs/formats)和[提供商](/zh-CN/docs/providers)。

</DocsHomeSection>
