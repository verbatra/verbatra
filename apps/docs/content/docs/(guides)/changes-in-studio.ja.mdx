実行をコミットする前に使います。翻訳の実行や編集でどのロケールファイルが変わったか、各ファイルでどのキーが変わったかを、Studio を離れずに確認できます。読み取り専用で、Studio はステージ、コミット、復元のどれもしません。

## Changes セクションを開く

[Studio を起動する](/ja/docs/review-in-studio#studio-を起動する)の手順で Studio を起動し、**Overview**（概要）ページを、ロケール表の下にある **Changes**（変更）までスクロールします。チェックアウト中のブランチ（または **Detached HEAD**（デタッチされた HEAD））が表示され、最後のコミットと差があるすべてのファイルが 10 個ずつ並びます。残りは **Show all N files**（N 個のファイルをすべて表示）で表示します。

| 状態 | 意味 |
| --- | --- |
| **Modified**（変更済み） | ファイルが最後のコミットと異なる |
| **Added**（追加） | ファイルが新規で、ステージされている |
| **Deleted**（削除） | ファイルが作業ツリーまたはインデックスから消えている |
| **Untracked**（未追跡） | git がまだファイルを追跡していない |
| **Conflicted**（競合） | ファイルに未解決のマージ競合がある |
| **Matches last commit**（最後のコミットと一致） | 開いたあとに差がなくなったファイル。閉じるまでそのまま残る |

ソースとターゲットのロケールファイルが一覧に載ります。`verbatra.lock.json` と `verbatra.provenance.json` も載りますが、状態だけを示し、キーの変更は示しません。変更のないプロジェクトでは、差分のあるロケールファイルがないと表示されます。

## キーの変更を読む

**Key changes (de)**（de のキーの変更）を押すと、そのロケールのファイルがキー単位で開き、最後のコミットと比較されます。**Changed**（変更あり）のキーは古いテキストと新しいテキストが並んで表示され、**Added** のキーと **Removed**（削除済み）のキーも表示されます。もう一度ボタンを押すと閉じます。同時に開けるロケールは 1 つです。変更または追加されたキーがソースにもある場合は、**Translations**（訳文）ページのそのエントリへのリンクが付きます。

- **1 つのファイルに複数のロケール**：`apple-xcstrings` のようなカタログは、すべてのロケールを 1 つのファイルに持つため、ロケールごとにボタンが 1 つあります。各ボタンはそのロケールだけを比較します。
- **長い一覧**：一覧に含まれるキーは最大 500 件で、各テキストは 2,000 文字で切り捨てられます。切り捨てが起きた場合、Studio は一覧が不完全であることを示し、切り捨てられたテキストに印を付けます。完全な差分は git 自体で確認できます。長い一覧は 50 件ずつ表示されます。
- **順序だけが変わった場合**：**Modified** でもキーとテキストが変わっていないファイルには、その旨が表示されます。
- **競合**：未解決のマージ競合があるファイルは、状態だけを示し、キーの変更は示しません。先に git で競合を解決してください。
- **安全なテキスト**：キーと値は、ロケール自身の言語と方向のプレーンテキストとして表示します。マークアップとしては扱いません。

## 表示する内容がない場合

比較できない場合、Studio はエラーを出さずに理由を説明します。たとえば次のような場合です。

- プロジェクトが git リポジトリの中にない、または git がインストールされていない、または git のバージョンが部分クローンに必要なバージョンより古い場合
- 別のユーザーがフォルダーを所有しているために git がフォルダーを拒否する場合、またはフォルダーがベアリポジトリの中にある場合
- リポジトリにコンテンツフィルターが設定されている場合（Studio はフィルターを実行しません）
- `files.pattern` が `../` などでロケールファイルをプロジェクトフォルダーの外に置いていて、一覧からそのファイルが漏れる可能性がある場合

読み取りに時間がかかりすぎた場合や失敗した場合は、ページのエラーと **Retry**（再試行）を表示します。`custom:` フォーマットのプロジェクトでは、変更されたファイルは表示されますが、キーの変更は表示されません。Studio がコミット済みのファイルを比較するときに使うのは組み込みのフォーマットアダプターだけで、カスタムアダプターは実行できないためです。詳しくは[カスタムフォーマットアダプターを書く](/ja/docs/custom-format-adapters)を参照してください。

## データの鮮度を知る

ディスク上でロケールファイル、ロックファイル、来歴ファイルが変わったとき、git のインデックスや `HEAD` が変わったとき（コミット、ブランチの切り替え、リセット、`git add`）、Studio のタブやウィンドウに戻ったときに、このセクションは再読み込みします。読み取りに失敗した場合、Studio は直前の結果を保持し、その旨を表示します。

同じ読み取りは、自分のコードから [`localeGitStatus` と `localeGitDiff`](/ja/docs/sdk/review#localegitstatus) として使えます。比較できない理由と、適用される git の安全策がすべて一覧にあります。
