Use this when a translation was reworded and you want the earlier wording back, or to see who changed one key and when. It reads git. Studio never stages, commits or reverts anything: restoring only fills the editor with the old text, and you save it like any edit.

## Open the History tab

Start Studio ([Review in Studio](/docs/review-in-studio#start-studio)), open a key in Translations and choose **History** next to **Locales**. Pick the locale if the project has several. Studio reads nothing from git until you open the tab.

The list starts with **Working tree (uncommitted)** when the file on disk differs from the last commit. Under it, newest first, comes every commit that changed the key's value in that locale. Each row shows:

| Part | What it tells you |
| --- | --- |
| Author, date, subject | the commit, with the author's name and never the email |
| Origin | who wrote the value, as recorded with that commit, left out when that record could not be read |
| Value | the text at that commit, in the locale's own language and direction |
| Changes from the previous value | words added or removed, marked by underline and strike-through as well as colour, and read aloud as "added" and "removed" |

Everything is plain text, never markup. A key that appears in a value or a subject is replaced by `[REDACTED]`.

## Restore an earlier value

1. Press **Restore** on a row. The editor opens on **Locales** with that value as a draft. Nothing is written yet.
2. Read the draft and press **Save**. The usual checks run, including placeholders, ICU and pinned keys, and a refusal is shown as it is with the file left alone. A saved value is recorded with the origin `human`.

If you have unsaved changes, Studio asks before it replaces them. **Keep editing** leaves your draft alone and **Discard** loads the restored value.

A value that already is the key's current value, a value that held an API key and a project Studio cannot write to get no **Restore**, and the row says why.

### When the source has changed

If the source text has changed since that commit, or Studio cannot tell, **Restore** first asks you to confirm. Saving then marks the key as up to date against the current source and adds the value to translation memory, so an old wording can be reused for similar keys. **Cancel** leaves everything as it was.

## Know what the list leaves out

Studio never presents a partial list as complete. A notice appears when:

- older commits were not read, because of the commit limit, a shallow clone or the read budget;
- a commit's file could not be read or parsed, or the value was too long, and Studio counts how many;
- the file on disk could not be compared with the last commit, for example during a merge conflict.

An empty list says whether it is empty or only the part Studio could read. Renames are not followed, edits that were never committed are missed, a key renamed in the source looks new, and a change that arrived by merge shows on the merge commit.

When git is missing, the folder is not a repository or git refuses it, Studio says so in a sentence. A read that fails or times out shows **Retry** and keeps the last list.

## Know how fresh it is

The tab reads again when a locale, lock or provenance file changes, when git's index or `HEAD` changes and when you return to the Studio tab. A background read never moves your focus.

In the Review editor, **Show history** opens the same list for that entry, and **Restore** fills its field.

The same reads are available as [`keyHistory`](/docs/sdk/history#keyhistory), to an [MCP client](/docs/cli/mcp) and to a [browser agent](/docs/agent-tools-in-studio).
