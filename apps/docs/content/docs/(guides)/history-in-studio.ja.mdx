訳文の表現が変わったあとで以前の表現を戻したいときや、誰がいつ 1 つのキーを変更したかを知りたいときに使います。読み取るのは git です。Studio はステージもコミットもせず、変更を元に戻すこともしません。復元はエディターに古いテキストを入れるだけで、保存は通常の編集と同じように行います。

## History タブを開く

[Studio を起動する](/ja/docs/review-in-studio#studio-を起動する)の手順で Studio を起動し、**Translations**（訳文）でキーを開いて、**Locales**（ロケール）の横にある **History**（履歴）を選びます。プロジェクトに複数のロケールがある場合は、ロケールを選びます。Studio がそのキーの履歴を git から読み込むのは、タブを開いたときだけです。

ディスク上のファイルが最後のコミットと異なる場合、一覧の先頭は **Working tree (uncommitted)**（作業ツリー（未コミット））です。その下に、そのロケールでキーの値を変更したすべてのコミットが新しい順に並びます。20 行ずつ表示され、残りは **Show N more**（さらに N 件を表示）で表示します。各行には次の内容が表示されます。

| 部分 | わかること |
| --- | --- |
| 作者、日付、短いハッシュ、件名 | コミットの情報。作者は名前だけで、メールアドレスは表示しない |
| 出どころ | そのコミットに記録された、値を書いた主体。記録を読み取れなかった場合は表示しない |
| 値 | そのコミット時点のテキスト。ロケール自身の言語と方向で、省略せずに表示する |
| 直前の値からの変更 | 追加または削除された単語。色に加えて下線と取り消し線で示し、「added」「removed」と読み上げられる |

表示はすべてプレーンテキストで、マークアップとしては扱いません。値、件名、作者名の中に現れた API キーは `[REDACTED]` に置き換えられます。

## 以前の値を復元する

1. 行の **Restore**（復元）を押します。エディターが **Locales** で開き、その値が下書きとして入ります。この時点では何も書き込まれません。
2. 下書きを読んで **Save**（保存）を押します。プレースホルダーや ICU を含む通常のチェックが実行されます。拒否された場合は、ファイルに手を加えずにそのまま表示されます。保存された値は、出どころ `human` で記録されます。

保存していない変更がある場合、Studio は先に確認します。**Save draft, then restore**（下書きを保存してから復元）は下書きを保存してから古い値を読み込みます。**Discard draft and restore**（下書きを破棄して復元）は下書きを捨てます。**Keep editing**（編集を続ける）は何も変えません。Review エディターでは、確認がダイアログの上部に表示され、下書きを置き換える方法は **Discard draft and restore** だけです。

行に **Restore** が付かず、理由が表示される場合があります。その値がキーの現在の値である場合、Studio が現在の値をまだ読み取っていないか読み取れなかった場合、値が API キーのように見える場合です。API キーのように見える値は、History に表示されず、ここから復元することもできません。

`pinnedKeys` のキーは人のために確保されています。そのため、Studio から保存した復元は通ります。エージェントによるそのキーの編集は拒否されます。

### ソースが変更されている場合

そのコミット以降にソーステキストが変更されている場合、**Restore** はまず確認を求めます。Studio が判断できない場合（そのコミットのロックファイルを読み取れない、またはキーのエントリがない場合）は、その旨を表示します。保存すると、キーは現在のソースに対して最新の状態になり、値が翻訳メモリに追加されます。そのため、古い表現を似たキーで再利用できます。**Cancel**（キャンセル）または Escape を押すと、何も変わりません。

## 一覧に含まれないものを知る

Studio は、一部だけの一覧を完全な一覧として示すことはありません。次の場合に通知が表示されます。

- コミット数の上限、浅いクローン、読み取りの予算のために、古いコミットを読み取っていない場合
- コミットのファイルを読み取れなかった、解析できなかった、または値が長すぎた場合（Studio は該当する件数を数える）
- ディスク上のファイルを最後のコミットと比較できなかった場合（たとえばマージ競合中）

Studio はまず 50 件のコミットを調べます。その上限で一覧が途切れた場合は、通知でそう示され、**Read further back**（さらに前を読み込む）で 1 回に最大 200 件まで読み込みます。それ以降は、Studio が読む範囲の限界であることだけが通知に表示されます。そのほかの原因にはそれぞれ専用の通知が表示され、**Read further back** は表示されません。空の一覧には、本当に空なのか、Studio が読んだ範囲が空なのかが示されます。ファイル名の変更は追跡されません。コミットされていない編集は検出されません。ソースで名前が変わったキーは新しいキーに見えます。マージで入った変更はマージコミットに表示されます。

git がない場合、フォルダーがリポジトリでない場合、または git がフォルダーを拒否する場合は、Studio が 1 文でそう伝えます。読み取りが失敗した場合やタイムアウトした場合は **Retry**（再試行）が表示され、直前の一覧が保持されます。

## データの鮮度を知る

ロケールファイル、ロックファイル、来歴ファイルが変わったとき、git のインデックスや `HEAD` が変わったとき、Studio のタブに戻ったときに、タブは再読み込みします。読み取りは間隔を空けて行われるため、連続したコミットで Studio に負荷がかかることはありません。バックグラウンドの読み取りがフォーカスを動かすことはありません。

Review エディターでは、**Show history**（履歴を表示）がそのエントリの同じ一覧を開き、同じ方法で再読み込みします。**Restore** は、そのエントリのフィールドに値を入れます。

同じ読み取りは [`keyHistory`](/ja/docs/sdk/history#keyhistory) として利用できるほか、MCP クライアント（[verbatra mcp](/ja/docs/cli/mcp)）とブラウザーエージェント（[ブラウザーエージェントで Studio を操作する](/ja/docs/agent-tools-in-studio)）からも利用できます。
