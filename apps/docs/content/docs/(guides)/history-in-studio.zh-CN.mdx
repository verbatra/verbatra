译文被改写后想找回之前的措辞，或者想知道谁在什么时候改了某个键时，用它。它读取 git。Studio 不会暂存、提交或还原任何内容：恢复只是把旧文本填入编辑器，你像保存其他编辑一样保存它。

## 打开 History 标签页

启动 Studio（见[在 Studio 中审校](/zh-CN/docs/review-in-studio#启动-studio)），在 **Translations**（翻译）中打开一个键，选择 **Locales**（语言环境）旁边的 **History**（历史记录）。项目有多个语言环境时，先选择语言环境。只有打开该标签页时，Studio 才会从 git 读取这个键的历史记录。

当磁盘上的文件与上次提交不同时，列表以 **Working tree (uncommitted)**（工作树，未提交）开头。其下按从新到旧的顺序，列出该语言环境中更改过这个键的值的每次提交，一次显示 20 行，其余的用 **Show N more**（再显示 N 条）展开。每行显示：

| 部分 | 说明 |
| --- | --- |
| 作者、日期、短哈希、提交主题 | 提交本身，作者只显示姓名，不显示邮箱 |
| Origin（来源） | 该值由谁写入，取自随该提交记录的信息，无法读取该记录时省略 |
| Value（值） | 该提交时的文本，使用该语言环境自己的语言和书写方向，绝不截断 |
| Changes from the previous value（与上一个值的差异） | 新增或删除的词，用下划线和删除线标出，不只靠颜色，并朗读为“added”和“removed” |

所有内容都是纯文本，绝不按 HTML 渲染。值、提交主题或作者姓名中出现的密钥会替换为 `[REDACTED]`。

## 恢复较早的值

1. 在某一行上按 **Restore**（恢复）。编辑器会在 **Locales** 中打开，并把该值作为草稿载入。此时还没有写入任何内容。
2. 阅读草稿，然后按 **Save**（保存）。通常的检查照常运行，包括占位符和 ICU，被拒绝时会原样显示拒绝信息，文件保持不变。保存的值以来源 `human` 记录。

如果你有未保存的更改，Studio 会先询问。**Save draft, then restore**（保存草稿，然后恢复）保留你的草稿，再载入旧值；**Discard draft and restore**（丢弃草稿并恢复）丢弃草稿；**Keep editing**（继续编辑）则保持原样。在 **Review**（审校）编辑器中，这个问题显示在对话框顶部，要替换草稿，只能用 **Discard draft and restore**。

以下情况中，该行没有 **Restore**，并会说明原因：该值就是键当前的值，Studio 还没有读取当前值或读取失败，或者该值看起来像 API 密钥（History 不显示这样的值，也无法从这里恢复）。

`pinnedKeys` 中的键留给人工处理，因此从 Studio 保存的恢复可以通过，而智能体对它的编辑会被拒绝。

### 源文本已更改时

如果自该提交以来源文本已更改，**Restore** 会先请你确认。Studio 无法判断时（该提交时的锁文件无法读取，或其中没有该键的条目），它会说明这一点。随后保存会把该键标记为相对当前源文本已是最新，并把该值加入翻译记忆库，这样旧措辞就可以复用于相似的键。**Cancel**（取消）或按 Escape 会保持原样。

## 了解列表遗漏了什么

Studio 绝不会把不完整的列表当作完整的列表呈现。出现以下情况时会显示通知：

- 较早的提交没有读取，原因是提交数量上限、浅克隆或读取预算；
- 某次提交的文件无法读取或解析，或者值太长，Studio 会统计有多少次；
- 磁盘上的文件无法与上次提交比较，例如处于合并冲突期间。

Studio 先检查 50 次提交。该上限使列表被截短时，通知会说明这一点，**Read further back**（继续向前读取）一步最多读取 200 次提交；之后通知只会说明 Studio 最多读到这里。其他每种原因都有各自的通知，其中任何一种都不会出现 **Read further back**。列表为空时，会说明是真的为空，还是只有 Studio 读取的部分为空。重命名不会被跟踪，从未提交的编辑会被漏掉，源文件中重命名的键看起来像新键，通过合并带来的更改显示在合并提交上。

git 缺失、目录不是仓库或 git 拒绝访问该目录时，Studio 用一句话说明。读取失败或超时时，会显示 **Retry**（重试）并保留上一次的列表。

## 了解数据有多新

语言文件、锁文件或来源记录文件发生更改时，git 的索引或 `HEAD` 发生变化时，以及你回到 Studio 的标签页时，该标签页会重新读取。读取之间留有间隔，因此连续的提交不会让 Studio 不堪重负。后台读取绝不会移动你的焦点。

在 Review 编辑器中，**Show history**（显示历史记录）会为该条目打开同一个列表，以同样的方式重新读取，**Restore** 会把值填入该条目的字段。

同样的读取也以 [`keyHistory`](/zh-CN/docs/sdk/history#keyhistory) 的形式提供，可供 MCP 客户端（见 [verbatra mcp](/zh-CN/docs/cli/mcp)）和浏览器智能体（见[用浏览器智能体操作 Studio](/zh-CN/docs/agent-tools-in-studio)）使用。
