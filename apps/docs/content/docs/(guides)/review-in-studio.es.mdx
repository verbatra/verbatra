Usa esto para revisar traducciones automáticas antes de publicarlas: encuentra lo pendiente, corrige valores a mano y aprueba o rechaza lo que escribió un proveedor, en Verbatra Studio, un panel local sobre tu proyecto.

Dos reglas valen en todo momento. **La edición local está siempre activa**, sujeta a las mismas comprobaciones de integridad que cualquier otra escritura. **El gasto con el proveedor está siempre desactivado** salvo que arranques Studio con `--allow-spend`.

## Arranca Studio

Studio se distribuye como paquete propio, al que llegas a través de la CLI:

```bash
npm install --save-dev @verbatra/studio
verbatra studio
```

Abre la URL que imprime, token incluido, y detén Studio con Ctrl+C. [`verbatra studio`](/docs/cli/studio) cubre el puerto, el token y cada opción. Cada página se actualiza en vivo cuando cambia un archivo de locale, el archivo de bloqueo o el archivo de procedencia.

## Lee la página Translations

Translations lista cada clave que falta, modificada o huérfana, como una **List** por locale con un filtro de texto o como un **Grid** de claves por locale, sobre una tabla con la cobertura de cada locale y el estado del [archivo de bloqueo](/docs/the-lock-file).

Haz clic en una clave para ver el valor de cada locale con un indicador de integridad: los placeholders coinciden, un desajuste de placeholders con los tokens nombrados, o una sintaxis de mensaje no válida. También se muestra:

| Detalle | Muestra |
| --- | --- |
| **Inline markup mismatch** | cada etiqueta que la traducción quitó (`-`) o añadió (`+`) <AvailableFrom version="0.5.1" pkg="@verbatra/studio" /> |
| **ICU arms mismatch** | ramas plural o select que no encajan con el idioma de destino; los valores de derecha a izquierda se muestran de derecha a izquierda ([Idiomas y locales](/docs/language-support#idiomas-de-derecha-a-izquierda)) <AvailableFrom version="0.6.0" pkg="@verbatra/studio" /> |
| Insignia de origen | quién escribió cada valor, leída de [`verbatra.provenance.json`](/docs/the-lock-file#procedencia-quién-escribió-cada-valor), por ejemplo **Machine**, **Human** o **Edited outside verbatra** <AvailableFrom version="0.6.0" pkg="@verbatra/studio" /> |

### Filtrar por estado

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

La vista List también filtra por locale y por estado, incluidos **Review queue** e **Integrity problems** (cualquier valor que no pasa las comprobaciones de placeholders, marcado o ICU). **Copy as review report** copia las claves pendientes como Markdown para un pull request.

### Edita con la puerta de integridad

**Edit** abre el editor. Guardar pasa el valor por la [puerta de integridad](/docs/translation-safety#la-puerta-de-integridad); un valor rechazado no se escribe, y se muestra el motivo. Una edición aceptada escribe el archivo de locale y actualiza el archivo de bloqueo. Editar no necesita ninguna opción y nunca llama a un proveedor.

#### Editor lado a lado

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

El editor muestra el origen y tu borrador lado a lado, con la descripción de la clave, los términos del glosario que tu borrador usa u omite, y su longitud frente al origen y a `maxLength`. Ctrl o Cmd con Enter guarda.

## Trabaja la cola de Review

La página Review lista cada valor que escribió una máquina y que nadie ha aprobado: una fila por locale y clave, con su origen y cualquier [señal de revisión](/docs/translation-safety#señales-de-revisión) de la última ejecución en esta máquina.

### Nombres de las señales

<AvailableFrom version="0.5.1" pkg="@verbatra/studio" />

Dos señales de revisión se leen **Over length budget** y **Reused after source edit**.

### Acciones por fila

<AvailableFrom version="0.5.0" pkg="@verbatra/studio" />

Filtra por locale o por texto en la clave, el origen o la traducción:

- **Edit** abre el editor con la puerta de integridad. Una edición aceptada saca la fila de la cola.
- **Approve** acepta el valor tal como está.
- **Reject** elimina el valor para que se sustituya, tras una confirmación.

### Decisiones guardadas

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

Ambas decisiones se guardan en `verbatra.provenance.json` según las reglas de [Decisiones de revisión](/docs/the-lock-file#decisiones-de-revisión), incluido lo que quita un rechazo. Una aprobación además necesita que el valor esté al día con su origen. Confirma juntos el archivo de locale, el archivo de bloqueo y el archivo de procedencia; en un proyecto XLIFF, edita en lugar de rechazar.

### Una cola para todo el equipo

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

La cola se lee de los archivos confirmados, así que un compañero que los descarga ve la misma cola. Un valor sale de ella en cuanto una persona lo aprueba, lo rechaza, lo escribe o lo importa; un valor aprobado que una máquina reescribe vuelve a entrar.

La barra de filtros cambia entre **Needs review** y **Approved** y acota por origen; con un locale elegido, **Approve all in** lo aprueba entero tras una confirmación. Para que un pull request falle mientras haya traducciones automáticas esperando, ejecuta [`verbatra check --require-reviewed`](/docs/cli/check#exigir-traducciones-revisadas) en la CI.

### Trabaja la cola con el teclado

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

Pulsa `j` o la flecha abajo para resaltar la primera entrada, y luego:

| Tecla | Acción |
| --- | --- |
| `j` o flecha abajo | entrada siguiente |
| `k` o flecha arriba | entrada anterior |
| `a` | aprobar la entrada resaltada |
| `r` | rechazarla (la confirmación se sigue abriendo) |
| `e` o Enter | abrirla en el editor |
| `t` | retraducirla (solo con `--allow-spend`; llama a tu proveedor) |
| `x` | seleccionarla o quitarla de la selección para una acción en bloque |
| `?` | mostrar u ocultar la lista de atajos |

Los atajos se pausan mientras escribes o hay un diálogo abierto. Tras una decisión se resalta la entrada siguiente, así que volver a pulsar `a` recorre la cola hacia abajo.

### Actúa sobre varias entradas a la vez

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

Marca filas (o la casilla de la cabecera para todo lo que muestra el filtro) y elige **Approve selected**, **Reject selected** o, con `--allow-spend`, **Retranslate selected**. Cada entrada se decide como se decidiría sola; los fallos se listan por causa y siguen seleccionados para reintentar. Un lote admite como máximo 100 entradas para aprobar o rechazar, o 20 para retraducir.

## Retraduce una clave marcada

Arranca Studio con el gasto permitido ([cómo se concede el gasto](/docs/cli/studio#gasto-y-herramientas-de-agente)):

```bash
verbatra studio --allow-spend
```

Aparece entonces un botón **Retranslate** en cada fila de Review, y en la vista de detalle de una clave para un valor con un defecto de integridad. Hace una sola llamada al proveedor, pasa el resultado por la puerta de integridad y deja el nuevo valor en la cola para que lo apruebes. Desde una fila de Review, un valor que escribió una persona nunca se sustituye; en su vista de detalle en Translations, elige **Replace anyway**. Sin `--allow-spend` el servidor ni siquiera registra el endpoint, así que el gasto no se puede activar desde el navegador.

## Traduce los cambios pendientes

Cuando el archivo de origen cambia mientras Studio está en marcha, un aviso nombra el archivo y las claves añadidas, modificadas o eliminadas. Con `--allow-spend`, además ofrece **Translate pending changes across all locales**: la misma ejecución que haría `verbatra translate`, con el resultado indicado en el propio aviso.

## Revisa la última ejecución en Activity

Activity muestra el historial de git de tus archivos de locale y el uso de tokens de la última ejecución registrada, con el medidor de presupuesto cuando hay un presupuesto de tokens configurado.

## Mantén el glosario al día en Settings

<AvailableFrom version="0.4.0" pkg="@verbatra/studio" />

Settings muestra la configuración con la que arrancó Studio y el glosario. Si el glosario es un archivo JSON, puedes añadir, editar y eliminar términos; cada cambio se escribe directamente en el archivo. Un glosario escrito dentro de `verbatra.config.ts` sigue siendo de solo lectura.

Una edición del glosario cambia lo que se le indica a la siguiente ejecución, nunca el texto ya escrito; reinicia Studio para que sus propias retraducciones la usen.

### Vista por locale

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

**Show translations for** cambia a la vista del [glosario](/docs/config-file#glossary) de un locale, con su traducción, las variantes prohibidas y la nota. La lista **Do not translate** mantiene los nombres de marca tal como se escriben.
