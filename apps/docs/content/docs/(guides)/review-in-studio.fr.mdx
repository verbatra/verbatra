Utilise ceci pour vérifier les traductions automatiques avant leur mise en ligne : trouve ce qui est en attente, corrige des valeurs à la main, et approuve ou rejette ce qu'un fournisseur a écrit, dans Verbatra Studio, un tableau de bord local au-dessus de ton projet.

Deux règles valent tout du long. **La modification locale est toujours active**, soumise aux mêmes contrôles d'intégrité que toute autre écriture. **La dépense auprès du fournisseur est toujours désactivée**, sauf si tu démarres Studio avec `--allow-spend`.

## Démarrer Studio

Studio est livré comme paquet à part, atteint via la CLI :

```bash
npm install --save-dev @verbatra/studio
verbatra studio
```

Ouvre l'URL qu'il affiche, token compris, et arrête Studio avec Ctrl+C. [`verbatra studio`](/docs/cli/studio) couvre le port, le token et toutes les options. Chaque page se rafraîchit en direct quand un fichier de locale, le fichier de verrouillage ou le fichier de provenance change.

## Lire la page Translations

Translations liste chaque clé manquante, modifiée et orpheline, sous forme de **List** par locale avec un filtre texte ou de **Grid** clé par locale, au-dessus d'un tableau de la couverture de chaque locale et de son état dans le [fichier de verrouillage](/docs/the-lock-file).

Clique sur une clé pour voir la valeur de chaque locale avec un indicateur d'intégrité : placeholders conformes, placeholders divergents avec les tokens nommés, ou syntaxe de message invalide. Également affiché :

| Détail | Affiche |
| --- | --- |
| **Inline markup mismatch** | chaque balise que la traduction a perdue (`-`) ou ajoutée (`+`) <AvailableFrom version="0.5.1" pkg="@verbatra/studio" /> |
| **ICU arms mismatch** | les branches plural ou select qui ne conviennent pas à la langue cible ; les valeurs de droite à gauche s'affichent de droite à gauche ([Prise en charge des langues](/docs/language-support#langues-de-droite-à-gauche)) <AvailableFrom version="0.6.0" pkg="@verbatra/studio" /> |
| Badge d'origine | qui a écrit chaque valeur, lu depuis [`verbatra.provenance.json`](/docs/the-lock-file#la-provenance-de-chaque-valeur), par exemple **Machine**, **Human** ou **Edited outside verbatra** <AvailableFrom version="0.6.0" pkg="@verbatra/studio" /> |

### Filtrer par état

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

La vue List filtre aussi par locale et par état, notamment **Review queue** et **Integrity problems** (toute valeur qui échoue aux contrôles de placeholders, de balisage ou ICU). **Copy as review report** copie les clés en attente en Markdown pour une pull request.

### Modifier avec la barrière d'intégrité

**Edit** ouvre l'éditeur. L'enregistrement fait passer la valeur par la [barrière d'intégrité](/docs/translation-safety#la-barrière-dintégrité) ; une valeur refusée n'est pas écrite, et la raison s'affiche. Une modification acceptée écrit le fichier de locale et met à jour le fichier de verrouillage. Modifier ne demande aucune option et n'appelle jamais de fournisseur.

#### Éditeur côte à côte

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

L'éditeur montre la source et ton brouillon côte à côte, avec la description de la clé, les termes du glossaire que ton brouillon utilise ou oublie, et sa longueur par rapport à la source et à `maxLength`. Ctrl ou Cmd avec Entrée enregistre.

## Traiter la file de relecture

La page Review liste chaque valeur écrite par une machine que personne n'a approuvée : une ligne par locale et par clé, avec le texte source au-dessus de la traduction, son origine et les éventuels [signalements de relecture](/docs/translation-safety#signalements-de-relecture) de la dernière exécution sur cette machine.

### Libellés des signalements

<AvailableFrom version="0.5.1" pkg="@verbatra/studio" />

Deux signalements de relecture s'affichent comme **Over length budget** et **Reused after source edit**.

### Actions par ligne

<AvailableFrom version="0.5.0" pkg="@verbatra/studio" />

Filtre par locale ou par texte dans la clé, la source ou la traduction, puis traite chaque ligne :

- **Edit** ouvre l'éditeur soumis à la barrière d'intégrité. Une modification acceptée retire la ligne.
- **Approve** accepte la valeur telle quelle.
- **Reject** supprime la valeur pour qu'elle soit remplacée, après une confirmation.

### Décisions enregistrées

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

Les deux décisions sont enregistrées dans `verbatra.provenance.json` selon les règles des [Décisions de relecture](/docs/the-lock-file#décisions-de-relecture), y compris ce qu'un rejet retire. Une approbation exige aussi que la valeur soit à jour par rapport à sa source. Commite ensemble le fichier de locale, le fichier de verrouillage et le fichier de provenance ; dans un projet XLIFF, modifie au lieu de rejeter.

### Une seule file pour toute l'équipe

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

La file est lue depuis les fichiers commités, donc un coéquipier qui les récupère voit la même file. Une valeur la quitte dès qu'une personne l'approuve, la rejette, l'écrit ou l'importe ; une valeur approuvée qu'une machine réécrit y revient.

La barre de filtres bascule entre **Needs review** et **Approved** et restreint par origine ; une locale choisie, **Approve all in** l'approuve en entier après une confirmation. Pour faire échouer une pull request tant que des traductions automatiques attendent, lance [`verbatra check --require-reviewed`](/docs/cli/check#exiger-des-traductions-relues) en CI.

### Traiter la file au clavier

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

Appuie sur `j` ou la flèche bas pour mettre en surbrillance la première entrée, puis :

| Touche | Action |
| --- | --- |
| `j` ou flèche bas | entrée suivante |
| `k` ou flèche haut | entrée précédente |
| `a` | approuver l'entrée en surbrillance |
| `r` | la rejeter (la confirmation s'ouvre quand même) |
| `e` ou Entrée | l'ouvrir dans l'éditeur |
| `t` | la retraduire (seulement avec `--allow-spend` ; appelle ton fournisseur) |
| `x` | la sélectionner ou désélectionner pour une action groupée |
| `?` | afficher ou masquer la liste des raccourcis |

Les raccourcis sont en pause pendant que tu tapes ou qu'une boîte de dialogue est ouverte. Après une décision, l'entrée suivante est mise en surbrillance, donc `a` à nouveau descend dans la file.

### Agir sur plusieurs entrées à la fois

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

Coche des lignes (ou la case d'en-tête pour tout ce que le filtre affiche), puis choisis **Approve selected**, **Reject selected** ou, avec `--allow-spend`, **Retranslate selected**. Chaque entrée est tranchée comme elle le serait seule ; les échecs sont listés par cause et restent sélectionnés pour réessayer. Un lot contient au plus 100 entrées à approuver ou rejeter, ou 20 à retraduire.

## Retraduire une clé signalée

Démarre Studio avec la dépense autorisée ([comment la dépense est accordée](/docs/cli/studio#dépenses-et-outils-dagent))  :

```bash
verbatra studio --allow-spend
```

Un bouton **Retranslate** apparaît alors sur chaque ligne de Review, et dans la vue détaillée d'une clé pour une valeur avec un défaut d'intégrité. Il fait un appel au fournisseur, passe le résultat par la barrière d'intégrité et laisse la nouvelle valeur dans la file pour que tu l'approuves. Depuis une ligne de Review, une valeur écrite par une personne n'est jamais remplacée ; dans sa vue détaillée sur Translations, choisis **Replace anyway**. Sans `--allow-spend`, le serveur n'enregistre pas du tout le point d'accès, donc la dépense ne peut pas être activée depuis le navigateur.

## Traduire les changements en attente

Quand le fichier source change pendant que Studio tourne, une notification nomme le fichier et les clés ajoutées, modifiées ou supprimées. Avec `--allow-spend`, elle propose aussi **Translate pending changes across all locales** : la même exécution que `verbatra translate`, avec le résultat affiché sur place.

## Voir la dernière exécution sur Activity

Activity montre l'historique git de tes fichiers de locale et la consommation de tokens de la dernière exécution enregistrée, avec la jauge de budget quand un budget de tokens est configuré.

## Garder le glossaire à jour dans Settings

<AvailableFrom version="0.4.0" pkg="@verbatra/studio" />

Settings montre la configuration avec laquelle Studio a démarré, et le glossaire. Si le glossaire est un fichier JSON, tu peux ajouter, modifier et supprimer des termes ; chaque changement est écrit directement dans le fichier. Un glossaire inline dans `verbatra.config.ts` reste en lecture seule.

Une modification du glossaire change ce que la prochaine exécution reçoit comme consigne, jamais un texte déjà écrit ; redémarre Studio pour que ses propres retraductions l'utilisent.

### Vue par locale

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

**Show translations for** bascule vers la vue du [glossaire](/docs/config-file#glossary) d'une locale, avec sa traduction, ses rendus interdits et sa note. La liste **Do not translate** garde les noms de marque tels quels.
