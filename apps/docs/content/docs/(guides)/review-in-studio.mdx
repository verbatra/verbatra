Use this to check machine translations before they ship: find what is pending, fix values by hand, and approve or reject what a provider wrote, in Verbatra Studio, a local dashboard over your project.

Two rules hold throughout. **Local editing is always on**, gated by the same integrity checks as every other write. **Provider spend is always off** unless you start Studio with `--allow-spend`.

## Start Studio

Studio ships as its own package, reached through the CLI:

```bash
npm install --save-dev @verbatra/studio
verbatra studio
```

Open the URL it prints, token included, and stop Studio with Ctrl+C. [`verbatra studio`](/docs/cli/studio) covers the port, the token and every flag. Every page refreshes live when a locale file, the lock file or the provenance file changes.

## Read the Translations page

Translations lists every missing, changed and orphaned key, as a **List** per locale with a text filter or as a key-by-locale **Grid**, above a table of each locale's coverage and [lock file](/docs/the-lock-file) state.

Click a key to see every locale's value with an integrity indicator: placeholders match, a placeholder mismatch with the tokens named, or invalid message syntax. Also shown:

| Detail | Shows |
| --- | --- |
| **Inline markup mismatch** | each tag the translation dropped (`-`) or added (`+`) <AvailableFrom version="0.5.1" pkg="@verbatra/studio" /> |
| **ICU arms mismatch** | plural or select arms that do not fit the target language; right-to-left values render right to left ([Language support](/docs/language-support#right-to-left-languages)) <AvailableFrom version="0.6.0" pkg="@verbatra/studio" /> |
| Origin badge | who wrote each value, read from [`verbatra.provenance.json`](/docs/the-lock-file#provenance-who-wrote-each-value), such as **Machine**, **Human** or **Edited outside verbatra** <AvailableFrom version="0.6.0" pkg="@verbatra/studio" /> |

### Filter by state

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

The List view also filters by locale and by state, including **Review queue** and **Integrity problems** (any value that fails the placeholder, markup or ICU checks). **Copy as review report** copies the pending keys as Markdown for a pull request.

### Edit with integrity gating

**Edit** opens the editor. Saving runs the value through the [integrity gate](/docs/translation-safety#the-integrity-gate); a value it refuses is not written, and the reason is shown. An accepted edit writes the locale file and updates the lock file. Editing needs no flag and never calls a provider.

#### Side-by-side editor

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

The editor shows the source and your draft side by side, with the key's description, the glossary terms your draft uses or misses, and its length against the source and `maxLength`. Ctrl or Cmd with Enter saves.

## Work the Review queue

The Review page lists every value a machine wrote that nobody has approved: one row per locale and key, with its origin and any [review flags](/docs/translation-safety#review-flags) from the last run on this machine.

### Flag labels

<AvailableFrom version="0.5.1" pkg="@verbatra/studio" />

Two review flags read **Over length budget** and **Reused after source edit**.

### Row actions

<AvailableFrom version="0.5.0" pkg="@verbatra/studio" />

Filter by locale or by text in the key, source or translation, then work each row:

- **Edit** opens the integrity-gated editor. An accepted edit clears the row.
- **Approve** accepts the value as it stands.
- **Reject** removes the value so it gets replaced, after a confirmation.

### Saved decisions

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

Both decisions are saved in `verbatra.provenance.json` under the rules in [Review decisions](/docs/the-lock-file#review-decisions), including what a rejection removes. An approval also needs the value to be up to date with its source. Commit the locale file, the lock file and the provenance file together; in an XLIFF project, edit instead of rejecting.

### One queue for the whole team

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

The queue is read from the committed files, so a teammate who pulls them sees the same queue. A value leaves it once a person approves, rejects, writes or imports it; an approved value that a machine rewrites comes back.

The filter bar switches between **Needs review** and **Approved** and narrows by origin; with a locale chosen, **Approve all in** approves all of it after a confirmation. To fail a pull request while machine translations wait, run [`verbatra check --require-reviewed`](/docs/cli/check#require-reviewed-translations) in CI.

### Work the queue from the keyboard

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

Press `j` or the down arrow to highlight the first entry, then:

| Key | Action |
| --- | --- |
| `j` or down arrow | next entry |
| `k` or up arrow | previous entry |
| `a` | approve the highlighted entry |
| `r` | reject it (the confirmation still opens) |
| `e` or Enter | open it in the editor |
| `t` | retranslate it (only with `--allow-spend`; calls your provider) |
| `x` | select or unselect it for a bulk action |
| `?` | show or hide the shortcut list |

Shortcuts pause while you type or a dialog is open. After a decision the next entry is highlighted, so `a` again works down the queue.

### Act on several entries at once

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

Tick rows (or the header box for everything the filter shows), then choose **Approve selected**, **Reject selected** or, with `--allow-spend`, **Retranslate selected**. Each entry is decided as it would be on its own; failures are listed by cause and stay selected for a retry. A batch holds at most 100 entries to approve or reject, or 20 to retranslate.

## Retranslate a flagged key

Start Studio with spend allowed ([how spend is granted](/docs/cli/studio#spend-and-agent-tools)):

```bash
verbatra studio --allow-spend
```

A **Retranslate** button then appears on each Review row, and in a key's detail view for a value with an integrity defect. It makes one provider call, runs the result through the integrity gate, and leaves the new value in the queue for you to approve. From a Review row, a value a person wrote is never replaced; in its detail view on Translations, choose **Replace anyway**. Without `--allow-spend` the server does not register the endpoint at all, so spend cannot be switched on from the browser.

## Translate pending changes

When the source file changes while Studio runs, a toast names the file and the keys added, changed or removed. With `--allow-spend`, it also offers **Translate pending changes across all locales**: the same run `verbatra translate` would do, with the result reported inline.

## Check the last run on Activity

Activity shows the git history of your locale files and the token usage of the last recorded run, with the budget meter when a token budget is configured.

## Keep the glossary current on Settings

<AvailableFrom version="0.4.0" pkg="@verbatra/studio" />

Settings shows the configuration Studio started with and the glossary. If the glossary is a JSON file, you can add, edit and remove terms; each change is written straight to the file. An inline glossary in `verbatra.config.ts` stays read-only.

A glossary edit changes what the next run is told, never text already written; restart Studio for its own retranslations to use it.

### Per-locale view

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

**Show translations for** switches to one locale's [glossary](/docs/config-file#glossary) view, with its translation, forbidden renderings and note. The **Do not translate** list keeps brand names as written.
