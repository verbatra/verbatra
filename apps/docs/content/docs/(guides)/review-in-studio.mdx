Check machine translations before they ship: find what is pending, fix values, and approve or reject what a provider wrote, in Verbatra Studio, a local dashboard.

Two rules hold. **Local editing is always on**, gated by the same integrity checks as other writes. **Provider spend is always off** unless you start Studio with `--allow-spend`.

## Start Studio

```bash
npm install --save-dev @verbatra/studio
verbatra studio
```

Open the URL it prints, token included; stop Studio with Ctrl+C. [`verbatra studio`](/docs/cli/studio) covers the port, token and flags. Every page refreshes live when a locale, lock or provenance file changes.

## Read the Translations page

### One key table

<AvailableFrom version="0.7.0" pkg="@verbatra/studio" />

Translations is one table of every key that needs attention: missing, changed, orphaned, protected, in the review queue or failing an integrity check. Each row shows the key, source text and a status per locale; pick a locale for translation, status and origin. Search also finds in-sync keys.

### Key details

Click a key to open its editor. It lists every locale's value with an integrity indicator: placeholders match, a placeholder mismatch with the tokens named, or invalid message syntax. Also shown:

| Detail | Shows |
| --- | --- |
| **Inline markup mismatch** | each tag the translation dropped (`-`) or added (`+`) <AvailableFrom version="0.5.1" pkg="@verbatra/studio" /> |
| **ICU arms mismatch** | plural or select arms that do not fit the target language; right-to-left values render right to left ([Language support](/docs/language-support#right-to-left-languages)) <AvailableFrom version="0.6.0" pkg="@verbatra/studio" /> |
| Origin badge | who wrote each value, read from [`verbatra.provenance.json`](/docs/the-lock-file#provenance-who-wrote-each-value), such as **Machine**, **Human** or **Edited outside verbatra** <AvailableFrom version="0.6.0" pkg="@verbatra/studio" /> |

### Filter by state

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

Chips beside the search narrow the table by state, including **Review queue** and **Integrity problems** (a value failing placeholder, markup or ICU checks). **Copy as review report** copies the pending keys as Markdown for a pull request.

### Edit with integrity gating

**Edit** opens that locale's draft. Saving runs the value through the [integrity gate](/docs/translation-safety#the-integrity-gate); a value it refuses is not written, and the reason is shown. An accepted edit writes the locale file and updates the lock file. Editing needs no flag and calls no provider.

#### Draft checks

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

The editor shows the key's description, the glossary terms your draft uses or misses, and its length against the source and `maxLength`. Ctrl or Cmd with Enter saves.

#### Beside the table

<AvailableFrom version="0.7.0" pkg="@verbatra/studio" />

From 1280px wide the editor sits beside the table; below that it opens as a drawer. Leaving the key with unsaved edits, by choosing another key, filtering, searching, opening another page or going Back, asks you to save, discard or keep editing; leaving Studio itself gets the browser's own confirmation.

## Work the Review queue

The Review page lists every value a machine wrote that nobody approved: one row per locale and key with the full source and translation (long values wrap), origin and any [review flags](/docs/translation-safety#review-flags) from the last run on this machine.

### Flag labels

<AvailableFrom version="0.5.1" pkg="@verbatra/studio" />

Two review flags read **Over length budget** and **Reused after source edit**.

### Row actions

<AvailableFrom version="0.5.0" pkg="@verbatra/studio" />

Filter by locale or text, then:

- **Edit** opens the integrity-gated editor. An accepted edit clears the row.
- **Approve** accepts the value.
- **Reject** removes the value for replacement, after confirming.

### Saved decisions

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

Both decisions are saved in `verbatra.provenance.json` under the [Review decisions](/docs/the-lock-file#review-decisions) rules, including what a rejection removes. An approval also needs the value to be up to date with its source. Commit the locale, lock and provenance files together; in an XLIFF project, edit instead of rejecting.

### One queue for the whole team

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

The queue is read from the committed files, so a teammate who pulls them sees it too. A value leaves it once a person approves, rejects, writes or imports it; an approved value that a machine rewrites comes back.

The **Needs review** and **Approved** chips switch the list and show counts; the bar narrows by origin; with a locale chosen, **Approve all in** approves all of it after a confirmation. To fail a pull request while machine translations wait, run [`verbatra check --require-reviewed`](/docs/cli/check#require-reviewed-translations) in CI.

### Work the queue from the keyboard

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

Press `j` or the down arrow to highlight the first entry, then:

| Key | Action |
| --- | --- |
| `j` or down arrow | next entry |
| `k` or up arrow | previous entry |
| `a` | approve the highlighted entry |
| `r` | reject it (the confirmation still opens) |
| `e` or Enter | open it in the editor |
| `t` | retranslate it (only with `--allow-spend`; calls your provider) |
| `x` | select or unselect it for a bulk action |
| `?` | show or hide the shortcut list |

Shortcuts pause while you type, in the filter bar, or in a dialog. After a decision the next entry is highlighted.

### Act on several entries at once

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

Tick rows (or the header box for all filtered rows), then choose **Approve selected**, **Reject selected** or, with `--allow-spend`, **Retranslate selected**. Each entry is decided as it would be on its own; failures are listed by cause and stay selected. A batch holds at most 100 entries to approve or reject, or 20 to retranslate.

## Retranslate a flagged key

Start Studio with spend allowed ([how spend is granted](/docs/cli/studio#spend-and-agent-tools)):

```bash
verbatra studio --allow-spend
```

A **Retranslate** button then appears on each Review row, and in a key's editor for a value with an integrity defect. It makes one provider call, runs the result through the integrity gate, and leaves the new value in the queue to approve. From a Review row, a value a person wrote is never replaced; in its editor on Translations, choose **Replace anyway**.

## Translate pending changes

When the source file changes while Studio runs, a toast names the file and the keys added, changed or removed. With `--allow-spend`, it also offers **Translate pending changes across all locales**: the same run `verbatra translate` would do, with the result reported inline.

## Keep the glossary current on the Glossary page

<AvailableFrom version="0.4.0" pkg="@verbatra/studio" />

Glossary has its own page, where it sat on Settings before 0.7.0. With a JSON glossary you can search, add, edit and remove terms, each written to the file. Removing a term asks first; unsaved edits ask before you leave. An inline glossary in `verbatra.config.ts` stays read-only.

An edit changes what the next run is told, never text already written.

### Per-locale view

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

**Show translations for** switches to one locale's [glossary](/docs/config-file#glossary) view: translation, forbidden renderings and note. The **Do not translate** list keeps brand names.
