Damit prüfst du maschinelle Übersetzungen, bevor sie ausgeliefert werden: Du findest, was offen ist, korrigierst Werte von Hand und gibst frei oder lehnst ab, was ein Provider geschrieben hat, in Verbatra Studio, einem lokalen Dashboard über deinem Projekt.

Zwei Regeln gelten durchgehend. **Lokales Bearbeiten ist immer an**, abgesichert durch dieselben Integritätsprüfungen wie jeder andere Schreibvorgang. **Kostenpflichtige Provider-Aufrufe sind immer aus**, außer du startest Studio mit `--allow-spend`.

## Starte Studio

Studio kommt als eigenes Paket und wird über die CLI gestartet:

```bash
npm install --save-dev @verbatra/studio
verbatra studio
```

Öffne die ausgegebene URL samt Token und beende Studio mit Strg+C. [`verbatra studio`](/docs/cli/studio) erklärt Port, Token und jedes Flag. Jede Seite aktualisiert sich live, wenn sich eine Locale-Datei, die Lock-Datei oder die Herkunftsdatei ändert.

## Lies die Seite Translations

Translations listet jeden fehlenden, geänderten und verwaisten Key, als **List** pro Locale mit Textfilter oder als **Grid** aus Keys und Locales, über einer Tabelle mit der Abdeckung jeder Locale und dem Zustand in der [Lock-Datei](/docs/the-lock-file).

Klick auf einen Key, um den Wert jeder Locale mit einer Integritätsanzeige zu sehen: Platzhalter stimmen, eine Platzhalter-Abweichung mit den benannten Tokens oder ungültige Nachrichtensyntax. Außerdem angezeigt:

| Detail | Zeigt |
| --- | --- |
| **Inline markup mismatch** | jedes Tag, das die Übersetzung weggelassen (`-`) oder hinzugefügt (`+`) hat <AvailableFrom version="0.5.1" pkg="@verbatra/studio" /> |
| **ICU arms mismatch** | Plural- oder Select-Zweige, die nicht zur Zielsprache passen; Werte von rechts nach links werden auch so dargestellt ([Sprachunterstützung](/docs/language-support#sprachen-die-von-rechts-nach-links-laufen)) <AvailableFrom version="0.6.0" pkg="@verbatra/studio" /> |
| Herkunfts-Badge | wer jeden Wert geschrieben hat, gelesen aus [`verbatra.provenance.json`](/docs/the-lock-file#herkunft-wer-welchen-wert-geschrieben-hat), etwa **Machine**, **Human** oder **Edited outside verbatra** <AvailableFrom version="0.6.0" pkg="@verbatra/studio" /> |

### Nach Zustand filtern

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

Die Listenansicht filtert außerdem nach Locale und Zustand, darunter **Review queue** und **Integrity problems** (jeder Wert, der die Prüfungen für Platzhalter, Markup oder ICU nicht besteht). **Copy as review report** kopiert die offenen Keys als Markdown für einen Pull Request.

### Bearbeiten mit Integritäts-Gate

**Edit** öffnet den Editor. Beim Speichern durchläuft der Wert das [Integritäts-Gate](/docs/translation-safety#das-integritäts-gate); ein abgelehnter Wert wird nicht geschrieben, und der Grund wird angezeigt. Eine angenommene Bearbeitung schreibt die Locale-Datei und aktualisiert die Lock-Datei. Bearbeiten braucht kein Flag und ruft nie einen Provider auf.

#### Editor mit Vergleichsansicht

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

Der Editor zeigt Quelle und Entwurf nebeneinander, mit der Beschreibung des Keys, den Glossarbegriffen, die dein Entwurf verwendet oder verfehlt, und seiner Länge im Vergleich zur Quelle und zu `maxLength`. Strg oder Cmd mit Enter speichert.

## Arbeite die Review-Warteschlange ab

Die Seite Review listet jeden Wert, den eine Maschine geschrieben und niemand freigegeben hat: eine Zeile pro Locale und Key, mit dem Quelltext über der Übersetzung, seiner Herkunft und etwaigen [Review-Flags](/docs/translation-safety#review-flags) aus dem letzten Lauf auf diesem Rechner.

### Flag-Bezeichnungen

<AvailableFrom version="0.5.1" pkg="@verbatra/studio" />

Zwei Review-Flags heißen **Over length budget** und **Reused after source edit**.

### Aktionen je Zeile

<AvailableFrom version="0.5.0" pkg="@verbatra/studio" />

Filtere nach Locale oder nach Text in Key, Quelle oder Übersetzung, dann arbeite jede Zeile ab:

- **Edit** öffnet den Editor mit Integritäts-Gate. Eine angenommene Bearbeitung entfernt die Zeile.
- **Approve** nimmt den Wert so an, wie er ist.
- **Reject** entfernt den Wert, damit er ersetzt wird, nach einer Bestätigung.

### Gespeicherte Entscheidungen

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

Beide Entscheidungen werden in `verbatra.provenance.json` nach den Regeln unter [Review-Entscheidungen](/docs/the-lock-file#review-entscheidungen) gespeichert, auch was eine Ablehnung entfernt. Eine Freigabe verlangt außerdem, dass der Wert zu seiner Quelle passt. Committe Locale-Datei, Lock-Datei und Herkunftsdatei zusammen; in einem XLIFF-Projekt bearbeitest du, statt abzulehnen.

### Eine Warteschlange für das ganze Team

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

Die Warteschlange wird aus den committeten Dateien gelesen, sodass eine Teamkollegin, die sie pullt, dieselbe Warteschlange sieht. Ein Wert verlässt sie, sobald eine Person ihn freigibt, ablehnt, schreibt oder importiert; ein freigegebener Wert, den eine Maschine neu schreibt, kommt zurück.

Die Filterleiste wechselt zwischen **Needs review** und **Approved** und grenzt nach Herkunft ein; mit gewählter Locale gibt **Approve all in** nach einer Bestätigung alles davon frei. Um einen Pull Request scheitern zu lassen, solange maschinelle Übersetzungen warten, führ in der CI [`verbatra check --require-reviewed`](/docs/cli/check#freigegebene-übersetzungen-verlangen) aus.

### Arbeite die Warteschlange mit der Tastatur ab

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

Drück `j` oder Pfeil nach unten, um den ersten Eintrag hervorzuheben, dann:

| Taste | Aktion |
| --- | --- |
| `j` oder Pfeil nach unten | nächster Eintrag |
| `k` oder Pfeil nach oben | vorheriger Eintrag |
| `a` | den hervorgehobenen Eintrag freigeben |
| `r` | ihn ablehnen (die Bestätigung öffnet sich trotzdem) |
| `e` oder Enter | ihn im Editor öffnen |
| `t` | ihn neu übersetzen (nur mit `--allow-spend`; ruft deinen Provider auf) |
| `x` | ihn für eine Sammelaktion auswählen oder abwählen |
| `?` | die Tastenkürzel ein- oder ausblenden |

Tastenkürzel pausieren, während du tippst oder ein Dialog offen ist. Nach einer Entscheidung wird der nächste Eintrag hervorgehoben, sodass du mit `a` die Warteschlange hinunterarbeitest.

### Bearbeite mehrere Einträge auf einmal

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

Hak Zeilen an (oder das Kästchen im Tabellenkopf für alles, was der Filter zeigt), dann wähl **Approve selected**, **Reject selected** oder, mit `--allow-spend`, **Retranslate selected**. Jeder Eintrag wird so entschieden wie einzeln; Fehlschläge werden nach Ursache gelistet und bleiben für einen neuen Versuch ausgewählt. Ein Stapel umfasst höchstens 100 Einträge zum Freigeben oder Ablehnen oder 20 zum Neuübersetzen.

## Übersetze einen markierten Key neu

Starte Studio mit erlaubten Ausgaben ([wie Ausgaben erlaubt werden](/docs/cli/studio#ausgaben-und-agent-tools)):

```bash
verbatra studio --allow-spend
```

Dann erscheint ein Button **Retranslate** in jeder Review-Zeile und in der Detailansicht eines Keys bei einem Wert mit Integritätsdefekt. Er macht einen Provider-Aufruf, schickt das Ergebnis durch das Integritäts-Gate und lässt den neuen Wert zur Freigabe in der Warteschlange. Aus einer Review-Zeile wird ein Wert, den eine Person geschrieben hat, nie ersetzt; wähl dafür in seiner Detailansicht unter Translations **Replace anyway**. Ohne `--allow-spend` registriert der Server den Endpunkt gar nicht, sodass sich Ausgaben nicht aus dem Browser einschalten lassen.

## Übersetze ausstehende Änderungen

Ändert sich die Quelldatei, während Studio läuft, nennt eine Benachrichtigung die Datei und die hinzugefügten, geänderten oder entfernten Keys. Mit `--allow-spend` bietet sie außerdem **Translate pending changes across all locales** an: denselben Lauf, den `verbatra translate` machen würde, mit dem Ergebnis direkt daneben.

## Prüfe den letzten Lauf unter Activity

Activity zeigt die Git-Historie deiner Locale-Dateien und den Token-Verbrauch des letzten erfassten Laufs, mit der Budgetanzeige, wenn ein Token-Budget konfiguriert ist.

## Halte das Glossar unter Settings aktuell

<AvailableFrom version="0.4.0" pkg="@verbatra/studio" />

Settings zeigt die Konfiguration, mit der Studio gestartet wurde, und das Glossar. Ist das Glossar eine JSON-Datei, kannst du Begriffe hinzufügen, bearbeiten und entfernen; jede Änderung wird direkt in die Datei geschrieben. Ein Inline-Glossar in `verbatra.config.ts` bleibt schreibgeschützt.

Eine Glossaränderung ändert, was dem nächsten Lauf gesagt wird, nie bereits geschriebenen Text; starte Studio neu, damit seine eigenen Neuübersetzungen sie nutzen.

### Ansicht pro Locale

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

**Show translations for** wechselt in die [Glossar](/docs/config-file#glossary)-Ansicht einer Locale, mit ihrer Übersetzung, verbotenen Varianten und Notiz. Die Liste **Do not translate** hält Markennamen so, wie sie geschrieben sind.
