Damit prüfst du maschinelle Übersetzungen, bevor sie ausgeliefert werden: Du findest, was offen ist, korrigierst Werte von Hand und gibst frei oder lehnst ab, was ein Provider geschrieben hat, in Verbatra Studio, einem lokalen Dashboard über deinem Projekt.

Zwei Regeln gelten durchgehend. **Lokales Bearbeiten ist immer an**, abgesichert durch dieselben Integritätsprüfungen wie jeder andere Schreibvorgang. **Kostenpflichtige Provider-Aufrufe sind immer aus**, außer du startest Studio mit `--allow-spend`.

## Starte Studio

```bash
npm install --save-dev @verbatra/studio
verbatra studio
```

Öffne die ausgegebene URL samt Token und beende Studio mit Strg+C. [`verbatra studio`](/de/docs/cli/studio) erklärt Port, Token und jedes Flag. Jede Seite aktualisiert sich live, wenn sich eine Locale-Datei, die Lock-Datei, die Herkunftsdatei oder die Limit-Datei ändert.

## Lies die Seite Translations

### Eine Key-Tabelle

<AvailableFrom version="0.7.0" pkg="@verbatra/studio" />

Translations ist eine Tabelle aller Keys, die Aufmerksamkeit brauchen: fehlend, geändert, verwaist, geschützt, in der Review-Warteschlange oder mit fehlgeschlagener Integritätsprüfung. Jede Zeile zeigt Key, Quelltext und einen Status pro Locale; wähl eine Locale für Übersetzung, Status und Herkunft. Die Suche findet auch Keys, die synchron sind.

### Key-Details

Klick auf einen Key, um seinen Editor zu öffnen. Er listet den Wert jeder Locale mit einer Integritätsanzeige: Platzhalter stimmen, eine Platzhalter-Abweichung mit den benannten Tokens oder ungültige Nachrichtensyntax. Außerdem angezeigt:

| Detail | Zeigt |
| --- | --- |
| **Inline markup mismatch** | jedes Tag, das die Übersetzung weggelassen (`-`) oder hinzugefügt (`+`) hat <AvailableFrom version="0.5.1" pkg="@verbatra/studio" /> |
| **ICU arms mismatch** | Plural- oder Select-Zweige, die nicht zur Zielsprache passen; Werte von rechts nach links werden auch so dargestellt ([Sprachunterstützung](/de/docs/language-support#sprachen-die-von-rechts-nach-links-laufen)) <AvailableFrom version="0.6.0" pkg="@verbatra/studio" /> |
| Herkunfts-Badge | wer jeden Wert geschrieben hat, gelesen aus [`verbatra.provenance.json`](/de/docs/the-lock-file#herkunft-wer-welchen-wert-geschrieben-hat), etwa **Machine**, **Human** oder **Edited outside verbatra** <AvailableFrom version="0.6.0" pkg="@verbatra/studio" /> |

### Nach Zustand filtern

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

Die Chips neben der Suche grenzen die Tabelle nach Zustand ein, darunter **Review queue** und **Integrity problems** (ein Wert, der die Prüfungen für Platzhalter, Markup oder ICU nicht besteht). **Copy as review report** kopiert die offenen Keys als Markdown für einen Pull Request.

### Bearbeiten mit Integritäts-Gate

**Edit** öffnet den Entwurf dieser Locale. Beim Speichern durchläuft der Wert das [Integritäts-Gate](/de/docs/translation-safety#das-integritäts-gate); ein abgelehnter Wert wird nicht geschrieben, und der Grund wird angezeigt. Eine angenommene Bearbeitung schreibt die Locale-Datei und aktualisiert die Lock-Datei.

#### Entwurfsprüfungen

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

Der Editor zeigt dir die Beschreibung des Keys, welche Glossarbegriffe dein Entwurf trifft oder auslässt und wie lang er im Vergleich zur Quelle und zu `maxLength` ist.
#### Ein Längenlimit setzen

<AvailableFrom version="0.7.0" pkg="@verbatra/studio" />

Unter der Längenzeile bearbeiten **Set limit**, **Change limit** und **Remove limit** den Eintrag des Keys in [`verbatra.limits.json`](/de/docs/config-file#maxlength), für jede Locale. Das `maxLength` der Konfiguration gewinnt und ist schreibgeschützt. Eine unbrauchbare Datei zeigt den Grund und sperrt das Bedienelement. Ein Limit ist nur ein Hinweis: Translate-Läufe markieren einen längeren Wert zur Prüfung, nichts wird blockiert. Studio setzt Limits nur für Keys der Quelle; ein Limit, das für den eigenen Key einer erzeugten Form geschrieben wurde, gilt weiterhin.

#### Nachrichten mit der ICU preview prüfen

<AvailableFrom version="0.7.0" pkg="@verbatra/studio" />

Mit `next-intl-json` oder `arb` rendert eine eingeklappte **ICU preview** unter dem Entwurf diesen einmal pro Zweig in Sprache und Schreibrichtung der Locale. Ein eingegebener Beispielwert fügt eine Zeile hinzu, wenn er einen Zweig erreicht, oder einen Hinweis, wenn er ungenutzt bleibt. Zahlen und Datumsangaben nutzen die Sprachdaten dieses Computers, deine App kann abweichen.

#### Neben der Tabelle

<AvailableFrom version="0.7.0" pkg="@verbatra/studio" />

Ab 1280px Breite sitzt der Editor neben der Tabelle; darunter öffnet er sich als Schublade. Verlässt du den Key mit ungespeicherten Änderungen, ob du einen anderen Key öffnest, filterst, suchst, eine andere Seite aufrufst oder zurückgehst, fragt Studio, ob du speichern, verwerfen oder weiterbearbeiten willst; beim Verlassen von Studio selbst bestätigt der Browser.

## Arbeite die Review-Warteschlange ab

Die Seite Review listet jeden Wert, den eine Maschine geschrieben und niemand freigegeben hat: eine Zeile pro Locale und Key, mit dem vollständigen Quelltext über der Übersetzung (lange Werte umbrechen), seiner Herkunft und etwaigen [Review-Flags](/de/docs/translation-safety#review-flags) aus dem letzten Lauf auf diesem Rechner.

### Flag-Bezeichnungen

<AvailableFrom version="0.5.1" pkg="@verbatra/studio" />

Zwei Review-Flags heißen **Over length budget** und **Reused after source edit**.

### Aktionen je Zeile

<AvailableFrom version="0.5.0" pkg="@verbatra/studio" />

Filtere nach Locale oder Text, dann arbeite jede Zeile ab:

- **Edit** öffnet den Editor mit Integritäts-Gate. Eine angenommene Bearbeitung entfernt die Zeile.
- **Approve** nimmt den Wert so an, wie er ist.
- **Reject** entfernt den Wert, damit er ersetzt wird, nach einer Bestätigung.

### Gespeicherte Entscheidungen

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

Beide Entscheidungen werden in `verbatra.provenance.json` nach den Regeln unter [Review-Entscheidungen](/de/docs/the-lock-file#review-entscheidungen) gespeichert. Eine Freigabe verlangt außerdem, dass der Wert zu seiner Quelle passt. Committe Locale-Datei, Lock-Datei und Herkunftsdatei zusammen; in einem XLIFF-Projekt bearbeitest du, statt abzulehnen.

### Eine Warteschlange für das ganze Team

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

Die Warteschlange wird aus den committeten Dateien gelesen, sodass eine Teamkollegin, die sie pullt, dieselbe Warteschlange sieht. Ein Wert verlässt sie, sobald eine Person ihn freigibt, ablehnt, schreibt oder importiert; ein freigegebener Wert, den eine Maschine neu schreibt, kommt zurück.

Die Chips **Needs review** und **Approved** wechseln die Liste und zeigen Zähler; die Leiste grenzt nach Herkunft ein; mit gewählter Locale gibt **Approve all in** nach einer Bestätigung alles davon frei. Um einen Pull Request scheitern zu lassen, solange maschinelle Übersetzungen warten, führ in der CI [`verbatra check --require-reviewed`](/de/docs/cli/check#freigegebene-übersetzungen-verlangen) aus.

### Arbeite die Warteschlange mit der Tastatur ab

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

Drück `j` oder Pfeil nach unten, um den ersten Eintrag hervorzuheben, dann:

| Taste | Aktion |
| --- | --- |
| `j` oder Pfeil nach unten | nächster Eintrag |
| `k` oder Pfeil nach oben | vorheriger Eintrag |
| `a` | den hervorgehobenen Eintrag freigeben |
| `r` | ihn ablehnen (die Bestätigung öffnet sich trotzdem) |
| `e` oder Enter | ihn im Editor öffnen |
| `t` | ihn neu übersetzen (nur mit `--allow-spend`; ruft deinen Provider auf) |
| `x` | ihn für eine Sammelaktion auswählen oder abwählen |
| `?` | die Tastenkürzel ein- oder ausblenden |

Tastenkürzel pausieren, während du tippst, der Fokus in der Filterleiste liegt oder ein Dialog offen ist. Nach einer Entscheidung wird der nächste Eintrag hervorgehoben.

### Bearbeite mehrere Einträge auf einmal

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

Hak Zeilen an (oder das Kästchen im Tabellenkopf für alles, was der Filter zeigt), dann wähl **Approve selected**, **Reject selected** oder, mit `--allow-spend`, **Retranslate selected**. Jeder Eintrag wird so entschieden wie einzeln; Fehlschläge werden nach Ursache gelistet und bleiben ausgewählt. Ein Stapel umfasst höchstens 100 Einträge zum Freigeben oder Ablehnen oder 20 zum Neuübersetzen.

## Übersetze einen markierten Key neu

Starte Studio mit erlaubten Ausgaben ([wie Ausgaben erlaubt werden](/de/docs/cli/studio#ausgaben-und-agent-tools)):

```bash
verbatra studio --allow-spend
```

Dann erscheint ein Button **Retranslate** in jeder Review-Zeile und im Editor eines Keys bei einem Wert mit Integritätsdefekt. Er macht einen Provider-Aufruf, schickt das Ergebnis durch das Integritäts-Gate und lässt den neuen Wert zur Freigabe in der Warteschlange. Aus einer Review-Zeile wird ein Wert, den eine Person geschrieben hat, nie ersetzt; wähl dafür in seinem Editor unter Translations **Replace anyway**.

## Übersetze ausstehende Änderungen

Ändert sich die Quelldatei, während Studio läuft, nennt eine Benachrichtigung die Datei und die hinzugefügten, geänderten oder entfernten Keys. Mit `--allow-spend` bietet sie außerdem **Translate pending changes across all locales** an: denselben Lauf, den `verbatra translate` machen würde.

## Prüfe Abdeckung und letzten Lauf unter Overview

<AvailableFrom version="0.7.0" pkg="@verbatra/studio" />

Overview ist die Seite, auf der Studio startet. Sie zeigt die Abdeckung jeder Locale mit ihrem Zustand in der [Lock-Datei](/de/docs/the-lock-file), die Git-Historie deiner Locale-Dateien und den Token-Verbrauch des letzten erfassten Laufs, mit der Budgetanzeige, wenn ein Token-Budget konfiguriert ist.

## Halte das Glossar auf der Seite Glossary aktuell

<AvailableFrom version="0.4.0" pkg="@verbatra/studio" />

Glossary hat eine eigene Seite, früher unter Settings. Bei einem JSON-Glossar kannst du Begriffe suchen, hinzufügen, bearbeiten und entfernen. Entfernen fragt zuerst; ungespeicherte Änderungen fragen vor dem Verlassen nach. Ein Inline-Glossar bleibt schreibgeschützt.

Eine Glossaränderung ändert, was dem nächsten Lauf gesagt wird, nie bereits geschriebenen Text; starte Studio neu, damit seine eigenen Neuübersetzungen sie nutzen.

### Ansicht pro Locale

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

**Show translations for** wechselt in die [Glossar](/de/docs/config-file#glossary)-Ansicht einer Locale, mit ihrer Übersetzung, verbotenen Varianten und Notiz. Die Liste **Do not translate** hält Markennamen so, wie sie geschrieben sind.
