Use this before a first run on a real project, or before any run someone has to approve. verbatra publishes no prices, because rates belong to the provider and change without notice. It counts what you will be billed for, and turns that into money once you give it your provider's current rates.

For a typical project, a few hundred keys into a few locales on a small model costs cents, and the next run costs almost nothing because only changed keys are sent.

## Count the work

```bash
verbatra translate --dry-run
```

```text output
verbatra translate (dry run)
  de: 400 would translate, 0 unchanged
  es: 400 would translate, 0 unchanged
  fr: 400 would translate, 0 unchanged
3 succeeded, 0 partial, 0 failed (dry run: nothing written)
```

`would translate` is the number of keys a real run would send: those missing from the target file plus those whose source text changed. A dry run constructs no provider, reads no key and writes nothing. Treat the count as an upper bound: it skips [the cache](/docs/the-cache), which serves repeat strings for free on a real run, and it does not merge identical source strings, which a real run sends once.

## Estimate the spend

<AvailableFrom version="0.11.0" />

```bash
verbatra translate --estimate
```

```text output
verbatra translate (estimate)
  de: 400 would translate, 0 unchanged
  es: 400 would translate, 0 unchanged
  fr: 400 would translate, 0 unchanged
  estimate: 1200 keys in 24 requests, ~40944 input + ~30720 output tokens
  estimated spend: no rate on file for gemini/gemini-2.5-flash; add rates.table["gemini/gemini-2.5-flash"] to your config to see a currency figure
  estimate excludes: cache hits, duplicate source strings, provider-side retries, translation length, tokenizer differences, repair requests
3 succeeded, 0 partial, 0 failed (dry run: nothing written)
```

`--estimate` implies `--dry-run`, so it spends nothing. It reports the unit your provider bills: tokens for an LLM, source characters for DeepL and Google Cloud Translation, and no API cost for a self-hosted `openai-compatible` or `libretranslate` server. With `--json`, the same figures sit under `result.estimate` per locale and in total, so a script can gate on them.

To see money, look up your model's current rate on the provider's own pricing page:

| Provider | Billed by | Pricing |
| --- | --- | --- |
| Gemini | input and output tokens (free tier available) | [Gemini API pricing](https://ai.google.dev/gemini-api/docs/pricing) |
| Anthropic | input and output tokens | [Anthropic pricing](https://www.anthropic.com/pricing) |
| OpenAI | input and output tokens | [OpenAI API pricing](https://openai.com/api/pricing/) |
| DeepL | source characters | [DeepL Pro pricing](https://www.deepl.com/pro) |
| Google Cloud Translation | source characters | [Cloud Translation pricing](https://cloud.google.com/translate/pricing) |
| openai-compatible, LibreTranslate | nothing: your own server | no API cost |

Then add it to the config with the date you read it:

```ts title="verbatra.config.ts"
export default defineConfig({
  // ...
  rates: {
    asOf: "2026-01-15",
    currency: "USD",
    table: {
      "gemini/gemini-2.5-flash": { inputPerMillionTokens: 0.1, outputPerMillionTokens: 0.4 },
    },
  },
});
```

The rates above are placeholders, not quoted prices. Every figure printed from them carries the `asOf` date, so an old rate card is visibly old. verbatra never invents a missing rate or prints `0.00` for a model it cannot price; it names the missing entry instead. See [`rates`](/docs/config-file#rates) for the key format and units.

## Know what the figure covers

The estimate performs the arithmetic you would otherwise do by hand:

- **Requests.** Each locale's keys are split into batches of at most [`maxBatchSize`](/docs/config-file#maxbatchsize) (default `50`), one request each, plus the batches [`generatePlurals`](/docs/config-file#generateplurals) would send.
- **Input.** Every LLM request carries fixed system rules (about 550 tokens) and a response schema (about 100 tokens), then the keys, their descriptions, the tone, and the target locale's full glossary. The prompt is measured by serializing the payload that would be sent, so a large glossary is counted on every request it rides on.
- **Output.** A translation does not exist yet, so it is sized as the source text plus 50 percent, since German, French and Russian often run a third to a half longer than English.
- **Tokens.** Characters are converted at about four per token, which fits English prose; other scripts run denser.

A real run usually costs less, for the two reasons the dry-run count is an upper bound. It can also cost more, and the `estimate excludes` line names each way. Two matter most:

- **Retries.** Each provider SDK retries a failed request on its own: two extra attempts for Anthropic, OpenAI, `openai-compatible` and Gemini, and five for DeepL. An attempt that reached the model is billed.
- **Repairs.** When keys come back missing, verbatra sends one repair request, which carries the system rules, glossary and tone again in full.

Plan with the figure; do not promise it as a ceiling. The estimate also covers `translate` only: retranslating one entry from [Studio](/docs/review-in-studio) or an agent tool spends on its own path.

## Cap the run

<AvailableFrom version="0.12.0" />

Give the run you agreed to a hard stop a little above the estimate's input plus output tokens:

```bash
verbatra translate --max-tokens 80000
```

A request that would pass the ceiling is withheld rather than sent, and its keys stay pending for the next run. When the config also sets `maxTokens`, the lower figure applies. DeepL, Google Cloud Translation and LibreTranslate report no tokens, so the ceiling is enforced against verbatra's own projection for them. See [Token ceiling](/docs/cli/translate#token-ceiling), and [`maxTokens` and `budgetBehavior`](/docs/config-file#maxtokens-and-budgetbehavior) for a budget that applies to every run.

## Calibrate on one locale

The precise number comes from a real run. Translate one locale and read the usage:

```bash
verbatra translate --locales de
```

```text output
verbatra translate
  de: 400 translated, 0 unchanged, 18400 tokens (10800 in, 7600 out)
  total: 18400 tokens (10800 in, 7600 out)
1 succeeded, 0 partial, 0 failed
```

Multiply by the number of remaining locales. With `--json`, the figures are `usage.inputTokens` and `usage.outputTokens`. The run spends real money, but the work is kept: that locale is done.

## Machine-translation providers

DeepL, Google Cloud Translation and LibreTranslate bill source characters, not tokens. verbatra sends them only the source text, with no system rules, key names or JSON around it, so there is no per-request overhead. Strings with placeholders or ICU syntax are withheld rather than risked, so the characters sent can be fewer than the raw total.

### Google Cloud Translation

<AvailableFrom version="0.10.0" />

Google Cloud Translation is counted like DeepL: source characters in the estimate, and a projected token figure for a `maxTokens` budget, marked as estimated on the run summary.

## Estimate from an agent

Two agent tools return what `translate --estimate --json` prints, for all locales or a subset, and never call a provider:

| Tool | Where |
| --- | --- |
| `translation.estimate` | the [MCP server](/docs/cli/mcp) <AvailableFrom version="0.3.0" pkg="@verbatra/mcp" /> |
| `verbatra_translation_estimate` | [Studio's agent tools](/docs/agent-tools-in-studio) <AvailableFrom version="0.6.0" pkg="@verbatra/studio" /> |

### Spend within the estimate

<AvailableFrom version="0.3.0" pkg="@verbatra/mcp" />

`translation.translatePending` then takes the same `locales` and a `maxTokens` ceiling. See [Estimate, then spend](/docs/cli/mcp#estimate-then-spend).

## Why the next run costs less

The figures above are the first-run cost. After that, verbatra sends only keys that are missing or whose source changed since [the lock file](/docs/the-lock-file) baseline, and [the cache](/docs/the-cache) reuses earlier translations of identical strings. Day to day you pay for the strings you edited. To rehearse for free, use Gemini's free tier or point `openai-compatible` at a local model; see [Providers](/docs/providers).
