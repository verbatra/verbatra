Usa esto antes de la primera ejecución en un proyecto real, o antes de cualquier ejecución que alguien tenga que aprobar. verbatra no publica precios, porque las tarifas son del proveedor y cambian sin avisar. Cuenta lo que se te va a facturar y lo convierte en dinero en cuanto le das las tarifas actuales de tu proveedor.

En un proyecto típico, unos cientos de claves a unos pocos locales con un modelo pequeño cuestan céntimos, y la siguiente ejecución casi nada, porque solo se envían las claves que cambiaron.

## Cuenta el trabajo

```bash
verbatra translate --dry-run
```

```text output
verbatra translate (dry run)
  de: 400 would translate, 0 unchanged
  es: 400 would translate, 0 unchanged
  fr: 400 would translate, 0 unchanged
3 succeeded, 0 partial, 0 failed (dry run: nothing written)
```

`would translate` es el número de claves que enviaría una ejecución real: las que faltan en el archivo de destino más las que cambiaron de texto de origen. Un dry run no construye ningún proveedor, no lee ninguna clave y no escribe nada. Toma la cifra como un límite superior: se salta [la caché](/docs/the-cache), que en una ejecución real sirve gratis las cadenas repetidas, y no agrupa las cadenas de origen idénticas, que una ejecución real envía una sola vez.

## Estima el gasto

<AvailableFrom version="0.11.0" />

```bash
verbatra translate --estimate
```

```text output
verbatra translate (estimate)
  de: 400 would translate, 0 unchanged
  es: 400 would translate, 0 unchanged
  fr: 400 would translate, 0 unchanged
  estimate: 1200 keys in 24 requests, ~40944 input + ~30720 output tokens
  estimated spend: no rate on file for gemini/gemini-2.5-flash; add rates.table["gemini/gemini-2.5-flash"] to your config to see a currency figure
  estimate excludes: cache hits, duplicate source strings, provider-side retries, translation length, tokenizer differences, repair requests
3 succeeded, 0 partial, 0 failed (dry run: nothing written)
```

`--estimate` implica `--dry-run`, así que no gasta nada. Informa en la unidad que factura tu proveedor: tokens para un LLM, caracteres de origen para DeepL y Google Cloud Translation, y ningún coste de API para un servidor propio `openai-compatible` o `libretranslate`. Con `--json`, las mismas cifras están en `result.estimate`, por locale y en total, para que un script pueda decidir con ellas.

Para ver dinero, consulta la tarifa actual de tu modelo en la página de precios del propio proveedor:

| Proveedor | Factura por | Precios |
| --- | --- | --- |
| Gemini | tokens de entrada y de salida (con nivel gratuito) | [Gemini API pricing](https://ai.google.dev/gemini-api/docs/pricing) |
| Anthropic | tokens de entrada y de salida | [Anthropic pricing](https://www.anthropic.com/pricing) |
| OpenAI | tokens de entrada y de salida | [OpenAI API pricing](https://openai.com/api/pricing/) |
| DeepL | caracteres de origen | [DeepL Pro pricing](https://www.deepl.com/pro) |
| Google Cloud Translation | caracteres de origen | [Cloud Translation pricing](https://cloud.google.com/translate/pricing) |
| openai-compatible, LibreTranslate | nada: tu propio servidor | sin coste de API |

Luego añádela a la configuración con la fecha en que la consultaste:

```ts title="verbatra.config.ts"
export default defineConfig({
  // ...
  rates: {
    asOf: "2026-01-15",
    currency: "USD",
    table: {
      "gemini/gemini-2.5-flash": { inputPerMillionTokens: 0.1, outputPerMillionTokens: 0.4 },
    },
  },
});
```

Las tarifas de arriba son marcadores, no precios citados. Cada cifra calculada con ellas lleva la fecha `asOf`, así que una tabla de precios antigua se ve antigua. verbatra nunca inventa una tarifa que falta ni imprime `0.00` para un modelo que no puede tarificar; en su lugar nombra la entrada que falta. El formato de las claves y las unidades están en [`rates`](/docs/config-file#rates).

## Entiende qué cubre la cifra

La estimación hace las cuentas que, si no, harías a mano:

- **Peticiones.** Las claves de cada locale se reparten en lotes de como mucho [`maxBatchSize`](/docs/config-file#maxbatchsize) (por defecto `50`), una petición por lote, más los lotes que enviaría [`generatePlurals`](/docs/config-file#generateplurals).
- **Entrada.** Cada petición a un LLM lleva unas reglas de sistema fijas (unos 550 tokens) y un esquema de respuesta (unos 100 tokens), y después las claves, sus descripciones, el tono y el glosario completo del locale de destino. El prompt se mide serializando la carga que se enviaría, así que un glosario grande cuenta en cada petición que lo lleva.
- **Salida.** La traducción aún no existe, así que se calcula como el texto de origen más un 50 por ciento, porque el alemán, el francés y el ruso suelen ser entre un tercio y la mitad más largos que el inglés.
- **Tokens.** Los caracteres se convierten a razón de unos cuatro por token, lo que encaja con prosa en inglés; otras escrituras son más densas.

Una ejecución real suele costar menos, por las dos razones por las que la cifra del dry run es un límite superior. También puede costar más, y la línea `estimate excludes` nombra cada motivo. Dos pesan más que el resto:

- **Reintentos.** El SDK de cada proveedor reintenta por su cuenta una petición fallida: dos intentos extra en Anthropic, OpenAI, `openai-compatible` y Gemini, y cinco en DeepL. Un intento que llegó al modelo se factura.
- **Reparaciones.** Cuando vuelven claves que faltan, verbatra envía una petición de reparación, que lleva de nuevo completos las reglas de sistema, el glosario y el tono.

Planifica con la cifra, pero no la prometas como techo. Además, la estimación solo cubre `translate`: volver a traducir una entrada desde [Studio](/docs/review-in-studio) o con una herramienta de agente gasta por su propio camino.

## Limita la ejecución

<AvailableFrom version="0.12.0" />

Pon a la ejecución acordada un tope firme algo por encima de la suma de tokens de entrada y salida estimados:

```bash
verbatra translate --max-tokens 80000
```

Una petición que superaría el tope se retiene en lugar de enviarse, y sus claves quedan pendientes para la siguiente ejecución. Si la configuración también fija `maxTokens`, se aplica la cifra menor. DeepL, Google Cloud Translation y LibreTranslate no informan de tokens, así que con ellos el tope se aplica contra la proyección propia de verbatra. Consulta [Tope de tokens](/docs/cli/translate#tope-de-tokens), y [`maxTokens` y `budgetBehavior`](/docs/config-file#maxtokens-y-budgetbehavior) para un presupuesto que valga en cada ejecución.

## Calibra con un locale

La cifra exacta sale de una ejecución real. Traduce un locale y lee el consumo:

```bash
verbatra translate --locales de
```

```text output
verbatra translate
  de: 400 translated, 0 unchanged, 18400 tokens (10800 in, 7600 out)
  total: 18400 tokens (10800 in, 7600 out)
1 succeeded, 0 partial, 0 failed
```

Multiplica por el número de locales que quedan. Con `--json`, las cifras son `usage.inputTokens` y `usage.outputTokens`. La ejecución gasta dinero real, pero el trabajo se conserva: ese locale ya está hecho.

## Proveedores de traducción automática

DeepL, Google Cloud Translation y LibreTranslate facturan caracteres de origen, no tokens. verbatra solo les envía el texto de origen, sin reglas de sistema, nombres de clave ni JSON alrededor, así que no hay coste fijo por petición. Las cadenas con marcadores o sintaxis ICU se retienen en lugar de arriesgarlas, así que los caracteres enviados pueden ser menos que el total bruto.

### Google Cloud Translation

<AvailableFrom version="0.10.0" />

Google Cloud Translation se cuenta como DeepL: caracteres de origen en la estimación y una cifra de tokens proyectada para un presupuesto `maxTokens`, marcada como estimada en el resumen de la ejecución.

## Estima desde un agente

<AvailableFrom version="0.3.0" pkg="@verbatra/mcp" />

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

La herramienta MCP `translation.estimate`, y `verbatra_translation_estimate` en [las herramientas de agente de Studio](/docs/agent-tools-in-studio), devuelven lo que imprime `translate --estimate --json`, para todos los locales o un subconjunto, y nunca llaman a un proveedor. Después, `translation.translatePending` acepta los mismos `locales` y un tope `maxTokens`. Consulta [Estimar y luego gastar](/docs/cli/mcp#estimar-y-luego-gastar).

## Por qué la siguiente ejecución cuesta menos

Las cifras de arriba son el coste de la primera ejecución. Después, verbatra solo envía las claves que faltan o cuyo origen cambió desde la referencia de [el archivo de bloqueo](/docs/the-lock-file), y [la caché](/docs/the-cache) reutiliza traducciones anteriores de cadenas idénticas. En el día a día pagas por las cadenas que editaste. Para ensayar gratis, usa el nivel gratuito de Gemini o apunta `openai-compatible` a un modelo local; consulta [Proveedores](/docs/providers).
