提交一次运行的结果之前用它：无需离开 Studio，就能看到翻译运行或编辑改动了哪些语言文件，以及每个文件中哪些键已更改。它只读取，Studio 不会暂存、提交或恢复任何内容。

## 打开 Changes 区域

启动 Studio（见[在 Studio 中审校](/zh-CN/docs/review-in-studio#启动-studio)），在 **Overview**（概览）页面中滚动到语言环境表格下方的 **Changes**（更改）。该区域显示已检出的分支（或 **Detached HEAD**（分离 HEAD）），并列出所有与上次提交不同的文件，一次显示 10 个，其余的用 **Show all N files**（显示全部 N 个文件）展开：

| 状态 | 含义 |
| --- | --- |
| **Modified**（已更改） | 文件与上次提交不同 |
| **Added**（已添加） | 文件是新增的，并且已暂存 |
| **Deleted**（已删除） | 文件已从工作树或索引中删除 |
| **Untracked**（未跟踪） | git 尚未跟踪该文件 |
| **Conflicted**（有冲突） | 文件有未解决的合并冲突 |
| **Matches last commit**（与上次提交一致） | 你打开过的文件，现已不再与上次提交不同，关闭前保留在原位 |

源语言环境和目标语言环境的文件都会列出，`verbatra.lock.json` 和 `verbatra.provenance.json` 也在其中，它们只显示状态，不显示键的更改。项目没有未提交的更改时，该区域会说明没有语言文件与上次提交不同。

## 查看键的更改

**Key changes (de)**（键的更改）会把该语言环境的文件按键展开，并与上次提交比较：**Changed**（已更改）的键并排显示旧文本和新文本，另外还有 **Added**（已添加）的键和 **Removed**（已移除）的键。再按一次按钮即可关闭，同一时间只能打开一个语言环境。源语言环境中同样存在的已更改或已添加的键，会链接到它在 **Translations**（翻译）中的条目。

- **一个文件，多个语言环境**：`apple-xcstrings` 这类消息目录把所有语言环境放在一个文件中，因此每个语言环境各有一个按钮。每个按钮只比较对应的语言环境。
- **长列表**：列表最多包含 500 个键，每段文本最多保留 2000 个字符。发生截断时，Studio 会说明列表不完整，并标出被截断的文本，完整差异可在 git 中查看。长列表一次显示 50 个键。
- **只有顺序变了**：已更改的文件如果键和文本都相同，Studio 会说明这一点。
- **冲突**：有未解决合并冲突的文件只显示状态，不显示键的更改。请先在 git 中解决冲突。
- **安全文本**：键和值按纯文本显示，使用该语言环境自己的语言和书写方向，绝不按 HTML 渲染。

## 没有内容可显示时

无法比较时，Studio 会给出说明，而不是抛出错误，例如：

- 项目不在 git 仓库中，或者未安装 git，或者 git 版本低于部分克隆所需的版本；
- git 因为目录属于其他用户而拒绝访问，或者该目录位于裸仓库内；
- 仓库配置了内容过滤器，而 Studio 不会运行它；
- `files.pattern` 把语言文件放在项目目录之外（例如使用 `../`），因此列表可能漏掉该文件。

读取耗时过长或失败时，页面会显示错误和 **Retry**（重试）。使用 `custom:` 格式的项目会显示已更改的文件，但不显示这些文件中键的更改：Studio 只用内置格式适配器比较已提交的文件，而内置适配器无法运行自定义适配器。详见[编写自定义格式适配器](/zh-CN/docs/custom-format-adapters)。

## 了解数据有多新

语言文件、锁文件或来源记录文件在磁盘上发生更改时，git 的索引或 `HEAD` 发生变化时（提交、切换分支、重置或 `git add`），以及你回到 Studio 的标签页或窗口时，该区域会重新读取。读取失败时，Studio 保留上一次的结果并说明情况。

你自己的代码也可以执行相同的读取：[`localeGitStatus` 和 `localeGitDiff`](/zh-CN/docs/sdk/review#localegitstatus) 会列出比较不可用的所有原因，以及它们采用的 git 保护措施。
