Nutze das vor dem ersten Lauf auf einem echten Projekt oder vor jedem Lauf, den jemand freigeben muss. verbatra veröffentlicht keine Preise, weil die Tarife dem Provider gehören und sich ohne Ankündigung ändern. Es zählt, wofür du bezahlst, und rechnet das in Geld um, sobald du ihm die aktuellen Tarife deines Providers gibst.

Für ein typisches Projekt kosten ein paar hundert Keys in ein paar Locales mit einem kleinen Modell Cents, und der nächste Lauf kostet fast nichts, weil nur geänderte Keys gesendet werden.

## Zähl die Arbeit

```bash
verbatra translate --dry-run
```

```text output
verbatra translate (dry run)
  de: 400 would translate, 0 unchanged
  es: 400 would translate, 0 unchanged
  fr: 400 would translate, 0 unchanged
3 succeeded, 0 partial, 0 failed (dry run: nothing written)
```

`would translate` ist die Zahl der Keys, die ein echter Lauf senden würde: die in der Zieldatei fehlenden plus die, deren Quelltext sich geändert hat. Ein Dry Run erzeugt keinen Provider, liest keinen Key und schreibt nichts. Betrachte die Zahl als Obergrenze: Sie lässt [den Cache](/docs/the-cache) aus, der wiederholte Strings in einem echten Lauf kostenlos liefert, und sie fasst identische Quellstrings nicht zusammen, die ein echter Lauf nur einmal sendet.

## Schätz die Ausgaben

<AvailableFrom version="0.11.0" />

```bash
verbatra translate --estimate
```

```text output
verbatra translate (estimate)
  de: 400 would translate, 0 unchanged
  es: 400 would translate, 0 unchanged
  fr: 400 would translate, 0 unchanged
  estimate: 1200 keys in 24 requests, ~40944 input + ~30720 output tokens
  estimated spend: no rate on file for gemini/gemini-2.5-flash; add rates.table["gemini/gemini-2.5-flash"] to your config to see a currency figure
  estimate excludes: cache hits, duplicate source strings, provider-side retries, translation length, tokenizer differences, repair requests
3 succeeded, 0 partial, 0 failed (dry run: nothing written)
```

`--estimate` schließt `--dry-run` ein und gibt also nichts aus. Es meldet die Einheit, die dein Provider abrechnet: Tokens bei einem LLM, Quellzeichen bei DeepL und Google Cloud Translation und keine API-Kosten bei einem selbst betriebenen `openai-compatible`- oder `libretranslate`-Server. Mit `--json` stehen dieselben Zahlen unter `result.estimate`, pro Locale und insgesamt, sodass ein Skript darauf reagieren kann.

Um Geldbeträge zu sehen, schlag den aktuellen Tarif deines Modells auf der Preisseite des Providers nach:

| Provider | Abgerechnet nach | Preise |
| --- | --- | --- |
| Gemini | Ein- und Ausgabe-Tokens (mit kostenlosem Kontingent) | [Gemini API pricing](https://ai.google.dev/gemini-api/docs/pricing) |
| Anthropic | Ein- und Ausgabe-Tokens | [Anthropic pricing](https://www.anthropic.com/pricing) |
| OpenAI | Ein- und Ausgabe-Tokens | [OpenAI API pricing](https://openai.com/api/pricing/) |
| DeepL | Quellzeichen | [DeepL Pro pricing](https://www.deepl.com/pro) |
| Google Cloud Translation | Quellzeichen | [Cloud Translation pricing](https://cloud.google.com/translate/pricing) |
| openai-compatible, LibreTranslate | nichts: dein eigener Server | keine API-Kosten |

Trag ihn dann mit dem Datum, an dem du ihn gelesen hast, in die Konfiguration ein:

```ts title="verbatra.config.ts"
export default defineConfig({
  // ...
  rates: {
    asOf: "2026-01-15",
    currency: "USD",
    table: {
      "gemini/gemini-2.5-flash": { inputPerMillionTokens: 0.1, outputPerMillionTokens: 0.4 },
    },
  },
});
```

Die Tarife oben sind Platzhalter, keine zitierten Preise. Jede daraus berechnete Zahl trägt das `asOf`-Datum, sodass eine alte Preistabelle sichtbar alt ist. verbatra erfindet nie einen fehlenden Tarif und druckt nie `0.00` für ein Modell, das es nicht bepreisen kann; stattdessen nennt es den fehlenden Eintrag. Schlüsselformat und Einheiten stehen unter [`rates`](/docs/config-file#rates).

## Wisse, was die Zahl abdeckt

Die Schätzung erledigt die Rechnung, die du sonst von Hand machen würdest:

- **Anfragen.** Die Keys jeder Locale werden in Stapel von höchstens [`maxBatchSize`](/docs/config-file#maxbatchsize) (Standard `50`) aufgeteilt, eine Anfrage pro Stapel, dazu die Stapel, die [`generatePlurals`](/docs/config-file#generateplurals) senden würde.
- **Eingabe.** Jede LLM-Anfrage enthält feste Systemregeln (etwa 550 Tokens) und ein Antwortschema (etwa 100 Tokens), dann die Keys, ihre Beschreibungen, den Ton und das vollständige Glossar der Ziel-Locale. Der Prompt wird gemessen, indem die Nutzlast serialisiert wird, die gesendet würde, sodass ein großes Glossar bei jeder Anfrage zählt, die es mitführt.
- **Ausgabe.** Eine Übersetzung gibt es noch nicht, also wird sie als Quelltext plus 50 Prozent angesetzt, weil Deutsch, Französisch und Russisch oft ein Drittel bis die Hälfte länger sind als Englisch.
- **Tokens.** Zeichen werden mit etwa vier pro Token umgerechnet, was zu englischem Fließtext passt; andere Schriften sind dichter.

Ein echter Lauf kostet meist weniger, aus denselben zwei Gründen, aus denen die Dry-Run-Zahl eine Obergrenze ist. Er kann auch mehr kosten, und die Zeile `estimate excludes` nennt jeden Weg dorthin. Zwei zählen am meisten:

- **Wiederholungen.** Das SDK jedes Providers wiederholt eine gescheiterte Anfrage selbst: zwei zusätzliche Versuche bei Anthropic, OpenAI, `openai-compatible` und Gemini, fünf bei DeepL. Ein Versuch, der das Modell erreicht hat, wird abgerechnet.
- **Reparaturen.** Wenn Keys fehlend zurückkommen, sendet verbatra eine Reparaturanfrage, die Systemregeln, Glossar und Ton noch einmal vollständig enthält.

Plane mit der Zahl, versprich sie aber nicht als Obergrenze. Die Schätzung deckt außerdem nur `translate` ab: Ein einzelner Eintrag, den du aus [Studio](/docs/review-in-studio) oder mit einem Agent-Tool neu übersetzt, verursacht Kosten auf eigenem Weg.

## Begrenze den Lauf

<AvailableFrom version="0.12.0" />

Gib dem vereinbarten Lauf einen harten Stopp knapp über der Summe aus geschätzten Ein- und Ausgabe-Tokens:

```bash
verbatra translate --max-tokens 80000
```

Eine Anfrage, die die Grenze überschreiten würde, wird zurückgehalten statt gesendet, und ihre Keys bleiben für den nächsten Lauf offen. Setzt die Konfiguration auch `maxTokens`, gilt der niedrigere Wert. DeepL, Google Cloud Translation und LibreTranslate melden keine Tokens, also wird die Grenze bei ihnen gegen verbatras eigene Hochrechnung durchgesetzt. Siehe [Token-Obergrenze](/docs/cli/translate#token-obergrenze) und für ein Budget, das für jeden Lauf gilt, [`maxTokens` und `budgetBehavior`](/docs/config-file#maxtokens-und-budgetbehavior).

## Kalibriere an einer Locale

Die genaue Zahl liefert ein echter Lauf. Übersetze eine Locale und lies den Verbrauch ab:

```bash
verbatra translate --locales de
```

```text output
verbatra translate
  de: 400 translated, 0 unchanged, 18400 tokens (10800 in, 7600 out)
  total: 18400 tokens (10800 in, 7600 out)
1 succeeded, 0 partial, 0 failed
```

Multipliziere mit der Zahl der übrigen Locales. Mit `--json` heißen die Werte `usage.inputTokens` und `usage.outputTokens`. Der Lauf kostet echtes Geld, aber die Arbeit bleibt: Diese Locale ist fertig.

## Maschinelle Übersetzungsdienste

DeepL, Google Cloud Translation und LibreTranslate rechnen Quellzeichen ab, keine Tokens. verbatra schickt ihnen nur den Quelltext, ohne Systemregeln, Key-Namen oder JSON drumherum, also gibt es keinen festen Aufschlag pro Anfrage. Strings mit Platzhaltern oder ICU-Syntax werden zurückgehalten statt riskiert, sodass weniger Zeichen gesendet werden können als die Rohsumme.

### Google Cloud Translation

<AvailableFrom version="0.10.0" />

Google Cloud Translation wird wie DeepL gezählt: Quellzeichen in der Schätzung und eine hochgerechnete Token-Zahl für ein `maxTokens`-Budget, in der Laufzusammenfassung als geschätzt markiert.

## Schätze aus einem Agenten heraus

Zwei Agent-Tools liefern, was `translate --estimate --json` ausgibt, für alle Locales oder eine Teilmenge, und rufen nie einen Provider auf:

| Tool | Wo |
| --- | --- |
| `translation.estimate` | der [MCP-Server](/docs/cli/mcp) <AvailableFrom version="0.3.0" pkg="@verbatra/mcp" /> |
| `verbatra_translation_estimate` | [Studios Agent-Tools](/docs/agent-tools-in-studio) <AvailableFrom version="0.6.0" pkg="@verbatra/studio" /> |

`translation.translatePending` nimmt danach dieselben `locales` und eine `maxTokens`-Grenze. Siehe [Erst schätzen, dann ausgeben](/docs/cli/mcp#erst-schätzen-dann-ausgeben).

## Warum der nächste Lauf weniger kostet

Die Zahlen oben sind die Kosten des ersten Laufs. Danach sendet verbatra nur Keys, die fehlen oder deren Quelle sich seit der Baseline in [der Lock-Datei](/docs/the-lock-file) geändert hat, und [der Cache](/docs/the-cache) verwendet frühere Übersetzungen identischer Strings wieder. Im Alltag bezahlst du für die Strings, die du bearbeitet hast. Um kostenlos zu proben, nutze das kostenlose Kontingent von Gemini oder richte `openai-compatible` auf ein lokales Modell; siehe [Provider](/docs/providers).
