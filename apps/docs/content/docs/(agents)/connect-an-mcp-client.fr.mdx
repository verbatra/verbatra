Sers-t'en pour qu'un agent de code lise l'état des traductions, corrige des valeurs et, seulement si tu l'autorises, lance des traductions via le serveur MCP de verbatra. Le client démarre le serveur comme processus enfant sur stdio : pas de port, rien à garder en marche toi-même.

Il te faut :

- un projet avec une config verbatra (sinon, lance d'abord [`npx verbatra init`](/docs/cli/init)) ;
- Node.js 22.14 ou plus récent ;
- une clé de fournisseur dans ton environnement, seulement si l'agent doit dépenser.

Les outils, leurs entrées et leurs résultats sont décrits dans [`verbatra mcp`](/docs/cli/mcp#tools).

<AvailableFrom version="0.2.0" pkg="@verbatra/mcp" />

## Choisir une commande de lancement

| Commande | Nécessite | Lit les fichiers `.env` |
| --- | --- | --- |
| `npx -y @verbatra/mcp` | rien d'installé | non |
| `npx verbatra mcp` | `@verbatra/cli` et `@verbatra/mcp` en dépendances de développement | oui : `.env.local`, puis `.env` |

Tous les exemples utilisent `npx -y @verbatra/mcp`, qui fonctionne dans n'importe quel projet. Deux commandes qui y ressemblent échouent : `npx -y @verbatra/cli mcp` sort avec `2` parce que la CLI n'installe jamais `@verbatra/mcp`, et `npx verbatra mcp` sans `@verbatra/cli` local récupère un paquet tiers du registre nommé `verbatra`.

Pointe le serveur vers le répertoire qui contient la config. Chaque section client explique comment ; la règle est dans [Répertoire du projet](/docs/cli/mcp#répertoire-du-projet).

<AvailableFrom version="0.3.0" pkg="@verbatra/mcp" />

Le serveur figure aussi dans le [registre MCP officiel](https://registry.modelcontextprotocol.io) sous le nom `io.github.verbatra/verbatra`.

## Décider si l'agent peut dépenser

Le serveur démarre en lecture seule : `translation.retranslateEntry` et `translation.translatePending` restent masqués, et aucun autre outil n'appelle un fournisseur ni ne lit de clé. Dans ce cas, laisse la clé et l'interrupteur de dépense hors de la config du client.

Pour que l'agent puisse dépenser, ajoute les deux :

- `--allow-spend` dans les arguments du serveur, ou `VERBATRA_MCP_ALLOW_SPEND=1` dans son environnement ([Outils payants](/docs/cli/mcp#outils-payants)) ;
- la variable de clé de ton fournisseur, par exemple `ANTHROPIC_API_KEY` ([Fournisseurs](/docs/providers)).

<AvailableFrom version="0.3.0" pkg="@verbatra/mcp" />

Même alors, le serveur demande à l'agent de lancer `translation.estimate` et d'attendre ton oui avant tout appel payant, et une config avec `provider: { id: "none" }` garde les deux outils payants masqués.

<Callout type="warn">
N'écris jamais une clé dans un fichier versionné. `.mcp.json`, `.codex/config.toml`, `.gemini/settings.json`, `.cursor/mcp.json`, `.vscode/mcp.json` et `.github/mcp.json` sont partagés avec l'équipe ; chaque section ci-dessous passe la clé par référence ou depuis ton environnement.
</Callout>

## Claude Code

Depuis la racine du projet :

```bash
claude mcp add --transport stdio --scope project verbatra -- npx -y @verbatra/mcp
```

Les options de Claude Code vont avant `--`, les arguments du serveur après. `--scope` choisit où l'entrée est stockée :

| Scope | Stockée dans | Qui l'obtient |
| --- | --- | --- |
| `local` (par défaut) | `~/.claude.json`, sous ce projet | toi, dans ce projet |
| `project` | `.mcp.json` à la racine du projet, versionné | toute personne qui ouvre le projet |
| `user` | `~/.claude.json` | toi, dans tous tes projets |

`--scope project` écrit ce `.mcp.json`, que tu peux aussi écrire à la main :

```json
{
  "mcpServers": {
    "verbatra": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@verbatra/mcp"]
    }
  }
}
```

<AvailableFrom version="0.12.0" />

[`verbatra init --agent`](/docs/cli/init#préparer-les-agents-de-code) écrit la même entrée à côté de chaque serveur que le fichier contient déjà.

Claude Code définit `CLAUDE_PROJECT_DIR` sur la racine du projet, donc pas besoin de `--cwd`, et transmet l'environnement avec lequel tu l'as lancé. Pour dépenser le temps d'une session, exporte la clé et lance-le avec l'interrupteur :

```bash
VERBATRA_MCP_ALLOW_SPEND=1 claude
```

Ne combine pas `--env KEY=value` avec `--scope project` : la valeur finirait dans `.mcp.json`. `claude mcp list` indique si le serveur se connecte. Voir la [documentation MCP de Claude Code](https://code.claude.com/docs/en/mcp).

### Le plugin verbatra

<AvailableFrom version="0.3.0" pkg="@verbatra/mcp" />

Le plugin regroupe les trois [skills verbatra](/docs/agent-recipes#le-pack-de-skills), ce serveur et un hook qui vérifie un fichier de locale après que Claude l'a modifié. Installe-le pour le projet :

```bash
claude plugin marketplace add verbatra/skills
claude plugin install verbatra@verbatra --scope project
```

Chaque membre de l'équipe l'installe une fois. Avec le scope `user` par défaut, il démarrerait dans chaque projet que tu ouvres.

- **Serveur** : `npx -y @verbatra/mcp` dans une version figée, avec `--cwd` sur le projet ouvert. Sans config, il démarre quand même ; lance `npx verbatra init` et l'appel suivant la trouve.
- **Dépenses** : désactivées tant que tu n'actives pas l'option `allowSpend` du plugin (`--config allowSpend=true` à l'installation, ou `/config`). Un `.claude/settings.json` versionné ne peut pas l'activer, et `VERBATRA_MCP_ALLOW_SPEND` dans ton shell n'atteint pas ce serveur.
- **Clé** : lue dans l'environnement avec lequel tu as lancé `claude` ; le plugin n'a pas d'option de clé.
- **Hook** : lance le `verbatra check --file <path>` du projet (CLI 0.12.0 ou plus récente, depuis `node_modules`) et renvoie à Claude la syntaxe, les placeholders, le balisage ou l'ICU cassés. Il ne télécharge rien et n'appelle aucun fournisseur.

Voir la [référence des plugins de Claude Code](https://code.claude.com/docs/en/plugins-reference).

## Codex

La CLI Codex, son extension d'IDE et l'application de bureau partagent `~/.codex/config.toml`, ou le `.codex/config.toml` d'un projet de confiance :

```bash
codex mcp add verbatra -- npx -y @verbatra/mcp --cwd /path/to/your/project
```

La même entrée à la main, dépenses autorisées ; `env_vars` nomme des variables que Codex transmet depuis son propre environnement, donc le fichier ne contient jamais la valeur :

```toml title=".codex/config.toml"
[mcp_servers.verbatra]
command = "npx"
args = ["-y", "@verbatra/mcp", "--allow-spend"]
cwd = "/path/to/your/project"
env_vars = ["ANTHROPIC_API_KEY"]
```

Pour une entrée en lecture seule, retire `--allow-spend` et `env_vars`. Une table `[mcp_servers.verbatra.env]` ou `codex mcp add --env` stockent la valeur elle-même. Voir la [documentation MCP de Codex](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).

## Gemini CLI

Gemini CLI lit `mcpServers` dans `.gemini/settings.json` ou `~/.gemini/settings.json`. Donne un `cwd` absolu, et garde une entrée qui en contient un dans tes paramètres utilisateur :

```json title="~/.gemini/settings.json"
{
  "mcpServers": {
    "verbatra": {
      "command": "npx",
      "args": ["-y", "@verbatra/mcp", "--allow-spend"],
      "cwd": "/path/to/your/project",
      "env": {
        "ANTHROPIC_API_KEY": "$ANTHROPIC_API_KEY"
      }
    }
  }
}
```

Gemini CLI cache les variables sensibles aux serveurs, donc la clé n'arrive que par `env`, où `$ANTHROPIC_API_KEY` est développé depuis son environnement. Pour une entrée en lecture seule, retire `--allow-spend` et `env`, et laisse `trust` non défini pour que chaque appel soit confirmé. `gemini mcp add -e KEY=value` stocke la valeur elle-même. `/mcp` affiche le serveur et ses outils. Voir la [documentation MCP de Gemini CLI](https://geminicli.com/docs/tools/mcp-server/).

## Cursor

Cursor lit `.cursor/mcp.json` dans le projet et `~/.cursor/mcp.json`. `${workspaceFolder}` est la racine du projet :

```json title=".cursor/mcp.json"
{
  "mcpServers": {
    "verbatra": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@verbatra/mcp", "--cwd", "${workspaceFolder}"]
    }
  }
}
```

Pour dépenser, ajoute `"--allow-spend"` à la fin de `args` et `"env": { "ANTHROPIC_API_KEY": "${env:ANTHROPIC_API_KEY}" }`, qui ne contient que le nom de la variable. Garde cette entrée dans `~/.cursor/mcp.json` si tout le monde ne doit pas dépenser. Voir la [documentation MCP de Cursor](https://cursor.com/docs/mcp).

## VS Code

VS Code (le mode agent de GitHub Copilot) lit `.vscode/mcp.json`. Sa clé de premier niveau est `servers`, et il démarre les serveurs dans le dossier du workspace, donc pas besoin de `--cwd`. Pour dépenser, déclare la clé comme input : VS Code la demande une fois et la stocke hors du fichier.

```json title=".vscode/mcp.json"
{
  "inputs": [
    {
      "type": "promptString",
      "id": "anthropic-key",
      "description": "Anthropic API key",
      "password": true
    }
  ],
  "servers": {
    "verbatra": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@verbatra/mcp", "--allow-spend"],
      "env": {
        "ANTHROPIC_API_KEY": "${input:anthropic-key}"
      }
    }
  }
}
```

Pour une entrée en lecture seule, retire `inputs`, `--allow-spend` et `env`, ou charge la clé avec `"envFile": "${workspaceFolder}/.env.local"`. Pour installer la version en lecture seule en une étape, utilise [Installer verbatra dans VS Code](vscode:mcp/install?%7B%22name%22%3A%22verbatra%22%2C%22command%22%3A%22npx%22%2C%22args%22%3A%5B%22-y%22%2C%22%40verbatra%2Fmcp%22%5D%7D) ou :

```bash
code --add-mcp '{"name":"verbatra","command":"npx","args":["-y","@verbatra/mcp"]}'
```

Voir la [référence de configuration MCP de VS Code](https://code.visualstudio.com/docs/agents/reference/mcp-configuration).

## GitHub Copilot

### Copilot cloud agent

Une personne administratrice du dépôt ajoute le serveur sous **Settings**, **Copilot**, **MCP servers**. Le cloud agent appelle chaque outil qu'on lui donne sans demander, donc `tools` est obligatoire ; cette liste autorisée contient chaque outil qui n'écrit rien et n'appelle aucun fournisseur :

```json
{
  "mcpServers": {
    "verbatra": {
      "type": "local",
      "command": "npx",
      "args": ["-y", "@verbatra/mcp"],
      "tools": [
        "project.snapshot",
        "project.doctor",
        "status.check",
        "status.diff",
        "lock.state",
        "key.value",
        "key.integrity",
        "glossary.get",
        "review.queue",
        "usage.summary",
        "translation.estimate"
      ]
    }
  }
}
```

Ajoute `translation.editEntry` et `glossary.write` seulement si l'agent doit écrire dans sa pull request. Laisse `review.approve` et `review.reject` dehors : une décision de relecture demande une personne. Laisse les dépenses désactivées, car personne ne valide un appel. Si tu les accordes quand même, il te faut les trois : un secret Agents comme `COPILOT_MCP_ANTHROPIC_API_KEY` (seul le préfixe `COPILOT_MCP_` atteint les serveurs MCP), `"env": { "ANTHROPIC_API_KEY": "$COPILOT_MCP_ANTHROPIC_API_KEY" }` avec `--allow-spend`, et l'outil payant dans `tools`.

Pour vérifier, assigne une issue à Copilot, ouvre **View session** et déplie **Start MCP Servers**. Voir [Extending the cloud agent with MCP](https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/configure-mcp-servers).

### Copilot CLI

```bash
copilot mcp add verbatra -- npx -y @verbatra/mcp --cwd /path/to/your/project
```

Cela écrit `~/.copilot/mcp-config.json`. Copilot CLI lit aussi `.mcp.json` et `.github/mcp.json` d'un projet de confiance. Il ne transmet à un serveur que `PATH`, donc `--allow-spend` va dans `args` et une clé dans le `env` de l'entrée, uniquement dans `~/.copilot/mcp-config.json`. `/mcp show verbatra` affiche son état. Voir [Adding MCP servers to Copilot CLI](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-mcp-servers).

## Windsurf

Cascade, dans Windsurf, lit un seul `mcp_config.json` pour tous les projets, donc donne un `--cwd` absolu :

```json title="mcp_config.json"
{
  "mcpServers": {
    "verbatra": {
      "command": "npx",
      "args": ["-y", "@verbatra/mcp", "--cwd", "/path/to/your/project"]
    }
  }
}
```

Pour dépenser, ajoute `"--allow-spend"` à la fin et `"env": { "ANTHROPIC_API_KEY": "${env:ANTHROPIC_API_KEY}" }`. Voir la [documentation MCP de Cascade](https://docs.devin.ai/desktop/cascade/mcp).

## Zed

Zed lit `context_servers` dans ses paramètres ; **Settings**, **AI**, **MCP Servers**, **Add Server** écrit l'entrée :

```json title="settings.json"
{
  "context_servers": {
    "verbatra": {
      "command": "npx",
      "args": ["-y", "@verbatra/mcp", "--cwd", "/path/to/your/project"],
      "env": {}
    }
  }
}
```

Un point vert sur cette page signifie que le serveur est actif. Une clé dans `env` est une valeur littérale, donc ajoute-la avec `--allow-spend` uniquement dans tes paramètres utilisateur, jamais dans `.zed/settings.json`. Voir la [documentation MCP de Zed](https://zed.dev/docs/ai/mcp).

## JetBrains AI Assistant

Ouvre **Settings**, **Tools**, **AI Assistant**, **Model Context Protocol (MCP)**, ajoute un serveur et colle :

```json
{
  "mcpServers": {
    "verbatra": {
      "command": "npx",
      "args": ["-y", "@verbatra/mcp"]
    }
  }
}
```

Règle **Working directory** sur la racine du projet. JetBrains ne documente pas comment un serveur reçoit ses variables d'environnement, donc garde cette entrée en lecture seule. Voir la [documentation MCP d'AI Assistant](https://www.jetbrains.com/help/ai-assistant/mcp.html).

## Claude Desktop

**Settings**, **Developer**, **Edit Config** ouvre `claude_desktop_config.json` (`~/Library/Application Support/Claude/` sous macOS, `%APPDATA%\Claude\` sous Windows). Il n'y a pas de projet, donc `--cwd` est absolu :

```json title="claude_desktop_config.json"
{
  "mcpServers": {
    "verbatra": {
      "command": "npx",
      "args": ["-y", "@verbatra/mcp", "--cwd", "/path/to/your/project"]
    }
  }
}
```

Pour dépenser, ajoute `"--allow-spend"` à la fin et `"env": { "ANTHROPIC_API_KEY": "..." }` ; le fichier vit hors de tout dépôt. Redémarre Claude Desktop après chaque modification. Le stderr du serveur va dans `mcp-server-verbatra.log` sous `~/Library/Logs/Claude` ou `%APPDATA%\Claude\logs`. Voir [Connect to local MCP servers](https://modelcontextprotocol.io/docs/develop/connect-local-servers).

## Tout autre client stdio

Donne au client :

- la commande `npx` avec `-y @verbatra/mcp`, ou le chemin d'un binaire `verbatra-mcp` installé ;
- `--cwd /path/to/your/project`, sauf s'il démarre les serveurs à la racine du projet ;
- `--config <path>` si la recherche vers le haut ne trouve pas la config ;
- `--allow-spend` et la variable de clé seulement si l'agent doit dépenser, via le mécanisme de secrets du client.

## Vérifier la connexion

Demande à l'agent d'appeler `project.snapshot`. Il n'appelle aucun fournisseur et renvoie les locales, le format et l'id du fournisseur, donc un mauvais répertoire se voit tout de suite. Le serveur n'écrit que des messages du protocole sur stdout, donc tout le reste apparaît dans le journal des serveurs du client.

<AvailableFrom version="0.3.0" pkg="@verbatra/mcp" />

- **`configured: false`** : le serveur n'a trouvé aucune config utilisable mais continue de tourner. Demande `project.doctor`, qui nomme chaque vérification échouée et son correctif, puis lance `npx verbatra init` ou corrige `--cwd`. Voir [Sans config](/docs/cli/mcp#sans-config).
- **Outils payants absents** : vérifie l'interrupteur de dépense et si le fournisseur est `none`.
- **Config modifiée** : pas besoin de redémarrer, sauf après avoir modifié un module que la config importe. Voir [Après un changement de config](/docs/cli/mcp#après-un-changement-de-config).
