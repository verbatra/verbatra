Diese Seite ist für ein Projekt gedacht, das bereits committete Locale-Dateien hat. Füge den Prompt unten in deinen KI-Coding-Agenten ein (Claude Code, Cursor oder jeden Agenten, der dein Projekt lesen, einen Link öffnen und Shell-Befehle ausführen kann). Der Agent liest die Schritte auf dieser Seite, prüft dein Setup, installiert verbatra, legt eine Konfiguration an, die zu dem passt, was er gefunden hat, und zeigt eine Vorschau eines Laufs; dann hält er an und bittet dich um Bestätigung, bevor er je wirklich einen Provider aufruft.

Wenn du verbatra selbst einrichtest, statt es einem Agenten zu überlassen, ist der [Schnellstart](/docs/quickstart) die menschliche Version desselben Wegs.

## Der Prompt

Kopiere den Block unten.

```text
Set up verbatra (`@verbatra/cli` on npm) in this project. Read
https://verbatra.kreitz-webdev.de/docs/start-with-ai.md and follow its steps in
order. Until I confirm, run only commands that spend nothing, and never run a
real `verbatra translate` without my explicit go-ahead. If you cannot open the
link, stop and tell me.
```

## Die Schritte, denen der Agent folgt

Der Prompt schickt den Agenten zur Markdown-Version dieser Seite. Agent: Folge diesen Schritten der Reihe nach und überspring nie den Halt in Schritt 7.

### 1. Das bestehende Setup prüfen

Bevor du etwas änderst, finde die i18n-Bibliothek in der `package.json` (zum Beispiel `i18next`, `vue-i18n`, `next-intl` oder `@ngx-translate/core`) und die Locale-Dateien selbst. Notiere die Quell-Locale, jede bereits vorhandene Ziel-Locale und das Pfadmuster mit einem `{locale}`-Token, etwa `locales/{locale}.json`. [Wähle deinen Stack](/docs/pick-your-stack) ordnet jedem Stack seine Format-ID und sein übliches Layout zu, und [Formate](/docs/formats) sagt, was jedes Format unangetastet lässt oder nie anlegt: Eine XLIFF-Datei und ein Xcode String Catalog etwa müssen schon existieren.

### 2. Die CLI installieren

```bash
npm install --save-dev @verbatra/cli
```

pnpm, yarn und bun funktionieren auch. Wenn pnpm mit `ERR_PNPM_IGNORED_BUILDS` endet, führ einmal `pnpm approve-builds` aus und bestätige keinen der beiden Einträge. Wenn npm vor Install-Skripten warnt, die `allowScripts` nicht abdeckt, lass sie unbestätigt: verbatra braucht keines davon.

### 3. Die Konfiguration ohne Rückfragen anlegen

```bash
npx verbatra init --provider <provider> --yes --json
```

Frag den Menschen, welcher Provider genutzt werden soll, außer das Projekt macht es schon klar. [Provider](/docs/providers) listet die IDs; `none` schaltet die maschinelle Übersetzung ab. Wähl nie einen Provider, der bei einem Dienst Kosten verursacht, dem der Mensch nicht zugestimmt hat, und übergib `init` nie einen Schlüsselwert. `init` erkennt das Format, das Pfadmuster und die Locales, gibt einen JSON-Envelope aus und fragt nie nach:

- Exit `0`: Vergleiche `result.config` mit dem, was du in Schritt 1 gefunden hast, beginnend mit jedem Eintrag in `result.sources`, der `default` sagt. Stimmt etwas nicht, führ den Befehl erneut mit dem richtigen `--format`, `--path`, `--source` oder `--targets` plus `--force` aus.
- Exit `2` mit `FORMAT_AMBIGUOUS` oder `LAYOUT_AMBIGUOUS`: Wähl aus `candidates` und führ den Befehl erneut mit `--format` oder `--path` aus. Sind die Kandidaten nebeneinanderliegende Namespace-Dateien, halt an und frag den Menschen, denn eine Konfiguration deckt ein Dateimuster ab.
- Exit `2` mit `MISSING_OPTIONS`: Die Meldung nennt jedes noch fehlende Flag.
- Exit `2` mit `CONFIG_EXISTS`: Frag den Menschen, bevor du `--force` übergibst.

[init](/docs/cli/init) beschreibt jedes Flag.

### 4. Den API-Schlüssel dem Menschen überlassen

Überspring diesen Schritt beim Provider `none`.

```bash
cp .env.example .env
```

Prüf, dass `.env` die Variable aus `result.apiKeyEnvVar` nennt, lass ihren Wert leer und sag dem Menschen, welche Variable er ausfüllen soll. Schreib, erfinde oder erfrage nie einen Schlüsselwert. Mach weiter, ohne darauf zu warten.

### 5. doctor ausführen

```bash
npx verbatra doctor --json
```

Behebe jede fehlschlagende Prüfung, die du durch Bearbeiten von `verbatra.config.ts` beheben kannst, und führ den Befehl erneut aus. Die Prüfung `api-key` besteht erst, wenn der Mensch den Schlüssel gesetzt hat, also dreh dich nicht in einer Schleife darum.

### 6. Vorschau ohne Kosten

```bash
npx verbatra check --json
npx verbatra diff --json
npx verbatra translate --dry-run --json
```

Keiner dieser Befehle ruft einen Provider auf, braucht einen Schlüssel oder schreibt eine Datei. Exit `1` von `check` oder `diff` heißt, dass eine Locale nicht synchron ist, was vor einem ersten Lauf zu erwarten ist; nur Exit `2` ist ein Setup-Problem. verbatra überschreibt nie einen vorhandenen Wert, auch nicht beim ersten Lauf: Übersetzt werden nur Schlüssel, die im Ziel fehlen. Ein leerer String zählt als vorhandener Wert, also frag den Menschen, bevor du Platzhalter-Schlüssel mit `""` löschst.

### 7. Anhalten und fragen

Fass zusammen, wie viele Schlüssel pro Locale ausstehen und was `translate --dry-run` gemeldet hat, und halt dann an. Ein echter Lauf kostet sofort und hat keine eigene Bestätigungsabfrage, also warte auf die ausdrückliche Zustimmung des Menschen. Nutze `--prune` nie, außer der Mensch hat ausdrücklich verlangt, verwaiste Schlüssel zu entfernen.

### 8. Nach der Zustimmung übersetzen

```bash
npx verbatra translate --json
```

Melde die Listen `succeeded`, `partial` und `failed` aus der Zusammenfassung. Eine Locale mit `partial` oder `failed` wurde trotzdem mit allem geschrieben, was gelungen ist.

### 9. Die richtigen Dateien committen

Committe `verbatra.config.ts`, `.env.example`, `verbatra.lock.json`, `verbatra.provenance.json`, sobald ein Lauf sie geschrieben hat, und die übersetzten Locale-Dateien. Committe nie `.env`, `.env.local`, `.verbatra-local/` oder `verbatra.cache.json`; `init` hat sie in die `.gitignore` eingetragen, also prüf, dass sie ignoriert werden.

## Warum diese Form

`translate` hat kein eigenes Ausgaben-Gate: Sobald eine gültige Konfiguration und ein API-Schlüssel existieren, ruft ein einfaches `verbatra translate` den Provider sofort auf, ohne Bestätigungsaufforderung. Die Schritte oben legen das Gate stattdessen in die Anweisungen des Agenten: `doctor`, `check`, `diff` und `translate --dry-run` sind alle kostenlos und nur lesend, sodass der Agent das gesamte Setup prüfen und dir genau zeigen kann, was passieren würde, bevor Schritt 8 kommt, der einzige Schritt, der etwas kostet.
