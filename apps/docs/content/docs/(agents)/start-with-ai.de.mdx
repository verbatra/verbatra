Diese Seite ist für ein Projekt gedacht, das bereits committete Locale-Dateien hat. Füge den Prompt unten in deinen KI-Coding-Agenten ein (Claude Code, Cursor oder jeden Agenten, der einen Link öffnen und Shell-Befehle ausführen kann). Er folgt den Schritten auf dieser Seite und fragt dich, bevor er je wirklich einen Provider aufruft.

## Der Prompt

```text
Set up verbatra (`@verbatra/cli` on npm) in this project. Read
https://verbatra.kreitz-webdev.de/docs/start-with-ai.md and follow its steps in
order. Until I confirm, run only commands that spend nothing, and never run a
real `verbatra translate` without my explicit go-ahead. Never write, invent, or
ask for an API key value. If you cannot open the link, stop and tell me.
```

## Die Schritte, denen der Agent folgt

Agent: Folge diesen Schritten der Reihe nach und überspring nie den Halt in Schritt 6.

### 1. Das bestehende Setup prüfen

Finde die i18n-Bibliothek in der `package.json` (zum Beispiel `i18next`, `vue-i18n`, `next-intl` oder `@ngx-translate/core`) und die Locale-Dateien selbst. Notiere die Quell-Locale, jede bereits vorhandene Ziel-Locale und das Pfadmuster mit einem `{locale}`-Token, etwa `locales/{locale}.json`. [Wähle deinen Stack](/docs/pick-your-stack) ordnet jedem Stack seine Format-ID und sein Layout zu; [Formate](/docs/formats) sagt, welche Dateien schon existieren müssen, etwa eine XLIFF-Datei oder ein Xcode String Catalog. Reines JSON ohne i18n-Bibliothek: Platzhalter `{{name}}` bedeuten `i18next-json`, einfache Klammern `{name}` bedeuten `vue-i18n-json`.

### 2. Die CLI installieren

```bash
npm install --save-dev @verbatra/cli
```

pnpm, yarn und bun funktionieren auch. Wenn pnpm mit `ERR_PNPM_IGNORED_BUILDS` endet, führ einmal `pnpm approve-builds` aus und bestätige keinen der beiden Einträge. Wenn npm vor Install-Skripten außerhalb von `allowScripts` warnt, lass sie unbestätigt: verbatra braucht keines davon.

### 3. Konfiguration und Agenten-Dateien anlegen

```bash
npx verbatra init --provider <provider> --yes --json --agent
```

Frag den Menschen, welcher Provider genutzt werden soll, außer das Projekt macht es schon klar, und übergib `init` nie einen Schlüsselwert. [Provider](/docs/providers) listet die IDs; `none` schaltet die maschinelle Übersetzung ab. `init` erkennt Format, Pfadmuster und Locales, gibt einen JSON-Envelope aus und fragt nie nach. `--agent` schreibt außerdem einen verbatra-Abschnitt in `AGENTS.md` (oder in `CLAUDE.md`, wenn das die einzige Anweisungsdatei ist) und den verbatra-MCP-Server, Ausgaben aus, in `.mcp.json`:

- Exit `0`: Vergleiche `result.config` mit dem, was du in Schritt 1 gefunden hast, beginnend mit jedem Eintrag in `result.sources`, der `default` sagt; `result.detection.layout` zeigt das Muster und die Locales, die der Scan gefunden hat. Stimmt etwas nicht, führ den Befehl erneut mit dem richtigen `--format`, `--path`, `--source` oder `--targets` plus `--force` aus.
- Exit `2` mit `FORMAT_AMBIGUOUS` oder `LAYOUT_AMBIGUOUS`: Wähl aus `candidates` und führ den Befehl erneut mit `--format` oder `--path` aus. Sind die Kandidaten nebeneinanderliegende Namespace-Dateien, halt an und frag den Menschen, denn eine Konfiguration deckt ein Dateimuster ab.
- Exit `2` mit `MISSING_OPTIONS`: Die Meldung nennt jedes noch fehlende Flag.
- Exit `2` mit `CONFIG_EXISTS`: Führ `npx verbatra init --agent --json` aus, um die Konfiguration zu behalten und nur die Agenten-Dateien zu ergänzen. Frag den Menschen, bevor du `--force` übergibst.

[init](/docs/cli/init#provider) beschreibt jedes Flag, auch `--base-url` und `--model` für einen OpenAI-kompatiblen oder LibreTranslate-Server.

### 4. Den API-Schlüssel dem Menschen überlassen

Überspring diesen Schritt beim Provider `none`.

```bash
cp .env.example .env
```

Prüf, dass `.env` die Variable aus `result.apiKeyEnvVar` nennt, lass ihren Wert leer und sag dem Menschen, welche Variable er ausfüllen soll. Schreib, erfinde oder erfrage nie einen Schlüsselwert. Mach weiter, ohne darauf zu warten.

### 5. Das Setup ohne Kosten prüfen

```bash
npx verbatra doctor --json
npx verbatra check --json
npx verbatra diff --json
npx verbatra translate --dry-run --json
```

Keiner dieser Befehle ruft einen Provider auf, braucht einen Schlüssel oder schreibt eine Datei. Behebe jede fehlschlagende `doctor`-Prüfung, die du durch Bearbeiten von `verbatra.config.ts` beheben kannst, und führ den Befehl erneut aus. Seine Prüfung `api-key` besteht erst, wenn der Mensch den Schlüssel gesetzt hat, also dreh dich nicht in einer Schleife darum. Exit `1` von `check` oder `diff` heißt, dass eine Locale nicht synchron ist, was vor einem ersten Lauf zu erwarten ist; nur Exit `2` ist ein Setup-Problem. Beim Provider `none` endet `translate --dry-run` mit `3`, wenn Schlüssel für einen menschlichen Übersetzer übrig bleiben, was ebenfalls zu erwarten ist. Übersetzt werden nur Schlüssel, die im Ziel fehlen, und ein leerer String zählt als vorhanden, also frag den Menschen, bevor du Platzhalter-Schlüssel mit `""` löschst.

### 6. Anhalten und fragen

Fass zusammen, wie viele Schlüssel pro Locale ausstehen und was `translate --dry-run` gemeldet hat, und halt dann an. Ein echter Lauf kostet sofort und hat keine eigene Bestätigungsabfrage, also warte auf die ausdrückliche Zustimmung des Menschen. Nutze `--prune` nie, außer der Mensch hat ausdrücklich verlangt, verwaiste Schlüssel zu entfernen.

### 7. Nach der Zustimmung übersetzen

```bash
npx verbatra translate --json
```

Melde die Listen `succeeded`, `partial` und `failed` aus der Zusammenfassung. Eine Locale mit `partial` oder `failed` wurde trotzdem mit allem geschrieben, was gelungen ist.

### 8. Committen und verbinden

Committe `verbatra.config.ts`, `.env.example`, die Anweisungsdatei und `.mcp.json` aus Schritt 3, `verbatra.lock.json`, `verbatra.provenance.json`, sobald ein Lauf sie geschrieben hat, und die übersetzten Locale-Dateien. Committe nie `.env`, `.env.local`, `.verbatra-local/` oder `verbatra.cache.json`; prüf, dass die `.gitignore` sie abdeckt.

Sag dem Menschen dann, dass er Claude Code neu starten und den Server `verbatra` des Projekts bestätigen soll, ohne zusätzlich das verbatra-Plugin zu installieren, das ihn ein zweites Mal registriert; `claude mcp list` zeigt die Verbindung. Ein anderer Client bekommt seinen einen Eintrag aus [Einen MCP-Client verbinden](/docs/connect-an-mcp-client).

## Warum diese Form

`translate` hat kein eigenes Ausgaben-Gate, also liegt das Gate in den Anweisungen des Agenten: Jeder Schritt vor Schritt 7 ist kostenlos und nur lesend.
