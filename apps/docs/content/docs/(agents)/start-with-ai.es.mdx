Esta página es para un proyecto que ya tiene archivos de locale en el repositorio. Pega el prompt de abajo en tu agente de IA para programar (Claude Code, Cursor o cualquier agente que pueda leer tu proyecto, abrir un enlace y ejecutar comandos de shell). El agente lee los pasos de esta página, revisa tu configuración, instala verbatra, crea una config que encaja con lo que encontró y muestra una vista previa de una ejecución; luego se detiene y te pide confirmación antes de llamar de verdad a un proveedor.

Si estás configurando verbatra tú mismo en lugar de dárselo a un agente, el [Inicio rápido](/docs/quickstart) es la versión humana del mismo recorrido.

## El prompt

Copia el bloque de abajo.

```text
Set up verbatra (`@verbatra/cli` on npm) in this project. Read
https://verbatra.kreitz-webdev.de/docs/start-with-ai.md and follow its steps in
order. Until I confirm, run only commands that spend nothing, and never run a
real `verbatra translate` without my explicit go-ahead. If you cannot open the
link, stop and tell me.
```

## Los pasos que sigue el agente

El prompt envía al agente a la versión Markdown de esta página. Agente: sigue estos pasos en orden y nunca te saltes la parada del paso 7.

### 1. Revisar la configuración existente

Antes de cambiar nada, busca la biblioteca de i18n en `package.json` (por ejemplo `i18next`, `vue-i18n`, `next-intl` o `@ngx-translate/core`) y los propios archivos de locale. Anota el locale de origen, cada locale de destino que ya exista y el patrón de ruta con un token `{locale}`, como `locales/{locale}.json`. [Elige tu stack](/docs/pick-your-stack) asigna a cada stack su id de formato y su estructura habitual, y [Formatos](/docs/formats) indica qué deja intacto o nunca crea cada formato: un archivo XLIFF y un Xcode String Catalog, por ejemplo, ya tienen que existir.

### 2. Instalar la CLI

```bash
npm install --save-dev @verbatra/cli
```

pnpm, yarn y bun también funcionan. Si pnpm termina con `ERR_PNPM_IGNORED_BUILDS`, ejecuta `pnpm approve-builds` una vez y no apruebes ninguna de las dos entradas. Si npm avisa de scripts de instalación que `allowScripts` no cubre, déjalos sin aprobar: verbatra no necesita ninguno.

### 3. Crear la config sin preguntas

```bash
npx verbatra init --provider <provider> --yes --json
```

Pregunta a la persona qué proveedor usar, salvo que el proyecto ya lo deje claro. [Proveedores](/docs/providers) lista los ids; `none` desactiva la traducción automática. Nunca elijas un proveedor que gaste en un servicio que la persona no haya aceptado, y nunca pases un valor de clave a `init`. `init` detecta el formato, el patrón de ruta y los locales, imprime un sobre JSON y nunca pregunta:

- Salida `0`: compara `result.config` con lo que encontraste en el paso 1, empezando por cada entrada de `result.sources` que diga `default`. Si algo está mal, vuelve a ejecutarlo con el `--format`, `--path`, `--source` o `--targets` correcto, más `--force`.
- Salida `2` con `FORMAT_AMBIGUOUS` o `LAYOUT_AMBIGUOUS`: elige entre los `candidates` y vuelve a ejecutarlo con `--format` o `--path`. Si los candidatos son archivos de namespace uno junto a otro, detente y pregunta a la persona, porque una config cubre un patrón de archivo.
- Salida `2` con `MISSING_OPTIONS`: el mensaje nombra cada flag que aún falta.
- Salida `2` con `CONFIG_EXISTS`: pregunta a la persona antes de pasar `--force`.

[init](/docs/cli/init) documenta cada flag.

### 4. Dejar la clave de API a la persona

Sáltate este paso con el proveedor `none`.

```bash
cp .env.example .env
```

Comprueba que `.env` nombra la variable de `result.apiKeyEnvVar`, deja su valor vacío y dile a la persona qué variable debe rellenar. Nunca escribas, inventes ni pidas un valor de clave. Sigue sin esperarla.

### 5. Ejecutar doctor

```bash
npx verbatra doctor --json
```

Corrige cada comprobación fallida que puedas editando `verbatra.config.ts` y vuelve a ejecutarlo. La comprobación `api-key` solo pasa cuando la persona ha puesto la clave, así que no entres en bucle con ella.

### 6. Vista previa sin gastar

```bash
npx verbatra check --json
npx verbatra diff --json
npx verbatra translate --dry-run --json
```

Ninguno de estos comandos llama a un proveedor, necesita una clave ni escribe un archivo. La salida `1` de `check` o `diff` significa que un locale no está sincronizado, lo esperado antes de una primera ejecución; solo la salida `2` es un problema de configuración. verbatra nunca sobrescribe un valor existente, ni siquiera en la primera ejecución: solo se traducen las claves que faltan en el destino. Una cadena vacía cuenta como valor existente, así que pregunta a la persona antes de borrar claves de marcador con `""`.

### 7. Detenerse y preguntar

Resume cuántas claves quedan pendientes por locale y qué informó `translate --dry-run`, y detente. Una ejecución real gasta de inmediato y no tiene su propio aviso de confirmación, así que espera la aprobación explícita de la persona. Nunca uses `--prune` salvo que la persona haya pedido eliminar las claves huérfanas.

### 8. Traducir tras la aprobación

```bash
npx verbatra translate --json
```

Informa de las listas `succeeded`, `partial` y `failed` del resumen. Un locale `partial` o `failed` se escribió igualmente con todo lo que salió bien.

### 9. Hacer commit de los archivos correctos

Haz commit de `verbatra.config.ts`, `.env.example`, `verbatra.lock.json`, `verbatra.provenance.json` cuando una ejecución lo haya escrito, y de los archivos de locale traducidos. Nunca hagas commit de `.env`, `.env.local`, `.verbatra-local/` ni `verbatra.cache.json`; `init` los añadió a `.gitignore`, así que confirma que se ignoran.

## Por qué esta forma

`translate` no tiene su propia barrera de gasto: en cuanto existen una config válida y una clave de API, un simple `verbatra translate` llama al proveedor de inmediato, sin ningún aviso de confirmación. Los pasos de arriba ponen esa barrera en las instrucciones del agente: `doctor`, `check`, `diff` y `translate --dry-run` son gratuitos y de solo lectura, así que el agente puede validar toda la configuración y mostrarte exactamente qué pasaría antes del paso 8, el único paso que gasta algo.
