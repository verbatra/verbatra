Use this to let a coding agent read translation status, fix values and, only if you allow it, run translations through verbatra's MCP server. The client starts the server as a child process over stdio, so there is no port and nothing to keep running.

You need:

- a project with a verbatra config (run [`npx verbatra init`](/docs/cli/init) first if there is none);
- Node.js 22.14 or later;
- a provider key in your environment, only if the agent should spend.

Tools, inputs and results are in [`verbatra mcp`](/docs/cli/mcp#tools).

<AvailableFrom version="0.2.0" pkg="@verbatra/mcp" />

## Pick a launch command

| Command | Needs | Reads `.env` files |
| --- | --- | --- |
| `npx -y @verbatra/mcp` | nothing installed | no |
| `npx verbatra mcp` | `@verbatra/cli` and `@verbatra/mcp` as dev dependencies | yes: `.env.local`, then `.env` |

Every example below uses `npx -y @verbatra/mcp`, which works in any project. Two look-alikes fail: `npx -y @verbatra/cli mcp` exits `2` because the CLI never installs `@verbatra/mcp`, and `npx verbatra mcp` without a local `@verbatra/cli` fetches an unrelated registry package named `verbatra`.

Point the server at the directory that holds the config. Each client section says how; [Project directory](/docs/cli/mcp#project-directory) has the rule.

<AvailableFrom version="0.3.0" pkg="@verbatra/mcp" />

The server is also listed in the [official MCP Registry](https://registry.modelcontextprotocol.io) as `io.github.verbatra/verbatra`.

## Decide whether the agent may spend

The server starts read-only: `translation.retranslateEntry` and `translation.translatePending` stay hidden, and no other tool calls a provider or reads a key. For that setup, leave the key and the spend switch out of the client config.

To let the agent spend, add both:

- `--allow-spend` in the server's arguments, or `VERBATRA_MCP_ALLOW_SPEND=1` in its environment ([Spend tools](/docs/cli/mcp#spend-tools));
- your provider's key variable, such as `ANTHROPIC_API_KEY` ([Providers](/docs/providers)).

<AvailableFrom version="0.3.0" pkg="@verbatra/mcp" />

Even then, the server tells the agent to run `translation.estimate` and wait for your yes before any spend call, and a config with `provider: { id: "none" }` keeps both spend tools hidden.

<Callout type="warn">
Never write a key into a committed file. `.mcp.json`, `.codex/config.toml`, `.gemini/settings.json`, `.cursor/mcp.json`, `.vscode/mcp.json` and `.github/mcp.json` are shared with the team; each section below passes the key by reference or from your environment instead.
</Callout>

## Claude Code

From the project root:

```bash
claude mcp add --transport stdio --scope project verbatra -- npx -y @verbatra/mcp
```

Claude Code's options go before `--`, the server's own arguments after it. `--scope` picks where the entry is stored:

| Scope | Stored in | Who gets it |
| --- | --- | --- |
| `local` (default) | `~/.claude.json`, under this project | you, in this project |
| `project` | `.mcp.json` at the project root, committed | everyone who opens the project |
| `user` | `~/.claude.json` | you, in every project |

`--scope project` writes this `.mcp.json`, which you can also write by hand:

```json
{
  "mcpServers": {
    "verbatra": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@verbatra/mcp"]
    }
  }
}
```

<AvailableFrom version="0.12.0" />

[`verbatra init --agent`](/docs/cli/init#set-up-coding-agents) writes the same entry next to any server the file already holds.

Claude Code sets `CLAUDE_PROJECT_DIR` to the project root, so no `--cwd` is needed, and passes on the environment you started it with. To spend for one session, export the key and start it with the switch:

```bash
VERBATRA_MCP_ALLOW_SPEND=1 claude
```

Do not combine `--env KEY=value` with `--scope project`: it writes the value into `.mcp.json`. Run `claude mcp list` to see whether the server connects. See the [Claude Code MCP documentation](https://code.claude.com/docs/en/mcp).

### The verbatra plugin

<AvailableFrom version="0.3.0" pkg="@verbatra/mcp" />

The plugin bundles the three [verbatra skills](/docs/agent-recipes#the-skills-pack), this server, and a hook that checks a locale file after Claude edits it. Install it for the project:

```bash
claude plugin marketplace add verbatra/skills
claude plugin install verbatra@verbatra --scope project
```

Each teammate installs it once. Under the default `user` scope it would start in every project you open.

- **Server**: `npx -y @verbatra/mcp` at a pinned version, with `--cwd` set to the open project. Without a config it still starts; run `npx verbatra init` and the next call picks the config up.
- **Spending**: off until you turn on the plugin's `allowSpend` option (`--config allowSpend=true` on install, or `/config`). A committed `.claude/settings.json` cannot turn it on, and `VERBATRA_MCP_ALLOW_SPEND` in your shell does not reach this server.
- **Key**: read from the environment you started `claude` with; the plugin has no key option.
- **Hook**: runs the project's own `verbatra check --file <path>` (CLI 0.12.0 or later, from `node_modules`) and hands broken syntax, placeholders, markup or ICU back to Claude. It downloads nothing and calls no provider.

See the [Claude Code plugins reference](https://code.claude.com/docs/en/plugins-reference).

## Codex

The Codex CLI, IDE extension and desktop app share `~/.codex/config.toml`, or a trusted project's `.codex/config.toml`:

```bash
codex mcp add verbatra -- npx -y @verbatra/mcp --cwd /path/to/your/project
```

The same entry by hand, with spending allowed; `env_vars` names variables Codex passes through from its own environment, so the file never holds the value:

```toml title=".codex/config.toml"
[mcp_servers.verbatra]
command = "npx"
args = ["-y", "@verbatra/mcp", "--allow-spend"]
cwd = "/path/to/your/project"
env_vars = ["ANTHROPIC_API_KEY"]
```

Drop `--allow-spend` and `env_vars` for a read-only entry. An `[mcp_servers.verbatra.env]` table or `codex mcp add --env` stores the value itself. See the [Codex MCP documentation](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).

## Gemini CLI

Gemini CLI reads `mcpServers` from `.gemini/settings.json` or `~/.gemini/settings.json`. Give an absolute `cwd`, and keep an entry with one in your user settings:

```json title="~/.gemini/settings.json"
{
  "mcpServers": {
    "verbatra": {
      "command": "npx",
      "args": ["-y", "@verbatra/mcp", "--allow-spend"],
      "cwd": "/path/to/your/project",
      "env": {
        "ANTHROPIC_API_KEY": "$ANTHROPIC_API_KEY"
      }
    }
  }
}
```

Gemini CLI hides sensitive variables from servers, so the key arrives only through `env`, where `$ANTHROPIC_API_KEY` is expanded from its environment. Drop `--allow-spend` and `env` for a read-only entry, and leave `trust` unset so every call is confirmed. `gemini mcp add -e KEY=value` stores the value itself. Run `/mcp` to see the server and its tools. See the [Gemini CLI MCP documentation](https://geminicli.com/docs/tools/mcp-server/).

## Cursor

Cursor reads `.cursor/mcp.json` in the project and `~/.cursor/mcp.json`. `${workspaceFolder}` is the project root:

```json title=".cursor/mcp.json"
{
  "mcpServers": {
    "verbatra": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@verbatra/mcp", "--cwd", "${workspaceFolder}"]
    }
  }
}
```

To spend, append `"--allow-spend"` to `args` and add `"env": { "ANTHROPIC_API_KEY": "${env:ANTHROPIC_API_KEY}" }`, which holds only the variable's name. Keep that entry in `~/.cursor/mcp.json` if not everyone should spend. See the [Cursor MCP documentation](https://cursor.com/docs/mcp).

## VS Code

VS Code (GitHub Copilot's agent mode) reads `.vscode/mcp.json`. Its top-level key is `servers`, and it starts servers in the workspace folder, so no `--cwd` is needed. To spend, declare the key as an input: VS Code prompts once and stores it outside the file.

```json title=".vscode/mcp.json"
{
  "inputs": [
    {
      "type": "promptString",
      "id": "anthropic-key",
      "description": "Anthropic API key",
      "password": true
    }
  ],
  "servers": {
    "verbatra": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@verbatra/mcp", "--allow-spend"],
      "env": {
        "ANTHROPIC_API_KEY": "${input:anthropic-key}"
      }
    }
  }
}
```

Drop `inputs`, `--allow-spend` and `env` for a read-only entry, or load the key with `"envFile": "${workspaceFolder}/.env.local"`. For a read-only install in one step, use [Install verbatra in VS Code](vscode:mcp/install?%7B%22name%22%3A%22verbatra%22%2C%22command%22%3A%22npx%22%2C%22args%22%3A%5B%22-y%22%2C%22%40verbatra%2Fmcp%22%5D%7D) or:

```bash
code --add-mcp '{"name":"verbatra","command":"npx","args":["-y","@verbatra/mcp"]}'
```

See the [VS Code MCP configuration reference](https://code.visualstudio.com/docs/agents/reference/mcp-configuration).

## GitHub Copilot

### Copilot cloud agent

A repository admin adds the server under **Settings**, **Copilot**, **MCP servers**. The cloud agent calls every tool it is given without asking, so `tools` is required; this allowlist holds every tool that neither writes nor calls a provider:

```json
{
  "mcpServers": {
    "verbatra": {
      "type": "local",
      "command": "npx",
      "args": ["-y", "@verbatra/mcp"],
      "tools": [
        "project.snapshot",
        "project.doctor",
        "status.check",
        "status.diff",
        "lock.state",
        "key.value",
        "key.integrity",
        "glossary.get",
        "review.queue",
        "usage.summary",
        "translation.estimate"
      ]
    }
  }
}
```

Add `translation.editEntry` and `glossary.write` only if the agent should write in its pull request. Keep `review.approve` and `review.reject` out: a review decision needs a person. Leave spending off, since nobody is asked before a call. If you grant it anyway, you need all three: an Agents secret such as `COPILOT_MCP_ANTHROPIC_API_KEY` (only the `COPILOT_MCP_` prefix reaches MCP servers), `"env": { "ANTHROPIC_API_KEY": "$COPILOT_MCP_ANTHROPIC_API_KEY" }` with `--allow-spend`, and the spend tool in `tools`.

To check it, assign an issue to Copilot, open **View session** and expand **Start MCP Servers**. See [Extending the cloud agent with MCP](https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/configure-mcp-servers).

### Copilot CLI

```bash
copilot mcp add verbatra -- npx -y @verbatra/mcp --cwd /path/to/your/project
```

This writes `~/.copilot/mcp-config.json`. Copilot CLI also reads a trusted project's `.mcp.json` and `.github/mcp.json`. It passes a server only `PATH`, so `--allow-spend` goes in `args` and a key into the entry's `env`, only in `~/.copilot/mcp-config.json`. Run `/mcp show verbatra` for its status. See [Adding MCP servers to Copilot CLI](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-mcp-servers).

## Windsurf

Windsurf's Cascade reads one `mcp_config.json` for all projects, so give an absolute `--cwd`:

```json title="mcp_config.json"
{
  "mcpServers": {
    "verbatra": {
      "command": "npx",
      "args": ["-y", "@verbatra/mcp", "--cwd", "/path/to/your/project"]
    }
  }
}
```

To spend, append `"--allow-spend"` and add `"env": { "ANTHROPIC_API_KEY": "${env:ANTHROPIC_API_KEY}" }`. See the [Cascade MCP documentation](https://docs.devin.ai/desktop/cascade/mcp).

## Zed

Zed reads `context_servers` from its settings; **Settings**, **AI**, **MCP Servers**, **Add Server** writes the entry:

```json title="settings.json"
{
  "context_servers": {
    "verbatra": {
      "command": "npx",
      "args": ["-y", "@verbatra/mcp", "--cwd", "/path/to/your/project"],
      "env": {}
    }
  }
}
```

A green dot in that page means the server is active. A key in `env` is a literal value, so add it and `--allow-spend` only in your user settings, never in `.zed/settings.json`. See the [Zed MCP documentation](https://zed.dev/docs/ai/mcp).

## JetBrains AI Assistant

Open **Settings**, **Tools**, **AI Assistant**, **Model Context Protocol (MCP)**, add a server, and paste:

```json
{
  "mcpServers": {
    "verbatra": {
      "command": "npx",
      "args": ["-y", "@verbatra/mcp"]
    }
  }
}
```

Set **Working directory** to the project root. JetBrains does not document how a server gets environment variables, so keep this entry read-only. See the [AI Assistant MCP documentation](https://www.jetbrains.com/help/ai-assistant/mcp.html).

## Claude Desktop

**Settings**, **Developer**, **Edit Config** opens `claude_desktop_config.json` (`~/Library/Application Support/Claude/` on macOS, `%APPDATA%\Claude\` on Windows). There is no project, so `--cwd` is absolute:

```json title="claude_desktop_config.json"
{
  "mcpServers": {
    "verbatra": {
      "command": "npx",
      "args": ["-y", "@verbatra/mcp", "--cwd", "/path/to/your/project"]
    }
  }
}
```

To spend, append `"--allow-spend"` and add `"env": { "ANTHROPIC_API_KEY": "..." }`; the file lives outside every repository. Restart Claude Desktop after each change. The server's stderr goes to `mcp-server-verbatra.log` in `~/Library/Logs/Claude` or `%APPDATA%\Claude\logs`. See [Connect to local MCP servers](https://modelcontextprotocol.io/docs/develop/connect-local-servers).

## Any other stdio client

Give the client:

- the command `npx` with `-y @verbatra/mcp`, or the path to an installed `verbatra-mcp` binary;
- `--cwd /path/to/your/project`, unless it starts servers in the project root;
- `--config <path>` if the upward search would not find the config;
- `--allow-spend` and the key variable only if the agent should spend, through the client's own secret mechanism.

## Check the connection

Ask the agent to call `project.snapshot`. It calls no provider and returns the locales, the format and the provider id, so a wrong directory shows at once. The server writes only protocol messages to stdout, so the client's server log shows anything else.

<AvailableFrom version="0.3.0" pkg="@verbatra/mcp" />

- **`configured: false`**: the server found no usable config but keeps running. Ask for `project.doctor`, which names each failed check and its fix, then run `npx verbatra init` or correct `--cwd`. See [Without a config](/docs/cli/mcp#without-a-config).
- **Spend tools missing**: check the spend switch and whether the provider is `none`.
- **Config edited**: no restart needed, except after editing a module the config imports. See [After a config change](/docs/cli/mcp#after-a-config-change).
