Use this to let a coding agent read translation status and fix values through verbatra's stdio MCP server. Register it once per client: a second entry starts a second server. You need a project with a verbatra config ([`npx verbatra init`](/docs/cli/init)) and Node.js 22.14 or later.

<AvailableFrom version="0.2.0" pkg="@verbatra/mcp" />

## Pick a launch command

| Command | Needs | Reads `.env` files |
| --- | --- | --- |
| `npx -y @verbatra/mcp` | nothing installed | no |
| `npx verbatra mcp` | `@verbatra/cli` and `@verbatra/mcp` as dev dependencies | yes: `.env.local`, then `.env` |

The examples use `npx -y @verbatra/mcp`. Avoid `npx -y @verbatra/cli mcp`, which exits `2` because the CLI never installs `@verbatra/mcp`. Each section says how to point the server at the config's directory; [Project directory](/docs/cli/mcp#project-directory) has the rule.

### MCP Registry

<AvailableFrom version="0.3.0" pkg="@verbatra/mcp" />

The server is also listed in the [official MCP Registry](https://registry.modelcontextprotocol.io) as `io.github.verbatra/verbatra`.

## Decide whether the agent may spend

The server starts with read and local edit tools only: spend tools stay hidden and no tool reads a key. To let the agent spend, add both:

- `--allow-spend` in the arguments, or `VERBATRA_MCP_ALLOW_SPEND=1` in the environment ([Spend tools](/docs/cli/mcp#spend-tools));
- your provider's key variable, such as `ANTHROPIC_API_KEY` ([Providers](/docs/providers)).

<Callout type="warn">
Never write a key into a committed file such as `.mcp.json`, `.codex/config.toml`, `.cursor/mcp.json` or `.vscode/mcp.json`.
</Callout>

To keep values from the agent's model, add `--redact-values`; see [Studio and MCP](/docs/data-handling#studio-and-mcp).

### Estimate first

<AvailableFrom version="0.3.0" pkg="@verbatra/mcp" />

The server still tells the agent to run `translation.estimate` and wait for your yes before spending.

## Claude Code

<Callout type="warn">
Never combine the verbatra plugin with a `verbatra` entry in `.mcp.json`: the plugin brings a second server.
</Callout>

### Let init write it

<AvailableFrom version="0.12.0" />

Recommended, from the project root:

```bash
npx verbatra init --agent
```

[`init --agent`](/docs/cli/init#set-up-coding-agents) writes the agent instruction file and this entry to the committed `.mcp.json`, spending off:

```json
{
  "mcpServers": {
    "verbatra": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@verbatra/mcp"]
    }
  }
}
```

Restart Claude Code and approve the `verbatra` server. Claude Code passes `CLAUDE_PROJECT_DIR` and your shell's environment, so no `--cwd` is needed. To spend for one session, export the key and run:

```bash
VERBATRA_MCP_ALLOW_SPEND=1 claude
```

Run `claude mcp list` to check the connection. See the [Claude Code MCP documentation](https://code.claude.com/docs/en/mcp).

### Other routes

#### Without the CLI

```bash
claude mcp add --transport stdio --scope project verbatra -- npx -y @verbatra/mcp
```

This writes the same `.mcp.json` entry. Never add `--env KEY=value` to a project entry: it writes the value into `.mcp.json`.

#### The verbatra plugin

<AvailableFrom version="0.3.0" pkg="@verbatra/mcp" />

Instead of `.mcp.json`, the plugin bundles the [verbatra skills](/docs/agent-recipes#the-skills-pack), this server, and a hook that checks a locale file after Claude edits it:

```bash
claude plugin marketplace add verbatra/skills
claude plugin install verbatra@verbatra --scope project
```

- **Server**: a pinned `@verbatra/mcp` with `--cwd` set to the open project.
- **Spending**: off until you turn on the plugin's `allowSpend` option (`--config allowSpend=true`, or `/config`). A committed file cannot turn it on.
- **Key**: read from the environment you started `claude` with.
- **Hook**: runs the project's own `verbatra check --file <path>` (CLI 0.12.0 or later) and reports broken syntax, placeholders, markup or ICU to Claude, calling no provider.

See the [Claude Code plugins reference](https://code.claude.com/docs/en/plugins-reference).

## Codex

Codex reads `~/.codex/config.toml`, or a trusted project's `.codex/config.toml`:

```bash
codex mcp add verbatra -- npx -y @verbatra/mcp --cwd /path/to/your/project
```

Or write it by hand, here with spending allowed; `env_vars` names variables Codex passes through, so the file never holds the value:

```toml title=".codex/config.toml"
[mcp_servers.verbatra]
command = "npx"
args = ["-y", "@verbatra/mcp", "--allow-spend"]
cwd = "/path/to/your/project"
env_vars = ["ANTHROPIC_API_KEY"]
```

Drop `--allow-spend` and `env_vars` for a no-spend entry. An `[mcp_servers.verbatra.env]` table or `codex mcp add --env` stores the value itself. See the [Codex MCP documentation](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).

## Gemini CLI

Gemini CLI reads `mcpServers` from `.gemini/settings.json` or `~/.gemini/settings.json`. Keep an entry with an absolute `cwd` in your user settings:

```json title="~/.gemini/settings.json"
{
  "mcpServers": {
    "verbatra": {
      "command": "npx",
      "args": ["-y", "@verbatra/mcp", "--allow-spend"],
      "cwd": "/path/to/your/project",
      "env": {
        "ANTHROPIC_API_KEY": "$ANTHROPIC_API_KEY"
      }
    }
  }
}
```

Gemini CLI hides sensitive variables from servers, so the key arrives only through `env`, expanded from its environment. Drop `--allow-spend` and `env` for a no-spend entry, and leave `trust` unset. Run `/mcp` to see the tools. See the [Gemini CLI MCP documentation](https://geminicli.com/docs/tools/mcp-server/).

## Cursor

Cursor reads `.cursor/mcp.json` and `~/.cursor/mcp.json`:

```json title=".cursor/mcp.json"
{
  "mcpServers": {
    "verbatra": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@verbatra/mcp", "--cwd", "${workspaceFolder}"]
    }
  }
}
```

To spend, append `"--allow-spend"` to `args` and add `"env": { "ANTHROPIC_API_KEY": "${env:ANTHROPIC_API_KEY}" }`, which holds only the variable's name. See the [Cursor MCP documentation](https://cursor.com/docs/mcp).

## VS Code

VS Code (GitHub Copilot's agent mode) reads `.vscode/mcp.json`, whose top-level key is `servers`. It starts servers in the workspace folder, so no `--cwd` is needed. To spend, declare the key as an input, which VS Code stores outside the file:

```json title=".vscode/mcp.json"
{
  "inputs": [
    {
      "type": "promptString",
      "id": "anthropic-key",
      "description": "Anthropic API key",
      "password": true
    }
  ],
  "servers": {
    "verbatra": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@verbatra/mcp", "--allow-spend"],
      "env": {
        "ANTHROPIC_API_KEY": "${input:anthropic-key}"
      }
    }
  }
}
```

Drop `inputs`, `--allow-spend` and `env` for a no-spend entry. Instead of the file, [Install verbatra in VS Code](vscode:mcp/install?%7B%22name%22%3A%22verbatra%22%2C%22command%22%3A%22npx%22%2C%22args%22%3A%5B%22-y%22%2C%22%40verbatra%2Fmcp%22%5D%7D) or this command adds the no-spend entry to your user profile; use one of the three, never two:

```bash
code --add-mcp '{"name":"verbatra","command":"npx","args":["-y","@verbatra/mcp"]}'
```

See the [VS Code MCP configuration reference](https://code.visualstudio.com/docs/agents/reference/mcp-configuration).

## GitHub Copilot

### Copilot cloud agent

A repository admin adds the server under **Settings**, **Copilot**, **MCP servers**. The cloud agent calls tools without asking, so list only tools that neither write nor call a provider:

```json
{
  "mcpServers": {
    "verbatra": {
      "type": "local",
      "command": "npx",
      "args": ["-y", "@verbatra/mcp"],
      "tools": [
        "project.snapshot",
        "project.doctor",
        "status.check",
        "status.diff",
        "lock.state",
        "key.value",
        "key.integrity",
        "glossary.get",
        "review.queue",
        "usage.summary",
        "translation.estimate"
      ]
    }
  }
}
```

Add `translation.editEntry` and `glossary.write` only if the agent should write in its pull request, and keep `review.approve` and `review.reject` out: a review decision needs a person. To check the setup, open the agent's **View session** and expand **Start MCP Servers**. See [Extending the cloud agent with MCP](https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/configure-mcp-servers).

### Copilot CLI

```bash
copilot mcp add verbatra -- npx -y @verbatra/mcp --cwd /path/to/your/project
```

This writes `~/.copilot/mcp-config.json`. Copilot CLI passes a server only `PATH`, so a key goes into that entry's `env` on your machine, never into a project file. See [Adding MCP servers to Copilot CLI](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-mcp-servers).

## Windsurf

Windsurf reads one `mcp_config.json` for all projects, so give an absolute `--cwd`:

```json title="mcp_config.json"
{
  "mcpServers": {
    "verbatra": {
      "command": "npx",
      "args": ["-y", "@verbatra/mcp", "--cwd", "/path/to/your/project"]
    }
  }
}
```

To spend, append `"--allow-spend"` and add `"env": { "ANTHROPIC_API_KEY": "${env:ANTHROPIC_API_KEY}" }`. See the [Cascade MCP documentation](https://docs.devin.ai/desktop/cascade/mcp).

## Zed

Zed reads `context_servers` from its settings; **Settings**, **AI**, **MCP Servers**, **Add Server** writes the entry:

```json title="settings.json"
{
  "context_servers": {
    "verbatra": {
      "command": "npx",
      "args": ["-y", "@verbatra/mcp", "--cwd", "/path/to/your/project"],
      "env": {}
    }
  }
}
```

A key in `env` is a literal value, so add it and `--allow-spend` only in your user settings, never in `.zed/settings.json`. See the [Zed MCP documentation](https://zed.dev/docs/ai/mcp).

## JetBrains AI Assistant

Open **Settings**, **Tools**, **AI Assistant**, **Model Context Protocol (MCP)**, add a server, and paste:

```json
{
  "mcpServers": {
    "verbatra": {
      "command": "npx",
      "args": ["-y", "@verbatra/mcp"]
    }
  }
}
```

Set **Working directory** to the project root, and keep this entry to read and local edit, no spend. See the [AI Assistant MCP documentation](https://www.jetbrains.com/help/ai-assistant/mcp.html).

## Claude Desktop

**Settings**, **Developer**, **Edit Config** opens `claude_desktop_config.json`. There is no project, so `--cwd` is absolute:

```json title="claude_desktop_config.json"
{
  "mcpServers": {
    "verbatra": {
      "command": "npx",
      "args": ["-y", "@verbatra/mcp", "--cwd", "/path/to/your/project"]
    }
  }
}
```

To spend, append `"--allow-spend"` and add `"env": { "ANTHROPIC_API_KEY": "..." }`; the file lives outside every repository. Restart Claude Desktop after each change. See [Connect to local MCP servers](https://modelcontextprotocol.io/docs/develop/connect-local-servers).

## Any other stdio client

Give the client the command `npx -y @verbatra/mcp`, plus `--cwd /path/to/your/project` unless it starts servers in the project root, and `--config <path>` if the config sits elsewhere. Pass `--allow-spend` and the key only through the client's secret mechanism.

## Check the connection

<AvailableFrom version="0.3.0" pkg="@verbatra/mcp" />

Ask the agent to call `project.snapshot`; it returns the locales, format and provider without calling it.

- **`configured: false`**: no usable config was found. Ask for `project.doctor`, then run `npx verbatra init` or fix `--cwd`. See [Without a config](/docs/cli/mcp#without-a-config).
- **Spend tools missing**: check the spend switch and whether the provider is `none`.
- **Config edited**: no restart needed; see [After a config change](/docs/cli/mcp#after-a-config-change).
