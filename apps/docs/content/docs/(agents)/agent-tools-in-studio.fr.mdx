Sers-t'en pour qu'un agent IA de navigateur, comme Gemini ou Claude dans Chrome, vérifie la dérive, traite la file de relecture et corrige des entrées dans l'onglet Studio que tu as ouvert. L'agent appelle des outils nommés au lieu de deviner la page. Ce n'est pas fait pour configurer un projet ni pour l'accès à distance.

Il te faut :

- Studio lancé sur ton projet ([Réviser dans Studio](/docs/review-in-studio#démarrer-studio)) ;
- Chrome 149 ou plus récent avec `chrome://flags/#enable-webmcp-testing` activé, ou un navigateur qui prend WebMCP en charge nativement, dans une fenêtre normale et non headless.

<Callout title="Expérimental">
WebMCP est une nouvelle capacité du navigateur derrière un flag, et sa surface peut encore changer.
</Callout>

## Activer les outils

```bash
verbatra studio --expose-agent-tools
```

`VERBATRA_STUDIO_AGENT_TOOLS=1` fait la même chose ; [Dépenses et outils d'agent](/docs/cli/studio#dépenses-et-outils-dagent) explique comment le flag et la variable sont résolus. Ouvre l'URL affichée dans le navigateur WebMCP, et l'agent de cet onglet trouve les outils. Dans un navigateur sans WebMCP, Studio n'enregistre rien et le tableau de bord ne change pas.

Pour que l'agent puisse appeler ton fournisseur, lance aussi Studio avec `--allow-spend` ([Dépenses et outils d'agent](/docs/cli/studio#dépenses-et-outils-dagent)).

L'agent lit chaque valeur sans masquage, comme la page l'affiche : Studio ne masque rien, car un agent dans l'onglet peut de toute façon lire la page. Pour cacher les valeurs à un agent, utilise plutôt le serveur MCP avec [`--redact-values`](/docs/cli/mcp#redacted-values) ; pour un projet sous NDA, voir [Studio et MCP](/docs/data-handling#studio-et-mcp).

## Savoir ce que l'agent peut appeler

Chaque outil est une action Studio avec le préfixe `verbatra_`. Les outils de lecture sont marqués en lecture seule, les outils d'écriture ne modifient que tes fichiers locaux, et les outils payants ne s'enregistrent qu'avec `--allow-spend`.

### Outils de lecture

| Outil | Ce qu'il fait |
| --- | --- |
| `verbatra_project_snapshot` | la config chargée, les capacités et les limites de débit sous `capabilities.limits` |
| `verbatra_status_check` | la couverture par locale |
| `verbatra_status_diff` | les clés manquantes, modifiées et orphelines par locale |
| `verbatra_glossary_get` | le glossaire résolu, secrets masqués |
| `verbatra_lock_state` | l'état du fichier de verrouillage par locale |
| `verbatra_history_list` | les commits récents sur les fichiers de locale, avec le nom de l'auteur ([jamais l'e-mail](/docs/data-handling#studio-et-mcp)) |
| `verbatra_key_integrity` | les contrôles de placeholders, de balisage et d'ICU d'une clé, dans les locales où sa source a changé |
| `verbatra_review_queue` | chaque valeur écrite par une machine que personne n'a approuvée, d'après les fichiers versionnés <AvailableFrom version="0.6.0" pkg="@verbatra/studio" /> |
| `verbatra_key_value` | la source et la cible d'une clé, avec qui a écrit la cible |
| `verbatra_key_context` | la description, les termes du glossaire et le `maxLength` d'une clé, et le contrôle d'un `draft` optionnel <AvailableFrom version="0.6.0" pkg="@verbatra/studio" /> |
| `verbatra_locale_values` | les valeurs des clés par locale cible, 200 par page par défaut, restreintes par `locales`, `keys` ou `query` <AvailableFrom version="0.6.0" pkg="@verbatra/studio" /> |
| `verbatra_locale_integrity` | chaque traduction qui échoue aux contrôles d'intégrité <AvailableFrom version="0.6.0" pkg="@verbatra/studio" /> |
| `verbatra_translation_estimate` | ce qu'un appel translate-pending enverrait et coûterait, sans appeler de fournisseur |
| `verbatra_usage_summary` | la consommation de tokens et le budget de la dernière exécution |

### Outils d'écriture

| Outil | Ce qu'il fait |
| --- | --- |
| `verbatra_glossary_write` | modifie un terme d'un glossaire stocké dans un fichier <AvailableFrom version="0.4.0" pkg="@verbatra/studio" /> |
| `verbatra_review_approve` | enregistre l'approbation d'une valeur par une personne nommée <AvailableFrom version="0.6.0" pkg="@verbatra/studio" /> |
| `verbatra_review_reject` | enregistre le rejet d'une personne nommée et retire la valeur |
| `verbatra_translation_editEntry` | écrit une valeur via le contrôle d'intégrité |

### Outils payants

| Outil | Ce qu'il fait |
| --- | --- |
| `verbatra_translation_retranslateEntry` | retraduit une clé dans une locale |
| `verbatra_translation_translatePending` | traduit tout ce qui est en attente, éventuellement pour certaines `locales` et sous un plafond `maxTokens` <AvailableFrom version="0.6.0" pkg="@verbatra/studio" /> |

`verbatra_key_integrity` ne renvoie que les locales où la source de la clé a changé, donc une liste vide signifie qu'il n'y avait rien à vérifier. Ses lignes sont plus plates que celles de [`key.integrity`](/docs/cli/mcp#entrées-et-résultats) dans le serveur MCP. Seul le serveur MCP a `project.doctor` et `report.provenance`. `verbatra_locale_values` pagine comme son `locale.values`, avec les mêmes `limit` et `cursor` ([Autres entrées et résultats](/docs/cli/mcp#autres-entrées-et-résultats)).

## Connaître les règles des outils

Chaque appel passe par le RPC loopback authentifié du tableau de bord, avec la même validation des entrées et le même [contrôle d'intégrité](/docs/translation-safety) : une valeur qui échoue à un contrôle est rejetée et rien n'est écrit.

### Règles par appel

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

- **Provenance** : une modification de l'agent est enregistrée avec l'origine `agent` et reste dans la file de relecture ; une modification depuis le tableau de bord est `human`. Les outils de lecture indiquent qui a écrit chaque valeur ([Le fichier de verrouillage](/docs/the-lock-file#la-provenance-de-chaque-valeur)).
- **Travail humain** : retraduire refuse la valeur d'une personne avec `KEY_PROTECTED` et une clé épinglée avec `KEY_PINNED`, et modifier refuse une clé épinglée ([Garder les traductions humaines](/docs/protecting-human-translations)).
- **Décisions de relecture** : approuver et rejeter servent seulement à transmettre ta décision. Les deux exigent `reviewer`, le nom de la personne, et `expectedValue`, le texte relu ; une valeur modifiée est refusée avec `REVIEW_VALUE_CHANGED`.
- **Pas d'outils groupés** : **Approve selected**, **Reject selected**, **Retranslate selected** et **Approve all in** restent entre les mains d'une personne.
- **Estimer d'abord** : une locale inconnue est refusée avec `UNKNOWN_LOCALE` avant toute dépense, et c'est le plus bas des `maxTokens` de l'appel et de la config qui s'applique ([Estimer le coût avant une exécution](/docs/estimating-cost)).
- **Limites de débit** : par minute glissante, 20 retraductions, 20 modifications, 20 écritures de glossaire, 60 décisions de relecture et 5 appels translate-pending, un à la fois. Un second appel pour une entrée encore en cours est refusé avec `ALREADY_IN_PROGRESS`.

## Lire un appel échoué

Chaque outil renvoie l'enveloppe du tableau de bord, donc un échec se lit `{ "ok": false, "error": { "code": ..., "message": ... } }`. En plus des codes du SDK, comme un rejet d'intégrité ou `UNKNOWN_KEY`, la couche RPC ajoute :

| Code | Signification |
| --- | --- |
| `REQUEST_INVALID` | la requête ou la réponse n'était pas une enveloppe lisible |
| `METHOD_UNKNOWN` | la méthode n'existe pas dans cette version de Studio |
| `SPEND_DISABLED` | une méthode payante alors que la dépense est coupée : Studio tourne sans `--allow-spend`, ou le fournisseur est `none` ; le message dit lequel |
| `PARAMS_INVALID` | un paramètre a échoué à la validation ; `issues` nomme chaque champ |
| `METHOD_RATE_LIMITED` | limite de débit dépassée ; `retryAfterSeconds` dit quand l'appel passera |
| `SESSION_EXPIRED` | Studio a redémarré avec un nouveau token ; ouvre l'URL qu'il a affichée |

## Réparer les outils dégradés

Si le navigateur rejette un enregistrement, chaque vue affiche un avertissement comme :

> Agent tools degraded: 2 of the agent tool registrations failed with SecurityError. The dashboard itself is unaffected. The browser console lists every failing tool.

Les outils qui se sont enregistrés restent appelables, et le tableau de bord fonctionne normalement. La console contient une ligne qui nomme chaque échec :

```text output
Verbatra agent tools: 2 of 20 tool registrations failed. verbatra_status_diff (SecurityError: ...); verbatra_key_value (SecurityError: ...)
```

Lis d'abord le nom de l'erreur, puis recharge l'onglet, ce qui relance l'enregistrement. Un flag manquant ou un navigateur sans WebMCP n'affiche jamais cet avis ; rien n'est enregistré, en silence. Une session sans `--allow-spend` tente deux enregistrements de moins, et ce n'est pas un échec.

## Mesurer le risque de dépense

Les outils n'ajoutent aucune exposition réseau : Studio n'écoute toujours que sur `127.0.0.1`, chaque requête porte le token de session, et les outils qui renvoient du texte du projet le marquent comme non fiable, pour que l'agent le traite comme des données.

<Callout type="warn">
Avec `--allow-spend` et `--expose-agent-tools` ensemble, un agent peut dépenser chez ton fournisseur sans confirmation par appel, jusqu'aux limites de débit. Studio ne distingue pas l'appel d'un agent de ton clic, il n'ajoute donc aucune boîte de validation. Pour lire et modifier seulement, laisse `--allow-spend` désactivé.
</Callout>
