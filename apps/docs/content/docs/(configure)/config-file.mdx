verbatra reads one small, non-secret config object and validates it before it does any work. No API key is ever read from it: each provider reads its key from an environment variable (see [Providers](/docs/providers#keys-come-from-the-environment)), so the config is safe to commit.

## A minimal config

```ts title="verbatra.config.ts"
import { defineConfig } from "@verbatra/sdk";

export default defineConfig({
  sourceLocale: "en",
  targetLocales: ["de", "fr"],
  format: "i18next-json",
  files: {
    pattern: "locales/{locale}.json",
  },
  provider: {
    id: "gemini",
    options: {
      model: "gemini-2.5-flash", // example model id; use your provider's current one
      maxOutputTokens: 4096,
    },
  },
});
```

`defineConfig` returns its argument unchanged and only types it: `options.model` completes to the selected provider's model ids, while at runtime any non-empty string is accepted.

## Every key

Unknown keys are rejected at every level, with `$schema` as the single exception, which is also why an API key cannot live in the config.

| Key | Type | Default | Since | Effect |
| --- | --- | --- | --- | --- |
| `$schema` | string | none | 0.9.0 | Points an editor at the [JSON Schema](#editor-validation); ignored at runtime. |
| `sourceLocale` | locale code | required | 0.1.0 | The locale your source strings are written in. |
| `targetLocales` | locale code array | required | 0.1.0 | At least one; never `sourceLocale`, never two equal ignoring case. |
| `format` | format id | required | 0.1.0 | The [format](/docs/formats) of your locale files, or a `custom:` id for an [outside adapter](/docs/custom-format-adapters). |
| `files.pattern` | string | required | 0.1.0 | The path to each locale file, with a `{locale}` token. |
| `files.localeStyle` | `"literal"`, `"posix"`, `"android"` | `"literal"` | 0.7.0 | How `{locale}` is spelled in the path. |
| `provider.id` | provider id | required | 0.1.0 | The translation provider, or `none` for no machine translation. |
| `provider.options` | object | required, except for `none` | 0.1.0 | The provider's own options, listed per provider on [Providers](/docs/providers). |
| `glossary` | object or file path | none | 0.1.0 | Fixed translations, forbidden renderings and do-not-translate terms. |
| `tone` | `"formal"`, `"informal"`, `"neutral"` | none | 0.1.0 | The register to translate in, applied [per provider](/docs/providers#tone-and-glossary-across-providers). |
| `prune` | boolean | `false` | 0.3.0 | Remove orphaned keys from target files and the lock; `translate --prune` overrides it. |
| `generatePlurals` | boolean | `false` | 0.3.0 | Synthesize the CLDR plural forms a target language needs. |
| `fuzzyCache.enabled` | boolean | required in the block | 0.11.0 | Reuse the translation of a source string that changed only slightly. |
| `fuzzyCache.threshold` | number, `0.5` to `1` | `0.9` | 0.11.0 | How alike the old and new source must be for a reuse. |
| `humanEdits` | `"protect"`, `"suggest"`, `"overwrite"` | `"protect"` | 0.12.0 | What a run does with a stale key a person wrote. |
| `pinnedKeys` | string array | none | 0.12.0 | Key patterns (`*` matches any run of characters) no machine write ever touches. |
| `network.policy` | `"any"`, `"local-only"`, `"allowlist"` | `"any"` | 0.12.0 | Which hosts a provider may connect to. See [Restrict network access](/docs/network-policy). |
| `network.allowedHosts` | string array | none; required for `"allowlist"` | 0.12.0 | Extra permitted hosts: names, `*.suffix` wildcards, IPs or CIDR ranges. |
| `sensitiveData.mode` | `"off"`, `"warn"`, `"block"`, `"redact"` | `"off"` | 0.12.0 | What a run does with [sensitive content](/docs/data-handling#sensitive-content-guard) before sending. |
| `sensitiveData.detectors` | detector id array | `secret`, `email`, `iban`, `credit-card` | 0.12.0 | Detectors to run; `phone`, `ip`, `private-host` are opt-in. |
| `sensitiveData.patterns` | string array | none | 0.12.0 | Regular expressions for your own terms, such as codenames. |
| `sensitiveData.allow` | string array | none | 0.12.0 | Matches never reported; `*` is a wildcard. |
| `maxBatchSize` | positive integer | `50` | 0.3.0 | The most entries sent in one provider request. |
| `maxLength` | map of key to positive integer | none | 0.11.0 | Per-key length budgets in grapheme clusters. |
| `maxTokens` | positive integer | none | 0.5.0 | A whole-run token budget. |
| `budgetBehavior` | `"warn"`, `"stop"` | `"warn"` | 0.5.0 | Whether reaching `maxTokens` only warns or stops sending. |
| `rates.asOf` | `YYYY-MM-DD` date | required in the block | 0.11.0 | The date you read the rates. |
| `rates.currency` | three uppercase letters | required in the block | 0.11.0 | The currency of every rate, such as `USD` or `EUR`. |
| `rates.table` | map of rate key to rate | required in the block | 0.11.0 | Rates keyed by `provider/model` or provider id. |
| `extract.framework` | `"i18next"` | required in the block | 0.11.0 | Which call sites the source scan looks for. |
| `extract.roots` | string array | required in the block | 0.11.0 | The directories to scan, at least one. |
| `extract.exclude` | string array | none | 0.11.0 | Directory names to skip on top of the built-in set. |
| `extract.literals.ignore` | string array | none | 0.11.0 | Exact texts `doctor --literals` holds back. |
| `extract.unused.ignore` | string array | none | 0.11.0 | Keys or `*` patterns `diff --unused` never reports as unused. |

### Locales and files

- **`files.pattern`** must contain `{locale}`, the only token it understands: `locales/{locale}.json` resolves to `locales/de.json`, against the working directory. It is a literal path, never a glob, so one config addresses one file per locale; for several namespace files see [Namespace layouts](/docs/formats#namespace-layouts). `apple-xcstrings` still needs the token, but every locale resolves to the same catalogue ([Xcode String Catalogs](/docs/formats#xcode-string-catalogs-xcstrings)).
- **`files.localeStyle`** decides what the token expands to:
  - `literal` writes the tag as configured, which the JSON, YAML, XLIFF, ARB, properties and Apple `.lproj` layouts need.
  - `posix` replaces `-` with `_`, for gettext and Java `messages_{locale}.properties`: `pt-BR` becomes `pt_BR`, `zh-Hant-TW` becomes `zh_Hant_TW`, `es-419` becomes `es_419`. A variant such as `de-1996` has no posix spelling. `gettext-po` spells scripts the gettext way (next section).
  - `android` expands to a whole resource directory, written as `res/{locale}/strings.xml`: `values` for the source, then `values-de`, `values-pt-rBR`, `values-b+zh+Hans`.

  A style refuses a locale it cannot spell rather than writing a directory the platform would ignore.

### gettext locale names

<AvailableFrom version="0.12.0" />

With `format: "gettext-po"` and `localeStyle: "posix"`, a file is named the gettext way, `language_REGION@modifier`, while the config keeps the BCP 47 code:

| Config code | File name |
| --- | --- |
| `pt-BR` | `pt_BR` |
| `es-419` | `es_419` |
| `sr-Latn` | `sr@latin` |
| `sr-Latn-RS` | `sr_RS@latin` |
| `uz-Cyrl` | `uz@cyrillic` |
| `ks-Deva-IN` | `ks_IN@devanagari` |
| `zh-Hant-TW` | `zh_TW` |
| `sr-Cyrl-RS` | `sr_RS` |

A script the language and region imply is left out, so configuring both `zh-TW` and `zh-Hant-TW` fails with `LOCALE_PATH_COLLISION`. A script with no gettext modifier, such as `zh-Hant` without a region, fails with `LOCALE_LAYOUT_INVALID`. [`verbatra init`](/docs/cli/init) reads these names back, and a created catalogue uses them in its `Language` header. Other formats keep the ICU spelling under `posix` (`sr_Latn`).

### Locale codes

<AvailableFrom version="0.12.0" />

Every locale code must be a tag `Intl.getCanonicalLocales` accepts, with a two- or three-letter language subtag; otherwise the load fails with `CONFIG_INVALID`, naming the field and the code. `pt_BR` is rejected (write `pt-BR` and set `localeStyle: "posix"`), and so is a language name such as `german`. A valid but non-canonical code, such as `zh-hant-tw` or the deprecated `iw`, works as written, and [`verbatra doctor`](/docs/cli/doctor) suggests the canonical form. verbatra never renames a file, and a respelled code keeps its state ([A respelled locale code](/docs/the-lock-file#a-respelled-locale-code)).

### provider

`provider.id` selects one of the [providers](/docs/providers), or `none`. From 0.12.0 any key under `provider` besides `id` and `options`, such as a misplaced `localeMap`, fails with `CONFIG_INVALID`. Every provider except `none` accepts `options.localeMap` and `options.requestTimeoutMs` ([Providers](/docs/providers#locale-codes-sent-to-the-provider)). For `none`, `options` may be omitted and must otherwise be `{}` ([Run without machine translation](/docs/human-only-workflow)).

### glossary

Terms translated a fixed way, inline or as a path to a JSON file of the same shape; the two forms never merge. Version 1 maps each source term to the translation every locale uses:

```ts title="verbatra.config.ts"
export default defineConfig({
  // ...
  glossary: {
    "Sign in": "Anmelden",
  },
  // or: glossary: "glossary.json",
});
```

A relative path resolves against the config file's directory. The file must be UTF-8, at most 1 MiB, and is read once at load. A missing file, invalid JSON, or an invalid shape fails with `CONFIG_INVALID`, naming the path and, for version 2, the field. Keep a `__proto__` term in a file: in a `verbatra.config.ts` literal JavaScript turns it into the prototype.

#### Per-locale glossary (version 2)

<AvailableFrom version="0.12.0" />

Version 2 gives each term a translation per locale, forbidden renderings, and terms to keep as written:

```json title="glossary.json"
{
  "version": 2,
  "terms": [
    {
      "source": "Dashboard",
      "targets": { "de": "Übersicht", "fr": "Tableau de bord" },
      "forbidden": { "de": ["Instrumententafel"] },
      "note": "The start page after sign-in",
      "partOfSpeech": "noun"
    },
    { "source": "Sign in", "target": "Anmelden", "caseSensitive": true }
  ],
  "doNotTranslate": ["verbatra", { "term": "Acme", "caseSensitive": false }]
}
```

| Field | Meaning |
| --- | --- |
| `version` | Always `2`; required, and any other number fails. |
| `terms[].source` | The source term; each term appears once. |
| `terms[].target` | The translation for every locale without its own `targets` entry. |
| `terms[].targets` | Translations per locale. A locale uses its own entry, then its base language's (`de` covers `de-AT`), then `target`, comparing canonical codes ignoring case. |
| `terms[].forbidden` | Renderings a locale must never use; a regional locale also obeys its base language's list. |
| `terms[].caseSensitive` | Match the term, translations and forbidden renderings with case. Default `false`. |
| `terms[].note`, `terms[].partOfSpeech` | Free-text context, sent to an LLM provider as data. |
| `doNotTranslate` | Terms copied untranslated. A bare string also keeps its case; `{ "term", "caseSensitive": false }` may change it. |

Each term needs a `target`, a `targets` entry or a `forbidden` list, and may not forbid its own translation, name a locale twice, or also appear in `doNotTranslate`. A request carries only its target locale's terms, and each locale's [cache](/docs/the-cache) fingerprint covers only those. A version 1 file keeps working with the same fingerprint; the SDK's [`updateGlossaryTerm`](/docs/sdk/config#updateglossaryterm) rewrites it as version 2 only for an edit version 1 cannot express.

<AvailableFrom version="0.4.0" pkg="@verbatra/studio" /> Only the file form can be edited from [Studio](/docs/review-in-studio), one term at a time; an inline glossary is read-only there. LLM providers are instructed to treat translations as binding, avoid forbidden renderings and keep do-not-translate terms; DeepL, Google Cloud Translation and LibreTranslate cannot apply them. Every provider's output is checked afterwards and flagged `GLOSSARY_TERM_MISSED` or `GLOSSARY_FORBIDDEN_TERM` ([review reasons](/docs/error-codes#review-reason-codes)).

### generatePlurals

When true, verbatra synthesizes the CLDR plural forms a target needs but the source lacks, such as Polish `few` and `many`; ordinal keys (`<key>_ordinal_<category>`) follow the CLDR ordinal rules. Only `i18next-json` with an LLM provider supports it. Everything else, and a locale without CLDR rules, gets the per-locale plural warning instead (assuming `one` and `other` for cardinals, `other` for ordinals). There is no CLI flag; the SDK's `translate()` takes a per-run override.

### fuzzyCache

`fuzzyCache: { enabled: true }` lets a key whose source changed reuse the translation of its earlier form when the two are at least `threshold` alike, always flagged `FUZZY_CACHE_REUSE`; the safety rules are under [Fuzzy reuse](/docs/the-cache#fuzzy-reuse). `--no-cache` bypasses it with the rest of the cache.

### humanEdits and pinnedKeys

`humanEdits` covers a stale key whose value a person wrote (`human`, `import` or `external` [provenance](/docs/the-lock-file#provenance-who-wrote-each-value)):

- `"protect"` keeps the value and does not send the key.
- `"suggest"` keeps the value and asks the provider for a suggestion that is never written.
- `"overwrite"` retranslates it; `translate --include-human` does this for one run.

A key matching `pinnedKeys` (for example `["legal.*", "brand.name"]`) is never machine-written, whatever `humanEdits` says. See [Keep human translations](/docs/protecting-human-translations).

### network

See [Restrict network access](/docs/network-policy).

```ts title="verbatra.config.ts"
network: { policy: "local-only", allowedHosts: ["gpu.lan"] }
```

### maxBatchSize

Missing and changed entries go out in sequential sub-batches of at most this size; a failed sub-batch is retried next run while the others proceed. No CLI flag overrides it.

### maxLength

A map from translation key to the longest value it may hold, for strings under a layout constraint:

```ts title="verbatra.config.ts"
maxLength: {
  "nav.dashboard": 18,
  "cta.submit": 12,
}
```

- **Only here.** No budget is derived from a description or a format's metadata. Keys match literally, never as globs; a key not in the map is never measured.
- **Grapheme clusters.** Length counts perceived characters: a multi-code-point emoji or a letter with a combining accent is one, and so is a CJK character although it renders about twice as wide. Whitespace counts, and the limit is inclusive.
- **When it is checked.** On every value `translate` produces for the key, cache reuses included. An up-to-date key is not measured, so a new budget flags nothing until its source changes; [`verbatra export --include-unchanged`](/docs/cli/export) measures every current value now.
- **Advisory.** An overrun is still written and locked, and reported as `MAX_LENGTH_EXCEEDED` in `needsReview`, Studio's Review queue, and the workbook's review columns.

### maxTokens and budgetBehavior

`maxTokens` is a whole-run budget: input plus output tokens, summed over every provider call (translation and plural generation) and every target locale. `translate --max-tokens <n>` sets a stricter, always-stopping ceiling for one run; the lower figure applies (from 0.12.0).

`budgetBehavior` decides what reaching it does:

- `"warn"`, the default, counts the spend and flags the overrun; the run continues as if no budget were set.
- `"stop"` <AvailableFrom version="0.11.0" /> makes it a ceiling (DeepL, Google Cloud Translation and LibreTranslate included). Before each request, the run projects its cost the same way [the pre-run estimate](/docs/estimating-cost) does and refuses one that would pass `maxTokens`. That request's keys are withheld, and so is every key not yet attempted: the rest of the current locale and every later locale, whose diff and orphan reporting still run. Withheld keys keep their prior lock hash and are retried next run.

Counting under `"stop"`:

- Every request is checked, including each half of a request re-split after a truncated response.
- After each request the total is reconciled to the usage the provider reported. A request that costs more than projected lands the difference afterwards, so a run can end above `maxTokens` by that one request's difference, and nothing more is sent.
- An admitted request can cost up to about twice its projection through the provider layer's own repair call for missing keys; that too lands at reconciliation.
- A failed or truncated request stays charged in full.
- The projection includes a fixed allowance for the LLM prompt (system rules and response schema), added for the machine-translation providers too. A request is projected as a whole batch, so a `maxTokens` below one batch's projection refuses it every run; the notice then says to lower `maxBatchSize` or raise `maxTokens`.
- Machine-translation providers report no token usage and are budgeted from the projection (`budget.supported: false`).

Scope and exit codes:

- The budget bounds one `translate` run. `watch` starts a fresh budget for every run it triggers, and a single-entry retranslation from [Studio](/docs/review-in-studio) or an agent tool is never capped.
- A live run with `maxTokens` and `--concurrency` above `1` is refused with exit `2` (`CONCURRENCY_BUDGET_CONFLICT`), because which locale loses work would depend on interleaving. A dry run is exempt.
- Under `"warn"` the exit code never changes. Under `"stop"`, a locale with withheld keys is `partial` if some keys landed and `failed` if none did; both exit `1`.
- `budgetBehavior` without `maxTokens` has no effect.

<Callout title="Two different maxTokens">
The top-level `maxTokens` is this whole-run budget. Anthropic's `provider.options.maxTokens` caps a single response; they are unrelated. See [Providers](/docs/providers#anthropic).
</Callout>

### rates

Read only by [`verbatra translate --estimate`](/docs/estimating-cost), which explains how rates turn into money; a live run ignores it.

```ts title="verbatra.config.ts"
rates: {
  asOf: "2026-01-15",
  currency: "USD",
  table: {
    "gemini/gemini-2.5-flash": { inputPerMillionTokens: 0.1, outputPerMillionTokens: 0.4 },
    deepl: { perMillionCharacters: 25 },
  },
}
```

A `table` key is `provider/model` for a provider with a model and the bare id for one without (`deepl`, `google-translate`). An entry is either token-billed (`inputPerMillionTokens` and `outputPerMillionTokens`) or character-billed (`perMillionCharacters`), never both; a negative rate is rejected. `openai-compatible` and `libretranslate` send no invoice, so their quantity is reported without a rate. An entry in the wrong unit is refused.

### extract

Read only by [`verbatra extract`](/docs/cli/extract), [`verbatra doctor --literals`](/docs/cli/doctor#untranslated-literals) and [`verbatra diff --unused`](/docs/cli/diff#unused-source-keys).

```ts title="verbatra.config.ts"
extract: {
  framework: "i18next",
  roots: ["src", "app"],
  exclude: ["generated"],
  literals: { ignore: ["Acme Inc."] },
  unused: { ignore: ["emails.*"] },
}
```

- **`framework`** is a closed set; `i18next` covers `t(...)`, `$t(...)` and `<object>.t(...)`. A framework without an extractor is rejected.
- **`roots`** resolve against the working directory; nothing outside them is read.
- **`exclude`** adds directory names (not paths), matched anywhere under a root, to the always-skipped `node_modules`, `.git`, `.next`, `.turbo`, `.verbatra`, `dist`, `build` and `coverage`.
- **`literals.ignore`** matches a literal's whole text with whitespace collapsed and character references decoded, so write `Tom & Jerry`, not `Tom &amp; Jerry`. A held-back literal is reported as suppressed.
- **`unused.ignore`** takes exact keys or `*` patterns for keys used only outside the scanned source (a server template, a CMS). It matches the decoded key the report shows (`Welcome. Enjoy`, not `Welcome\. Enjoy`), and a match is reported as ignored.

## Discovery order

verbatra searches upward from the working directory and uses the first source it finds, stopping at the nearest directory containing `.git` (or your home directory), so it never picks up a config above your repository:

1. `package.json` (a `"verbatra"` property)
2. `.verbatrarc`
3. `.verbatrarc.json`
4. `.verbatrarc.yaml`
5. `.verbatrarc.yml`
6. `.verbatrarc.js`
7. `.verbatrarc.cjs`
8. `.verbatrarc.ts`
9. `verbatra.config.js`
10. `verbatra.config.cjs`
11. `verbatra.config.ts`

`--config <path>` loads one file instead, relative to the working directory. In the SDK an in-memory `configOverride` beats `configPath`, which beats the search ([SDK recipes](/docs/programmatic-api)).

## Editor validation

<AvailableFrom version="0.9.0" />

`@verbatra/sdk` ships a JSON Schema generated from the zod schema the SDK validates with:

```text
node_modules/@verbatra/sdk/dist/config-schema.json
```

`.verbatrarc.json` and `.verbatrarc` accept a `$schema` key, which VS Code reads:

```json title=".verbatrarc.json"
{
  "$schema": "./node_modules/@verbatra/sdk/dist/config-schema.json",
  "sourceLocale": "en",
  "targetLocales": ["de", "fr"],
  "format": "i18next-json",
  "files": { "pattern": "locales/{locale}.json" },
  "provider": { "id": "gemini", "options": { "model": "gemini-2.5-flash", "maxOutputTokens": 4096 } }
}
```

The extensionless `.verbatrarc` also needs a file match, which a workspace mapping gives:

```json title=".vscode/settings.json"
{
  "json.schemas": [
    {
      "fileMatch": [".verbatrarc", ".verbatrarc.json"],
      "url": "./node_modules/@verbatra/sdk/dist/config-schema.json"
    }
  ]
}
```

A YAML config takes a comment for the YAML Language Server:

```yaml title=".verbatrarc.yaml"
# yaml-language-server: $schema=./node_modules/@verbatra/sdk/dist/config-schema.json
sourceLocale: en
targetLocales: [de, fr]
```

The `package.json` property cannot get a schema; the executable forms are typed by `defineConfig` instead.

### What the document cannot check

These rules have no JSON Schema expression, so only loading the config checks them:

- `targetLocales` must not include `sourceLocale`, or two locales differing only in case.
- A locale code must pass `Intl.getCanonicalLocales` (the grammar misses a repeated variant such as `de-1996-1996`).
- Every `provider.options.localeMap` key must be `sourceLocale` or a target locale.
- `apiKeyEnvVar` (openai-compatible) must not name a hosted provider's key variable.
- A `network.allowedHosts` entry must be a valid address or range (not an octet above 255, an oversized CIDR prefix, or malformed IPv6).
- A `sensitiveData.patterns` entry must be a valid regular expression.
- An inline version 2 glossary must satisfy the term rules under [glossary](#per-locale-glossary-version-2).

## The working directory and .env

The working directory (where you run verbatra, or `--cwd`) anchors the config search and locale paths; which commands load `.env.local` and `.env` from it is under [Environment files](/docs/cli#environment-files).

## When loading fails

- [`CONFIG_NOT_FOUND`](/docs/error-codes#config_not_found): no config in any searched place, or the `--config` path does not exist.
- [`CONFIG_INVALID`](/docs/error-codes#config_invalid): a config was found but is unusable: it fails to parse, fails validation, or names an unreadable glossary file. The message lists every issue with its key path, and an unknown top-level key adds the hint that API keys come from the environment. A parse failure names the file (with line and column for YAML) but never quotes its content, and every message passes through key redaction.

The CLI exits `2` for both.
