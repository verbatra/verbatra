Wähle einen Provider über die `id` im `provider`-Block deiner [Konfiguration](/docs/config-file). Anthropic, OpenAI, Gemini und openai-compatible sind Sprachmodelle; DeepL, Google Cloud Translation und LibreTranslate sind Maschinenübersetzungsdienste; `none` schaltet maschinelle Übersetzung ab. Modell-Ids auf dieser Seite sind Beispiele, keine Empfehlungen. Die Sprachabdeckung steht unter [Sprachen und Locales](/docs/language-support), und was jeder Provider bekommt, unter [Datenverarbeitung und Datenschutz](/docs/data-handling).

## Welchen soll ich nehmen?

Jeder Provider funktioniert mit jedem Format und jedem Befehl, und ein späterer Wechsel heißt, eine `id` zu ändern.

| Wenn du willst | Nimm |
| --- | --- |
| Kostenlos, für ein kleines Projekt mit nicht vertraulichen Strings | **Gemini**: ein kostenloses API-Kontingent, Keys aus dem [Google AI Studio](https://aistudio.google.com/apikey). Außerhalb von EWR, Schweiz und Vereinigtem Königreich darf Google Anfragen im kostenlosen Kontingent nutzen und von Menschen prüfen lassen ([Bedingungen](/docs/data-handling#aufbewahrung-und-auftragsverarbeitung-beim-anbieter)). |
| Die beste Qualität für eine Produktions-App | **Anthropic** oder **OpenAI**, beide bezahlt. |
| Hohes Volumen, ein natives Glossar, kein LLM | **DeepL**, kostenloses oder bezahltes Kontingent. |
| Die breiteste Abdeckung mit einem API-Schlüssel auf Google Cloud | **Google Cloud Translation** (Basic, v2). |
| Offline, kostenfrei, nichts verlässt dein Netzwerk | **openai-compatible** mit LM Studio, Ollama oder vLLM. |
| Kein Sprachmodell, aber selbst gehostet | **LibreTranslate** auf deinem eigenen Server. |
| Gar keine maschinelle Übersetzung | **none**: nur Translation Memory und Menschen. |

## Keys kommen aus der Umgebung

verbatra liest nie einen Key aus der Konfiguration. Jeder gehostete Provider liest eine Variable:

| Provider-Id | Umgebungsvariable |
| --- | --- |
| `anthropic` | `ANTHROPIC_API_KEY` |
| `openai` | `OPENAI_API_KEY` |
| `gemini` | `GEMINI_API_KEY` |
| `deepl` | `DEEPL_API_KEY` |
| `google-translate` | `GOOGLE_TRANSLATE_API_KEY` |

Setze sie in `.env` (das `verbatra init` in `.gitignore` einträgt), in deiner Shell oder in deinem CI-Secret-Store, und committe sie nie. Eine ungesetzte oder leere Variable scheitert mit [`MISSING_API_KEY`](/docs/error-codes#missing_api_key), das die Variable nennt, aber nie einen Wert. `openai-compatible` und `libretranslate` brauchen meist keinen Key; siehe ihre Abschnitte.

## Anthropic

```ts title="verbatra.config.ts"
provider: {
  id: "anthropic",
  options: {
    model: "claude-sonnet-4-6", // example model id
    maxTokens: 4096,
  },
}
```

| Option | Typ | Default | Wirkung |
| --- | --- | --- | --- |
| `model` | String | erforderlich | Die Modell-Id. |
| `maxTokens` | positive Ganzzahl | erforderlich | Begrenzt die Ausgabe-Tokens einer Antwort ([Limits](#ausgabe-token-limits)); hat nichts mit dem Top-Level-Budget zu tun. |
| `requestTimeoutMs` | positive Ganzzahl | `120000` | Begrenzt jeden Anfrageversuch ([Anfrage-Timeout](#anfrage-timeout)). |
| `localeMap` | Zuordnung von Locale zu Code | keine | Überschreibt den gesendeten Code pro Locale ([Locale-Codes](#an-den-provider-gesendete-locale-codes)). |

Liest `ANTHROPIC_API_KEY`.

## DeepL

```ts title="verbatra.config.ts"
provider: {
  id: "deepl",
  options: {
    glossaryId: "<your-glossary-id>",
  },
}
```

| Option | Typ | Default | Wirkung |
| --- | --- | --- | --- |
| `glossaryId` | String | keine | Ein Glossar, das du in DeepL angelegt hast, nativ angewendet. |
| `requestTimeoutMs` | positive Ganzzahl | `120000` | Die Mindestwartezeit pro Versuch, bis zu fünf Versuche. |
| `localeMap` | Zuordnung von Locale zu Code | keine | Überschreibt den gesendeten Code pro Locale. |

Liest `DEEPL_API_KEY`; `options` darf `{}` sein. DeepL hat kein Modell und kein Ausgabe-Token-Limit und stuft mit einem Hinweis herab, statt fehlzuschlagen:

- **Platzhalter** reisen als nummerierte Markierungen in einem ignorierten Tag (`Hello {{name}}` als `Hello <x>{0}</x>`) und werden wieder eingesetzt. `PLACEHOLDER_UNSUPPORTED` hält einen Wert zurück, dessen Platzhalter nicht wörtlich darin steht oder dessen übriger Text `<`, `>`, `{` oder `}` enthält (ICU-Argumente, Markup, Vergleichszeichen), und ein Ergebnis mit verlorener, wiederholter, geänderter oder bloßer Markierung, unbekannter Entity oder fremdem Tag. Reines Markup geht als Klartext hinaus. <AvailableFrom version="0.12.0" />
- **Tonfall** wird auf Formalität abgebildet (`formal` formeller, `informal` informeller, `neutral` weggelassen). Angefragt wird mit `prefer_more` oder `prefer_less`, sodass ein Key aus dem kostenlosen Kontingent oder eine Sprache ohne Formalität wie Schwedisch zurückfällt statt zu scheitern. Das [Glossar](#tonfall-und-glossar-über-die-provider-hinweg) wird nicht angewendet.

<AvailableFrom version="0.12.0" />

verbatra liefert DeepLs datierte [Sprachtabelle](https://developers.deepl.com/docs/getting-started/supported-languages) mit und lehnt eine nicht aufgeführte Sprache mit `LOCALE_UNSUPPORTED_BY_PROVIDER` ab, bevor etwas ausgegeben wird. Eine `glossaryId` funktioniert nur, wenn beide Sprachen auf DeepLs Glossarliste stehen (etwa `DE`, `EN`, `FR`, `JA`, `ZH`).

## Google Cloud Translation

<AvailableFrom version="0.10.0" />

```ts title="verbatra.config.ts"
provider: {
  id: "google-translate",
  options: {},
}
```

| Option | Typ | Default | Wirkung |
| --- | --- | --- | --- |
| `requestTimeoutMs` | positive Ganzzahl | `120000` | Begrenzt den ganzen Aufruf (keine Wiederholungen). |
| `localeMap` | Zuordnung von Locale zu Code | keine | Überschreibt den gesendeten Code pro Locale. |

Liest `GOOGLE_TRANSLATE_API_KEY`, einen einfachen API-Schlüssel für ein Google-Cloud-Projekt, in dem die Cloud Translation API aktiviert ist. Verwendet wird die Basic-Stufe (v2); Advanced (v3) braucht einen Service-Account, der nicht zu einem Key aus einer Umgebungsvariable passt.

- **Platzhalter** werden wie bei DeepL maskiert, in `<span translate="no">`; Zeilenumbrüche, Tabs und doppelte Leerzeichen werden ebenfalls zurückgehalten. <AvailableFrom version="0.12.0" />
- **Codes.** Jeder gesendete Code wird vor jedem Aufruf als wohlgeformtes BCP 47 geprüft (`en_US` scheitert mit `INVALID_REQUEST`). Regionale Codes sind erlaubt; ein Paar, das Google ablehnt, scheitert mit `INVALID_REQUEST` von der API.

<AvailableFrom version="0.12.0" />

verbatra liefert Googles datierte [Sprachtabelle](https://docs.cloud.google.com/translate/docs/languages) mit und lehnt eine nicht aufgeführte Sprache ab, bevor etwas ausgegeben wird. Ein regionaler Code, dessen Sprache nur als Ganzes aufgeführt ist, etwa `de-AT`, wird mit einer Warnung so gesendet, wie er geschrieben ist.

## openai-compatible

Jeder Server, der die OpenAI-Chat-Completions-API spricht: LM Studio, Ollama, vLLM oder eine gehostete API mit demselben Protokoll.

```ts title="verbatra.config.ts"
provider: {
  id: "openai-compatible",
  options: {
    baseUrl: "http://192.168.178.74:1234/v1",
    model: "qwen2.5-14b-instruct", // example: whatever your server exposes
    maxOutputTokens: 1024,
  },
}
```

| Option | Typ | Default | Wirkung |
| --- | --- | --- | --- |
| `baseUrl` | `http`- oder `https`-URL | erforderlich | Der Server, einschließlich seines API-Pfads, meist `/v1`. Eine URL ohne ihn besteht die Validierung und scheitert zur Anfragezeit. |
| `model` | String | erforderlich | Das Modell, das dein Server anbietet. |
| `maxOutputTokens` | positive Ganzzahl | erforderlich | Begrenzt die Ausgabe-Tokens einer Antwort. |
| `apiKeyEnvVar` | Variablenname | keine | Die Variable mit einem Key für diesen Server; nie die Variable eines gehosteten Providers. |
| `requestTimeoutMs` | positive Ganzzahl | `120000` | Begrenzt jeden Anfrageversuch. |
| `localeMap` | Zuordnung von Locale zu Code | keine | Überschreibt den gesendeten Code pro Locale. |

Eine gehostete API funktioniert genauso, zum Beispiel Mistral:

```ts title="verbatra.config.ts"
provider: {
  id: "openai-compatible",
  options: {
    baseUrl: "https://api.mistral.ai/v1",
    model: "mistral-large-latest", // example: check Mistral's current model list
    maxOutputTokens: 4096,
    apiKeyEnvVar: "MISTRAL_API_KEY",
  },
}
```

Das Antwortformat ist dasselbe strikte Schema wie bei `openai`, aber vor der Validierung wird das erste balancierte JSON-Objekt aus umgebender Prosa oder einem Code-Fence extrahiert. Die Ausgabe durchläuft trotzdem jede Schema- und Integritätsprüfung. `verbatra init --provider openai-compatible --base-url <url> --model <name>` schreibt diesen Block ([init](/docs/cli/init#provider)), und `--api-key-env-var <NAME>` ergänzt den Namen der Variable.

### Keys sind optional

Der Key wird der Reihe nach aufgelöst:

1. **`apiKeyEnvVar`**: Wenn gesetzt, muss seine Variable einen Key enthalten, sonst scheitert der Lauf mit `MISSING_API_KEY`.
2. **`OPENAI_COMPATIBLE_API_KEY`**: wird verwendet, wenn sie gesetzt und nicht leer ist; sonst macht verbatra weiter.
3. **`"local"`**: ein fester, nicht geheimer Platzhalter, der einen Server ohne Key funktionieren lässt.

`apiKeyEnvVar` kann nicht die Variable eines gehosteten Providers nennen, und der Client liest nie `OPENAI_API_KEY`, ein gehosteter Key erreicht also nie eine eigene `baseUrl`.

<Callout type="warn" title="Ein echter Key über Klartext-http reist unverschlüsselt">
Klartext-`http://` ist zu jedem Host erlaubt, was sicher ist, solange kein Key konfiguriert ist. Mit einem Key und einer `http://`-URL zu einem Nicht-Loopback-Host geht der Key unverschlüsselt durch dein Netzwerk, und verbatra warnt nicht davor. Verwende `https://` für einen Server, der einen Key braucht.
</Callout>

### Ein lokales Modell wählen

Bevorzuge ein instruktionsoptimiertes Modell ohne Reasoning und mit guter mehrsprachiger Abdeckung, so groß, wie deine Hardware es gut ausführt; `qwen2.5-14b-instruct` ist ein sinnvoller Standard. Reasoning-Modelle und stark quantisierte Builds neigen dazu, die Antwort in Prosa zu verpacken oder abzuschneiden, was als `INVALID_RESPONSE` oder `OUTPUT_TRUNCATED` scheitert, statt eine korrupte Übersetzung zu schreiben. Brauchst du ein Reasoning-Modell, gib ihm Platz ([Ausgabe-Token-Limits](#ausgabe-token-limits)).

## LibreTranslate

<AvailableFrom version="0.12.0" />

Ein selbst gehosteter [LibreTranslate](https://github.com/LibreTranslate/LibreTranslate)-Server: neuronale Maschinenübersetzung (Argos Translate), kein Sprachmodell. verbatra ruft nur seine HTTP-API auf, die AGPL-3.0-Lizenz des Servers erstreckt sich also nicht auf dein Projekt.

```ts title="verbatra.config.ts"
provider: {
  id: "libretranslate",
  options: {
    baseUrl: "http://localhost:5000",
  },
}
```

| Option | Typ | Default | Wirkung |
| --- | --- | --- | --- |
| `baseUrl` | `http`- oder `https`-URL | erforderlich | Die API-Wurzel, ohne `/translate`. |
| `requestTimeoutMs` | positive Ganzzahl | `120000` | Begrenzt den ganzen Aufruf (keine Wiederholungen). |
| `localeMap` | Zuordnung von Locale zu Code | keine | Überschreibt den gesendeten Code pro Locale. |

Seine Sprachen sind die auf deinem Server installierten Modelle:

```bash
docker run -p 5000:5000 libretranslate/libretranslate --load-only en,de,fr
```

- **Key.** `LIBRETRANSLATE_API_KEY` wird nur als `api_key` gesendet, wenn sie gesetzt ist. Ein mit `--api-keys` gestarteter Server lässt den Lauf mit `MISSING_API_KEY` scheitern, wenn sie nicht gesetzt ist, und mit `AUTH_FAILED`, wenn er sie ablehnt.
- **Platzhalter** werden wie bei DeepL maskiert, als bloße `{0}`-Markierungen; Markup bleibt erhalten, daher zählen nur geschweifte Klammern neben einem Platzhalter.
- **Markup.** Ein Wert mit HTML-artigen Tags wird im `html`-Format gesendet, sodass der Text innerhalb der Tags übersetzt wird und die Tags bleiben; eine Formulierung über ein Tag hinweg kann leiden, und veränderte Tags werden abgelehnt.
- **Sprachprüfung.** Jedes Ziel ist bei jedem Lauf `unverified` mit einer `LOCALE_UNVERIFIED_BY_PROVIDER`-Warnung; `verbatra doctor --locales --live` prüft sie gegen das `/languages` des Servers.

`verbatra init --provider libretranslate --base-url <url>` schreibt diesen Block.

## none

<AvailableFrom version="0.12.0" />

Schaltet maschinelle Übersetzung per Richtlinie ab, für eine NDA oder Firmenregel, die verbietet, Strings an irgendeinen Dienst zu senden.

```ts title="verbatra.config.ts"
provider: { id: "none" }
```

`options` darf fehlen oder `{}` sein. Es wird kein Provider erzeugt, kein Key gelesen und keine Anfrage gestellt; was jeder Befehl stattdessen tut, steht unter [Ohne maschinelle Übersetzung arbeiten](/docs/human-only-workflow).

## Tonfall und Glossar über die Provider hinweg

Jede Anfrage enthält nur die Glossarbegriffe ihrer Ziel-Locale, und die Ausgabe jedes Providers wird danach gegen sie geprüft.

| Provider | `tone` | `glossary` |
| --- | --- | --- |
| Anthropic, OpenAI, Gemini, openai-compatible | gesendet und eingehalten | Übersetzungen, verbotene Wiedergaben, `doNotTranslate`-Begriffe und Notizen als bindende Daten gesendet |
| DeepL | auf Formalität abgebildet; `FORMALITY_DOWNGRADED` bei einem kostenlosen Key oder einer Sprache ohne Formalität | `GLOSSARY_IGNORED`; nur `glossaryId` wird angewendet |
| Google Cloud Translation, LibreTranslate | `FORMALITY_DOWNGRADED` bei `formal` oder `informal` | `GLOSSARY_IGNORED` |

## Verhalten, das jeder Provider teilt

### Batching

Die Arbeit einer Locale geht in sequenziellen Sub-Batches von höchstens [`maxBatchSize`](/docs/config-file#maxbatchsize) Einträgen hinaus (Default `50`). Ein fehlgeschlagener Sub-Batch wird zurückgehalten und beim nächsten Lauf erneut versucht, während der Rest weiter vorankommt. DeepL und Google Cloud Translation teilen einen Sub-Batch zusätzlich auf, damit er in ihre eigenen Anfragegrenzen passt.

### Wiederholungen

Rate-Limits und Serverfehler werden mit Backoff wiederholt: Die Clients von OpenAI, Anthropic und DeepL machen das selbst, und verbatra ergänzt dasselbe für Gemini. Google Cloud Translation und LibreTranslate wiederholen nicht: Ein Rate-Limit oder Serverfehler taucht sofort als `RATE_LIMITED` oder `PROVIDER_UNAVAILABLE` auf.

### Anfrage-Timeout

`requestTimeoutMs` begrenzt jede Anfrage, damit ein Server, der die Verbindung annimmt, aber nie antwortet, keinen Lauf blockieren und die Schreibsperre einer Locale offen halten kann. Der Default ist `120000` ms (zwei Minuten); erhöhe ihn für ein langsames lokales Modell oder eine große `maxBatchSize`.

```ts title="verbatra.config.ts"
provider: {
  id: "openai-compatible",
  options: {
    baseUrl: "http://192.168.178.74:1234/v1",
    model: "qwen2.5-14b-instruct",
    maxOutputTokens: 1024,
    requestTimeoutMs: 300000, // 5 minutes
  },
}
```

- **Pro Versuch.** Clients wiederholen `429` und `5xx` ein paarmal, jeder Versuch mit dem vollen Timeout. Anthropic, OpenAI, openai-compatible und Gemini wiederholen auch einen Versuch, der in den Timeout gelaufen ist, und alle außer Gemini einen Verbindungsfehler, ein hängender Server braucht also bis zu drei Timeouts plus Backoff, bis aufgegeben wird.
- **Der Fehler nennt die Ursache.** `TIMEOUT` heißt, dass ein Versuch rechtzeitig keine Antwort bekommen hat; wiederholt abgelehnte Verbindungen scheitern als `PROVIDER_ERROR`.
- **DeepL** wartet pro Versuch mindestens den Timeout, bis zu fünf Versuche, und kann eine laufende Anfrage nicht abbrechen, ein unterbrochener Lauf lässt sie also bei DeepL zu Ende laufen.
- **Google Cloud Translation und LibreTranslate** senden eine Anfrage ohne Wiederholungen, der Timeout deckt also den ganzen Aufruf ab.

### An den Provider gesendete Locale-Codes

<AvailableFrom version="0.12.0" />

Dateien, Lock-Datei und Translation Memory verwenden immer die Codes deiner Konfiguration. Nur die Anfrage wird in das übersetzt, was der Provider erwartet:

| Provider | Quell-Locale | Ziel-Locale |
| --- | --- | --- |
| DeepL | Nur die Sprache: `en-US` als `EN`, `zh-Hant-TW` als `ZH`. | `zh-Hant`, `zh-TW`, `zh-HK`, `zh-MO` als `ZH-HANT`; `zh-Hans`, `zh-CN`, `zh-SG` als `ZH-HANS`. DeepL-Varianten bleiben (`EN-GB`, `EN-US`, `PT-BR`, `PT-PT`, `ES-419`, `FR-CA`, `FR-FR`, `DE-CH`, `DE-DE`). Spanisch mit einer lateinamerikanischen oder karibischen Region (`MX`, `AR`, `CO`, `CL`, `PE`, `VE`, `EC`, `GT`, `CU`, `BO`, `DO`, `HN`, `PY`, `SV`, `NI`, `CR`, `PA`, `UY`, `PR`, `US`, `419`) als `ES-419`. Andere Regionen und Schriften fallen weg: `de-AT` als `DE`. |
| Google Cloud Translation | `zh-Hant` (`zh-HK`, `zh-MO`) als `zh-TW`, `zh-Hans` (`zh-SG`) als `zh-CN`, `nb` als `no`; alles andere so, wie es geschrieben ist. | Wie bei der Quelle. |
| LibreTranslate | Nur die Sprache (`de-AT` als `de`), außer dass `pt-BR` bleibt und Chinesisch als `zh-Hans` oder `zh-Hant` geht (`zh-TW` als `zh-Hant`). | Wie bei der Quelle. |
| Anthropic, OpenAI, Gemini, openai-compatible | So, wie er geschrieben ist, mit dem englischen Namen der Sprache. | So, wie er geschrieben ist, mit den englischen Namen von Sprache, Schrift und Region. |

Ein LLM erhält zum Beispiel `sr-Latn` mit `{ "name": "Serbian (Latin)", "script": "Latin" }`, und eine feste Regel bittet es, in dieser Schrift und Variante zu schreiben; ein Code, den Node.js nicht benennen kann, wird ohne Namen gesendet. DeepL hat kein allgemeines Englisch oder Portugiesisch als Ziel, ein Ziel, das am Ende ein bloßes `en` oder `pt` ist (etwa `en-AU`), wird deshalb vor dem Lauf abgelehnt: Bilde es auf `EN-GB`, `EN-US`, `PT-BR` oder `PT-PT` ab.

`localeMap` überschreibt den Code pro Locale, und ein Eintrag gewinnt immer:

```ts title="verbatra.config.ts"
provider: {
  id: "deepl",
  options: {
    localeMap: {
      "en-AU": "EN-GB",
      "fr-BE": "FR-FR",
    },
  },
}
```

- **Keys** müssen `sourceLocale` oder eine Ziel-Locale sein, so geschrieben wie konfiguriert; alles andere scheitert mit `CONFIG_INVALID`. Es gehört unter `options` (direkt unter `provider` scheitert es), bei jedem Provider außer `none`.
- **Werte** sind nicht leere Strings mit höchstens 64 Zeichen und werden unverändert gesendet: an einen Maschinenübersetzungs-Provider als Sprachcode, an ein LLM anstelle des Codes (`"pt-BR (Brazilian Portuguese)"` funktioniert). Die Sprachnamen für ein LLM kommen trotzdem aus dem Key. Ein Wert, der DeepL weiterhin ein bloßes `EN` oder `PT` schickt, scheitert mit `INVALID_REQUEST`; ein Wert, den der Provider ablehnt, lässt seinen Sub-Batch scheitern.
- **Wirkung auf das Translation Memory.** Nur neue und geänderte Strings gehen mit einem neuen Code hinaus. Ein nicht leeres `localeMap` ist Teil des Fingerprints im [Translation Memory](/docs/the-cache), eine Änderung beginnt also einen eigenen Bereich.

### Die Sprachunterstützung eines Providers prüfen

<AvailableFrom version="0.12.0" />

Jede konfigurierte Locale wird beurteilt, bevor etwas ausgegeben wird:

| Provider | Beurteilt gegen | Vor dem Lauf abgelehnt | Gewarnt bei |
| --- | --- | --- | --- |
| DeepL | Seine mitgelieferte Sprachtabelle, mit Glossar- und Formalitätsunterstützung je Sprache | Eine nicht aufgeführte Quell- oder Zielsprache | Einem Glossar für ein Paar außerhalb der Glossarsprachen, einem Tonfall ohne Formalität, einem nur teilweise aufgeführten Code |
| Google Cloud Translation | Seine mitgelieferte Sprachtabelle | Eine nicht aufgeführte Sprache | Jedem Glossar, einem Tonfall `formal` oder `informal`, einem regionalen Code, der nur als Sprache aufgeführt ist |
| LibreTranslate | Nichts vor einem Lauf; mit `doctor --live` das `/languages` des Servers | Nie | Jeder Ziel-Locale bei jedem Lauf, jedem Glossar, einem Tonfall `formal` oder `informal` |
| Anthropic, OpenAI, Gemini, openai-compatible | Nichts: Ein LLM akzeptiert jede Sprache | Nie | Einer Sprache außerhalb der [gut getesteten Liste](/docs/language-support#unterstützung-vor-einem-lauf-prüfen) |
| none | Entfällt | Nie | Nie |

[`verbatra doctor`](/docs/cli/doctor#locale-unterstützung) meldet jedes Urteil, und `--locales` ergänzt den gesendeten Code sowie Glossar- und Formalitätsunterstützung. Eine nicht unterstützte Locale wird mit [`LOCALE_UNSUPPORTED_BY_PROVIDER`](/docs/error-codes#locale_unsupported_by_provider) (Exit `2`) abgelehnt, bevor ein Provider erzeugt wird; eine Warnung lehnt nie ab und erscheint als [Hinweis](/docs/error-codes#sdk-notice-codes).

`verbatra doctor --live` ruft zuerst die aktuelle Liste ab (DeepL `/v3/languages`, Cloud Translation `languages`, LibreTranslate `/languages`, ohne Kontingent zu verbrauchen), wenn der Key gesetzt ist (LibreTranslate braucht keinen) und die [Netzwerkrichtlinie](/docs/network-policy) es erlaubt. Die Live-Liste fließt nur in den Bericht ein; `translate` verwendet immer die mitgelieferte Tabelle. Für eine seitdem ergänzte Sprache bilde die Locale in `localeMap` ab: Ein expliziter Code wird mit einer Warnung gesendet, nicht abgelehnt.

### Strukturierte Fehler

Ein Provider-Fehlschlag erscheint als [strukturierter, geheimnisfreier Fehler](/docs/translation-safety#fehler-geben-nichts-preis), der nur seinen eigenen Sub-Batch betrifft. Bei openai-compatible und LibreTranslate nennt ein `PROVIDER_ERROR` Host und Port der `baseUrl` (nie ihren Pfad, Query-String oder Benutzerangaben); Google Cloud Translation nennt `translation.googleapis.com`, nie den Query-String mit seinem Key.

### Ausgabe-Token-Limits

Die LLM-Provider begrenzen die Tokens jeder Antwort. Ein Modell, das an der Grenze stoppt, erzeugt `OUTPUT_TRUNCATED`:

> The provider stopped because the output-token limit was reached. Reduce the batch size or raise the configured max output tokens.

verbatra teilt einen abgeschnittenen Sub-Batch zuerst in Hälften, bis hinunter zu einem Eintrag, und hält nur einen Eintrag zurück, der weiterhin überläuft. Um das dauerhaft zu beheben, senke `maxBatchSize` oder erhöhe `maxTokens` (Anthropic) beziehungsweise `maxOutputTokens`. Ein Reasoning-Modell verbraucht verborgene Reasoning-Tokens aus demselben Budget und kann es erschöpfen, bevor es irgendetwas schreibt, gib ihm also reichlich Spielraum. Die Maschinenübersetzungs-Provider haben keinen Abschneidefall.

### Review-Flags

Eine verdächtige Übersetzung wird bei jedem Provider zum Review markiert, nicht abgelehnt. Siehe [Review-Gründe](/docs/error-codes#review-reason-codes) und [In Studio prüfen](/docs/review-in-studio).
