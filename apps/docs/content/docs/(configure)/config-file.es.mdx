verbatra lee un único objeto de configuración pequeño y sin secretos, y lo valida antes de hacer ningún trabajo. Ninguna clave de API se lee jamás de él: cada proveedor lee su clave de una variable de entorno (consulta [Proveedores](/docs/providers#las-claves-vienen-del-entorno)), así que la configuración se puede confirmar sin riesgo.

## Una configuración mínima

```ts title="verbatra.config.ts"
import { defineConfig } from "@verbatra/sdk";

export default defineConfig({
  sourceLocale: "en",
  targetLocales: ["de", "fr"],
  format: "i18next-json",
  files: {
    pattern: "locales/{locale}.json",
  },
  provider: {
    id: "gemini",
    options: {
      model: "gemini-2.5-flash", // example model id; use your provider's current one
      maxOutputTokens: 4096,
    },
  },
});
```

`defineConfig` devuelve su argumento sin cambios y solo le da tipos: `options.model` autocompleta con los IDs de modelo del proveedor seleccionado, mientras que en tiempo de ejecución se acepta cualquier cadena no vacía.

## Cada clave

Las claves desconocidas se rechazan en todos los niveles, con `$schema` como única excepción, y por eso mismo una clave de API no puede vivir en la configuración.

| Clave | Tipo | Por defecto | Desde | Efecto |
| --- | --- | --- | --- | --- |
| `$schema` | string | ninguno | 0.9.0 | Apunta un editor al [JSON Schema](#validación-en-el-editor); se ignora en tiempo de ejecución. |
| `sourceLocale` | código de locale | obligatoria | 0.1.0 | El locale en el que están escritas tus cadenas de origen. |
| `targetLocales` | array de códigos de locale | obligatoria | 0.1.0 | Al menos uno; nunca `sourceLocale`, nunca dos iguales sin distinguir mayúsculas. |
| `format` | id de formato | obligatoria | 0.1.0 | El [formato](/docs/formats) de tus archivos de locale, o un id `custom:` para un [adaptador externo](/docs/custom-format-adapters). |
| `files.pattern` | string | obligatoria | 0.1.0 | La ruta de cada archivo de locale, con un token `{locale}`. |
| `files.localeStyle` | `"literal"`, `"posix"`, `"android"` | `"literal"` | 0.7.0 | Cómo se escribe `{locale}` en la ruta. |
| `provider.id` | id de proveedor | obligatoria | 0.1.0 | El proveedor de traducción, o `none` para no usar traducción automática. |
| `provider.options` | objeto | obligatoria, salvo con `none` | 0.1.0 | Las opciones propias del proveedor, listadas por proveedor en [Proveedores](/docs/providers). |
| `glossary` | objeto o ruta de archivo | ninguno | 0.1.0 | Traducciones fijas, traducciones prohibidas y términos que no se traducen. |
| `tone` | `"formal"`, `"informal"`, `"neutral"` | ninguno | 0.1.0 | El registro en el que traducir, aplicado [por proveedor](/docs/providers#tono-y-glosario-entre-proveedores). |
| `prune` | boolean | `false` | 0.3.0 | Elimina las claves huérfanas de los archivos de destino y del bloqueo; `translate --prune` tiene prioridad. |
| `generatePlurals` | boolean | `false` | 0.3.0 | Sintetiza las formas plurales CLDR que necesita un idioma de destino. |
| `fuzzyCache.enabled` | boolean | obligatoria en el bloque | 0.11.0 | Reutiliza la traducción de una cadena de origen que cambió solo un poco. |
| `fuzzyCache.threshold` | número, de `0.5` a `1` | `0.9` | 0.11.0 | Cuánto deben parecerse el origen antiguo y el nuevo para reutilizar. |
| `humanEdits` | `"protect"`, `"suggest"`, `"overwrite"` | `"protect"` | 0.12.0 | Qué hace una ejecución con una clave obsoleta que escribió una persona. |
| `pinnedKeys` | array de strings | ninguno | 0.12.0 | Patrones de claves (`*` coincide con cualquier secuencia de caracteres) que ninguna escritura automática toca nunca. |
| `network.policy` | `"any"`, `"local-only"`, `"allowlist"` | `"any"` | 0.12.0 | A qué hosts puede conectarse un proveedor. Consulta [Restringe el acceso a la red](/docs/network-policy). |
| `network.allowedHosts` | array de strings | ninguno; obligatoria con `"allowlist"` | 0.12.0 | Hosts permitidos adicionales: nombres, comodines `*.suffix`, IPs o rangos CIDR. |
| `maxBatchSize` | entero positivo | `50` | 0.3.0 | El máximo de entradas enviadas en una sola petición al proveedor. |
| `maxLength` | mapa de clave a entero positivo | ninguno | 0.11.0 | Presupuestos de longitud por clave, en clústeres de grafemas. |
| `maxTokens` | entero positivo | ninguno | 0.5.0 | Un presupuesto de tokens para toda la ejecución. |
| `budgetBehavior` | `"warn"`, `"stop"` | `"warn"` | 0.5.0 | Si alcanzar `maxTokens` solo avisa o detiene el envío. |
| `rates.asOf` | fecha `YYYY-MM-DD` | obligatoria en el bloque | 0.11.0 | La fecha en que leíste las tarifas. |
| `rates.currency` | tres letras mayúsculas | obligatoria en el bloque | 0.11.0 | La moneda de todas las tarifas, como `USD` o `EUR`. |
| `rates.table` | mapa de clave de tarifa a tarifa | obligatoria en el bloque | 0.11.0 | Tarifas indexadas por `provider/model` o por id de proveedor. |
| `extract.framework` | `"i18next"` | obligatoria en el bloque | 0.11.0 | Qué llamadas busca el análisis del código fuente. |
| `extract.roots` | array de strings | obligatoria en el bloque | 0.11.0 | Los directorios que se analizan, al menos uno. |
| `extract.exclude` | array de strings | ninguno | 0.11.0 | Nombres de directorio que se omiten además del conjunto integrado. |
| `extract.literals.ignore` | array de strings | ninguno | 0.11.0 | Textos exactos que `doctor --literals` retiene. |
| `extract.unused.ignore` | array de strings | ninguno | 0.11.0 | Claves o patrones `*` que `diff --unused` nunca señala como sin uso. |

### Locales y archivos

- **`files.pattern`** debe contener `{locale}`, el único token que entiende: `locales/{locale}.json` se resuelve a `locales/de.json`, contra el directorio de trabajo. Es una ruta literal, nunca un glob, así que una configuración direcciona un archivo por locale; para varios archivos de namespace consulta [Diseños con namespaces](/docs/formats#diseños-con-namespaces). `apple-xcstrings` sigue necesitando el token, pero todos los locales se resuelven al mismo catálogo ([Xcode String Catalogs](/docs/formats#xcode-string-catalogs-xcstrings)).
- **`files.localeStyle`** decide en qué se expande el token:
  - `literal` escribe la etiqueta tal como está configurada, que es lo que necesitan los diseños JSON, YAML, XLIFF, ARB, properties y `.lproj` de Apple.
  - `posix` reemplaza `-` por `_`, para gettext y el diseño Java `messages_{locale}.properties`: `pt-BR` pasa a `pt_BR`, `zh-Hant-TW` a `zh_Hant_TW`, `es-419` a `es_419`. Una variante como `de-1996` no tiene escritura posix. `gettext-po` escribe los scripts a la manera de gettext (siguiente sección).
  - `android` se expande a un directorio de recursos completo, escrito como `res/{locale}/strings.xml`: `values` para el origen, y luego `values-de`, `values-pt-rBR`, `values-b+zh+Hans`.

  Un estilo rechaza un locale que no puede escribir en lugar de escribir un directorio que la plataforma ignoraría.

### Nombres de locale de gettext

<AvailableFrom version="0.12.0" />

Con `format: "gettext-po"` y `localeStyle: "posix"`, un archivo se nombra a la manera de gettext, `language_REGION@modifier`, mientras la configuración conserva el código BCP 47:

| Código en la configuración | Nombre de archivo |
| --- | --- |
| `pt-BR` | `pt_BR` |
| `es-419` | `es_419` |
| `sr-Latn` | `sr@latin` |
| `sr-Latn-RS` | `sr_RS@latin` |
| `uz-Cyrl` | `uz@cyrillic` |
| `ks-Deva-IN` | `ks_IN@devanagari` |
| `zh-Hant-TW` | `zh_TW` |
| `sr-Cyrl-RS` | `sr_RS` |

Un script que el idioma y la región ya implican se omite, así que configurar a la vez `zh-TW` y `zh-Hant-TW` falla con `LOCALE_PATH_COLLISION`. Un script sin modificador de gettext, como `zh-Hant` sin región, falla con `LOCALE_LAYOUT_INVALID`. [`verbatra init`](/docs/cli/init) lee estos nombres de vuelta, y un catálogo creado los usa en su cabecera `Language`. Los demás formatos mantienen bajo `posix` la escritura de ICU (`sr_Latn`).

### Códigos de locale

<AvailableFrom version="0.12.0" />

Cada código de locale debe ser una etiqueta que `Intl.getCanonicalLocales` acepte, con una subetiqueta de idioma de dos o tres letras; si no, la carga falla con `CONFIG_INVALID`, nombrando el campo y el código. `pt_BR` se rechaza (escribe `pt-BR` y pon `localeStyle: "posix"`), y también un nombre de idioma como `german`. Un código válido pero no canónico, como `zh-hant-tw` o el obsoleto `iw`, funciona tal como está escrito, y [`verbatra doctor`](/docs/cli/doctor) sugiere la forma canónica. verbatra nunca renombra un archivo, y un código reescrito conserva su estado ([Un código de locale reescrito](/docs/the-lock-file#un-código-de-locale-reescrito)).

### provider

`provider.id` selecciona uno de los [proveedores](/docs/providers) o `none`. Bajo `provider` solo se permiten `id` y `options`; desde 0.12.0 cualquier otra clave, como un `localeMap` mal colocado, falla con `CONFIG_INVALID`. Todos los proveedores salvo `none` aceptan `options.localeMap` y `options.requestTimeoutMs` ([Proveedores](/docs/providers#códigos-de-locale-enviados-al-proveedor)). Con `none`, `options` puede omitirse y, si se indica, debe ser `{}` ([Trabajar sin traducción automática](/docs/human-only-workflow)).

### glossary

Términos que se traducen de una forma fija, en línea o como ruta a un archivo JSON con la misma forma; las dos formas nunca se fusionan. La versión 1 asigna a cada término de origen la traducción que usan todos los locales:

```ts title="verbatra.config.ts"
export default defineConfig({
  // ...
  glossary: {
    "Sign in": "Anmelden",
  },
  // or: glossary: "glossary.json",
});
```

Una ruta relativa se resuelve contra el directorio del archivo de configuración. El archivo debe estar en UTF-8, no superar 1 MiB, y se lee una vez al cargar. Un archivo ausente, JSON inválido o una forma inválida fallan con `CONFIG_INVALID`, nombrando la ruta y, en la versión 2, el campo. Pon un término `__proto__` en un archivo: en un literal de `verbatra.config.ts`, JavaScript lo convierte en el prototipo.

#### Glosario por locale (versión 2)

<AvailableFrom version="0.12.0" />

La versión 2 da a cada término una traducción por locale, traducciones prohibidas y términos que se quedan tal como están escritos:

```json title="glossary.json"
{
  "version": 2,
  "terms": [
    {
      "source": "Dashboard",
      "targets": { "de": "Übersicht", "fr": "Tableau de bord" },
      "forbidden": { "de": ["Instrumententafel"] },
      "note": "The start page after sign-in",
      "partOfSpeech": "noun"
    },
    { "source": "Sign in", "target": "Anmelden", "caseSensitive": true }
  ],
  "doNotTranslate": ["verbatra", { "term": "Acme", "caseSensitive": false }]
}
```

| Campo | Significado |
| --- | --- |
| `version` | Siempre `2`; obligatorio, y cualquier otro número falla. |
| `terms[].source` | El término de origen; cada término aparece una vez. |
| `terms[].target` | La traducción para cada locale que no tenga entrada propia en `targets`. |
| `terms[].targets` | Traducciones por locale. Un locale usa su propia entrada, luego la de su idioma base (`de` cubre `de-AT`) y luego `target`, comparando códigos canónicos sin distinguir mayúsculas. |
| `terms[].forbidden` | Traducciones que un locale nunca debe usar; un locale regional también se rige por la lista de su idioma base. |
| `terms[].caseSensitive` | Comparar el término, las traducciones y las traducciones prohibidas distinguiendo mayúsculas. Por defecto `false`. |
| `terms[].note`, `terms[].partOfSpeech` | Contexto en texto libre, que un proveedor LLM recibe como datos. |
| `doNotTranslate` | Términos que se copian sin traducir. Un string simple conserva además sus mayúsculas; `{ "term", "caseSensitive": false }` puede cambiarlas. |

Cada término necesita un `target`, una entrada en `targets` o una lista `forbidden`, y no puede prohibir su propia traducción, nombrar un locale dos veces ni aparecer también en `doNotTranslate`. Una petición solo lleva los términos de su locale de destino, y la huella de [caché](/docs/the-cache) de cada locale solo cubre esos. Un archivo de la versión 1 sigue funcionando con la misma huella; [`updateGlossaryTerm`](/docs/sdk/config#updateglossaryterm) del SDK lo reescribe como versión 2 solo para una edición que la versión 1 no puede expresar.

<AvailableFrom version="0.4.0" pkg="@verbatra/studio" /> Solo la forma de archivo se puede editar desde [Studio](/docs/review-in-studio), término a término; un glosario en línea es de solo lectura allí. A los proveedores LLM se les instruye para tratar las traducciones como vinculantes, evitar las traducciones prohibidas y conservar los términos que no se traducen; DeepL, Google Cloud Translation y LibreTranslate no pueden aplicarlos. La salida de cada proveedor se comprueba después y se marca con `GLOSSARY_TERM_MISSED` o `GLOSSARY_FORBIDDEN_TERM` ([motivos de revisión](/docs/error-codes#review-reason-codes)).

### generatePlurals

Cuando es true, verbatra sintetiza las formas plurales CLDR que un destino necesita y el origen no tiene, como `few` y `many` en polaco; las claves ordinales (`<key>_ordinal_<category>`) siguen las reglas ordinales CLDR. Solo lo admite `i18next-json` con un proveedor LLM. Todo lo demás, y un locale sin reglas CLDR, recibe en su lugar el aviso de plurales por locale (suponiendo `one` y `other` para los cardinales y `other` para los ordinales). No hay opción de CLI; `translate()` del SDK acepta un override por ejecución.

### fuzzyCache

`fuzzyCache: { enabled: true }` permite que una clave cuyo origen cambió reutilice la traducción de su forma anterior cuando ambas se parecen al menos `threshold`, siempre marcada como `FUZZY_CACHE_REUSE`; las reglas de seguridad están en [Reutilización difusa](/docs/the-cache#reutilización-difusa). No hay opción de CLI; `--no-cache` lo omite junto con el resto de la caché.

### humanEdits y pinnedKeys

`humanEdits` cubre una clave obsoleta cuyo valor escribió una persona (procedencia `human`, `import` o `external`, consulta [procedencia](/docs/the-lock-file#procedencia-quién-escribió-cada-valor)):

- `"protect"` conserva el valor y no envía la clave.
- `"suggest"` conserva el valor y pide al proveedor una sugerencia que nunca se escribe.
- `"overwrite"` la retraduce; `translate --include-human` hace esto para una ejecución.

Una clave que coincide con `pinnedKeys` (por ejemplo `["legal.*", "brand.name"]`) nunca se escribe de forma automática, diga lo que diga `humanEdits`. Consulta [Conserva las traducciones humanas](/docs/protecting-human-translations).

### network

La política y sus hosts; qué permite cada una y cómo fijarla desde el entorno está en [Restringe el acceso a la red](/docs/network-policy).

```ts title="verbatra.config.ts"
network: { policy: "local-only", allowedHosts: ["gpu.lan"] }
```

### maxBatchSize

Las entradas faltantes y modificadas de un locale se envían en sublotes secuenciales que no superan este tamaño, así que una petición sobredimensionada no puede hacer fallar el locale entero; un sublote fallido se reintenta en la siguiente ejecución mientras los demás siguen avanzando. No hay opción de CLI ni override por ejecución.

### maxLength

Un mapa de clave de traducción al valor más largo que puede contener, para cadenas sujetas a una restricción de maquetación:

```ts title="verbatra.config.ts"
maxLength: {
  "nav.dashboard": 18,
  "cta.submit": 12,
}
```

- **Solo aquí.** Ningún presupuesto se deduce de una descripción ni de los metadatos de un formato. Las claves se comparan literalmente, nunca como globs; una clave ausente del mapa nunca se mide.
- **Clústeres de grafemas.** La longitud cuenta caracteres percibidos: un emoji de varios puntos de código o una letra con un acento combinante cuentan como uno, y también un carácter CJK aunque se dibuje cerca del doble de ancho. Los espacios cuentan, y el límite es inclusivo.
- **Cuándo se comprueba.** En cada valor que `translate` produce para la clave, reutilizaciones de caché incluidas. Una clave al día no se mide, así que un presupuesto nuevo no marca nada hasta que su origen cambie; [`verbatra export --include-unchanged`](/docs/cli/export) mide ahora mismo cada valor actual.
- **Informativo.** Un exceso se sigue escribiendo y bloqueando, y se informa como `MAX_LENGTH_EXCEEDED` en `needsReview`, en la cola de revisión de Studio y en las columnas de revisión del libro de Excel.

### maxTokens y budgetBehavior

`maxTokens` es un presupuesto para toda la ejecución: tokens de entrada más de salida, sumados en cada llamada al proveedor (traducción y generación de plurales) y en cada locale de destino. `translate --max-tokens <n>` fija para una ejecución un techo más estricto que siempre detiene; se aplica la cifra menor (desde 0.12.0).

`budgetBehavior` decide qué pasa al alcanzarlo:

- `"warn"`, el valor por defecto, cuenta el gasto y señala el exceso; la ejecución continúa como si no hubiera presupuesto.
- `"stop"` <AvailableFrom version="0.11.0" /> lo convierte en un techo (DeepL, Google Cloud Translation y LibreTranslate incluidos). Antes de cada petición, la ejecución proyecta su coste igual que [la estimación previa](/docs/estimating-cost) y rechaza una que superaría `maxTokens`. Las claves de esa petición se retienen, y también cada clave aún no intentada: el resto del locale actual y cada locale posterior, cuyo diff e informe de huérfanas siguen ejecutándose. Las claves retenidas conservan su hash anterior en el bloqueo y se reintentan en la siguiente ejecución.

Cómo cuenta `"stop"`:

- Se comprueba cada petición, incluida cada mitad de una petición que se vuelve a dividir tras una respuesta truncada.
- Después de cada petición el total se reconcilia con el uso que informó el proveedor. Una petición que cuesta más de lo proyectado aporta la diferencia a posteriori, así que una ejecución puede terminar por encima de `maxTokens` por la diferencia de esa única petición, y no se envía nada más.
- Una petición admitida puede costar hasta cerca del doble de su proyección por la propia petición de reparación de la capa de proveedor para claves que faltan; eso también llega en la reconciliación.
- Una petición fallida o truncada sigue cargada por completo, ya que el proveedor normalmente facturó su prompt.
- Una ejecución detenida no deja ningún archivo a medio escribir ni ninguna entrada de bloqueo para trabajo retenido.
- La proyección incluye una asignación fija para el prompt del LLM (reglas de sistema y esquema de respuesta), que se suma también para los proveedores de traducción automática. Una petición se proyecta como un lote entero, así que un `maxTokens` por debajo de la proyección de un lote lo rechaza en cada ejecución; el aviso indica entonces que bajes `maxBatchSize` o subas `maxTokens`.
- DeepL, Google Cloud Translation y LibreTranslate no informan de uso de tokens y se presupuestan a partir de la proyección; `budget.supported: false` en el resumen de la ejecución marca la cuenta propia de verbatra.

Alcance y códigos de salida:

- El presupuesto acota una ejecución de `translate`. `watch` arranca un presupuesto nuevo para cada ejecución que dispara, y retraducir una sola entrada desde [Studio](/docs/review-in-studio) o desde una herramienta de agente nunca tiene tope.
- Una ejecución real con `maxTokens` y `--concurrency` por encima de `1` se rechaza con salida `2` (`CONCURRENCY_BUDGET_CONFLICT`), porque qué locale pierde trabajo dependería del entrelazado. Un dry run queda exento.
- Con `"warn"` el código de salida nunca cambia. Con `"stop"`, un locale con claves retenidas es `partial` si algunas claves llegaron y `failed` si no llegó ninguna; ambos salen con `1`.
- `budgetBehavior` sin `maxTokens` no tiene efecto.

<Callout title="Dos maxTokens distintos">
El `maxTokens` de nivel superior es este presupuesto de toda la ejecución. El `provider.options.maxTokens` de Anthropic limita una sola respuesta; no tienen relación. Consulta [Proveedores](/docs/providers#anthropic).
</Callout>

### rates

Solo lo lee [`verbatra translate --estimate`](/docs/estimating-cost), que explica cómo las tarifas se convierten en dinero; una ejecución real lo ignora.

```ts title="verbatra.config.ts"
rates: {
  asOf: "2026-01-15",
  currency: "USD",
  table: {
    "gemini/gemini-2.5-flash": { inputPerMillionTokens: 0.1, outputPerMillionTokens: 0.4 },
    deepl: { perMillionCharacters: 25 },
  },
}
```

Una clave de `table` es `provider/model` para un proveedor con modelo y el id a secas para uno sin él (`deepl`, `google-translate`). Una entrada se factura por tokens (`inputPerMillionTokens` y `outputPerMillionTokens`) o por caracteres (`perMillionCharacters`), nunca ambas cosas; una tarifa negativa se rechaza. `openai-compatible` y `libretranslate` no emiten factura, así que su cantidad se informa sin tarifa. Una entrada en la unidad equivocada se rechaza.

### extract

Solo lo leen [`verbatra extract`](/docs/cli/extract), [`verbatra doctor --literals`](/docs/cli/doctor#literales-sin-traducir) y [`verbatra diff --unused`](/docs/cli/diff#claves-de-origen-sin-uso).

```ts title="verbatra.config.ts"
extract: {
  framework: "i18next",
  roots: ["src", "app"],
  exclude: ["generated"],
  literals: { ignore: ["Acme Inc."] },
  unused: { ignore: ["emails.*"] },
}
```

- **`framework`** es un conjunto cerrado; `i18next` cubre `t(...)`, `$t(...)` y `<object>.t(...)`. Un framework sin extractor se rechaza.
- **`roots`** se resuelven contra el directorio de trabajo; nunca se lee nada fuera de ellas.
- **`exclude`** añade nombres de directorio (no rutas), que coinciden en cualquier punto bajo una raíz, a los que siempre se omiten: `node_modules`, `.git`, `.next`, `.turbo`, `.verbatra`, `dist`, `build` y `coverage`.
- **`literals.ignore`** coincide con el texto completo de un literal con los espacios reducidos y las referencias de caracteres decodificadas, así que escribe `Tom & Jerry`, no `Tom &amp; Jerry`. Un literal retenido se notifica como suprimido.
- **`unused.ignore`** acepta claves exactas o patrones `*` para claves usadas solo fuera del código analizado (una plantilla de servidor, un CMS). Coincide con la clave decodificada que muestra el informe (`Welcome. Enjoy`, no `Welcome\. Enjoy`), y una coincidencia se notifica como ignorada.

## Orden de descubrimiento

verbatra busca hacia arriba desde el directorio de trabajo y usa la primera fuente que encuentra, deteniéndose en el directorio más cercano que contenga `.git` (o en tu directorio personal), así que nunca recoge una configuración por encima de tu repositorio:

1. `package.json` (una propiedad `"verbatra"`)
2. `.verbatrarc`
3. `.verbatrarc.json`
4. `.verbatrarc.yaml`
5. `.verbatrarc.yml`
6. `.verbatrarc.js`
7. `.verbatrarc.cjs`
8. `.verbatrarc.ts`
9. `verbatra.config.js`
10. `verbatra.config.cjs`
11. `verbatra.config.ts`

`--config <path>` carga un solo archivo en su lugar, relativo al directorio de trabajo. En el SDK, un `configOverride` en memoria tiene prioridad sobre `configPath`, que a su vez tiene prioridad sobre la búsqueda ([Recetas del SDK](/docs/programmatic-api)).

## Validación en el editor

<AvailableFrom version="0.9.0" />

`@verbatra/sdk` publica un JSON Schema generado a partir del esquema zod con el que valida el SDK:

```text
node_modules/@verbatra/sdk/dist/config-schema.json
```

`.verbatrarc.json` y `.verbatrarc` aceptan una clave `$schema`, que VS Code lee:

```json title=".verbatrarc.json"
{
  "$schema": "./node_modules/@verbatra/sdk/dist/config-schema.json",
  "sourceLocale": "en",
  "targetLocales": ["de", "fr"],
  "format": "i18next-json",
  "files": { "pattern": "locales/{locale}.json" },
  "provider": { "id": "gemini", "options": { "model": "gemini-2.5-flash", "maxOutputTokens": 4096 } }
}
```

El `.verbatrarc` sin extensión necesita además una correspondencia de archivos, que da una asociación en el espacio de trabajo:

```json title=".vscode/settings.json"
{
  "json.schemas": [
    {
      "fileMatch": [".verbatrarc", ".verbatrarc.json"],
      "url": "./node_modules/@verbatra/sdk/dist/config-schema.json"
    }
  ]
}
```

Una configuración YAML lleva un comentario para el YAML Language Server:

```yaml title=".verbatrarc.yaml"
# yaml-language-server: $schema=./node_modules/@verbatra/sdk/dist/config-schema.json
sourceLocale: en
targetLocales: [de, fr]
```

La propiedad de `package.json` no puede recibir un esquema; las formas ejecutables las tipa `defineConfig` en su lugar.

### Lo que el documento no puede comprobar

Estas reglas no tienen expresión en JSON Schema, así que solo las comprueba la carga de la configuración:

- `targetLocales` no debe incluir `sourceLocale`, ni dos locales que solo difieran en mayúsculas.
- Un código de locale debe pasar `Intl.getCanonicalLocales` (la gramática no ve una variante repetida como `de-1996-1996`).
- Cada clave de `provider.options.localeMap` debe ser `sourceLocale` o un locale de destino.
- `apiKeyEnvVar` (openai-compatible) no debe nombrar la variable de clave de un proveedor alojado.
- Una entrada de `network.allowedHosts` debe ser una dirección o un rango válidos (no un octeto mayor que 255, un prefijo CIDR demasiado largo ni un IPv6 mal formado).
- Un glosario en línea de la versión 2 debe cumplir las reglas de términos de [glossary](#glosario-por-locale-versión-2).

## El directorio de trabajo y .env

El directorio de trabajo (donde ejecutas verbatra, o `--cwd`) ancla la búsqueda de configuración y las rutas de locale; qué comandos cargan `.env.local` y `.env` desde él está en [Archivos de entorno](/docs/cli#archivos-de-entorno).

## Cuando la carga falla

- [`CONFIG_NOT_FOUND`](/docs/error-codes#config_not_found): no hay configuración en ningún sitio buscado, o la ruta de `--config` no existe.
- [`CONFIG_INVALID`](/docs/error-codes#config_invalid): se encontró una configuración pero no se puede usar: no se puede parsear, falla la validación o nombra un archivo de glosario ilegible. El mensaje lista cada problema con la ruta de su clave, y una clave de nivel superior desconocida añade la pista de que las claves de API vienen del entorno. Un fallo de parseo nombra el archivo (con línea y columna en YAML) pero nunca cita su contenido, y cada mensaje pasa por la redacción de claves.

La CLI sale con `2` en ambos casos.
