Select a provider by `id` in the `provider` block of your [config](/docs/config-file). Anthropic, OpenAI, Gemini and openai-compatible are language models; DeepL, Google Cloud Translation and LibreTranslate are machine-translation services; `none` turns machine translation off. Model ids on this page are examples, not recommendations. Language coverage is on [Languages and locales](/docs/language-support), and what each provider receives on [Data handling and privacy](/docs/data-handling).

## Which one should I pick?

Every provider works with every format and command, and switching later means editing one `id`.

| If you want | Use |
| --- | --- |
| Free, for a small project with non-confidential strings | **Gemini**: a free API tier, keys from [Google AI Studio](https://aistudio.google.com/apikey). Outside the EEA, Switzerland and the UK, Google may use free-tier requests and have humans review them ([terms](/docs/data-handling#vendor-retention-and-data-processing-terms)). |
| The best quality for a production app | **Anthropic** or **OpenAI**, both paid. |
| High volume, a native glossary, no LLM | **DeepL**, free or paid tier. It skips strings with placeholders. |
| The widest coverage from an API key on Google Cloud | **Google Cloud Translation** (Basic, v2). It skips strings with placeholders. |
| Offline, no cost, nothing leaving your network | **openai-compatible** with LM Studio, Ollama or vLLM. |
| No language model, but self-hosted | **LibreTranslate** on your own server. |
| No machine translation at all | **none**: memory and humans only. |

## Keys come from the environment

verbatra never reads a key from the config. Each hosted provider reads one variable:

| Provider id | Environment variable |
| --- | --- |
| `anthropic` | `ANTHROPIC_API_KEY` |
| `openai` | `OPENAI_API_KEY` |
| `gemini` | `GEMINI_API_KEY` |
| `deepl` | `DEEPL_API_KEY` |
| `google-translate` | `GOOGLE_TRANSLATE_API_KEY` |

Set it in `.env` (which `verbatra init` gitignores), your shell, or your CI secret store, and never commit it. An unset or empty variable fails with `MISSING_API_KEY`, naming the variable but never a value. The SDK wraps it as `PROVIDER_CONSTRUCTION_FAILED`: the CLI prints that code with `(cause: MISSING_API_KEY)`, and `--json` carries `"causeCode": "MISSING_API_KEY"`. From 0.12.0 the error also carries `envVar`, and the CLI prints a `next:` hint naming the variable to set. `openai-compatible` and `libretranslate` usually need no key; see their sections.

## Anthropic

```ts title="verbatra.config.ts"
provider: {
  id: "anthropic",
  options: {
    model: "claude-sonnet-4-6", // example model id
    maxTokens: 4096,
  },
}
```

| Option | Type | Default | Effect |
| --- | --- | --- | --- |
| `model` | string | required | The model id. |
| `maxTokens` | positive integer | required | Caps one response's output tokens ([limits](#output-token-limits)); unrelated to the top-level budget. |
| `requestTimeoutMs` | positive integer | `120000` | Bounds each request attempt ([Request timeout](#request-timeout)). |
| `localeMap` | map of locale to code | none | Overrides the code sent per locale ([Locale codes](#locale-codes-sent-to-the-provider)). |

Reads `ANTHROPIC_API_KEY`.

<Callout title="The free tier and its limits">
A key from [Google AI Studio](https://aistudio.google.com/apikey) needs no billing. The free tier caps requests per minute and per day (per model, and it changes), so a first run over many locales can hit the cap. Brief rate limits are retried, a sustained cap is not: translate one locale at a time or lower `maxBatchSize`, then re-run, which only picks up what is still missing.
</Callout>

## DeepL

```ts title="verbatra.config.ts"
provider: {
  id: "deepl",
  options: {
    glossaryId: "<your-glossary-id>",
  },
}
```

| Option | Type | Default | Effect |
| --- | --- | --- | --- |
| `glossaryId` | string | none | A glossary you created in DeepL, applied natively. |
| `requestTimeoutMs` | positive integer | `120000` | The minimum wait per attempt, up to five attempts. |
| `localeMap` | map of locale to code | none | Overrides the code sent per locale. |

Reads `DEEPL_API_KEY`; `options` may be `{}`. DeepL has no model and no output-token limit, and degrades with a notice rather than failing:

- **Glossary.** Your config glossary's translations and do-not-translate terms are not applied (`GLOSSARY_IGNORED`); forbidden renderings are only checked afterwards.
- **Tone** maps to formality (`formal` more, `informal` less, `neutral` omitted). A free-tier key, or a language without formality such as Swedish, falls back to the default register with `FORMALITY_DOWNGRADED`; from 0.12.0 verbatra asks with `prefer_more` and `prefer_less` so the request does not fail.
- **Placeholders.** A string with placeholders or ICU is withheld with `PLACEHOLDER_UNSUPPORTED`; use an LLM provider for those.

<AvailableFrom version="0.12.0" />

verbatra ships DeepL's dated [language table](https://developers.deepl.com/docs/getting-started/supported-languages) and refuses an unlisted language with `LOCALE_UNSUPPORTED_BY_PROVIDER` before anything is spent. A `glossaryId` works only when both languages are on DeepL's glossary list (such as `DE`, `EN`, `FR`, `JA`, `ZH`).

## Google Cloud Translation

<AvailableFrom version="0.10.0" />

```ts title="verbatra.config.ts"
provider: {
  id: "google-translate",
  options: {},
}
```

| Option | Type | Default | Effect |
| --- | --- | --- | --- |
| `requestTimeoutMs` | positive integer | `120000` | Bounds the whole call (no retries). |
| `localeMap` | map of locale to code | none | Overrides the code sent per locale. |

Reads `GOOGLE_TRANSLATE_API_KEY`, a plain API key for a Google Cloud project with the Cloud Translation API enabled. It uses the Basic (v2) tier; Advanced (v3) needs a service account, which does not fit an environment-variable key.

- **No formality, no glossary.** A `formal` or `informal` tone reports `FORMALITY_DOWNGRADED`; a glossary translation or do-not-translate term reports `GLOSSARY_IGNORED`.
- **Placeholders.** A string with placeholders or ICU is withheld with `PLACEHOLDER_UNSUPPORTED`.
- **Codes.** Each code sent is checked as well-formed BCP 47 before any call (`en_US` fails with `INVALID_REQUEST`). Regional codes are allowed; a pair Google rejects fails with `INVALID_REQUEST` from the API.

<AvailableFrom version="0.12.0" />

verbatra ships Google's dated [language table](https://docs.cloud.google.com/translate/docs/languages) and refuses an unlisted language before anything is spent. A regional code whose language is listed only as a whole, such as `de-AT`, is sent as written with a warning.

## openai-compatible

Any server speaking the OpenAI Chat Completions API: LM Studio, Ollama, vLLM, or a hosted API with the same protocol.

```ts title="verbatra.config.ts"
provider: {
  id: "openai-compatible",
  options: {
    baseUrl: "http://192.168.178.74:1234/v1",
    model: "qwen2.5-14b-instruct", // example: whatever your server exposes
    maxOutputTokens: 1024,
  },
}
```

| Option | Type | Default | Effect |
| --- | --- | --- | --- |
| `baseUrl` | `http` or `https` URL | required | The server, including its API path, usually `/v1`. A URL without it passes validation and fails at request time. |
| `model` | string | required | Whatever model your server exposes. |
| `maxOutputTokens` | positive integer | required | Caps one response's output tokens. |
| `apiKeyEnvVar` | variable name | none | The variable holding a key for this server; never a hosted provider's variable. |
| `requestTimeoutMs` | positive integer | `120000` | Bounds each request attempt. |
| `localeMap` | map of locale to code | none | Overrides the code sent per locale. |

A hosted API works the same way, for example Mistral:

```ts title="verbatra.config.ts"
provider: {
  id: "openai-compatible",
  options: {
    baseUrl: "https://api.mistral.ai/v1",
    model: "mistral-large-latest", // example: check Mistral's current model list
    maxOutputTokens: 4096,
    apiKeyEnvVar: "MISTRAL_API_KEY",
  },
}
```

The response format is the same strict schema as `openai`, but the first balanced JSON object is extracted from any surrounding prose or code fence before validation, since smaller models add them. The output still goes through every schema and integrity check. `verbatra init --provider openai-compatible --base-url <url> --model <name>` writes this block ([init](/docs/cli/init#providers)), and `--api-key-env-var <NAME>` adds the variable's name.

### Keys are optional

The key resolves in order:

1. **`apiKeyEnvVar`**: if set, its variable must hold a key, or the run fails with `MISSING_API_KEY`.
2. **`OPENAI_COMPATIBLE_API_KEY`**: used when set and non-empty; otherwise verbatra moves on.
3. **`"local"`**: a fixed, non-secret placeholder, which is what makes a keyless server work.

`apiKeyEnvVar` cannot name a hosted provider's variable, and the client never reads `OPENAI_API_KEY`, so a hosted key never reaches a custom `baseUrl`.

<Callout type="warn" title="A real key over plaintext http travels in cleartext">
Plaintext `http://` is allowed to any host, which is safe while no key is configured. With a key and a non-loopback `http://` URL, the key crosses your network unencrypted, and verbatra does not warn about it. Use `https://` for a server that needs a key.
</Callout>

### Choosing a local model

Prefer an instruction-tuned, non-reasoning model with strong multilingual coverage, as large as your hardware runs well; `qwen2.5-14b-instruct` is a reasonable default. Reasoning models and heavily quantized builds tend to wrap the answer in prose or truncate it, which fails as `INVALID_RESPONSE` or `OUTPUT_TRUNCATED` instead of writing a corrupt translation. If you need a reasoning model, give it room ([Output-token limits](#output-token-limits)).

## LibreTranslate

<AvailableFrom version="0.12.0" />

A self-hosted [LibreTranslate](https://github.com/LibreTranslate/LibreTranslate) server: neural machine translation (Argos Translate), no language model. verbatra only calls its HTTP API, so the server's AGPL-3.0 license does not extend to your project.

```ts title="verbatra.config.ts"
provider: {
  id: "libretranslate",
  options: {
    baseUrl: "http://localhost:5000",
  },
}
```

| Option | Type | Default | Effect |
| --- | --- | --- | --- |
| `baseUrl` | `http` or `https` URL | required | The API root, without `/translate`. |
| `requestTimeoutMs` | positive integer | `120000` | Bounds the whole call (no retries). |
| `localeMap` | map of locale to code | none | Overrides the code sent per locale. |

Its languages are the models installed on your server:

```bash
docker run -p 5000:5000 libretranslate/libretranslate --load-only en,de,fr
```

- **Key.** `LIBRETRANSLATE_API_KEY` is sent as `api_key` only when set. A server started with `--api-keys` fails the run with `MISSING_API_KEY` when it is unset, and with `AUTH_FAILED` when it rejects it.
- **No formality, no glossary**: `FORMALITY_DOWNGRADED` and `GLOSSARY_IGNORED`, as for Google; output is still checked against the glossary.
- **Placeholders** are masked as numbered markers (`Hello {{name}}` travels as `Hello {0}`) and restored. A value comes back only when every marker returns once, otherwise it is withheld with `PLACEHOLDER_UNSUPPORTED`; a value with ICU syntax is never sent.
- **Markup.** A value with HTML-style tags is sent in `html` format, so the text inside tags is translated and the tags stay; phrasing across a tag may suffer, and changed tags are refused.
- **Language check.** Every target is `unverified` with a `LOCALE_UNVERIFIED_BY_PROVIDER` warning on every run; `verbatra doctor --locales --live` checks them against the server's `/languages`.

`verbatra init --provider libretranslate --base-url <url>` writes this block.

## none

<AvailableFrom version="0.12.0" />

Disables machine translation by policy, for an NDA or company rule that forbids sending strings to any service.

```ts title="verbatra.config.ts"
provider: { id: "none" }
```

`options` may be omitted or `{}`. No provider is constructed, no key is read, and no request is made. `translate` and `watch` fill keys only from [the translation memory](/docs/the-cache) and report the rest as `unfilled` (`translate` exits `3`). [Studio](/docs/cli/studio) and the [MCP server](/docs/cli/mcp) never offer spending actions, and the SDK's `retranslateEntry` fails with `MACHINE_TRANSLATION_DISABLED`. The memory is a bucket of its own: carry entries over with `tmx export` before switching and `tmx import` after. `verbatra init --provider none` scaffolds it; see [Run without machine translation](/docs/human-only-workflow).

## Tone and glossary across providers

Every request carries only its target locale's glossary terms, and every provider's output is checked against them afterwards.

| Provider | `tone` | `glossary` |
| --- | --- | --- |
| Anthropic, OpenAI, Gemini, openai-compatible | sent and honored | translations, forbidden renderings, do-not-translate terms and notes sent as binding data |
| DeepL | mapped to formality; `FORMALITY_DOWNGRADED` on a free key or a language without it | `GLOSSARY_IGNORED`; only `glossaryId` applies |
| Google Cloud Translation, LibreTranslate | `FORMALITY_DOWNGRADED` for `formal` or `informal` | `GLOSSARY_IGNORED` |

## Behavior every provider shares

### Batching

A locale's work goes out in sequential sub-batches of at most [`maxBatchSize`](/docs/config-file#maxbatchsize) entries (default `50`). A failed sub-batch is withheld and retried next run while the rest proceed. DeepL and Google Cloud Translation also split a sub-batch to fit their own request caps.

### Retries

Rate limits and server errors are retried with a short backoff: the OpenAI, Anthropic and DeepL clients do it themselves, and verbatra adds the same for Gemini. Google Cloud Translation and LibreTranslate do not retry: a rate limit or server error surfaces at once as `RATE_LIMITED` or `PROVIDER_UNAVAILABLE`, and the sub-batch is picked up next run.

### Request timeout

`requestTimeoutMs` bounds each request, so a server that accepts a connection but never answers cannot stall a run and hold a locale's write lock. The default is `120000` ms (two minutes); raise it for a slow local model or a large `maxBatchSize`.

```ts title="verbatra.config.ts"
provider: {
  id: "openai-compatible",
  options: {
    baseUrl: "http://192.168.178.74:1234/v1",
    model: "qwen2.5-14b-instruct",
    maxOutputTokens: 1024,
    requestTimeoutMs: 300000, // 5 minutes
  },
}
```

- **Per attempt.** Clients retry `429` and `5xx` a few times, each attempt with the full timeout. Anthropic, OpenAI, openai-compatible and Gemini also retry a timed-out attempt, and all but Gemini a connection error, so a hung server takes up to three timeouts plus backoff to give up.
- **The error names the cause.** Repeated rate limits, server errors or refused connections fail as `RATE_LIMITED`, `PROVIDER_UNAVAILABLE` or `PROVIDER_ERROR`; `TIMEOUT` means one attempt got no answer in time.
- **DeepL** waits at least the timeout per attempt, up to five attempts, and cannot abort a request in flight, so an interrupted run leaves it to settle at DeepL.
- **Google Cloud Translation and LibreTranslate** send one request with no retries, so the timeout covers the whole call.

Only the failed sub-batch is affected; its keys come back next run.

### Locale codes sent to the provider

<AvailableFrom version="0.12.0" />

Files, the lock and the memory always use your config's codes. Only the request is translated to what the provider expects:

| Provider | Source locale | Target locale |
| --- | --- | --- |
| DeepL | The language alone: `en-US` as `EN`, `zh-Hant-TW` as `ZH`. | `zh-Hant`, `zh-TW`, `zh-HK`, `zh-MO` as `ZH-HANT`; `zh-Hans`, `zh-CN`, `zh-SG` as `ZH-HANS`. DeepL variants stay (`EN-GB`, `EN-US`, `PT-BR`, `PT-PT`, `ES-419`, `FR-CA`, `FR-FR`, `DE-CH`, `DE-DE`). Spanish with a Latin American or Caribbean region (`MX`, `AR`, `CO`, `CL`, `PE`, `VE`, `EC`, `GT`, `CU`, `BO`, `DO`, `HN`, `PY`, `SV`, `NI`, `CR`, `PA`, `UY`, `PR`, `US`, `419`) as `ES-419`. Other regions and scripts are dropped: `de-AT` as `DE`. |
| Google Cloud Translation | `zh-Hant` (`zh-HK`, `zh-MO`) as `zh-TW`, `zh-Hans` (`zh-SG`) as `zh-CN`, `nb` as `no`; everything else as written. | Same as the source. |
| LibreTranslate | The language alone (`de-AT` as `de`), except `pt-BR` stays and Chinese goes as `zh-Hans` or `zh-Hant` (`zh-TW` as `zh-Hant`). | Same as the source. |
| Anthropic, OpenAI, Gemini, openai-compatible | As written, with its English language name. | As written, with its English language, script and region names. |

An LLM receives, for example, `sr-Latn` with `{ "name": "Serbian (Latin)", "script": "Latin" }`, and a fixed rule asks it to write that script and variant; a code Node.js cannot name is sent without one. DeepL has no generic English or Portuguese target, so a target ending up as bare `en` or `pt` (such as `en-AU`) is refused before the run: map it to `EN-GB`, `EN-US`, `PT-BR` or `PT-PT`.

`localeMap` overrides the code per locale, and an entry always wins:

```ts title="verbatra.config.ts"
provider: {
  id: "deepl",
  options: {
    localeMap: {
      "en-AU": "EN-GB",
      "fr-BE": "FR-FR",
    },
  },
}
```

- **Keys** must be `sourceLocale` or a target locale, spelled as configured; anything else fails with `CONFIG_INVALID`. It belongs under `options` (directly under `provider` it fails), for every provider except `none`.
- **Values** are non-empty strings of at most 64 characters, sent unchanged: as the language code to a machine-translation provider, in place of the code to an LLM (`"pt-BR (Brazilian Portuguese)"` works). LLM language names still come from the key. A value that still sends DeepL a bare `EN` or `PT` fails with `INVALID_REQUEST`; a value the provider rejects fails its sub-batch.
- **Effect on memory.** Only new and changed strings go out with a new code. A non-empty map is part of the [memory](/docs/the-cache) fingerprint, so changing it starts a separate bucket.

### Checking a provider's language support

<AvailableFrom version="0.12.0" />

Every configured locale is judged before anything is spent:

| Provider | Judged against | Refused before the run | Warned about |
| --- | --- | --- | --- |
| DeepL | Its shipped language table, with glossary and formality support per language | An unlisted source or target language | A glossary for a pair outside the glossary languages, a tone without formality, a partly listed code |
| Google Cloud Translation | Its shipped language table | An unlisted language | Any glossary, a `formal` or `informal` tone, a regional code listed only as a language |
| LibreTranslate | Nothing before a run; the server's `/languages` with `doctor --live` | Never | Every target locale on every run, any glossary, a `formal` or `informal` tone |
| Anthropic, OpenAI, Gemini, openai-compatible | Nothing: an LLM accepts any language | Never | A language outside the [well-tested list](/docs/language-support#checking-support-before-a-run) |
| none | Not applicable | Never | Never |

[`verbatra doctor`](/docs/cli/doctor#locale-support) reports each verdict, and `--locales` adds the code sent and glossary and formality support. `translate` (dry run and estimate included), `watch` at startup, and a single-key retranslation refuse an unsupported locale with `LOCALE_UNSUPPORTED_BY_PROVIDER` and exit `2` before any provider is built. Warnings never refuse; they appear as notices (`LOCALE_UNVERIFIED_BY_PROVIDER`, `LOCALE_NOT_WELL_TESTED`, `GLOSSARY_UNSUPPORTED_BY_PROVIDER`, `FORMALITY_UNSUPPORTED_BY_PROVIDER`).

The tables are dated copies. `verbatra doctor --live` first fetches the current list (DeepL `/v3/languages`, Cloud Translation `languages`, LibreTranslate `/languages`, no quota used) when the key is set (LibreTranslate needs none) and the [network policy](/docs/network-policy) allows it. The live list only informs the report; `translate` always uses the shipped table. For a language added since, map the locale in `localeMap`: an explicit code is sent with a warning, not refused.

### Structured errors

A provider failure never surfaces as a raw SDK error, which could carry headers or a key: verbatra raises a structured error with a stable code and a fixed, secret-free message ([Provider error codes](/docs/error-codes#provider-error-codes)). Only its own sub-batch is affected. For openai-compatible and LibreTranslate, a `PROVIDER_ERROR` names the host and port of `baseUrl` (never its path, query or user info), such as `The translation provider request to localhost:11434 failed: the connection was refused.`; Google Cloud Translation names `translation.googleapis.com`, never the query carrying its key.

### Output-token limits

The LLM providers cap each response's tokens. A model that stops at the cap raises `OUTPUT_TRUNCATED`:

> The provider stopped because the output-token limit was reached. Reduce the batch size or raise the configured max output tokens.

verbatra first re-splits a truncated sub-batch into halves, down toward one entry, and withholds only an entry that still overflows. To fix it for good, lower `maxBatchSize` or raise `maxTokens` (Anthropic) or `maxOutputTokens`. A reasoning model spends hidden reasoning tokens from the same budget and can run out before writing anything, so give it generous headroom. The machine-translation providers have no truncation case.

### Review flags

Every accepted translation goes through the same post-translation checks, and a suspicious one (identical to its source, or missing a glossary term) is flagged for review rather than rejected. See [review reasons](/docs/error-codes#review-reason-codes) and [Review in Studio](/docs/review-in-studio).
