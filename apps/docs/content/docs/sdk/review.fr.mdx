## Opérations sur une seule clé

Ce sont les points d'accroche que Verbatra Studio pilote ; utilise-les pour construire ton propre outillage de révision. Toutes résolvent `locale` et `key` de nouveau à chaque appel et lèvent `UNKNOWN_LOCALE` ou `UNKNOWN_KEY` quand l'un des deux n'existe pas.

### keyValue

Lit la valeur source actuelle d'une clé et, quand elle existe, sa valeur cible actuelle pour une locale. En lecture seule.

```ts title="Signature"
function keyValue(
  input: KeyValueInput,
  deps?: KeyValueDeps,
): Promise<KeyValueResult>;
```

<SdkTypeTable name="KeyValueInput" />

**Renvoie :** `KeyValueResult`

**Lève :** [`UNKNOWN_FORMAT`](/docs/error-codes#unknown_format), [`UNKNOWN_LOCALE`](/docs/error-codes#unknown_locale), [`LOCALE_LAYOUT_INVALID`](/docs/error-codes#locale_layout_invalid), [`LOCALE_PATH_COLLISION`](/docs/error-codes#locale_path_collision), [`SOURCE_UNREADABLE`](/docs/error-codes#source_unreadable), [`SOURCE_INVALID`](/docs/error-codes#source_invalid), [`UNKNOWN_KEY`](/docs/error-codes#unknown_key)

Renvoie `{ source, target? }` ; `target` est absent exactement quand la clé n'existe pas encore dans cette locale.

Quand `target` est présent, le résultat porte aussi `provenance`, la `KeyProvenance` interprétée de la clé : `{ origin, provider?, model?, reviewState, reviewer? }`.

<AvailableFrom version="0.12.0" />

Le résultat porte aussi `description` quand le fichier de la locale source en donne une pour la clé : une `@key.description` ARB, une note XLIFF, un commentaire gettext, un commentaire `.strings` d'Apple ou un commentaire `.resx` .NET.

### keyContext

<AvailableFrom version="0.12.0" />

Lit ce dont un traducteur a besoin pour écrire une clé dans une locale cible : tout ce que renvoie `keyValue`, plus les termes du glossaire qui s'appliquent au texte source et le `maxLength` de la clé. Passe un `draft` pour le vérifier par rapport à ces termes. En lecture seule.

```ts title="Signature"
function keyContext(
  input: KeyContextInput,
  deps?: KeyContextDeps,
): Promise<KeyContext>;
```

<SdkTypeTable name="KeyContextInput" />

**Renvoie :** `KeyContext`

**Lève :** [`UNKNOWN_FORMAT`](/docs/error-codes#unknown_format), [`UNKNOWN_LOCALE`](/docs/error-codes#unknown_locale), [`LOCALE_LAYOUT_INVALID`](/docs/error-codes#locale_layout_invalid), [`LOCALE_PATH_COLLISION`](/docs/error-codes#locale_path_collision), [`SOURCE_UNREADABLE`](/docs/error-codes#source_unreadable), [`SOURCE_INVALID`](/docs/error-codes#source_invalid), [`UNKNOWN_KEY`](/docs/error-codes#unknown_key)

Un glossaire illisible ne lève pas d'erreur : `glossary` est vide et `glossaryNotice` porte le code et le message expurgé de l'erreur. `draftCheck` indique, pour chaque terme applicable, si le brouillon utilise la traduction exigée et quelles variantes interdites il emploie.

### localeHistory

<AvailableFrom version="0.12.0" />

Liste les commits git récents qui ont modifié le fichier source ou un fichier de locale cible, du plus récent au plus ancien. En lecture seule ; il lance `git log` via l'`execFile` injectable.

```ts title="Signature"
function localeHistory(
  input: LocaleHistoryInput,
  deps?: LocaleHistoryDeps,
): Promise<LocaleHistoryResult>;
```

<SdkTypeTable name="LocaleHistoryInput" />

**Renvoie :** `LocaleHistoryResult`

**Lève :** [`LOCALE_LAYOUT_INVALID`](/docs/error-codes#locale_layout_invalid), [`LOCALE_PATH_COLLISION`](/docs/error-codes#locale_path_collision)

Chaque commit porte `hash`, `author`, `authorDate`, `subject` et `touchedPaths`. `author` est le nom après `.mailmap`, jamais l'e-mail. `limit` vaut `LOCALE_HISTORY_LIMIT_DEFAULT` (`50`) par défaut et `LOCALE_HISTORY_LIMIT_CAP` (`200`) au plus. Les caractères de contrôle et de mise en forme bidirectionnelle sont retirés de `author` et `subject`, et un commit dont les métadonnées ne se lisent pas est omis. Si git manque, si le projet n'est pas un dépôt, ou si `git log` dépasse `LOCALE_HISTORY_TIMEOUT_MS` ou écrit plus que `LOCALE_HISTORY_MAX_OUTPUT_BYTES`, le résultat est `{ available: false, reason }`, avec une raison de `LOCALE_HISTORY_UNAVAILABLE_REASONS`. Consulte [Studio et MCP](/docs/data-handling#studio-et-mcp).

### editEntry

Écrit une correction saisie par un humain pour une clé et une locale. La valeur candidate passe la même barrière d'intégrité qu'une traduction de fournisseur avant que quoi que ce soit n'atteigne le disque ; à l'acceptation, le fichier de locale et l'entrée de verrou de cette clé sont mis à jour sous le verrou d'écriture de la locale. N'appelle jamais de fournisseur.

```ts title="Signature"
function editEntry(
  input: EditEntryInput,
  deps?: EditEntryDeps,
): Promise<EditEntryResult>;
```

<SdkTypeTable name="EditEntryInput" />

**Renvoie :** `EditEntryResult`

**Lève :** [`UNKNOWN_FORMAT`](/docs/error-codes#unknown_format), [`UNKNOWN_LOCALE`](/docs/error-codes#unknown_locale), [`LOCALE_LAYOUT_INVALID`](/docs/error-codes#locale_layout_invalid), [`LOCALE_PATH_COLLISION`](/docs/error-codes#locale_path_collision), [`SOURCE_UNREADABLE`](/docs/error-codes#source_unreadable), [`SOURCE_INVALID`](/docs/error-codes#source_invalid), [`UNKNOWN_KEY`](/docs/error-codes#unknown_key), [`KEY_PINNED`](/docs/error-codes#key_pinned), [`LOCK_CONTENDED`](/docs/error-codes#lock_contended), [`TARGET_UNWRITABLE`](/docs/error-codes#target_unwritable), [`LOCALE_STATE_NOT_CARRIED_OVER`](/docs/error-codes#locale_state_not_carried_over), [`LOCK_TIMEOUT_INVALID`](/docs/error-codes#lock_timeout_invalid), [`LOCK_FILE_INVALID`](/docs/error-codes#lock_file_invalid), [`PROVENANCE_FILE_INVALID`](/docs/error-codes#provenance_file_invalid)

Renvoie un résultat à deux branches : `{ accepted: true, value }`, ou `{ accepted: false, reason: "placeholder" | "markup" | "icu" | "degenerate" | "empty", value }` sans rien écrire. `"empty"` couvre une valeur vide ou uniquement composée d'espaces pour une source qui a du texte : une modification ne peut pas exprimer l'effacement d'une clé, alors utilise pour ça la sentinelle `[[CLEAR]]` du classeur. L'ensemble des raisons est livré sous forme du tuple `INTEGRITY_GATE_REASONS` : construis tout schéma d'exécution ou table exhaustive à partir de lui plutôt que de retaper les membres. Un refus `placeholder` ou `markup` porte en plus `details` : les placeholders ou balises en cause, chacun préfixé de `-` pour un élément que la source avait et que la valeur candidate a supprimé, ou de `+` pour un élément que la valeur candidate a inventé.

La valeur écrite est enregistrée dans `verbatra.provenance.json` avec l'origine `human`. Passe `actor: "agent"` quand un agent d'IA l'a écrite, pour que l'enregistrement le dise ; c'est la surface appelante qui l'affirme et rien ne le vérifie. Le fichier de provenance est vérifié avant que la valeur ne passe le contrôle : un fichier corrompu lève `PROVENANCE_FILE_INVALID` et rien n'est écrit, et celui d'un verbatra plus récent, ou celui que l'enregistrement ferait dépasser la taille que verbatra relit, est laissé intact pendant que la valeur est écrite sans enregistrement.

<AvailableFrom version="0.12.0" />

Avec `actor: "agent"`, une clé qui correspond aux `pinnedKeys` de la config lève `KEY_PINNED` avant toute lecture ou écriture. La modification d'une clé épinglée par une personne est acceptée.

<AvailableFrom version="0.12.0" />

`lockAcquireTimeoutMs` borne l'attente du verrou d'écriture de la locale avant que l'appel échoue avec `LOCK_CONTENDED` (dix minutes par défaut), `onLockWait` signale cette attente, et une borne invalide échoue avec `LOCK_TIMEOUT_INVALID` avant toute lecture.

### retranslateEntry

Relance le fournisseur pour exactement une clé et une locale : un appel à entrée unique via le même chemin de fournisseur que `translate`, passé par les mêmes contrôles d'intégrité. À l'acceptation, il écrit le fichier de locale et l'entrée de verrou pour cette clé seulement.

```ts title="Signature"
function retranslateEntry(
  input: RetranslateEntryInput,
  deps?: RetranslateEntryDeps,
): Promise<RetranslateEntryResult>;
```

<SdkTypeTable name="RetranslateEntryInput" />

**Renvoie :** `RetranslateEntryResult`

**Lève :** [`MACHINE_TRANSLATION_DISABLED`](/docs/error-codes#machine_translation_disabled), [`LOCK_TIMEOUT_INVALID`](/docs/error-codes#lock_timeout_invalid), [`UNKNOWN_FORMAT`](/docs/error-codes#unknown_format), [`UNKNOWN_LOCALE`](/docs/error-codes#unknown_locale), [`LOCALE_UNSUPPORTED_BY_PROVIDER`](/docs/error-codes#locale_unsupported_by_provider), [`LOCALE_LAYOUT_INVALID`](/docs/error-codes#locale_layout_invalid), [`LOCALE_PATH_COLLISION`](/docs/error-codes#locale_path_collision), [`SOURCE_UNREADABLE`](/docs/error-codes#source_unreadable), [`SOURCE_INVALID`](/docs/error-codes#source_invalid), [`UNKNOWN_KEY`](/docs/error-codes#unknown_key), [`KEY_PINNED`](/docs/error-codes#key_pinned), [`KEY_PROTECTED`](/docs/error-codes#key_protected), [`PROVIDER_CONSTRUCTION_FAILED`](/docs/error-codes#provider_construction_failed), [`NETWORK_POLICY_VIOLATION`](/docs/error-codes#network_policy_violation), [`CONFIG_INVALID`](/docs/error-codes#config_invalid), [`LOCK_CONTENDED`](/docs/error-codes#lock_contended), [`TARGET_UNWRITABLE`](/docs/error-codes#target_unwritable), [`LOCALE_STATE_NOT_CARRIED_OVER`](/docs/error-codes#locale_state_not_carried_over), [`LOCK_FILE_INVALID`](/docs/error-codes#lock_file_invalid), [`PROVENANCE_FILE_INVALID`](/docs/error-codes#provenance_file_invalid)

Renvoie `{ accepted: true, value, reviewReasons }` (les codes de raison de révision, s'il y en a, qui s'appliquent à la nouvelle valeur) ou `{ accepted: false, reason: "placeholder" | "markup" | "icu" | "degenerate" | "empty", value }`. Contrairement à `translate`, un échec de fournisseur lève ici : une `ProviderError`, exportée depuis `@verbatra/sdk`, avec un `code` stable comme `RATE_LIMITED` ou `AUTH_FAILED`. Sous `provider: { id: "none" }`, il lève d'abord `MACHINE_TRANSLATION_DISABLED`, avant de lire ou de verrouiller quoi que ce soit.

La nouvelle valeur est enregistrée dans `verbatra.provenance.json` comme `machine`, avec l'`id` du fournisseur qui a répondu et le modèle configuré. Un fournisseur issu de ton propre `createProvider` est enregistré sous son propre `id`, et sans le modèle quand cet `id` diffère de celui configuré. Un fichier de provenance corrompu lève `PROVENANCE_FILE_INVALID` avant l'appel au fournisseur.

<AvailableFrom version="0.12.0" />

Une clé dont la valeur actuelle a été écrite, importée ou modifiée hors de verbatra par une personne lève `KEY_PROTECTED` dans le verrou d'écriture, avant l'appel au fournisseur, sauf si tu passes `includeHuman: true` ou si la config fixe `humanEdits: "overwrite"`. Si le fichier de provenance vient d'un verbatra plus récent, toute valeur existante compte comme protégée. Une clé qui correspond à `pinnedKeys` lève `KEY_PINNED` avant la construction du fournisseur, même avec `includeHuman`.

### approveEntry

<AvailableFrom version="0.12.0" />

Enregistre qu'une personne a relu la valeur actuelle d'une clé dans une locale et l'accepte. N'écrit que `verbatra.provenance.json`, jamais un fichier de locale ni le fichier de verrouillage, et n'appelle aucun fournisseur. L'approbation enregistre aussi le hash source de la clé dans le fichier de verrouillage, si bien qu'elle redevient non relue dès que la source change ; toute écriture ultérieure qui change la valeur démarre un nouvel enregistrement non relu.

```ts title="Signature"
function approveEntry(
  input: ReviewDecisionInput,
  deps?: ReviewDecisionDeps,
): Promise<ReviewDecisionResult>;
```

<SdkTypeTable name="ReviewDecisionInput" />

**Renvoie :** `ReviewDecisionResult`

**Lève :** [`REVIEWER_INVALID`](/docs/error-codes#reviewer_invalid), [`LOCK_TIMEOUT_INVALID`](/docs/error-codes#lock_timeout_invalid), [`UNKNOWN_FORMAT`](/docs/error-codes#unknown_format), [`UNKNOWN_LOCALE`](/docs/error-codes#unknown_locale), [`LOCALE_LAYOUT_INVALID`](/docs/error-codes#locale_layout_invalid), [`LOCALE_PATH_COLLISION`](/docs/error-codes#locale_path_collision), [`SOURCE_UNREADABLE`](/docs/error-codes#source_unreadable), [`SOURCE_INVALID`](/docs/error-codes#source_invalid), [`UNKNOWN_KEY`](/docs/error-codes#unknown_key), [`LOCK_CONTENDED`](/docs/error-codes#lock_contended), [`REVIEW_VALUE_CHANGED`](/docs/error-codes#review_value_changed), [`LOCALE_STATE_NOT_CARRIED_OVER`](/docs/error-codes#locale_state_not_carried_over), [`REVIEW_SOURCE_CHANGED`](/docs/error-codes#review_source_changed), [`LOCK_FILE_INVALID`](/docs/error-codes#lock_file_invalid), [`PROVENANCE_FILE_INVALID`](/docs/error-codes#provenance_file_invalid), [`PROVENANCE_FILE_UNWRITABLE`](/docs/error-codes#provenance_file_unwritable)

`expectedValue` est le texte que la personne a vu : l'appel lève `REVIEW_VALUE_CHANGED` quand la clé n'a pas de valeur ou en a une autre, et `REVIEW_SOURCE_CHANGED` quand la source a changé depuis l'écriture de la valeur. `reviewer` est un texte libre facultatif d'au plus 64 caractères sans caractère de contrôle (sinon `REVIEWER_INVALID`), stocké dans le fichier commité et jamais rempli par verbatra. Renvoie `{ locale, key, provenance }`. Une valeur sans enregistrement préalable, ou modifiée hors de verbatra, est enregistrée avec l'origine `unknown`.

### rejectEntry

<AvailableFrom version="0.12.0" />

Enregistre qu'une personne a relu la valeur actuelle d'une clé dans une locale et la refuse, et supprime cette valeur pour qu'elle soit remplacée. La clé est retirée du fichier de locale et son entrée de verrou est supprimée : `check` et `diff` la signalent comme manquante et la prochaine exécution de `translate` la remplit à nouveau (avec `provider: { id: "none" }`, elle reste manquante jusqu'à ce que quelqu'un écrive une valeur). L'enregistrement de provenance est conservé comme `rejected` avec un hash du texte supprimé, et l'entrée correspondante de la mémoire de traduction de cette machine est retirée. Un `translate` ultérieur ignore tout succès exact ou approximatif de la mémoire pour la clé dont le texte correspond à ce hash, si bien que la mémoire d'une autre machine ne peut pas non plus ramener le texte. N'appelle aucun fournisseur.

```ts title="Signature"
function rejectEntry(
  input: ReviewDecisionInput,
  deps?: ReviewDecisionDeps,
): Promise<ReviewDecisionResult>;
```

<SdkTypeTable name="ReviewDecisionInput" />

**Renvoie :** `ReviewDecisionResult`

**Lève :** [`REVIEWER_INVALID`](/docs/error-codes#reviewer_invalid), [`LOCK_TIMEOUT_INVALID`](/docs/error-codes#lock_timeout_invalid), [`UNKNOWN_FORMAT`](/docs/error-codes#unknown_format), [`UNKNOWN_LOCALE`](/docs/error-codes#unknown_locale), [`LOCALE_LAYOUT_INVALID`](/docs/error-codes#locale_layout_invalid), [`LOCALE_PATH_COLLISION`](/docs/error-codes#locale_path_collision), [`SOURCE_UNREADABLE`](/docs/error-codes#source_unreadable), [`SOURCE_INVALID`](/docs/error-codes#source_invalid), [`UNKNOWN_KEY`](/docs/error-codes#unknown_key), [`LOCK_CONTENDED`](/docs/error-codes#lock_contended), [`REVIEW_VALUE_CHANGED`](/docs/error-codes#review_value_changed), [`LOCALE_STATE_NOT_CARRIED_OVER`](/docs/error-codes#locale_state_not_carried_over), [`TARGET_UNWRITABLE`](/docs/error-codes#target_unwritable), [`REVIEW_REJECT_UNSUPPORTED`](/docs/error-codes#review_reject_unsupported), [`REVIEW_RESTORE_FAILED`](/docs/error-codes#review_restore_failed), [`LOCK_FILE_INVALID`](/docs/error-codes#lock_file_invalid), [`PROVENANCE_FILE_INVALID`](/docs/error-codes#provenance_file_invalid), [`PROVENANCE_FILE_UNWRITABLE`](/docs/error-codes#provenance_file_unwritable)

L'entrée est vérifiée comme pour `approveEntry`, sauf qu'une source périmée n'empêche pas un rejet. Renvoie `{ locale, key, provenance }`. Un format qui garde une clé qu'on ne lui a pas transmise, XLIFF, lève `REVIEW_REJECT_UNSUPPORTED` après avoir restauré le fichier.

Les deux appels prennent le verrou d'écriture de la locale. `lockAcquireTimeoutMs` borne l'attente de ce verrou (dix minutes par défaut) et échoue avec `LOCK_CONTENDED` une fois écoulée, et `onLockWait` signale cette attente ; une valeur qui n'est pas un nombre entier de millisecondes d'au moins 0 lève `LOCK_TIMEOUT_INVALID` avant toute lecture. Ce délai ne borne pas le verrou du fichier de verrouillage pris pour enregistrer la décision, qui accorde toujours les dix minutes par défaut.

Les deux appels vérifient le fichier de provenance avant d'écrire quoi que ce soit et ne signalent jamais une décision qu'ils n'ont pas pu enregistrer : un fichier écrit par un verbatra plus récent, ou un fichier que la décision ferait grossir au-delà de la taille que verbatra relit, lève `PROVENANCE_FILE_UNWRITABLE`.

## Révision et retraduction par lots

<AvailableFrom version="0.12.0" />

Chacun de ces appels exécute l'appel à clé unique correspondant une fois par entrée, dans l'ordre
donné, et renvoie `{ results }` avec un résultat par entrée dans cet ordre. Une entrée qui échoue
n'arrête pas le lot : son résultat est `{ locale, key, ok: false, code, message }`, avec le code du
`SdkError`, de l'erreur d'adaptateur ou du `ProviderError` qui l'a arrêtée et un message expurgé, et
l'entrée suivante s'exécute. Toute autre erreur arrête le lot avec une `BatchInterruptedError` qui
porte les résultats des entrées déjà exécutées, dont les écritures sont déjà sur le disque. Une
liste `entries` vide renvoie des `results` vides.

### approveEntries

Exécute `approveEntry` pour chaque entrée avec les mêmes vérifications ; `reviewer` s'applique à
chaque entrée. Un résultat réussi est `{ ok: true, locale, key, provenance }`.
`lockAcquireTimeoutMs` borne l'attente de chaque entrée pour le verrou d'écriture de sa locale, et
`onLockWait` signale cette attente. Une entrée dont le verrou reste pris au-delà du délai échoue
avec `LOCK_CONTENDED`, et chaque entrée suivante qui a besoin du même verrou reçoit
`{ locale, key, ok: false, skipped: true, code: "LOCK_CONTENDED", message }` au lieu d'attendre à
nouveau ; les entrées des autres locales sont toujours décidées. Les appels à une seule entrée
`approveEntry` et `rejectEntry` acceptent les deux mêmes options.

```ts title="Signature"
function approveEntries(
  input: ReviewEntriesInput,
  deps?: ReviewDecisionDeps,
): Promise<ReviewEntriesResult>;
```

<SdkTypeTable name="ReviewEntriesInput" />

**Renvoie :** `ReviewEntriesResult`

**Lève :** [`LOCK_TIMEOUT_INVALID`](/docs/error-codes#lock_timeout_invalid)

### rejectEntries

Exécute `rejectEntry` pour chaque entrée et retire
chaque valeur rejetée. Un résultat réussi est `{ ok: true, locale, key, provenance }`. Un délai de
verrou dépassé fait ignorer les entrées suivantes qui ont besoin de ce verrou, comme pour
`approveEntries`.

```ts title="Signature"

  input: ReviewEntriesInput,
  deps?: ReviewDecisionDeps,

```

**Renvoie :** `ReviewEntriesResult`

**Lève :** [`LOCK_TIMEOUT_INVALID`](/docs/error-codes#lock_timeout_invalid)

### approveLocale

<AvailableFrom version="0.12.0" />

Approuve toute la file de révision d'une locale, ou seulement ses valeurs ayant l'une des `origins`,
en une seule écriture de `verbatra.provenance.json`, sous le verrou d'écriture de la locale. Chaque
approbation est enregistrée comme `approveEntry` en enregistre une, avec le hash de source contre
lequel elle a été donnée. Elle ne prend aucune valeur attendue : elle approuve ce que la file
contient au moment de l'appel, donc montre d'abord la file à la personne qui relit. Renvoie
`{ locale, approved, sourceChanged }` : les clés approuvées, et les clés de la file laissées non
relues parce que leur source a changé depuis leur écriture. Elle n'écrit que le fichier de
provenance, n'appelle aucun fournisseur et échoue avec `PROVENANCE_FILE_UNWRITABLE` plutôt que de
signaler des approbations qu'elle n'a pas pu enregistrer.

```ts title="Signature"
function approveLocale(

): Promise<ApproveLocaleResult>;
```

### retranslateEntries

Exécute `retranslateEntry` pour chaque entrée, et fait donc jusqu'à un appel au fournisseur par
entrée. Ce n'est pas une exécution de `translate` : `maxTokens` et `budgetBehavior` ne s'appliquent
pas, et le nombre d'entrées est la seule limite de ce qu'il dépense. Un résultat terminé est
`{ ok: true, locale, key, result }`, où `result` est ce que `retranslateEntry` a renvoyé, y compris
une valeur refusée par la barrière d'intégrité. Une valeur écrite par une personne échoue avec
`KEY_PROTECTED`, sauf si tu passes `includeHuman: true`. `lockAcquireTimeoutMs` borne l'attente de
chaque entrée pour le verrou d'écriture de sa locale, avant l'appel au fournisseur, et
`onLockWait` signale cette attente.

```ts title="Signature"
function retranslateEntries(
  input: RetranslateEntriesInput,
  deps?: RetranslateEntryDeps,
): Promise<RetranslateEntriesResult>;
```

<SdkTypeTable name="RetranslateEntriesInput" />

**Renvoie :** `RetranslateEntriesResult`

**Lève :** [`LOCK_TIMEOUT_INVALID`](/docs/error-codes#lock_timeout_invalid)

<AvailableFrom version="0.12.0" />

Une erreur qui ferait échouer toutes les entrées de la même façon arrête les appels au
fournisseur : `MISSING_API_KEY`, `AUTH_FAILED`, `RATE_LIMITED` (ce qui couvre un quota épuisé),
`NETWORK_POLICY_VIOLATION`, `PROVIDER_CONSTRUCTION_FAILED`, `CONFIG_INVALID` ou
`MACHINE_TRANSLATION_DISABLED`. L'entrée qui l'a rencontrée échoue comme d'habitude, et chaque
entrée suivante reçoit `{ locale, key, ok: false, skipped: true, code, message }` avec ce code,
sans autre appel au fournisseur.

Une entrée dont le verrou d'écriture de la locale reste pris au-delà de `lockAcquireTimeoutMs`
échoue avec `LOCK_CONTENDED`, et chaque entrée suivante qui a besoin du même verrou est ignorée de
la même façon avec ce code au lieu d'attendre à nouveau : les entrées de cette locale, ou de toutes
les locales pour un format qui garde toutes les locales dans un seul fichier. Les entrées des
autres locales continuent.

### BatchInterruptedError

<AvailableFrom version="0.12.0" />

Levée par `approveEntries`, `rejectEntries` et `retranslateEntries` quand une erreur qui n'est pas
le résultat d'une seule entrée, comme une défaillance inattendue du système de fichiers, arrête un
lot en cours de route. `results` contient les résultats des entrées terminées avant, dans l'ordre,
`entry` nomme le `{ locale, key }` en cours, et `cause` est l'erreur d'origine. Les entrées après
`entry` ne se sont pas exécutées.

```ts title="Signature"
class BatchInterruptedError<R = ReviewBatchOutcome | RetranslateBatchOutcome> extends Error
```

<SdkTypeTable name="BatchInterruptedError" />
