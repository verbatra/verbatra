## Anatomie du RunSummary

`translate`, `importWorkbook` et chaque exécution `watch` réussie se résolvent en un `RunSummary` :

```ts
interface RunSummary {
  dryRun: boolean;          // true when nothing was written and no provider was called
  locales: LocaleSummary[]; // one entry per target locale, in config order
  succeeded: string[];      // locales whose run succeeded
  partial: string[];        // locales written with keys still missing; the CLI exits 1 on these
  failed: string[];         // locales whose run failed
  usage?: UsageSummary;     // summed input/output tokens; absent when no call reported usage
  budget?: RunBudget;       // present only when maxTokens is configured
  estimate?: RunEstimate;   // present only when the run was asked for a pre-run estimate
}

interface LocaleSummary {
  locale: string;
  status: "succeeded" | "partial" | "failed";
  translated: string[];          // keys translated this run (in dry-run, keys that would be)
  cacheHits: string[];           // keys served from the translation-memory cache this run
  fuzzyHits: FuzzyCacheHit[];    // reuses for a source string that changed, with their scores
  unchanged: string[];           // keys already up to date
  orphaned: string[];            // target keys with no matching source key (always reported)
  pruned: string[];              // orphaned keys removed this run; empty unless pruning is on
  invalidIcuSource: string[];    // source keys skipped for invalid ICU
  integrityMismatches: string[]; // translations the integrity gate withheld
  integrityRefusals?: { key: string; reason: string; details?: string[] }[]; // why each was withheld; translate, watch, and importWorkbook
  providerFailures: string[];    // keys withheld because nothing was translated for them
  budgetWithheld: string[];      // keys never sent because a "stop" budget already tripped
  sensitiveWithheld: string[];   // keys sensitiveData kept from the provider (block or redact)
  generated: string[];           // CLDR plural forms synthesized this run
  unfilled: string[];            // blank import rows, or keys a human-only translate left for a human
  protected: { key: string; reason: string; suggestion?: string; suggestionStatus?: string }[]; // keys left for a person
  malformedRows: { row: number; line?: number; column: string }[]; // import only: rows the reader could not parse
  duplicateKeys: { key: string; row: number; line?: number }[];    // import only: later rows for a duplicated key
  notices: LocaleNotice[];       // provider notices and SDK notices for this locale
  needsReview: { key: string; reasons: string[] }[]; // accepted keys flagged for a second look
  usage?: UsageSummary;          // this locale's summed tokens; absent if nothing reported usage
  error?: { code: string; message: string }; // only on a "failed" locale, and not on every one
}
```

Les parties à connaître :

- **needsReview** liste les clés acceptées et écrites que les heuristiques de révision ont signalées, chacune avec ses codes de raison, listés et expliqués sous [Signalements de révision](/docs/translation-safety#signalements-de-révision). L'ensemble est livré sous forme du tuple `REVIEW_REASON_CODES` : construis tout schéma d'exécution ou table exhaustive à partir de lui plutôt que de retaper les membres. Un signalement de révision est consultatif et ne retient jamais une clé, donc une clé n'apparaît jamais à la fois dans `needsReview` et `integrityMismatches`. Voir [Réviser les traductions dans Studio](/docs/review-in-studio) pour traiter la file.
- **notices** vivent par locale, jamais au premier niveau. On y trouve les avis de fournisseur (par exemple une dégradation DeepL) et les avis du SDK avec les codes `PLURAL_CATEGORIES_INCOMPLETE`, `SUB_BATCH_FAILED`, `BLANK_ROW_BASELINE_RETAINED`, `HANDOFF_REVIEWS_RECORDED` (depuis 0.12.0 : des clés qu'une remise XLIFF a marquées relues ou finales ont été enregistrées comme approuvées), `BUDGET_TOKENS_EXCEEDED`, `CACHE_VERSION_UNRECOGNIZED`, `PROVENANCE_VERSION_UNRECOGNIZED`, `LOCALE_STATE_CARRIED_OVER` (l'état rangé sous une graphie avec tiret bas comme `pt_BR` a été déplacé vers le `pt-BR` configuré ; voir [Un code de locale réécrit](/docs/the-lock-file#un-code-de-locale-réécrit)), `LOCALE_STATE_CARRY_OVER_SKIPPED` (ce déplacement est laissé à l'exécution suivante parce que le verrou de garde du fichier de verrou est resté occupé ou n'a pu être ni lu ni créé, ou qu'un fichier n'a pas pu être écrit ; sauf si seule la mémoire de traduction est restée derrière, la locale ne s'est pas exécutée et a échoué avec `LOCALE_STATE_NOT_CARRIED_OVER`), `PROVENANCE_FILE_TOO_LARGE` (enregistrer une locale aurait fait dépasser à `verbatra.provenance.json` la taille que verbatra relit, le fichier a donc été laissé tel quel) et, depuis 0.12.0, les quatre avertissements de la vérification de prise en charge des locales, levés avant toute dépense et aussi lors d'une exécution à blanc : `LOCALE_UNVERIFIED_BY_PROVIDER` (le code envoyé ne figure pas dans la table du fournisseur, seule sa langue de base y figure ou il vient de `localeMap`), `LOCALE_NOT_WELL_TESTED` (une cible LLM hors de la liste des langues bien testées), `GLOSSARY_UNSUPPORTED_BY_PROVIDER` et `FORMALITY_UNSUPPORTED_BY_PROVIDER` (un glossaire ou un ton que le fournisseur ne peut pas appliquer pour la locale). L'avis de cache concerne toute l'exécution (un seul fichier, partagé par chaque locale), il est donc attaché à chaque locale de l'exécution.
- **usage** est `undefined`, jamais un zéro fabriqué, dès que rien dans ce périmètre n'a rapporté d'usage : un dry run n'appelle jamais de fournisseur, et DeepL ne rapporte jamais de tokens. `RunSummary.usage` est la somme sur les locales.
- **budget** n'apparaît que quand `maxTokens` est configuré : `{ maxTokens, behavior, supported, tokensUsed, exceeded }`. `supported` indique si `tokensUsed` est entièrement l'usage rapporté par le fournisseur lui-même ; il vaut `false` dès qu'une requête revient sans chiffre exploitable, et le total est alors en partie la projection de verbatra, comptée et appliquée de la même façon. Un dry run, ou toute exécution qui n'a envoyé aucune requête, rapporte `supported: true` avec `tokensUsed: 0` : rien n'a été envoyé, donc rien n'a été projeté. Sous `behavior: "stop"`, le plafond est vérifié avant chaque requête que l'exécution envoie, y compris chaque moitié d'une requête redécoupée, donc `tokensUsed` finit au plafond ou en dessous, à un résidu près : la dernière requête admise est réconciliée avec ce que le fournisseur a rapporté, ce qui peut pousser le total au-dessus du plafond après coup. Plus rien n'est envoyé ensuite. Deux choses échappent à ce qu'une réservation peut borner, car elles se produisent à l'intérieur d'une requête déjà admise : la couche fournisseur envoie une requête de réparation qui lui est propre quand des clés manquent, donc un lot admis peut coûter jusqu'à près du double de sa projection, et le compte ne vaut que ce que rapporte le fournisseur. Les deux arrivent à la réconciliation, et plus rien n'est admis ensuite. Le budget borne un appel à `translate` : `watch` en démarre un neuf par exécution, et `retranslateEntry` n'est pas couvert du tout.
- **error.code** sur une locale échouée est une chaîne préservée (le code du fournisseur ou de l'adaptateur sous-jacent, avec `LOCALE_FAILED` seulement en dernier recours), donc ne le traite pas comme un ensemble fermé. Une locale `failed` ne porte pas toujours `error` : une locale dont toutes les clés ont été retenues, et figurent donc dans `integrityMismatches`, `providerFailures` ou `budgetWithheld`, échoue sans que rien ne soit levé. La raison se trouve dans ces listes et dans ses `notices`, comme `SUB_BATCH_FAILED` pour un lot du fournisseur en échec ou `BUDGET_TOKENS_EXCEEDED` pour le budget de tokens. Teste `status`, jamais la présence de `error`.
- **estimate** n'apparaît que lorsque l'exécution a demandé une estimation préalable. Sa liste
  `caveats` n'est jamais vide et nomme ce que le chiffre laisse de côté, sous forme de membres de
  `EstimateCaveatCode` :
  - `CACHE_NOT_CONSULTED` : la mémoire de traduction n'est pas lue, donc les clés qu'une exécution
    réelle servirait depuis le cache sont quand même comptées. S'applique à chaque estimation.
  - `SOURCE_DUPLICATES_NOT_DEDUPLICATED` : une exécution réelle envoie un seul représentant par chaîne
    source identique ; l'estimation compte chaque clé. S'applique à chaque estimation.
  - `TRANSPORT_RETRIES_NOT_COUNTED` : un seul appel facturable est compté par requête prévue, alors que
    les SDK des fournisseurs peuvent réessayer en dessous un appel échoué et qu'une tentative réessayée
    peut quand même être facturée. S'applique à chaque estimation.
  - `TRANSLATION_LENGTH_IS_ESTIMATED` : la réponse est dimensionnée à partir de la source plus une marge
    d'expansion fixe, donc une langue cible plus longue rapporte davantage de tokens de complétion.
    Fournisseurs facturés au token uniquement.
  - `TOKEN_COUNT_IS_HEURISTIC` : les tokens sont déduits du nombre de caractères, pas du tokenizer du
    fournisseur lui-même. Fournisseurs facturés au token uniquement.
  - `REPAIR_REQUESTS_NOT_COUNTED` : le tour de réparation pour les clés revenues manquantes, et la
    nouvelle tentative en deux moitiés pour une réponse tronquée, ne sont pas comptés. Fournisseurs
    facturés au token uniquement.
- **cacheHits** liste les clés servies depuis le [cache de mémoire de traduction](/docs/the-cache) plutôt que par le fournisseur. **fuzzyHits** liste les clés qui ont réutilisé une traduction pour une chaîne source qui avait changé, chacune portant `key`, `similarity` et le `previousSource` correspondant ; elle est vide tant que `fuzzyCache` n'est pas activé, et ces clés ne sont jamais comptées dans **cacheHits**. **unfilled**, **malformedRows** et **duplicateKeys** ne sont remplis que par `importWorkbook` (une exécution `translate` les laisse vides) : une ligne vide dont la clé demande toujours une traduction au moment de l'import (qu'elle ait été exportée comme `new` ou comme `changed`), une ligne du classeur que le lecteur n'a pas pu analyser, et une clé en double dont la première occurrence a gagné. Le `line` optionnel des deux derniers est la ligne du fichier où commence l'enregistrement, présent uniquement pour un import délimité (`csv` ou `tsv`). La seule exception est un projet [100 % humain](/docs/human-only-workflow) : là, `translate` et `watch` listent dans **unfilled** chaque clé pour laquelle la mémoire de traduction n'avait pas d'entrée exacte, et **fuzzyHits** reste vide car aucune réutilisation approximative n'y est jamais appliquée.
- **protected** liste les clés qu'une exécution de `translate` a laissées tranquilles, chacune avec sa `reason` (`human`, `import`, `external` ou `pinned`) et, avec `humanEdits: "suggest"`, une `suggestion` (la réponse du fournisseur ou une entrée exacte de la mémoire de traduction, jamais une correspondance approximative), qui n'a pas été écrite, et un `suggestionStatus` : `planned` lors d'un dry run, `suggested` ou pourquoi pas (`integrity-mismatch`, `provider-failure`, `budget-withheld`). Une suggestion en échec ne change jamais le statut d'une locale. Elles ne sont pas dans **translated**, ne changent jamais le statut d'une locale et restent obsolètes pour `check`. `importWorkbook` le laisse vide. Voir [Protéger les traductions humaines](/docs/protecting-human-translations).

### budgetStanding

<AvailableFrom version="0.11.0" />

Classe un `RunBudget` dans l'une des trois valeurs `BudgetStanding`, la même classification que rapportent la ligne de budget de la CLI, Studio et l'outil d'agent `usage.summary` : `"within"` quand l'exécution n'a jamais atteint son plafond, `"stopped-before-ceiling"` quand un budget `"stop"` a retenu une requête alors que `tokensUsed` restait sous `maxTokens`, et `"reached"` quand `tokensUsed` a atteint ou dépassé `maxTokens`. Utilise-le plutôt que de lire seulement `exceeded`, qui vaut `true` dans les deux derniers cas.

```ts title="Signature"
function budgetStanding(budget: RunBudget): BudgetStanding;
```

**Renvoie :** `BudgetStanding`
