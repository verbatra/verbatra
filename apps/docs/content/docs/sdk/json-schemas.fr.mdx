Chaque `result` que la CLI affiche avec `--json` a un schéma zod dans le SDK, lié à la compilation au type TypeScript qu'il décrit, si bien que les deux ne peuvent pas diverger. Chaque schéma analyse aussi une valeur venant d'un verbatra plus récent : il accepte les champs qu'il ne liste pas et les ignore. Les mêmes schémas sont publiés comme documents JSON Schema ; leurs URL et la règle de versions se trouvent sur [Codes de sortie et sortie JSON](/docs/cli/output#schémas).

## Schémas de résultat

Décrit un [`RunSummary`](/docs/sdk/run-summary), le `result` de `translate`, `watch` et `import`. Publié sous `run-summary.json`.

## Publication

`SDK_JSON_SCHEMAS` liste chaque document que le SDK publie sous `@verbatra/sdk/schemas/`, chacun avec son `name`, son `title`, son `io` et son `schema` zod. `JSON_SCHEMA_BASE_URL` vaut `https://verbatra.kreitz-webdev.de/schema/v1/`.

### renderJsonSchemas

Génère des documents JSON Schema (draft 2020-12) à partir d'une liste de `JsonSchemaDocument`, indexés par nom. Un document de sortie accepte toute propriété qu'il ne liste pas ; un document d'entrée, comme la configuration, garde ses objets fermés. Un schéma qui intègre un document de l'une des deux listes y renvoie par URL.

```ts title="Signature"
function renderJsonSchemas(
  documents: readonly JsonSchemaDocument[],
  references?: readonly JsonSchemaDocument[],
): Readonly<Record<string, JsonSchemaObject>>;
```

**Renvoie :** un document par entrée de `documents`, chacun avec `$schema`, `$id` et `title`.

### jsonSchemaUrl

Renvoie l'URL publique d'un document publié, qui est aussi son `$id` : `jsonSchemaUrl("run-summary")` vaut `https://verbatra.kreitz-webdev.de/schema/v1/run-summary.json`.

```ts title="Signature"
function jsonSchemaUrl(name: string): string;
```

**Renvoie :** `string`
