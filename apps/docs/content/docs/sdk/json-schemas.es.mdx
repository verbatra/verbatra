Cada `result` que la CLI imprime con `--json` tiene un esquema zod en el SDK, fijado en tiempo de compilación al tipo de TypeScript que describe, así que los dos no pueden divergir. Cada esquema también analiza un valor de un verbatra más nuevo: acepta los campos que no enumera y los descarta. Los mismos esquemas se publican como documentos JSON Schema; sus URL y la regla de versiones están en [Códigos de salida y salida JSON](/docs/cli/output#esquemas).

## Esquemas de resultado

Describe un [`RunSummary`](/docs/sdk/run-summary), el `result` de `translate`, `watch` e `import`. Se publica como `run-summary.json`.


## Publicación

`SDK_JSON_SCHEMAS` enumera cada documento que el SDK publica en `@verbatra/sdk/schemas/`, cada uno con su `name`, `title`, `io` y su `schema` de zod. `JSON_SCHEMA_BASE_URL` es `https://verbatra.kreitz-webdev.de/schema/v1/`.

### renderJsonSchemas

Genera documentos JSON Schema (draft 2020-12) a partir de una lista de `JsonSchemaDocument`, indexados por nombre. Un documento de salida admite cualquier propiedad que no enumera; un documento de entrada, como la configuración, conserva sus objetos cerrados. Un esquema que incluye un documento de cualquiera de las dos listas lo referencia por URL.

```ts title="Firma"
function renderJsonSchemas(
  documents: readonly JsonSchemaDocument[],
  references?: readonly JsonSchemaDocument[],
): Readonly<Record<string, JsonSchemaObject>>;
```

**Devuelve:** un documento por cada entrada de `documents`, cada uno con `$schema`, `$id` y `title`.

### jsonSchemaUrl

Devuelve la URL pública de un documento publicado, que también es su `$id`: `jsonSchemaUrl("run-summary")` es `https://verbatra.kreitz-webdev.de/schema/v1/run-summary.json`.

```ts title="Firma"
function jsonSchemaUrl(name: string): string;
```

**Devuelve:** `string`
