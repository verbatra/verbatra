Jedes `result`, das die CLI unter `--json` ausgibt, hat ein zod-4-Schema im SDK, das zur Compile-Zeit an den TypeScript-Typ gebunden ist, den es beschreibt: dieselben Felder, dieselben optionalen Felder und dieselben Werttypen. Eine Änderung an einem ohne das andere lässt den Build scheitern. Sein `parse` akzeptiert auch einen Wert aus einem neueren verbatra: Es erlaubt Felder, die es nicht aufführt, und entfernt sie aus dem Ergebnis. Dieselben Schemas werden als JSON-Schema-Dokumente veröffentlicht; ihre URLs und die Versionsregel stehen unter [Exit-Codes und JSON-Ausgabe](/docs/cli/output#schemas).

## Ergebnis-Schemas

Beschreibt eine [`RunSummary`](/docs/sdk/run-summary), das `result` von `translate`, `watch` und `import`. Veröffentlicht als `run-summary.json`.

```ts title="Signatur"

```

## Veröffentlichen

`SDK_JSON_SCHEMAS` listet jedes Dokument auf, das das SDK unter `@verbatra/sdk/schemas/` veröffentlicht, jeweils mit `name`, `title`, `io` und dem zod-`schema`. `JSON_SCHEMA_BASE_URL` ist `https://verbatra.kreitz-webdev.de/schema/v1/`. `KNOWN_ERROR_CODES` listet jeden Fehlercode des SDK, der Provider und der Adapter; das Schema des Fehler-Envelopes bietet sie als Hinweis an und akzeptiert trotzdem jeden Code.

### renderJsonSchemas

Erzeugt verbatras eigene JSON-Schema-Dokumente (Draft 2020-12) aus einer Liste von `JsonSchemaDocument`s, nach Namen geordnet. Jedes erhält die `$id`, die `jsonSchemaUrl` für seinen Namen liefert, eine URL dieser Seite. Nutze es also nur für verbatras Dokumente und `renderOutputJsonSchema` für ein eigenes Schema. Ein Ausgabedokument erlaubt jede Eigenschaft, die es nicht aufführt; ein Eingabedokument wie die Konfiguration behält seine geschlossenen Objekte. Ein Schema, das ein Dokument aus einer der beiden Listen einbettet, verweist per URL darauf.

```ts title="Signatur"
function renderJsonSchemas(
  documents: readonly JsonSchemaDocument[],
  references?: readonly JsonSchemaDocument[],
): Readonly<Record<string, JsonSchemaObject>>;
```

**Rückgabe:** ein Dokument pro Eintrag in `documents`, jeweils mit `$schema`, `$id` und `title`.

### renderOutputJsonSchema

Erzeugt das JSON Schema eines einzelnen zod-Schemas so, wie die Ausgabedokumente erzeugt werden, ohne `$id`, etwa für das `outputSchema` eines MCP-Tools.

```ts title="Signatur"
function renderOutputJsonSchema(schema: z.ZodType): JsonSchemaObject;
```

**Rückgabe:** `JsonSchemaObject`

### jsonSchemaUrl

Gibt die öffentliche URL eines veröffentlichten Dokuments zurück, die zugleich seine `$id` ist: `jsonSchemaUrl("run-summary")` ergibt `https://verbatra.kreitz-webdev.de/schema/v1/run-summary.json`.

```ts title="Signatur"
function jsonSchemaUrl(name: string): string;
```

**Rückgabe:** `string`
