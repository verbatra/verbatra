CLI 在 `--json` 下输出的每个 `result`，在 SDK 中都有一个 zod 4 schema，并在编译期与它所描述的 TypeScript 类型绑定：字段相同，可选字段相同，值类型相同，所以只改其中一个而不改另一个，构建就会失败。它的 `parse` 也接受来自更新版 verbatra 的值：它允许未列出的字段，并把这些字段从结果中去掉。同样的 schema 也以 JSON Schema 文档的形式发布；它们的 URL 和版本规则见[退出码与 JSON 输出](/zh-CN/docs/cli/output#schema)。

## 发布

`SDK_JSON_SCHEMAS` 列出 SDK 在 `@verbatra/sdk/schemas/` 下发布的每个文档，每个都带有它的 `name`、`title`、`io` 和 zod `schema`。`JSON_SCHEMA_BASE_URL` 是 `https://verbatra.kreitz-webdev.de/schema/v1/`。`KNOWN_ERROR_CODES` 列出每个 SDK、提供商和适配器错误码；错误信封（envelope）schema 把它们作为提示提供，同时接受任何错误码。

### renderJsonSchemas

根据一组 `JsonSchemaDocument` 生成 verbatra 自己的 JSON Schema 文档（draft 2020-12），按名称作键。每个文档获得由 `jsonSchemaUrl` 按其名称给出的 `$id`，即本站上的一个 URL，所以它只用于 verbatra 自己的文档，你自己的 schema 请用 `renderOutputJsonSchema`。输出文档允许它未列出的每个属性；输入文档（如配置）保持封闭对象。嵌入了任一列表中某个文档的 schema，会按 URL 引用它。

```ts title="签名"
function renderJsonSchemas(
  documents: readonly JsonSchemaDocument[],
  references?: readonly JsonSchemaDocument[],
): Readonly<Record<string, JsonSchemaObject>>;
```

**返回**：`documents` 的每个条目对应一个文档，每个都带有 `$schema`、`$id` 和 `title`。

### renderOutputJsonSchema

按生成输出文档的方式，为单个 zod schema 生成 JSON Schema，不带 `$id`，例如用于 MCP 工具的 `outputSchema`。

```ts title="签名"
function renderOutputJsonSchema(schema: z.ZodType): JsonSchemaObject;
```

**返回**：`JsonSchemaObject`

### jsonSchemaUrl

返回已发布文档的公开 URL，它同时也是该文档的 `$id`：`jsonSchemaUrl("run-summary")` 是 `https://verbatra.kreitz-webdev.de/schema/v1/run-summary.json`。

```ts title="签名"
function jsonSchemaUrl(name: string): string;
```

**返回**：`string`
