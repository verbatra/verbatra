CLI が `--json` で出力するすべての `result` には、SDK に zod 4 のスキーマがあり、コンパイル時に、それが表す TypeScript の型と一致するよう固定されています。フィールド、省略可能なフィールド、値の型が同じなので、片方だけを変更するとビルドが失敗します。その `parse` は、より新しい verbatra の値も受け付けます。列挙されていないフィールドを許可し、結果からは取り除きます。同じスキーマが JSON Schema のドキュメントとして公開されています。その URL とバージョニングの規則は、[終了コードと JSON 出力](/ja/docs/cli/output#スキーマ)にあります。

## 結果のスキーマ

`translate`、`watch`、`import` の `result` である [`RunSummary`](/ja/docs/sdk/run-summary) を表します。`run-summary.json` として公開されます。

```ts title="シグネチャ"
const runSummarySchema: z.ZodObject<{ ... }, z.core.$strip>;
```

## 公開

`SDK_JSON_SCHEMAS` は、`@verbatra/sdk/schemas/` の下で SDK が公開するすべてのドキュメントを、それぞれの `name`、`title`、`io`、zod の `schema` とともに一覧にしたものです。`JSON_SCHEMA_BASE_URL` は `https://verbatra.kreitz-webdev.de/schema/v1/` です。`KNOWN_ERROR_CODES` は、SDK、プロバイダー、アダプターのすべてのエラーコードを一覧にしたものです。エラーエンベロープのスキーマは、これらをヒントとして示しつつ、どのコードも受け付けます。

### renderJsonSchemas

`JsonSchemaDocument` のリストから、verbatra 自身の JSON Schema ドキュメント（draft 2020-12）を、名前をキーにして生成します。各ドキュメントには、`jsonSchemaUrl` がその名前に対して返す `$id`（このサイトの URL）が付きます。そのため、これは verbatra のドキュメント専用に使い、自分のスキーマには `renderOutputJsonSchema` を使ってください。出力ドキュメントは、列挙されていないプロパティをすべて許可します。設定のような入力ドキュメントは、閉じたオブジェクトのままです。どちらかのリストのドキュメントを埋め込むスキーマは、そのドキュメントを URL で参照します。

```ts title="シグネチャ"
function renderJsonSchemas(
  documents: readonly JsonSchemaDocument[],
  references?: readonly JsonSchemaDocument[],
): Readonly<Record<string, JsonSchemaObject>>;
```

**戻り値**：`documents` の各エントリに対応する 1 つのドキュメントで、それぞれ `$schema`、`$id`、`title` を持ちます。

### renderOutputJsonSchema

1 つの zod スキーマの JSON Schema を、出力ドキュメントと同じ方法で、`$id` なしで生成します。たとえば MCP ツールの `outputSchema` に使えます。

```ts title="シグネチャ"
function renderOutputJsonSchema(schema: z.ZodType): JsonSchemaObject;
```

**戻り値**：`JsonSchemaObject`

### jsonSchemaUrl

公開されているドキュメントの公開 URL を返します。これは `$id` でもあります。`jsonSchemaUrl("run-summary")` は `https://verbatra.kreitz-webdev.de/schema/v1/run-summary.json` です。

```ts title="シグネチャ"
function jsonSchemaUrl(name: string): string;
```

**戻り値**：`string`
