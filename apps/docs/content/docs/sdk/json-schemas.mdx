Every `result` the CLI prints under `--json` has a zod schema in the SDK, pinned at compile time to the TypeScript type it describes, so the two cannot drift apart. Each one parses a value from a newer verbatra too: it accepts fields it does not list and drops them. The same schemas are published as JSON Schema documents; their URLs and the versioning rule are on [Exit codes and JSON output](/docs/cli/output#schemas).

## Publishing

`SDK_JSON_SCHEMAS` lists every document the SDK publishes under `@verbatra/sdk/schemas/`, each with its `name`, `title`, `io` and zod `schema`. `JSON_SCHEMA_BASE_URL` is `https://verbatra.kreitz-webdev.de/schema/v1/`.

### renderJsonSchemas

Generates JSON Schema documents (draft 2020-12) from a list of `JsonSchemaDocument`s, keyed by name. An output document allows every property it does not list; an input document, such as the config, keeps its closed objects. A schema that embeds a document from either list refers to it by URL.

```ts title="Signature"
function renderJsonSchemas(
  documents: readonly JsonSchemaDocument[],
  references?: readonly JsonSchemaDocument[],
): Readonly<Record<string, JsonSchemaObject>>;
```

**Returns:** one document per entry of `documents`, each with `$schema`, `$id` and `title`.

### jsonSchemaUrl

Returns the public URL of a published document, which is also its `$id`: `jsonSchemaUrl("run-summary")` is `https://verbatra.kreitz-webdev.de/schema/v1/run-summary.json`.

```ts title="Signature"
function jsonSchemaUrl(name: string): string;
```

**Returns:** `string`
