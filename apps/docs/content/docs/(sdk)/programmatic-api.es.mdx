La [referencia del SDK](/docs/sdk) cataloga cada punto de entrada. Esta página es la compañera práctica:
recetas de principio a fin que puedes copiar en un script y ejecutar. Una cosa que preparar primero: el
SDK no carga archivos `.env` (eso lo hace la CLI), así que asegúrate de que la variable de entorno del
proveedor está definida antes de que se ejecute tu script, por ejemplo:

```bash
node --env-file=.env translate.mjs
```

## Traducción única en un script

Carga la configuración, ejecuta el flujo y luego lee el resumen: el titular en `succeeded` y `failed`,
el gasto de tokens en `usage` y las claves que merecen una mirada humana en el `needsReview` de cada
locale. Los problemas de toda la ejecución lanzan un `SdkError`; los resultados por locale son datos en
el resumen.

```ts
import { loadConfig, translate } from "@verbatra/sdk";

const config = await loadConfig();
const summary = await translate({ config });

console.log(
  `${summary.succeeded.length} ok, ${summary.partial.length} partial, ${summary.failed.length} failed`,
);

if (summary.usage !== undefined) {
  console.log(`tokens: ${summary.usage.inputTokens} in, ${summary.usage.outputTokens} out`);
}

for (const locale of summary.locales) {
  if (locale.status === "failed") {
    console.error(`${locale.locale}: ${locale.error?.code} ${locale.error?.message}`);
    continue;
  }
  for (const entry of locale.needsReview) {
    console.warn(`review ${locale.locale}/${entry.key}: ${entry.reasons.join(", ")}`);
  }
}

if (summary.failed.length > 0 || summary.partial.length > 0) {
  process.exitCode = 1;
}
```

Un locale `partial` es aquel cuyo archivo se escribió con claves aún faltantes. No es un éxito: la
CLI sale con `1` ante él, y tu propio script debería tratarlo igual: por eso la comprobación de
arriba mira `partial` junto a `failed`.

Pasa `dryRun: true` para previsualizar sin llamar a un proveedor ni escribir nada, y `prune: true` o
`generatePlurals: true` para anular esas opciones de configuración en una sola ejecución. Pasa
`locales: ["de"]` para restringir la ejecución a un subconjunto de los destinos configurados, que es
como recorres un proveedor con límite de tasa un idioma cada vez; un locale no configurado lanza
`UNKNOWN_LOCALE` antes de leer ni gastar nada. Pon
`concurrency` por encima de 1 para traducir locales en paralelo (no permitido con un presupuesto
`maxTokens` en una ejecución real) y `cache: false` para omitir la
[caché de memoria de traducción](/docs/the-cache).

## Estima una ejecución antes de gastar

<AvailableFrom version="0.11.0" />

`estimate: true` implica `dryRun`, así que la ejecución no construye ningún proveedor, no lee
ninguna clave de API y no escribe nada. La cifra aparece en `RunSummary.estimate`. Ramifica según
`unit` para la dimensión facturada y según `pricing` para saber si había una cifra en moneda:
verbatra no trae tarifas propias, así que un coste solo aparece cuando la configuración lleva un
bloque `rates` para este proveedor y este modelo.

```ts
import { loadConfig, translate } from "@verbatra/sdk";

const summary = await translate({ config: await loadConfig(), estimate: true });
const estimate = summary.estimate;

if (estimate !== undefined) {
  console.log(`${estimate.keys} keys in ${estimate.requests} requests to ${estimate.rateKey}`);

  if (estimate.unit === "tokens") {
    console.log(`about ${estimate.inputTokens} in, ${estimate.outputTokens} out`);
  } else {
    console.log(`about ${estimate.sourceCharacters} source characters`);
  }

  if (estimate.pricing === "priced") {
    console.log(`about ${estimate.cost} ${estimate.currency}, rates read ${estimate.asOf}`);
    for (const locale of estimate.locales) {
      console.log(`  ${locale.locale}: ${locale.cost}`);
    }
  } else {
    console.log(`no currency figure: ${estimate.pricing}`);
  }

  console.log(`leaves out: ${estimate.caveats.join(", ")}`);
}
```

Acota el plan, no la factura: una ejecución real suele gastar menos, porque consulta la
[caché de memoria de traducción](/docs/the-cache) y agrupa las cadenas de origen idénticas, y puede
gastar más por cada motivo que nombra `caveats`. `resolveDryRun` es el único sitio donde se decide
la regla de que `estimate` implica `dryRun`, así que llámalo en lugar de repetirla. Para el método
detrás de los números, consulta [Estimar el coste](/docs/estimating-cost).

`caveats` nunca está vacío. Sus códigos (`EstimateCaveatCode`) son:

- `CACHE_NOT_CONSULTED`: no se lee la memoria de traducción, así que las claves que una ejecución
  real serviría desde la caché se cuentan igualmente. Se aplica a toda estimación.
- `SOURCE_DUPLICATES_NOT_DEDUPLICATED`: una ejecución real envía un representante por cada cadena
  de origen idéntica; la estimación cuenta cada clave. Se aplica a toda estimación.
- `TRANSPORT_RETRIES_NOT_COUNTED`: se cuenta una llamada facturable por cada petición planificada,
  aunque los SDK del proveedor pueden reintentar por debajo una llamada fallida y un intento
  reintentado puede facturarse igualmente. Se aplica a toda estimación.
- `TRANSLATION_LENGTH_IS_ESTIMATED`: la respuesta se dimensiona a partir del origen más un margen
  de expansión fijo, así que un idioma de destino que se alarga más informa de más tokens de
  completado. Solo proveedores que facturan por tokens.
- `TOKEN_COUNT_IS_HEURISTIC`: los tokens se derivan del número de caracteres, no del tokenizador
  propio del proveedor. Solo proveedores que facturan por tokens.
- `REPAIR_REQUESTS_NOT_COUNTED`: no se cuentan la ronda de reparación para las claves que volvieron
  faltantes ni el reintento en mitades de una respuesta cortada. Solo proveedores que facturan por
  tokens.

## Comprueba en CI sin escribir

`check` lee y compara sin llamar a un proveedor ni tocar ningún archivo, y su indicador `inSync` es true
exactamente cuando no hay nada faltante ni obsoleto. Eso lo convierte en la puerta natural de CI.

```ts
import { check, loadConfig } from "@verbatra/sdk";

const summary = await check({ config: await loadConfig() });

if (!summary.inSync) {
  for (const locale of summary.locales) {
    if (!locale.inSync) {
      console.error(`${locale.locale}: ${locale.missing} missing, ${locale.stale} stale`);
    }
  }
  process.exitCode = 1;
}
```

¿Necesitas los nombres de las claves en lugar de contadores? Cambia a `diff`, que devuelve listas de
claves `missing`, `changed` y `orphaned` por locale con la misma puerta `hasPendingChanges`. ¿Ejecutas
la CLI en CI en su lugar? Consulta [CI y códigos de salida](/docs/ci-and-exit-codes).

## Vigila en un proceso de larga duración

`watch` dispara una ejecución inmediatamente al arrancar, y luego una por cada cambio del origen,
una vez pasado el anti-rebote, informando de cada una a través de `onRun`. Para un apagado limpio,
haz `await controller.stop()`: cierra el watcher y espera a que termine la ejecución en curso antes
de que salga tu proceso.

```ts
import { loadConfig, watch } from "@verbatra/sdk";

const config = await loadConfig();
const controller = await watch({
  config,
  onRun: (result) => {
    if (result.status === "succeeded") {
      console.log(`ran: ${result.summary.succeeded.length} ok, ${result.summary.failed.length} failed`);
    } else {
      console.error(`run failed: ${result.error.code} ${result.error.message}`);
    }
  },
});

process.on("SIGINT", () => {
  void controller.stop().then(() => {
    process.exit(0);
  });
});
```

Un fallo de ejecución después del arranque nunca lanza; llega como `{ status: "failed" }` y la
vigilancia continúa.

## Extrae claves de tu código fuente

<AvailableFrom version="0.11.0" />

`extract` es el único punto de entrada que lee código de aplicación en lugar de un archivo de
locale. Solo escribe el catálogo de origen, y solo claves realmente nuevas: una clave ya existente
conserva su valor, y una clave que ninguna llamada menciona se deja intacta. Todo lo que el análisis
no puede resolver vuelve como datos, así que un dry run es una buena puerta antes de la ejecución
que escribe.

```ts
import { extract, loadConfig } from "@verbatra/sdk";

const config = await loadConfig();
const preview = await extract({ config, dryRun: true });

console.log(`${preview.scannedFiles} files scanned, ${preview.existingKeys} keys already present`);
for (const added of preview.added) {
  console.log(`+ ${added.key} = ${JSON.stringify(added.value)} (${added.file}:${added.line})`);
}
for (const conflict of preview.conflicts) {
  console.warn(`${conflict.key} has two defaults: ${conflict.values.join(" | ")}`);
}
for (const site of preview.dynamic) {
  console.warn(`non-static key argument at ${site.file}:${site.line}`);
}
for (const diagnostic of preview.diagnostics) {
  console.warn(`${diagnostic.file}: ${diagnostic.reason}`);
}

if (preview.added.length > 0 && preview.conflicts.length === 0) {
  const run = await extract({ config });
  console.log(`wrote ${run.added.length} keys to ${run.sourcePath}: ${run.written}`);
}
```

`config.extract` tiene que nombrar el framework y las raíces de código, o la llamada lanza
`EXTRACT_NOT_CONFIGURED`. El descubrimiento pasa por el miembro opcional `readDirectory` de
`SdkFs`, así que un `deps.fs` propio sin él se rechaza con `EXTRACT_FS_UNSUPPORTED`, y un catálogo
de origen que no se puede escribir lanza `SOURCE_UNWRITABLE`.

## Genera un catálogo tipado

<AvailableFrom version="0.11.0" />

`generateTypes` declara el catálogo de origen como TypeScript: una unión de todas las claves, más
los argumentos que interpola cada mensaje. Lee un archivo y escribe un archivo, y dos ejecuciones
sobre un catálogo sin cambios escriben bytes idénticos, que es lo que hace del modo `check` una
puerta de CI utilizable.

```ts
import { generateTypes, loadConfigWithMeta } from "@verbatra/sdk";

const loaded = await loadConfigWithMeta();
const out = "src/generated/messages.d.ts";
const configPath = loaded.source.kind === "override" ? undefined : loaded.source.filepath;

const result = await generateTypes({
  config: loaded.config,
  out,
  ...(configPath !== undefined ? { configPath } : {}),
});

console.log(`${result.keys} keys in ${result.path}, ${result.withArguments} take arguments`);
for (const message of result.unresolved) {
  console.warn(`arguments not claimed for ${message.key}: ${message.reason}`);
}

// In CI, compare instead of writing.
const gate = await generateTypes({ config: loaded.config, out, check: true });
if (gate.stale) {
  console.error(`${gate.path} is out of date, re-generate it`);
  process.exitCode = 1;
}
```

Pasa `configPath` para que el archivo de configuración que cargó la ejecución se rechace como ruta
de salida. Una ejecución con `check` no escribe nada, no rechaza nada por su contenido y solo
informa de `stale`. Todo lo que rechaza una ejecución que escribe, con `TYPES_OUTPUT_CONFLICT`,
está listado en la página de [`verbatra types`](/docs/cli/types); una declaración que no se puede
escribir lanza `TYPES_UNWRITABLE`.

## Construye un pseudolocale

<AvailableFrom version="0.11.0" />

`pseudolocalize` construye un locale falso solo a partir de las cadenas de origen, para que los
recortes de maquetación y las cadenas que nunca se extrajeron salgan a la luz antes de que exista
ninguna clave de API. No construye ningún proveedor ni hace ninguna petición de red, y su salida
cae fuera de `files.pattern`, así que `translate` nunca gasta en él y `check` y `diff` nunca
informan de él como desfasado.

```ts
import { loadConfig, pseudolocalize } from "@verbatra/sdk";

const result = await pseudolocalize({ config: await loadConfig() });

console.log(`${result.locale} written to ${result.path}: ${result.written}`);
console.log(`${result.transformed} of ${result.entries} entries transformed`);
for (const key of result.copied) {
  console.warn(`copied from source verbatim, a pseudolocalized value would not pass the gate: ${key}`);
}
```

`locale` es `en-XA` por defecto y `out` es `.verbatra-local/pseudo`. Un pseudolocale que nombre
un locale configurado, o un `out` que caería sobre un archivo de locale configurado, se rechaza
con `PSEUDO_OUTPUT_CONFLICT` antes de leer o escribir nada. La transformación es determinista, así
que una segunda ejecución sobre un origen sin cambios no reescribe nada e informa de `written`
como false.

## Edita y retraduce una sola clave

Estos son los puntos de integración que usa Verbatra Studio; úsalos para construir tu propio flujo de
revisión. Lee los valores actuales con `keyValue`, guarda una corrección humana con `editEntry` o vuelve
a ejecutar el proveedor para una clave con `retranslateEntry`. Ambos escritores pasan el valor candidato
por las mismas comprobaciones de integridad que una ejecución completa y devuelven un
resultado de dos ramas en lugar de lanzar ante un valor rechazado.

```ts
import { editEntry, keyValue, loadConfig, retranslateEntry } from "@verbatra/sdk";

const config = await loadConfig();

// Read the live values feeding your edit UI.
const current = await keyValue({ config, locale: "de", key: "checkout.title" });
console.log(`source: ${current.source}, target: ${current.target ?? "(not yet translated)"}`);

// Save a human-typed correction. No provider call.
const edit = await editEntry({
  config,
  locale: "de",
  key: "checkout.title",
  value: "Zur Kasse",
});
if (!edit.accepted) {
  console.error(`rejected (${edit.reason} check failed), nothing written`);
}

// Or ask the provider for a fresh translation of just this key.
const retry = await retranslateEntry({ config, locale: "de", key: "checkout.title" });
if (retry.accepted) {
  console.log(`wrote: ${retry.value}`);
  if (retry.reviewReasons.length > 0) {
    console.warn(`flagged for review: ${retry.reviewReasons.join(", ")}`);
  }
}
```

Un locale o una clave desconocidos lanzan `UNKNOWN_LOCALE` o `UNKNOWN_KEY`, y `retranslateEntry` lanza
el `ProviderError` propio del proveedor (por ejemplo `RATE_LIMITED`) cuando la llamada en sí falla.
Consulta [Revisión en Studio](/docs/review-in-studio) para los mismos puntos de integración detrás de
una interfaz.

## Lee todos los valores de golpe

<AvailableFrom version="0.10.0" />

`localeValues` es la contraparte en bloque de `keyValue`: una pasada sobre los archivos que ya están
en disco, que devuelve el texto de origen y de destino actual de cada clave por locale. Recurre a
él cuando quien llama necesita buscar o escanear contenido traducido en lugar de nombres de clave.

```ts
import { loadConfig, localeValues } from "@verbatra/sdk";

const report = await localeValues({ config: await loadConfig(), locales: ["de", "fr"] });

for (const { locale, values } of report) {
  for (const [key, pair] of Object.entries(values)) {
    if (pair.source === undefined) {
      console.warn(`${locale}/${key}: orphaned, no source key any more`);
    } else if (pair.target === undefined) {
      console.warn(`${locale}/${key}: not translated yet`);
    } else if (pair.target.includes("TODO")) {
      console.log(`${locale}/${key}: ${pair.target}`);
    }
  }
}
```

Solo lectura: no llama a ningún proveedor, no escribe nada y no toca ni el archivo de bloqueo ni la
caché. Omite `locales` para cubrir todos los locales de destino configurados.

## El ciclo de ida y vuelta del libro

Exporta las cadenas que necesitan traducción a un libro de Excel, entrégaselo a un traductor y luego
importa el archivo rellenado de vuelta. `importWorkbook` ejecuta las mismas comprobaciones de desfase
e integridad que `translate` y devuelve la misma forma `RunSummary`, así que una entrega
manual encaja exactamente en los mismos informes que usas para una ejecución automática.

```ts
import { exportWorkbook, importWorkbook, loadConfig } from "@verbatra/sdk";

const config = await loadConfig();

// Write a workbook of the missing and changed strings.
const exported = await exportWorkbook({ config });
for (const sheet of exported.locales) {
  console.log(`${sheet.locale}: ${sheet.rows} rows`);
}
console.log(`wrote ${exported.path}`);

// ...later, after the translator returns the file, import it back.
const summary = await importWorkbook({ config, workbook: exported.path });
console.log(`${summary.succeeded.length} locales ok, ${summary.failed.length} failed`);
```

Pasa `dryRun: true` a `importWorkbook` para validar un archivo devuelto sin escribir nada. Consulta
[Traducción humana](/docs/manual-translation) para saber qué pueden editar los traductores y cómo se
validan las filas.

## El ciclo de ida y vuelta de TMX

<AvailableFrom version="0.11.0" />

`importTmx` y `exportTmx` mueven la [memoria de traducción](/docs/the-cache) hacia y desde TMX, el
formato de intercambio que producen y leen las plataformas de traducción más extendidas. Esto no es
el par del libro en otro formato: el libro entrega a un traductor humano el delta pendiente de un
solo locale, mientras que este par mueve la memoria entera como un único archivo multilingüe entre
herramientas.

```ts
import { exportTmx, importTmx, loadConfig, tmxErrorLocation } from "@verbatra/sdk";

const config = await loadConfig();

// Validate another tool's file before it touches the memory.
try {
  const preview = await importTmx({ config, file: "legacy.tmx", dryRun: true });
  console.log(`${preview.units} units, source language ${preview.sourceLanguage ?? "undeclared"}`);
  for (const locale of preview.locales) {
    console.log(
      `${locale.locale}: +${locale.added}, kept ${locale.kept}, conflicting ${locale.conflicting}`,
    );
  }

  // Then land it. Pass overwrite: true to let the file win where the two disagree.
  const landed = await importTmx({ config, file: "legacy.tmx" });
  if (!landed.memoryWritable) {
    console.error("the memory file was written by a newer verbatra and was left untouched");
  }
} catch (error) {
  const at = tmxErrorLocation(error);
  if (at === undefined) {
    throw error;
  }
  console.error(`legacy.tmx is malformed at line ${at.line}, column ${at.column}`);
}

// ...and hand this project's memory to another tool.
const exported = await exportTmx({ config, out: "out/memory.tmx" });
console.log(`${exported.units} units to ${exported.path}`);
```

Ninguno construye un proveedor, lee una clave de API ni hace una llamada de red. `importTmx`
informa de los datos dañados en lugar de lanzar sobre ellos: un archivo rechazado lanza
`SOURCE_INVALID`, y `tmxErrorLocation` lee el sitio a partir de ese error sin hacer un cast sobre
él ni sobre su `cause`. Solo se exportan las entradas bajo la huella de configuración actual, que
es el mismo conjunto que reutilizaría una ejecución.

## Una configuración sin archivo

`loadConfig` acepta un `configOverride` en memoria, validado exactamente igual que un archivo cargado,
así que puedes manejar verbatra enteramente desde código sin ningún archivo de configuración en disco.

```ts
import { loadConfig, translate } from "@verbatra/sdk";

const config = await loadConfig({
  configOverride: {
    sourceLocale: "en",
    targetLocales: ["de", "fr"],
    format: "i18next-json",
    files: { pattern: "locales/{locale}.json" },
    provider: { id: "gemini", options: { model: "gemini-2.5-flash", maxOutputTokens: 4096 } },
  },
});

await translate({ config });
```

Para cada forma de entrada, la anatomía completa de `RunSummary` y la tabla de códigos de `SdkError`,
consulta la [referencia del SDK](/docs/sdk).
