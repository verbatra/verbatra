The [SDK reference](/docs/sdk) catalogs every entry point. This page is the hands-on companion:
end-to-end recipes you can copy into a script and run. One thing to set up first: the SDK does not
load `.env` files (the CLI does that), so make sure the provider's environment variable is set
before your script runs, for example:

```bash
node --env-file=.env translate.mjs
```

## One-shot translate in a script

Load the config, run the flow, then read the summary: the headline from `succeeded` and `failed`,
token spend from `usage`, and the keys worth a human look from each locale's `needsReview`.
Whole-run problems throw an `SdkError`; per-locale outcomes are data on the summary.

```ts
import { loadConfig, translate } from "@verbatra/sdk";

const config = await loadConfig();
const summary = await translate({ config });

console.log(
  `${summary.succeeded.length} ok, ${summary.partial.length} partial, ${summary.failed.length} failed`,
);

if (summary.usage !== undefined) {
  console.log(`tokens: ${summary.usage.inputTokens} in, ${summary.usage.outputTokens} out`);
}

for (const locale of summary.locales) {
  if (locale.status === "failed") {
    console.error(`${locale.locale}: ${locale.error?.code} ${locale.error?.message}`);
    continue;
  }
  for (const entry of locale.needsReview) {
    console.warn(`review ${locale.locale}/${entry.key}: ${entry.reasons.join(", ")}`);
  }
}

if (summary.failed.length > 0 || summary.partial.length > 0) {
  process.exitCode = 1;
}
```

A `partial` locale is one whose file was written with keys still missing. It is not a success:
the CLI exits `1` on it, and your own script should treat it the same way, which is why the check
above tests `partial` alongside `failed`.

Pass `dryRun: true` to preview without calling a provider or writing anything, and `prune: true`
or `generatePlurals: true` to override those config options for one run. Pass `locales: ["de"]` to
restrict the run to a subset of the configured targets, which is how you work through a
rate-limited provider one language at a time; an unconfigured locale throws `UNKNOWN_LOCALE` before
anything is read or spent. Set `concurrency` above 1
to translate locales in parallel (not allowed with a `maxTokens` budget on a live run) and
`cache: false` to bypass the [translation-memory cache](/docs/the-cache).

## Estimate a run before spending

<AvailableFrom version="0.11.0" />

`estimate: true` implies `dryRun`, so the run constructs no provider, reads no API key, and writes
nothing. The figure lands on `RunSummary.estimate`. Branch on `unit` for the billed dimension and
on `pricing` for whether a currency figure was available: verbatra ships no rates of its own, so a
cost appears only when the config carries a `rates` block for this provider and model.

```ts
import { loadConfig, translate } from "@verbatra/sdk";

const summary = await translate({ config: await loadConfig(), estimate: true });
const estimate = summary.estimate;

if (estimate !== undefined) {
  console.log(`${estimate.keys} keys in ${estimate.requests} requests to ${estimate.rateKey}`);

  if (estimate.unit === "tokens") {
    console.log(`about ${estimate.inputTokens} in, ${estimate.outputTokens} out`);
  } else {
    console.log(`about ${estimate.sourceCharacters} source characters`);
  }

  if (estimate.pricing === "priced") {
    console.log(`about ${estimate.cost} ${estimate.currency}, rates read ${estimate.asOf}`);
    for (const locale of estimate.locales) {
      console.log(`  ${locale.locale}: ${locale.cost}`);
    }
  } else {
    console.log(`no currency figure: ${estimate.pricing}`);
  }

  console.log(`leaves out: ${estimate.caveats.join(", ")}`);
}
```

It bounds the plan, not the invoice: a live run usually spends less, because it consults the
[translation-memory cache](/docs/the-cache) and collapses identical source strings, and it can
spend more for every reason `caveats` names. `resolveDryRun` is the one place the
`estimate`-implies-`dryRun` rule is decided, so call it rather than restating it. For the method
behind the numbers, see [Estimating cost](/docs/estimating-cost).

## Check in CI without writing

`check` reads and diffs without calling a provider or touching any file, and its `inSync` flag is
true exactly when nothing is missing or stale. That makes it the natural CI gate.

```ts
import { check, loadConfig } from "@verbatra/sdk";

const summary = await check({ config: await loadConfig() });

if (!summary.inSync) {
  for (const locale of summary.locales) {
    if (!locale.inSync) {
      console.error(`${locale.locale}: ${locale.missing} missing, ${locale.stale} stale`);
    }
  }
  process.exitCode = 1;
}
```

Need the key names instead of counts? Swap in `diff`, which returns `missing`, `changed`, and
`orphaned` key lists per locale with the same `hasPendingChanges` gate. Running the CLI in CI
instead? See [CI and exit codes](/docs/ci-and-exit-codes).

## Watch in a long-running process

`watch` fires one run immediately at startup, then one per debounced source change, reporting each
through `onRun`. For a clean shutdown, await `controller.stop()`: it closes the watcher and waits
for the in-flight run to finish before your process exits.

```ts
import { loadConfig, watch } from "@verbatra/sdk";

const config = await loadConfig();
const controller = await watch({
  config,
  onRun: (result) => {
    if (result.status === "succeeded") {
      console.log(`ran: ${result.summary.succeeded.length} ok, ${result.summary.failed.length} failed`);
    } else {
      console.error(`run failed: ${result.error.code} ${result.error.message}`);
    }
  },
});

process.on("SIGINT", () => {
  void controller.stop().then(() => {
    process.exit(0);
  });
});
```

A run failure after startup never throws; it arrives as `{ status: "failed" }` and watching
continues.

## Extract keys from your source code

<AvailableFrom version="0.11.0" />

`extract` is the one entry point that reads application code rather than a locale file. It writes
only the source catalog, and only genuinely new keys: an existing key keeps its value, and a key no
call site mentions is left alone. Everything the scan cannot resolve comes back as data, so a
dry run makes a good gate before the writing run.

```ts
import { extract, loadConfig } from "@verbatra/sdk";

const config = await loadConfig();
const preview = await extract({ config, dryRun: true });

console.log(`${preview.scannedFiles} files scanned, ${preview.existingKeys} keys already present`);
for (const added of preview.added) {
  console.log(`+ ${added.key} = ${JSON.stringify(added.value)} (${added.file}:${added.line})`);
}
for (const conflict of preview.conflicts) {
  console.warn(`${conflict.key} has two defaults: ${conflict.values.join(" | ")}`);
}
for (const site of preview.dynamic) {
  console.warn(`non-static key argument at ${site.file}:${site.line}`);
}
for (const diagnostic of preview.diagnostics) {
  console.warn(`${diagnostic.file}: ${diagnostic.reason}`);
}

if (preview.added.length > 0 && preview.conflicts.length === 0) {
  const run = await extract({ config });
  console.log(`wrote ${run.added.length} keys to ${run.sourcePath}: ${run.written}`);
}
```

`config.extract` has to name the framework and the source roots, or the call throws
`EXTRACT_NOT_CONFIGURED`. Discovery goes through the optional `readDirectory` member of `SdkFs`, so
a custom `deps.fs` without it is refused with `EXTRACT_FS_UNSUPPORTED`, and a source catalog that
cannot be written raises `SOURCE_UNWRITABLE`.

## Generate a typed catalog

<AvailableFrom version="0.11.0" />

`generateTypes` declares the source catalog as TypeScript: a union of every key, plus the arguments
each message interpolates. It reads one file and writes one file, and two runs over an unchanged
catalog write byte-identical bytes, which is what makes the `check` mode a usable CI gate.

```ts
import { generateTypes, loadConfigWithMeta } from "@verbatra/sdk";

const loaded = await loadConfigWithMeta();
const out = "src/generated/messages.d.ts";
const configPath = loaded.source.kind === "override" ? undefined : loaded.source.filepath;

const result = await generateTypes({
  config: loaded.config,
  out,
  ...(configPath !== undefined ? { configPath } : {}),
});

console.log(`${result.keys} keys in ${result.path}, ${result.withArguments} take arguments`);
for (const message of result.unresolved) {
  console.warn(`arguments not claimed for ${message.key}: ${message.reason}`);
}

// In CI, compare instead of writing.
const gate = await generateTypes({ config: loaded.config, out, check: true });
if (gate.stale) {
  console.error(`${gate.path} is out of date, re-generate it`);
  process.exitCode = 1;
}
```

Pass `configPath` so the config file the run loaded is refused as an output path. A `check` run
writes nothing, refuses nothing for its content, and only reports `stale`. Everything a generating
run refuses, with `TYPES_OUTPUT_CONFLICT`, is listed on the
[`verbatra types`](/docs/cli/types) page; a declaration that cannot be written raises
`TYPES_UNWRITABLE`.

## Build a pseudolocale

<AvailableFrom version="0.11.0" />

`pseudolocalize` builds a fake locale from the source strings alone, so layout truncation and
strings that were never extracted show up before any API key exists. It constructs no provider and
makes no network request, and its output lands outside `files.pattern`, so `translate` never spends
on it and `check` and `diff` never report it as drifted.

```ts
import { loadConfig, pseudolocalize } from "@verbatra/sdk";

const result = await pseudolocalize({ config: await loadConfig() });

console.log(`${result.locale} written to ${result.path}: ${result.written}`);
console.log(`${result.transformed} of ${result.entries} entries transformed`);
for (const key of result.copied) {
  console.warn(`copied from source verbatim, a pseudolocalized value would not pass the gate: ${key}`);
}
```

`locale` defaults to `en-XA` and `out` to `.verbatra-local/pseudo`. A pseudolocale that names a
configured locale, or an `out` that would land on a configured locale file, is refused with
`PSEUDO_OUTPUT_CONFLICT` before anything is read or written. The transform is deterministic, so a
second run over unchanged source rewrites nothing and reports `written` as false.

## Edit and retranslate a single key

These are the seams Verbatra Studio drives; use them to build your own review flow. Read the
current values with `keyValue`, save a human correction with `editEntry`, or re-run the provider
for one key with `retranslateEntry`. Both writers gate the candidate value through the same
integrity checks as a full run and return a two-armed result instead of throwing on a
rejected value.

```ts
import { editEntry, keyValue, loadConfig, retranslateEntry } from "@verbatra/sdk";

const config = await loadConfig();

// Read the live values feeding your edit UI.
const current = await keyValue({ config, locale: "de", key: "checkout.title" });
console.log(`source: ${current.source}, target: ${current.target ?? "(not yet translated)"}`);

// Save a human-typed correction. No provider call.
const edit = await editEntry({
  config,
  locale: "de",
  key: "checkout.title",
  value: "Zur Kasse",
});
if (!edit.accepted) {
  console.error(`rejected (${edit.reason} check failed), nothing written`);
}

// Or ask the provider for a fresh translation of just this key.
const retry = await retranslateEntry({ config, locale: "de", key: "checkout.title" });
if (retry.accepted) {
  console.log(`wrote: ${retry.value}`);
  if (retry.reviewReasons.length > 0) {
    console.warn(`flagged for review: ${retry.reviewReasons.join(", ")}`);
  }
}
```

An unknown locale or key throws `UNKNOWN_LOCALE` or `UNKNOWN_KEY`, and `retranslateEntry` throws
the provider's own `ProviderError` (for example `RATE_LIMITED`) when the call itself fails. See
[Review in Studio](/docs/review-in-studio) for the same seams behind a UI.

## Read every value in bulk

<AvailableFrom version="0.10.0" />

`localeValues` is the bulk counterpart to `keyValue`: one pass over the files already on disk,
returning every key's current source and target text per locale. Reach for it when a caller needs
to search or scan translation content rather than key names.

```ts
import { loadConfig, localeValues } from "@verbatra/sdk";

const report = await localeValues({ config: await loadConfig(), locales: ["de", "fr"] });

for (const { locale, values } of report) {
  for (const [key, pair] of Object.entries(values)) {
    if (pair.source === undefined) {
      console.warn(`${locale}/${key}: orphaned, no source key any more`);
    } else if (pair.target === undefined) {
      console.warn(`${locale}/${key}: not translated yet`);
    } else if (pair.target.includes("TODO")) {
      console.log(`${locale}/${key}: ${pair.target}`);
    }
  }
}
```

Read-only: it calls no provider, writes nothing, and touches neither the lock file nor the cache.
Omit `locales` to cover every configured target locale.

## The workbook round-trip

Export the strings that need translating into an Excel workbook, hand it to a translator, then
import the filled file back. `importWorkbook` runs the same drift and integrity checks as
`translate` and returns the same `RunSummary` shape, so a manual handoff slots into the exact
reporting you use for an automated run.

```ts
import { exportWorkbook, importWorkbook, loadConfig } from "@verbatra/sdk";

const config = await loadConfig();

// Write a workbook of the missing and changed strings.
const exported = await exportWorkbook({ config });
for (const sheet of exported.locales) {
  console.log(`${sheet.locale}: ${sheet.rows} rows`);
}
console.log(`wrote ${exported.path}`);

// ...later, after the translator returns the file, import it back.
const summary = await importWorkbook({ config, workbook: exported.path });
console.log(`${summary.succeeded.length} locales ok, ${summary.failed.length} failed`);
```

Pass `dryRun: true` to `importWorkbook` to validate a returned file without writing anything. See
[Manual translation](/docs/manual-translation) for what translators may edit and how rows are
validated.

## The TMX round-trip

<AvailableFrom version="0.11.0" />

`importTmx` and `exportTmx` move the [translation memory](/docs/the-cache) in and out of TMX, the
interchange format the mainstream translation platforms produce and consume. This is not the
workbook pair in another format: the workbook hands one locale's pending delta to a human
translator, while this pair moves the whole memory as one multilingual file between tools.

```ts
import { exportTmx, importTmx, loadConfig, tmxErrorLocation } from "@verbatra/sdk";

const config = await loadConfig();

// Validate another tool's file before it touches the memory.
try {
  const preview = await importTmx({ config, file: "legacy.tmx", dryRun: true });
  console.log(`${preview.units} units, source language ${preview.sourceLanguage ?? "undeclared"}`);
  for (const locale of preview.locales) {
    console.log(
      `${locale.locale}: +${locale.added}, kept ${locale.kept}, conflicting ${locale.conflicting}`,
    );
  }

  // Then land it. Pass overwrite: true to let the file win where the two disagree.
  const landed = await importTmx({ config, file: "legacy.tmx" });
  if (!landed.memoryWritable) {
    console.error("the memory file was written by a newer verbatra and was left untouched");
  }
} catch (error) {
  const at = tmxErrorLocation(error);
  if (at === undefined) {
    throw error;
  }
  console.error(`legacy.tmx is malformed at line ${at.line}, column ${at.column}`);
}

// ...and hand this project's memory to another tool.
const exported = await exportTmx({ config, out: "out/memory.tmx" });
console.log(`${exported.units} units to ${exported.path}`);
```

Neither constructs a provider, reads an API key, nor makes a network call. `importTmx` reports
damaged data rather than throwing on it: a refused file raises `SOURCE_INVALID`, and
`tmxErrorLocation` reads the place out of that error without casting it or its `cause`. Only entries
under the current configuration fingerprint are exported, which is the same set a run would reuse.

## A config without a file

`loadConfig` accepts an in-memory `configOverride`, validated exactly like a loaded file, so you
can drive verbatra entirely from code with no config file on disk.

```ts
import { loadConfig, translate } from "@verbatra/sdk";

const config = await loadConfig({
  configOverride: {
    sourceLocale: "en",
    targetLocales: ["de", "fr"],
    format: "i18next-json",
    files: { pattern: "locales/{locale}.json" },
    provider: { id: "gemini", options: { model: "gemini-2.5-flash", maxOutputTokens: 4096 } },
  },
});

await translate({ config });
```

For every input shape, the full `RunSummary` anatomy, and the `SdkError` code table, see the
[SDK reference](/docs/sdk).
