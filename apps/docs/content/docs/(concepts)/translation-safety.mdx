verbatra trusts neither the strings it translates nor what a provider sends back. Every value
passes an integrity gate before it can be written, whatever the gate rejects surfaces as data
instead of failing the run, and secrets stay out of every error path.

| Layer | Guards against | On failure |
| --- | --- | --- |
| Prompt-injection boundary | a string that reads like an instruction | nothing to fail: strings are only ever data |
| Integrity gate | broken placeholders, ICU, markup, empty or degenerate values | the key is withheld and retried next run |
| Review flags | a value that is valid but suspicious | the key is written and queued for a person |
| Token budget | spend past a ceiling you set | the rest of the run is withheld, or flagged |
| Structured errors | a key or header leaking into a message | a stable code with a fixed message |

## Untrusted strings and the prompt-injection boundary

A translatable string can contain text that looks like an instruction ("ignore your
instructions"), so verbatra treats every string as untrusted input. The system rules sent to an LLM
provider are compile-time constants. Everything variable (the entries, your glossary and tone, the
language names, a plural's target categories) travels only in the user-turn JSON payload, never in
the instruction channel. The response must match a fixed schema; a response with a key that was
never requested fails its whole sub-batch.

### Language, script and region names

<AvailableFrom version="0.12.0" />

A locale code alone is not always enough: `sr-Latn` often comes back in Cyrillic, and `pt-BR` and
`pt-PT` blur together. So an LLM provider also receives the English name of each language, with its
script and region when the code names them, looked up with `Intl.DisplayNames` from the data built
into Node.js:

| Locale | Names sent |
| --- | --- |
| `sr-Latn` | `{ "name": "Serbian (Latin)", "script": "Latin" }` |
| `zh-Hant-TW` | `{ "name": "Chinese (Traditional, Taiwan)", "script": "Traditional", "region": "Taiwan" }` |
| `es-419` | `{ "name": "Spanish (Latin America)", "region": "Latin America" }` |
| `qaa` (private use) | none: the code is sent alone |

The names come from the locale in your config, even when a `localeMap` entry sends a different
code, and travel as data like the rest; one fixed system rule asks the model to write in the named
script and variant. They are not part of the [cache](/docs/the-cache) fingerprint. The
machine-translation providers receive codes only; see
[Languages and locales](/docs/language-support).

## The integrity gate

A schema-valid translation can still be broken, so one gate decides from the candidate value itself
whether to accept it; the provider's own report is never trusted. The same gate runs on every write
path: a provider answer, a cache hit, a workbook import row, and an edit typed in Studio. A value
shared by several keys with the same source text is gated per key against each key's own source.

| Check | A candidate is refused when |
| --- | --- |
| Placeholders | its placeholders differ from the source's, compared as a multiset (counts matter, order does not). What counts as a placeholder is defined per [format](/docs/formats). |
| ICU | for next-intl and ARB, it no longer parses as an ICU message, or its plural arms do not fit the target language (below). The comparison is branch-aware, so a placeholder invented inside one plural arm is caught. |
| Invented tokens | for i18next, ngx-translate and YAML, it adds a `{name}`-shaped token the source never had. Dropping one is allowed, since single braces are literal text there. |
| Inline markup | its HTML or XML tags differ from the source's, or are unbalanced (below). |
| Degeneracy | it is a repetition loop, or its length ran away from the source. |
| Emptiness | it is empty or whitespace for a non-empty source. Clearing a translation is a deliberate act: the workbook's `[[CLEAR]]` sentinel does it ([Manual translation](/docs/manual-translation)). |

A candidate that breaks several checks is refused with one reason, the first that applies in this
order: `empty`, `icu` (does not parse), `placeholder`, `markup`, `icu` (arms), `degenerate`. Each
reason, and the details verbatra prints with it, is listed under
[Integrity refusal reasons](/docs/error-codes#integrity-refusal-reasons).

What the gate guarantees: a refused value is never written. It appears on the run summary as an
integrity mismatch, keeps its previous hash in [the lock file](/docs/the-lock-file), and is retried
next run. A key that got no translation at all (the provider call failed, or the key was still
missing after one repair request) is reported as a provider failure instead, and retries the same
way. On the source side, a key whose own value is invalid ICU is set aside before translation.

What it does not guarantee: that the translation is correct. It proves structure, not meaning.

### Plural arms per target language

<AvailableFrom version="0.12.0" />

An ICU plural has one arm per CLDR plural category of its language: English has `one` and `other`,
Russian and Polish four, Arabic and Welsh six, Japanese only `other`. For next-intl and ARB,
verbatra reads the target language's categories from the CLDR data built into Node.js:

- An LLM provider is asked for exactly those arms (cardinal for `plural`, ordinal for
  `selectordinal`). The categories travel as data, so the injection boundary is unchanged.
- The gate refuses a `plural` or `selectordinal` that lacks a required arm or keeps one the language
  does not have, on every write path, and names each wrong arm.
- Exact-value arms such as `=0` must all survive, and a translation may add more. `select` arms are
  your code's keys, so a translation keeps exactly the source's.
- For a locale Node.js has no plural rules for, only `other` is required.

A value written before this check, such as a French plural without `many`, stays until its source
changes; [`verbatra check --qa`](/docs/cli/check#quality-check) finds it now. How plurals work in the
other formats is on [Languages and locales](/docs/language-support#plurals).

### Inline markup parity

<AvailableFrom version="0.11.0" />

Rich text reaches a string as inline markup: a `<b>` in an i18next `Trans` block, an escaped
`&lt;b&gt;` in an Android `<string>`, an `<a href>` in a gettext catalog. A dropped or broken tag
breaks rendering, so the gate compares tag names and attribute names as a multiset:

- **Refused**: a dropped, invented or renamed tag; a changed set of attribute names (adding `dir`
  included); unbalanced or mis-nested markup; two tags merged into one.
- **Accepted**: the same tags in another order; a translated attribute value such as `title` or
  `alt`; `<br>` written as `<br/>`.
- **Guarded values**: a URL attribute must keep its scheme and host (`/docs` may become `/de/docs`,
  never `https://evil.example/docs`), a `javascript:` URL is refused, and values such as `style`,
  event handlers or a `<meta content>` must stay exactly as in the source.
- **Not translated**: the content of `script`, `style` and similar elements must come back
  unchanged. Escape such a tag in prose (`&lt;script&gt;`) to translate the text around it.

Markup invented into a string that had none is refused too, while an ordinary bracketed word such
as `<Enter>` is read as text. Tags the format already reports as placeholders are left to the
placeholder check. Comments, raw text and malformed sources: see [`markup`](/docs/error-codes#markup).

## Review flags

A second, advisory layer flags suspicious results for a person. A flag never withholds a key: the value is written,
locked, and put on the needs-review queue.

| Reason | Flags a translation that |
| --- | --- |
| [`LENGTH_RATIO_OUTLIER`](/docs/error-codes#length_ratio_outlier) | is far shorter or longer than its source, weighted by script |
| [`MAX_LENGTH_EXCEEDED`](/docs/error-codes#max_length_exceeded) | is longer than the key's [`maxLength`](/docs/config-file#maxlength) budget <AvailableFrom version="0.11.0" /> |
| [`EQUALS_SOURCE`](/docs/error-codes#equals_source) | is identical to its source text |
| [`GLOSSARY_TERM_MISSED`](/docs/error-codes#glossary_term_missed) | misses a glossary term's translation, or alters a do-not-translate term |
| [`GLOSSARY_FORBIDDEN_TERM`](/docs/error-codes#glossary_forbidden_term) | uses a rendering the glossary forbids <AvailableFrom version="0.12.0" /> |
| [`INTEGRITY_REORDERED`](/docs/error-codes#integrity_reordered) | keeps every placeholder but in another order |
| [`PROVIDER_DEGRADED`](/docs/error-codes#provider_degraded) | came from a batch the provider degraded, such as a dropped formality |
| [`FUZZY_CACHE_REUSE`](/docs/error-codes#fuzzy_cache_reuse) | was [reused from a similar, edited source](/docs/the-cache#fuzzy-reuse) <AvailableFrom version="0.11.0" /> |
| [`FOREIGN_PLACEHOLDER_CHANGED`](/docs/error-codes#foreign_placeholder_changed) | drops or changes a placeholder-like token its [format](/docs/formats) does not interpolate, such as `{name}` in i18next <AvailableFrom version="0.12.0" /> |
| [`BIDI_CONTROLS_CHANGED`](/docs/error-codes#bidi_controls_changed) | leaves a direction control unclosed, or adds an override that reverses text <AvailableFrom version="0.12.0" /> |

DeepL, Google and LibreTranslate get such a token masked, and withhold a value they cannot mask
or restore ([`PLACEHOLDER_UNSUPPORTED`](/docs/error-codes#placeholder_unsupported)); the flag covers LLMs and people.

Cache hits and values shared between keys go through the same heuristics as fresh translations.
Flagged keys appear per locale as `needsReview` on the run summary, in the workbook's review
columns, and on [Studio's Review page](/docs/review-in-studio). A key leaves the queue once a person
approves, rejects or rewrites its value; see
[Review decisions](/docs/the-lock-file#review-decisions).

## The token budget

With `maxTokens` configured, verbatra counts a run's tokens across every call and locale. `budgetBehavior: "warn"`
(the default) only flags an overrun; `"stop"` withholds the request that would pass the ceiling and
every candidate after it, to be retried next run.

What the budget guarantees: work done before the ceiling stays written and locked, and nothing is
left half-written. What it does not: a request in flight can cost more than projected, the ceiling
bounds one run (not a `watch` session), and Studio or agent retranslations are not covered. The
exact rules are under
[`maxTokens` and `budgetBehavior`](/docs/config-file#maxtokens-and-budgetbehavior).

## Errors never leak

When a provider call fails, the raw SDK error (which can carry request headers or credentials) is
discarded, never bound, logged or re-thrown. In its place verbatra raises a structured error with a
stable code and a fixed, secret-free message; the codes are under
[Provider error codes](/docs/error-codes#provider-error-codes). Where keys come from and how they are redacted is on
[Data handling](/docs/data-handling#api-keys).

## Where you see it

Everything above is data on the [run summary](/docs/sdk/run-summary), per locale, and one locale's
failure never stops the others.
