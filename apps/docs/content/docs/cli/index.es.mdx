`@verbatra/cli` incluye el binario `verbatra`, una capa fina sobre [`@verbatra/sdk`](/docs/sdk). Estos comandos hacen el trabajo:

<Cards>
  <Card title="init" href="/docs/cli/init">Crea una configuración de verbatra y un `.env.example` para este proyecto.</Card>
  <Card title="extract" href="/docs/cli/extract">Analiza el código de tu aplicación en busca de llamadas de traducción y añade las claves nuevas al archivo del locale de origen.</Card>
  <Card title="translate" href="/docs/cli/translate">Traduce cada locale de destino una vez y luego sale.</Card>
  <Card title="watch" href="/docs/cli/watch">Retraduce en cada cambio del origen hasta que lo interrumpas.</Card>
  <Card title="check" href="/docs/cli/check">Informa de qué claves faltan o están obsoletas por locale, solo lectura.</Card>
  <Card title="diff" href="/docs/cli/diff">Lista las claves exactas que se añadirían, se retraducirían o están huérfanas por locale, solo lectura.</Card>
  <Card title="report" href="/docs/cli/report">Imprime un informe de solo lectura: `report provenance` lista qué traducciones escribió una máquina y cuáles revisó una persona.</Card>
  <Card title="doctor" href="/docs/cli/doctor">Valida la configuración del proyecto e informa de todos los problemas a la vez, sin llamar a un proveedor.</Card>
  <Card title="pseudo" href="/docs/cli/pseudo">Genera un pseudolocale a partir de las cadenas de origen, sin llamar a un proveedor.</Card>
  <Card title="types" href="/docs/cli/types">Genera declaraciones de TypeScript para las claves de tu catálogo y los argumentos de sus mensajes, sin llamar a un proveedor.</Card>
  <Card title="export" href="/docs/cli/export">Exporta las cadenas sin traducir para un traductor humano, como libro de Excel, como un archivo CSV o TSV por locale o como un archivo XLIFF por locale para una herramienta TAO.</Card>
  <Card title="import" href="/docs/cli/import">Importa un libro rellenado o un archivo delimitado de vuelta a los archivos de locale.</Card>
  <Card title="tmx" href="/docs/cli/tmx">Importa una memoria de traducción TMX de otra herramienta a la memoria de este proyecto, o exporta la memoria de este proyecto como archivo TMX.</Card>
  <Card title="studio" href="/docs/cli/studio">Arranca Verbatra Studio, el panel local de traducción.</Card>
  <Card title="mcp" href="/docs/cli/mcp">Arranca un servidor MCP por stdio que expone las herramientas de verbatra a un cliente MCP.</Card>

## Instala e invoca

Instala `@verbatra/cli` como dependencia de desarrollo y luego ejecuta el binario a través de tu gestor de paquetes:

| Gestor de paquetes | Instalación | Ejecución |
| --- | --- | --- |
| npm | `npm install --save-dev @verbatra/cli` | `npx verbatra <command>` |
| pnpm | `pnpm add --save-dev @verbatra/cli` | `pnpm verbatra <command>` (o `pnpm exec verbatra <command>`) |
| yarn | `yarn add --dev @verbatra/cli` | `yarn verbatra <command>` |
| bun | `bun add --dev @verbatra/cli` | `bun run verbatra <command>` |

Necesitas Node.js `>=22.14.0`.

¿Quieres probar un comando antes de instalar? `npx @verbatra/cli <command>` (npm) o `pnpm dlx @verbatra/cli <command>` (pnpm) funcionan sin una instalación local previa.

## Flags globales

Estos flags significan lo mismo en cada comando que los acepta, así que las páginas de comandos solo listan sus propios flags. La última columna nombra los comandos que no aceptan un flag.

| Flag | Argumento | Por defecto | Efecto | No lo aceptan |
| --- | --- | --- | --- | --- |
| `--cwd` | `<path>` | directorio actual | resuelve la config y los archivos de locale desde este directorio; `init` escribe ahí sus archivos | ninguno |
| `--config` | `<path>` | buscar uno | carga este archivo de config en lugar de buscar uno; consulta el [orden de búsqueda](/docs/config-file) | `init` |
| `--json` | ninguno | desactivado | imprime un [sobre](/docs/cli/output#salida-json) legible por máquina en stdout, una línea por registro; los errores siguen yendo a stderr | `mcp`, `studio` |
| `-q`, `--quiet` | ninguno | desactivado | imprime solo resultados, avisos y errores: sin progreso, sugerencias ni líneas informativas; funciona antes o después del nombre del comando | ninguno |
| `--no-color` | ninguno | color en un terminal | nunca colorea la salida; consulta [Salida en el terminal](/docs/cli/output#salida-en-el-terminal) | ninguno |
| `-h`, `--help` | ninguno | desactivado | imprime la ayuda del programa o del comando y sale con `0` | ninguno |
| `-V`, `--version` | ninguno | desactivado | imprime la versión de la CLI y sale con `0` | ninguno |

Un comando o flag desconocido sale con `2`. `mcp` nunca escribe en stdout, porque stdout es su canal de protocolo, así que rechaza `--json` con `USAGE_ERROR`.

## Archivos de entorno

`translate`, `watch`, `doctor`, `studio` y `mcp` cargan `.env.local` y luego `.env` desde el directorio de trabajo antes de ejecutarse. `doctor --literals` es la excepción: no lee ninguna clave de API, así que no carga ninguno de los dos archivos. Una variable ya definida en tu entorno real siempre gana, y un valor en `.env.local` gana a la misma variable en `.env`. Las claves de API se leen solo del entorno, nunca del archivo de configuración ni de un flag: consulta [Proveedores](/docs/providers). Los comandos de solo lectura (`check`, `diff`, `report`), los comandos de entrega (`export`, `import`), `extract`, `init`, `pseudo`, `types` y `tmx` nunca llaman a un proveedor y no cargan archivos `.env`.
