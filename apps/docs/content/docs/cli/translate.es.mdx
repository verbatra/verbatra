---
title: verbatra translate
description: Traduce cada locale de destino una vez y luego termina.
type: reference
---
Ejecuta una pasada de traducción sobre cada locale de destino y termina. `translate` compara el origen con [el archivo de bloqueo](/docs/the-lock-file), envía al proveedor solo los strings nuevos o modificados, ejecuta las [comprobaciones de integridad](/docs/translation-safety), escribe los archivos de locale y actualiza el bloqueo. Nunca envía dos veces un string sin cambios.

## Sinopsis

```bash
verbatra translate [flags]
```

## Flags

| Flag | Argumento | Por defecto | Efecto |
| --- | --- | --- | --- |
| `--locales` | `<list>` | cada locale de destino configurado | traduce solo este subconjunto separado por comas; un locale no configurado falla con `UNKNOWN_LOCALE`, una lista vacía sale con `2` |
| `--dry-run` | ninguno | desactivado | informa de lo que cambiaría una ejecución sin llamar a un proveedor ni escribir archivos; no necesita clave de API |
| `--prune` | ninguno | la opción `prune` de la configuración, si no, desactivado | elimina las claves huérfanas (en un archivo de destino, ausentes del origen) del archivo escrito y del bloqueo |
| `--lock-timeout` | `<seconds>` | `600` | espera este tiempo por un bloqueo de escritura ocupado de un locale; un entero de `1` a `3600` |
| `--concurrency` | `<n>` | `1` | traduce hasta `n` locales de destino a la vez; un entero de `1` a `100`, rechazado con un presupuesto de tokens |
| `--max-tokens` | `<n>` | el `maxTokens` de la configuración | tope duro de tokens para esta ejecución; se aplica el menor entre este y el `maxTokens` de la configuración |
| `--no-cache` | ninguno | desactivado (caché activa) | omite la [caché de memoria de traducción](/docs/the-cache) (`verbatra.cache.json`) en esta ejecución |
| `--include-human` | ninguno | desactivado | retraduce también, solo en esta ejecución, las claves obsoletas que escribió o importó una persona; las [claves fijadas](/docs/protecting-human-translations#fijar-claves) no se tocan |
| `--estimate` | ninguno | desactivado | estima lo que la ejecución enviaría y costaría, y termina; implica `--dry-run` |

También acepta los [flags globales](/docs/cli#flags-globales) `--cwd`, `--config` y `--json`. Antes de ejecutarse, `translate` carga los [archivos de entorno](/docs/cli#archivos-de-entorno).

## Comportamiento

### Ejecución de prueba

`--dry-run` no construye ningún proveedor, así que no necesita clave de API y no puede gastar nada. Lee los archivos de origen y de destino, los compara con el archivo de bloqueo e informa exactamente de lo que cambiaría una ejecución real. No escribe nada (ni archivo de locale, ni actualización del bloqueo, ni instantánea del estado de ejecución), no lee ni escribe la caché y no toma ningún bloqueo de escritura, así que nunca espera a una ejecución en curso.

Por defecto una ejecución no borra nada: las claves huérfanas se informan y se quedan donde están. `--prune` elimina exactamente esas claves, y `--prune --dry-run` te las muestra antes.

### Estimación de coste

<AvailableFrom version="0.12.0" />

`--estimate` añade a la ejecución de prueba una estimación previa: cuántas claves se enviarían, cuántas peticiones al proveedor serían y la cantidad que factura el proveedor (tokens en un LLM, caracteres de origen en DeepL o Google Cloud Translation, nada en un endpoint `openai-compatible` autoalojado o en un proyecto solo humano). Una cifra en moneda solo aparece cuando la configuración tiene un bloque `rates` que cubre el proveedor y el modelo; si no, se nombra la clave de tarifa que falta en lugar de inventar `0.00`. Consulta [Estimar el coste](/docs/estimating-cost).

### Un subconjunto de locales

<AvailableFrom version="0.11.0" />

`--locales de,fr` limita la ejecución a una parte de los destinos configurados. Los demás locales conservan sus archivos, sus entradas de bloqueo y sus entradas de caché. Úsalo en un plan gratuito con límite de peticiones para traducir un locale cada vez, o para repetir un único locale que salió parcial. La instantánea del estado de ejecución describe entonces solo ese subconjunto.

### Bloqueos de escritura e interrupciones

Un locale espera hasta `--lock-timeout` por un [bloqueo de escritura](/docs/the-lock-file#el-bloqueo-de-escritura) ocupado y luego falla con `LOCK_CONTENDED`, mientras los demás locales siguen. Un bloqueo que dejó un proceso de verbatra que ya no corre en esta máquina se recupera al momento. El timeout solo limita esa espera, anterior a cualquier llamada al proveedor: registrar un archivo escrito en el archivo de bloqueo espera siempre hasta el valor por defecto de diez minutos, para que ningún archivo escrito quede sin registrar. Ctrl-C o SIGTERM liberan los bloqueos de la ejecución antes de que el comando termine.

### Tope de tokens

<AvailableFrom version="0.12.0" />

`--max-tokens` siempre es una parada dura: una petición al proveedor que superaría el tope se retiene, diga lo que diga `budgetBehavior`, y sus claves aparecen como `budgetWithheld`. Se cuenta igual que un [presupuesto `maxTokens`](/docs/config-file#maxtokens-y-budgetbehavior) configurado y puede endurecer ese presupuesto, nunca relajarlo. Una ejecución que el tope dejó a medias sale con `1`. Ejecuta antes `--estimate` para elegir una cifra.

### Locales en paralelo

`--concurrency` se rechaza con salida `2` cuando hay un presupuesto de tokens (de `maxTokens` o de `--max-tokens`), porque el orden en que se intercalan los locales decidiría cuál pierde el trabajo restante; una ejecución de prueba queda exenta. Si aparece un error de toda la ejecución, como un archivo de bloqueo dañado, mientras hay locales en marcha, no empieza ninguno más, y los que están en curso terminan y liberan sus bloqueos antes de que el comando salga con `2`.

### Claves que escribió una persona

<AvailableFrom version="0.12.0" />

Una clave obsoleta cuyo valor escribió, importó o cambió una persona fuera de verbatra se conserva por defecto: aparece como `protected`, no se envía al proveedor y sigue obsoleta para `verbatra check`. Una línea en stderr dice cuántas se conservaron y remite a `--include-human`, que las retraduce durante una ejecución (`humanEdits: "overwrite"`). Las claves protegidas no cambian el código de salida, salvo en un proyecto solo humano. Consulta [Proteger las traducciones humanas](/docs/protecting-human-translations).

### Proyectos solo humanos

<AvailableFrom version="0.12.0" />

En un proyecto [solo humano](/docs/human-only-workflow) (`provider: { id: "none" }`) no se llama a ningún proveedor. Las claves que cubre la memoria de traducción se escriben, y cualquier otra clave ausente o modificada aparece como `unfilled` y da salida `3`; un locale fallido o parcial sigue ganando con `1`. Aquí una ejecución de prueba sí lee la memoria, así que su plan muestra las mismas claves `cacheHits` y `unfilled`, y `--estimate` no informa de nada facturado; ambos salen con `3` igual. Pasa las claves `unfilled` a una persona con [`verbatra export`](/docs/cli/export).

### Locales fallidos y parciales

<AvailableFrom version="0.9.0" />

Que falle un locale no es fatal: la ejecución termina y sale con `1`. Un locale **parcial** también sale con `1`: su archivo se escribió pero aún faltan claves, normalmente porque falló un sublote del proveedor o la puerta de integridad rechazó una traducción. La salida legible lista cada clave rechazada bajo `integrity-withheld` con su motivo (`placeholder`, `markup`, `icu`, `degenerate` o `empty`); con `--json`, cada locale los lleva en `integrityRefusals`.

### Locales no admitidos

<AvailableFrom version="0.12.0" />

Un locale que el proveedor DeepL o Google Cloud Translation configurado no admite rechaza toda la ejecución con `LOCALE_UNSUPPORTED_BY_PROVIDER` y salida `2`, también en una ejecución de prueba y con `--estimate`, antes de gastar nada. Déjalo fuera con `--locales` o consulta [Soporte de idiomas](/docs/language-support#comprobar-el-soporte-antes-de-una-ejecución). Un glosario o un tono que el proveedor no puede aplicar solo añade un aviso (`GLOSSARY_UNSUPPORTED_BY_PROVIDER`, `FORMALITY_UNSUPPORTED_BY_PROVIDER`), igual que `LOCALE_UNVERIFIED_BY_PROVIDER` y, en un LLM, `LOCALE_NOT_WELL_TESTED`.

### Salida JSON

Con `--json`, stdout lleva un [sobre](/docs/cli/output#salida-json) cuyo `result` es un `RunSummary`:

```ts
interface RunSummary {
  dryRun: boolean;          // whether this was a dry run (no provider calls, no writes)
  locales: LocaleSummary[]; // one entry per target locale, in config order
  succeeded: string[];      // locales whose run succeeded
  partial: string[];        // locales written with keys still missing; these exit 1 too
  failed: string[];         // locales whose run failed
  usage?: UsageSummary;     // summed input/output tokens; absent when no call reported usage
  budget?: RunBudget;       // the token-budget outcome; present only when maxTokens is configured
  estimate?: RunEstimate;   // the pre-run cost estimate; present only when --estimate was passed
}
```

Cada `LocaleSummary` lleva las listas de claves por locale (traducidas, sin cambios, huérfanas, retenidas, marcadas para revisión y más); la forma completa está en [la referencia del SDK](/docs/sdk/run-summary).

### Información en el terminal

<AvailableFrom version="0.12.0" />

`translate` nombra los locales y el proveedor antes de la ejecución, y después imprime el tiempo transcurrido, los tokens usados y el siguiente comando. En un terminal interactivo el progreso es una línea con spinner; cuando stderr está redirigido, cada paso es una línea propia:

```text output
verbatra: translating 2 locales with gemini/gemini-2.5-flash
verbatra: translating de
verbatra: de batch 1/1
verbatra: de: writing
verbatra: de done, 12 translated
verbatra: translating fr
verbatra: fr batch 1/1
verbatra: fr: writing
verbatra: fr done, 12 translated
verbatra: run finished, 2 locales processed
[ok] done in 4.2s, 1830 tokens
next: verbatra check (confirm every locale is in sync)
```

Una ejecución de prueba o una estimación termina cada locale con `would translate`. Un locale que falla termina con `failed`, y la línea final indica cuántos fallaron. Estas líneas van a stderr, y `--quiet` las omite. Consulta [Salida en el terminal](/docs/cli/output#salida-en-el-terminal).

## Ejemplos

```bash
# traduce una vez con la configuración que encuentre
verbatra translate

# muestra las claves que se eliminarían, sin gastar nada
verbatra translate --prune --dry-run

# un locale cada vez, que es lo que necesita un plan gratuito con límite
verbatra translate --locales de

# dimensiona y pon precio a la ejecución sin gastar nada
verbatra translate --estimate

# para antes de que la ejecución supere 50000 tokens
verbatra translate --max-tokens 50000

# retraduce también las claves obsoletas que escribió una persona
verbatra translate --include-human
```

## Códigos de salida

| Código | Significado |
| --- | --- |
| `0` | todos los locales de destino quedaron completos |
| `1` | la ejecución terminó, pero un locale falló o quedó parcial |
| `2` | no pudo ejecutarse: un error de configuración, origen, formato, proveedor, locale no admitido o archivo de bloqueo, o un error de uso |
| `3` | proyecto solo humano: la ejecución (también de prueba o con `--estimate`) terminó limpia, pero quedan claves para una traducción humana |
| `130` | interrumpido con Ctrl-C (SIGINT) tras liberar los bloqueos de escritura |
| `143` | detenido con SIGTERM tras liberar los bloqueos de escritura |

Tras una interrupción, stderr termina con `verbatra: interrupted (SIGINT), released locks`, o con `--json` con el registro `{"type":"interrupted","signal":"SIGINT","locksReleased":true}`. Consulta [el contrato de códigos de salida](/docs/cli/output#códigos-de-salida).
