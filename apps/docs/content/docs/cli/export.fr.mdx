---
title: verbatra export
description: Exporte les chaînes non traduites dans une remise pour traducteurs, sous forme de classeur Excel stylisé ou d'un fichier CSV ou TSV par locale.
---
Écris les chaînes à traduire dans un classeur Excel stylisé qu'un humain peut remplir et renvoyer pour [`verbatra import`](/docs/cli/import). Par défaut, le classeur ne porte que les chaînes manquantes et modifiées : les mêmes clés qu'une exécution automatisée enverrait à un fournisseur. `export` n'appelle jamais de fournisseur et n'a besoin d'aucune clé d'API.

## Synopsis

```bash
verbatra export [flags]
```

## Options

| Option | Argument | Défaut | Effet |
| --- | --- | --- | --- |
| `--cwd` | `<path>` | répertoire courant | résout la config et les fichiers de locale depuis ce répertoire |
| `--config` | `<path>` | recherche automatique | charge ce fichier de config au lieu d'en chercher un |
| `--out` | `<path>` | `verbatra-translations.xlsx`, ou `verbatra-translations` avec `csv` et `tsv` | écrit la remise ici : un chemin de fichier avec `xlsx`, un répertoire avec `csv` et `tsv` |
| `--format` | `<format>` | `xlsx` | écrit un classeur Excel (`xlsx`) ou un fichier délimité par locale (`csv`, `tsv`) |
| `--locales` | `<list>` | toutes les cibles configurées | sous-ensemble de locales cibles à exporter, séparées par des virgules |
| `--include-unchanged` | aucun | désactivé | exporte aussi les chaînes déjà à jour |
| `--json` | aucun | désactivé | affiche une [enveloppe JSON](/docs/ci-and-exit-codes#sortie-json) sur stdout portant le résultat d'export (chemin et nombre de lignes par locale) sous `result`, ou le code d'erreur si l'exécution échoue ; la ligne d'erreur lisible par un humain va toujours sur stderr |

Une valeur `--locales` vide ou inconnue est rejetée avec le code de sortie `2` plutôt que de ne rien exporter en silence.

## Exemples

```bash
# write the workbook with missing and changed strings
verbatra export

# only the German and French sheets, to a specific path
verbatra export --locales de,fr --out handoff/round-2.xlsx

# one de.csv and fr.csv under handoff/
verbatra export --format csv --out handoff
```

## CSV et TSV

`--format csv` et `--format tsv` écrivent du texte brut au lieu d'un classeur : un `<locale>.csv` ou `<locale>.tsv` par locale exportée, avec les mêmes colonnes dans le même ordre qu'une feuille du classeur. `--out` désigne alors le répertoire où les fichiers sont écrits, et ce répertoire est créé s'il n'existe pas.

Un fichier délimité se lit dans un diff et s'ouvre partout, mais il ne porte aucune protection de cellule : chaque colonne est modifiable et la colonne `Source hash` est visible. Un hash modifié n'est jamais considéré comme fiable : l'import le compare à la source réelle et retient la ligne.

Chaque export délimité écrit en plus un manifeste caché dans le répertoire, `.verbatra-export-csv.json` ou `.verbatra-export-tsv.json`, qui nomme les locales qu'il vient d'écrire. C'est ce qui permet à un nouvel export avec une sélection `--locales` plus étroite de retirer du service les locales qu'il abandonne : leurs fichiers restent sur le disque, et [`verbatra import`](/docs/cli/import) les refuse comme des reliquats au lieu d'appliquer une traduction périmée. L'export ne supprime rien du répertoire de sortie, un fichier que tu y as placé n'est donc jamais en danger.

## Codes de sortie

| Code | Signification |
| --- | --- |
| `0` | la remise a été écrite |
| `2` | impossible de s'exécuter : une erreur globale, ou une erreur d'utilisation (y compris une valeur `--locales` vide ou inconnue) |

`export` n'a pas de mode d'échec par locale, donc il ne sort jamais avec `1`.
