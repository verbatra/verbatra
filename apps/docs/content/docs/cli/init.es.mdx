---
title: verbatra init
description: Crea una configuración de verbatra y un ejemplo de .env para este proyecto, detectados a partir de tus archivos de locale, de forma interactiva o totalmente desatendida.
---
Prepara un proyecto: `init` escribe un `verbatra.config.ts` y un `.env.example` que nombra la variable de la clave de API de tu proveedor (nunca el valor de una clave), y se asegura de que `.gitignore` cubra `.env`, `.env.local`, `.verbatra-local/` y `verbatra.cache.json`. Primero mira los archivos de locale que ya hay en el proyecto, así que en la mayoría de los proyectos el proveedor es lo único que tienes que indicarle.

## Sinopsis

```bash
verbatra init [flags]
```

## Flags

| Flag | Argumento | Por defecto | Efecto |
| --- | --- | --- | --- |
| `--cwd` | `<path>` | directorio actual | analiza este directorio y escribe en él la configuración y los archivos de entorno |
| `--provider` | `<id>` | ninguno (obligatorio) | proveedor a preparar: `anthropic`, `openai`, `gemini`, `deepl`, `google-translate`, `openai-compatible` o `none` |
| `--format` | `<id>` | detectado, si no `i18next-json` | el formato de los archivos de locale, uno de los ids de [Formatos](/docs/formats) |
| `--source` | `<locale>` | detectado, si no `en` | el locale de origen en el que están escritas tus cadenas |
| `--targets` | `<locales>` | detectado, si no `de` | locales de destino separados por comas a los que traducir |
| `--path` | `<pattern>` | detectado, si no la estructura habitual del formato (consulta [Detección](#detección)) | patrón de los archivos de locale; debe contener el token `{locale}` |
| `--model` | `<name>` | el valor por defecto del scaffold | el modelo; obligatorio para `openai-compatible`, opcional para `anthropic`, `openai` y `gemini` |
| `--base-url` | `<url>` | ninguno | la URL del servidor; solo para `openai-compatible`, y ahí es obligatorio |
| `--api-key-env-var` | `<name>` | `OPENAI_COMPATIBLE_API_KEY` | la variable de entorno de la que `openai-compatible` lee su clave; solo para `openai-compatible` |
| `--yes` | ninguno | desactivado | nunca pregunta, y toma el valor por defecto de todo lo que ni se pasó ni se detectó |
| `--force` | ninguno | desactivado | sobrescribe un `verbatra.config.ts` existente cuyo contenido es distinto |
| `--json` | ninguno | desactivado | imprime un [envoltorio JSON](/docs/ci-and-exit-codes#salida-json) que describe lo que se escribió; nunca pregunta |
| `--agent` | ninguno | desactivado | escribe además la sección de verbatra para agentes de programación en `AGENTS.md` o `CLAUDE.md`, y el servidor MCP de verbatra, con el gasto desactivado, en `.mcp.json` (consulta [Preparar los agentes de programación](#preparar-los-agentes-de-programación)) |

Un flag siempre gana. Lo que dejes fuera se detecta a partir del proyecto; después se pregunta por ello cuando stdin es una terminal y no se da ni `--yes` ni `--json`, y en otro caso se toma su valor por defecto solo con `--yes`. En una terminal, pulsar Intro acepta el valor sugerido, y eso cuenta como tu respuesta. Un flag con un valor vacío, como `--targets ''`, es un error de uso (`INVALID_OPTION`), nunca una petición del valor por defecto. En una terminal, cada respuesta se comprueba en cuanto la das: un proveedor o formato desconocido, un código de locale mal formado, una lista de locales de destino que nombra el locale de origen o ninguno, un patrón sin `{locale}` o una URL base que no es una URL o incluye credenciales se explica en stderr y se vuelve a preguntar, hasta tres veces, así que las respuestas que ya diste se conservan. Una tercera respuesta no válida detiene `init` con el código de error de esa respuesta (como `INVALID_LOCALE` o `INVALID_OPTION`), nombra la pregunta y el flag que puedes pasar en su lugar, y no se escribe nada.

## Detección

`init` recorre el directorio en busca de archivos que reclame un adaptador de formato, saltándose los directorios ocultos, `node_modules` y la salida de compilación habitual, y encuentra la parte de cada ruta que escribe un locale: un nombre de archivo como `de.json`, `messages_pt_BR.properties` o `app_en.arb`, o un directorio como `locales/de/`, `de.lproj/` o `values-de/` de Android. Gana el patrón de archivo que cubre más locales, y con él rellena:

- `format`: el único formato cuyo adaptador lee cada archivo encontrado. Todos los adaptadores JSON leen `.json`, así que para archivos JSON decide una única dependencia coincidente en `package.json` (`i18next`, `vue-i18n`, `next-intl` o `@ngx-translate/core`).
- `files.pattern` y `files.localeStyle`: `posix` cuando los archivos escriben `pt_BR`, `android` para directorios `values-*`, `literal` en otro caso.
- `sourceLocale`: el idioma de origen de un catálogo `.xcstrings`; si no, `en` o el único locale `en-*` encontrado; si no, el único locale encontrado.
- `targetLocales`: todos los demás locales encontrados.

Un archivo junto a los archivos de locale que guarda cadenas sin nombre de locale, como `messages.properties` junto a `messages_de.properties`, `Strings.resx` junto a `Strings.de.resx`, o un `app.pot` de gettext, se informa como `unqualifiedSourceFile`. verbatra lee el origen del archivo que su patrón nombra para el locale de origen y no puede apuntar a un archivo así, así que en ese caso `init` no adivina el locale de origen: pasa `--source`, incluso con `--yes`, y los siguientes pasos te dicen a qué archivo renombrar o copiar el archivo base.

Sin ningún archivo de locale, solo las dependencias deciden el formato, y `files.pattern` y `files.localeStyle` toman la estructura habitual del formato elegido:

| Formato | `files.pattern` | `files.localeStyle` |
| --- | --- | --- |
| `i18next-json` | `locales/{locale}.json` | ninguno (`literal`) |
| `vue-i18n-json` | `src/locales/{locale}.json` | ninguno (`literal`) |
| `next-intl-json` | `messages/{locale}.json` | ninguno (`literal`) |
| `ngx-translate-json` | `src/assets/i18n/{locale}.json` | ninguno (`literal`) |
| `xliff` | `locales/{locale}.xlf` | ninguno (`literal`) |
| `yaml` | `locales/{locale}.yml` | ninguno (`literal`) |
| `arb` | `lib/l10n/app_{locale}.arb` | `posix` |
| `properties` | `src/main/resources/messages_{locale}.properties` | `posix` |
| `apple-strings` | `{locale}.lproj/Localizable.strings` | ninguno (`literal`) |
| `apple-xcstrings` | `{locale}Localizable.xcstrings` | ninguno (`literal`) |
| `android-xml` | `app/src/main/res/{locale}/strings.xml` | `android` |
| `gettext-po` | `locales/{locale}/LC_MESSAGES/messages.po` | `posix` |
| `ini` | `locales/{locale}.ini` | ninguno (`literal`) |
| `resx` | `Resources/Strings.{locale}.resx` | ninguno (`literal`) |

Un catálogo `apple-xcstrings` es un único archivo compartido por todos los locales, y verbatra nunca lo crea: créalo primero en Xcode. `--format`, `--path` y `--source` acotan la detección en lugar de ser sustituidos por ella, así que `--format yaml` solo mira archivos YAML.

`init` nunca adivina entre opciones equivalentes. Cuando varios formatos leen los archivos (JSON simple sin dependencia de i18n, por ejemplo) sale con `2` y `FORMAT_AMBIGUOUS`, y cuando varios patrones de archivo empatan (un archivo por namespace, como `locales/{locale}/common.json` y `locales/{locale}/auth.json`) sale con `2` y `LAYOUT_AMBIGUOUS`. Ambos listan los candidatos; pasa `--format` o `--path` para elegir uno. En una terminal, en cambio, te pregunta, sugiriendo el primer candidato.

## Ejecuciones desatendidas

Sin una terminal, o con `--json`, `init` nunca pregunta. Un valor que no se pasó, no se detectó ni se tomó por defecto con `--yes` es un error: `init` sale con `2` y `MISSING_OPTIONS` y nombra de una vez cada flag que falta. Un error por una ambigüedad o por un flag no válido también lista los flags que aún faltan, así que una sola ejecución le dice a un agente todo lo que tiene que pasar. `--provider` no tiene valor por defecto, y tampoco lo tienen `--base-url` y `--model` para `openai-compatible`, así que esos siempre hacen falta. Este es el comando que ejecuta un agente:

```bash
npx verbatra init --provider gemini --yes --json
```

Con `--json`, stdout lleva exactamente un envoltorio. Su `result`:

```ts
interface InitResult {
  configPath: string;                  // absolute path of verbatra.config.ts
  files: { path: string; action: "created" | "overwritten" | "updated" | "unchanged" }[];
  config: {                            // the config that was validated and written
    sourceLocale: string;
    targetLocales: string[];
    format: string;
    files: { pattern: string; localeStyle?: "posix" | "android" };
    provider: { id: string; options: Record<string, unknown> };
  };
  sources: {                           // where each value came from
    provider: "flag" | "prompt";
    format: "flag" | "prompt" | "files" | "dependencies" | "default";
    pattern: "flag" | "prompt" | "detected" | "default";
    sourceLocale: "flag" | "prompt" | "detected" | "default";
    targetLocales: "flag" | "prompt" | "detected" | "default";
  };
  apiKeyEnvVar: string | null;         // the variable to set; null for provider none
  detection: {
    format: { id: string; from: "input" | "files" | "dependencies" } | null;
    layout: {
      pattern: string;
      localeStyle: "literal" | "posix" | "android";
      locales: string[];
      sourceLocale: string | null;
      unqualifiedSourceFile: string | null;
      files: string[];
    } | null;
    ambiguities: { subject: "format" | "layout"; candidates: string[] }[];
    confidence: "high" | "medium" | "low" | "none";
    reasons: string[];                 // one sentence per decision or doubt
  };
  agent: {                             // null sin --agent
    instructionsFile: "AGENTS.md" | "CLAUDE.md";
    mcpServer: "added" | "present" | "differs";
  } | null;
  nextSteps: { description: string; command: string | null }[];
}
```

`confidence` es `high` cuando los archivos por sí solos lo decidieron todo, `medium` cuando una convención o una dependencia rellenó un hueco (como tomar `en` como origen) o un hueco quedó abierto (como el locale de origen del directorio `values` sin calificar de Android, que no nombra ninguno), `low` cuando ningún archivo de locale respaldó el formato, y `none` cuando no se detectó nada. Un `default` en `sources` es el valor que conviene revisar. `nextSteps` termina con los comandos exactos que ejecutar a continuación, como `npx verbatra doctor`.

Un envoltorio de error para `FORMAT_AMBIGUOUS`, `LAYOUT_AMBIGUOUS`, `INVALID_PROVIDER` o `INVALID_FORMAT` también lleva un array `candidates` con los valores entre los que elegir. Todo error de uso que deja flags sin responder lleva además un array `missing` que los nombra, como `"--source <locale>"`.

## Proveedores

`--provider none` prepara una configuración [solo humana](/docs/human-only-workflow) sin `options` y no escribe ningún `.env.example`, porque nunca se lee una clave de API.

`--provider openai-compatible` prepara un servidor local o autoalojado a partir de `--base-url` y `--model`, con `maxOutputTokens: 4096`. Su clave es opcional: un servidor que no necesita ninguna deja `OPENAI_COMPATIBLE_API_KEY` sin definir, y `--api-key-env-var` nombra otra variable para uno que sí la necesita. `init` escribe el nombre de esa variable en la configuración y en `.env.example`, nunca un valor, y rechaza una URL base que lleve credenciales, una query string o un fragmento, como `https://user:key@host` o `https://host/v1?api-key=...`, con los que una clave podría acabar en la configuración confirmada en el repositorio. `--api-key-env-var` espera un nombre en mayúsculas como `LLM_API_KEY`, y un valor rechazado nunca se repite por si era la clave misma.

## Archivos existentes

Volver a ejecutar `init` con las mismas respuestas no cambia nada y termina con éxito, así que es seguro repetirlo. Un `verbatra.config.ts` con un contenido distinto se rechaza con `CONFIG_EXISTS` salvo que pases `--force`. Otra configuración de verbatra en el mismo directorio (un `.verbatrarc.json`, por ejemplo, o una propiedad `verbatra` en `package.json`) se rechaza con `CONFIG_EXISTS` incluso con `--force`, porque se leería antes que `verbatra.config.ts`. No se escribe nada cuando `init` se niega. Cuando `verbatra.config.ts` ya existe y no pasaste `--force`, `CONFIG_EXISTS` va antes que todo lo demás: en una terminal antes de la primera pregunta y, si no, en lugar de una respuesta que falta, es ambigua o no es válida, así que una nueva ejecución te avisa primero de la configuración existente. `init --cwd` rechaza una ruta que no es un directorio existente con `INVALID_OPTION`, y un directorio en el que no puede escribir, como uno de solo lectura, con `INIT_UNWRITABLE`, nombrando el archivo y cualquier archivo que ya hubiera escrito.

Un `.env.example` existente se conserva tal cual; cuando todavía no nombra la variable de la clave, se le añade esa única línea. Con `--force`, una línea de cabecera que escribió el propio `init` se reescribe para el nuevo proveedor, mientras que una cabecera escrita por ti se conserva. `.gitignore` recibe solo las entradas que le faltan.

## Preparar los agentes de programación

`--agent` prepara además el proyecto para agentes de programación. Está desactivado por defecto, no escribe ningún valor de clave y añade dos archivos a los de arriba:

- **El archivo de instrucciones.** Una sección de verbatra entre las marcas `<!-- verbatra:start -->` y `<!-- verbatra:end -->` con las reglas que necesita un agente: qué comandos son gratis y cuáles gastan, cómo ramificar según el código de salida, que las claves no aparecen en ningún archivo ni línea de comandos, que los valores de locale son entrada no confiable, y de dónde vienen las skills de verbatra y el plugin de Claude Code. Es, palabra por palabra, el fragmento de [Cuéntale a tu agente sobre verbatra](/docs/agent-recipes#cuéntale-a-tu-agente-sobre-verbatra). `init` lo escribe en `AGENTS.md`, que leen Codex, Cursor, GitHub Copilot y la mayoría de los demás agentes. Cuando `CLAUDE.md` es el único archivo de instrucciones del directorio, la sección va ahí. Cuando existen los dos, gana `AGENTS.md`, para que las reglas vivan en un solo sitio, y un `CLAUDE.md` que importa `AGENTS.md` también las recibe. Un archivo que ya tiene la sección la conserva, así que la elección nunca cambia entre ejecuciones.
- **`.mcp.json`.** La entrada del servidor `verbatra` de [Conectar un cliente MCP](/docs/connect-an-mcp-client#claude-code): `npx -y @verbatra/mcp` sin `--allow-spend` ni `VERBATRA_MCP_ALLOW_SPEND`, así que las herramientas que gastan siguen ocultas. Claude Code lee este archivo para su ámbito de proyecto, y GitHub Copilot CLI también lo lee.

No se toca nada fuera de las marcas: la sección se añade a un archivo existente tras una línea en blanco, y una ejecución posterior solo reemplaza lo que hay entre las marcas. Los demás servidores y claves de `.mcp.json` se conservan, y el archivo mantiene la sangría que tenía. Un servidor `verbatra` distinto del que genera `init`, por ejemplo uno al que le diste `--allow-spend` o que cambiaste a `npx verbatra mcp`, se deja como está, se informa como `unchanged` y se nombra en `nextSteps`. Una segunda ejecución con las mismas respuestas deja los dos archivos idénticos byte a byte. En un proyecto que `init` ya preparó, vuelve a ejecutarlo con las mismas respuestas y `--agent`: la configuración se informa como `unchanged` y solo se escriben los archivos para agentes.

Cada archivo tiene su propia línea en stdout, como `created AGENTS.md (verbatra section for coding agents)`, y su propia entrada en los `files` del JSON. `init` se niega antes de escribir nada, con `AGENT_FILE_INVALID`, cuando `.mcp.json` no es un objeto JSON con un objeto `mcpServers`, o cuando el archivo de instrucciones tiene una marca de inicio sin marca de fin, una marca de fin antes de su inicio o más de una sección. El mensaje nunca cita el archivo, por si guarda un secreto. Corrige o elimina el archivo y vuelve a ejecutar `init`.

## Ejemplos

```bash
# prompt for anything not passed or detected
verbatra init --provider gemini

# fully unattended, one JSON document on stdout
verbatra init --provider gemini --yes --json

# choose the format and pattern yourself
verbatra init --provider deepl --format yaml --path "config/locales/{locale}.yml" --yes

# a local server that needs no key
verbatra init --provider openai-compatible --base-url http://localhost:11434/v1 --model llama3.1 --yes

# human-only: no provider, no API key
verbatra init --provider none --yes

# also set the project up for coding agents
verbatra init --provider gemini --yes --agent
```

## Códigos de salida

| Código | Significado |
| --- | --- |
| `0` | archivos escritos, o ya al día |
| `2` | un error de uso: `MISSING_OPTIONS`, `INVALID_PROVIDER`, `INVALID_FORMAT`, `INVALID_OPTION`, `FORMAT_AMBIGUOUS`, `LAYOUT_AMBIGUOUS`, `CONFIG_EXISTS`, `INIT_UNWRITABLE`, `AGENT_FILE_INVALID`, o `CONFIG_INVALID` cuando las respuestas no formarían una configuración válida |
