title: verbatra watch
description: Re-translate on every source change until interrupted.

Watch the source locale file and re-run a translation after each debounced change, until you interrupt it. `watch` runs an initial translation at startup, then keeps your target locales current as you save. Each run works exactly like [`verbatra translate`](/docs/cli/translate).

## Synopsis

```bash
verbatra watch [flags]
```

## Flags

| Flag | Argument | Default | Effect |
| --- | --- | --- | --- |
| `--locales` | `<list>` | every configured target locale | watch only this comma-separated subset; checked once at startup, where an unconfigured locale fails with `UNKNOWN_LOCALE` |
| `--debounce` | `<ms>` | `300` | wait this many milliseconds after the last change before translating; a whole number from `1` to `60000` |
| `--lock-timeout` | `<seconds>` | `600` | wait this long for a held per-locale write lock in each run; a whole number from `1` to `3600` |
| `--concurrency` | `<n>` | `1` | translate up to `n` target locales at once per run; a whole number from `1` to `100`, refused under a `maxTokens` budget |
| `--no-cache` | none | off (cache on) | bypass the [translation-memory cache](/docs/the-cache) (`verbatra.cache.json`) on every run |

Also takes the [global flags](/docs/cli#global-flags) `--cwd`, `--config` and `--json`; here `--json` prints one record per run. Before it starts, `watch` loads `.env.local` and then `.env` from the working directory; a variable already set in the real environment wins.

## Behavior

### Each run

Every run translates the `--locales` subset, or every target, with a fresh token budget. A locale whose [write lock](/docs/the-lock-file) stays contended past `--lock-timeout` fails with `LOCK_CONTENDED` in that run's summary while the other locales still run; a lock left by a verbatra process that is no longer running is reclaimed at once. A failed run never stops the watcher.

A `--concurrency` above `1` together with a configured `maxTokens` budget is refused at startup with exit `2`, before the initial run, because which locale loses its remaining work would depend on how the locales interleave.

### Stopping

<AvailableFrom version="0.12.0" />

The first interrupt (Ctrl-C or SIGTERM) lets the current run finish, stops the watcher, and exits `0`. A second interrupt while that shutdown is still in flight force-stops with exit `130`, after releasing the session's write locks. Without `--json`, stderr says `verbatra: waiting for changes...` after every run, `verbatra: press Ctrl-C to stop` after the startup line on an interactive terminal, and `verbatra: stopped` once the shutdown has finished.

### JSON output

With `--json`, stdout is NDJSON: one [envelope](/docs/cli/output#json-output) per run, with `command: "watch"`. A succeeded run is an `ok: true` record carrying that run's [`RunSummary`](/docs/cli/translate#json-output); a failed run is an `ok: false` record with the failure's own code, or `WATCH_RUN_FAILED` when it had none, plus its `hint` when it has one. A failed run is only a record: it neither stops the watcher nor changes the exit code. The startup line, the stopping notice and progress go to stderr. Without `--json`, a run's summary goes to stdout and a failed run's `verbatra: error [CODE] message` line to stderr.

### Terminal feedback

<AvailableFrom version="0.12.0" />

Without `--json`, `watch` names the source file once a change to it has settled, then reports the run as `translate` does, with the same spinner on an interactive terminal:

```text output
verbatra: change detected: locales/en.json
verbatra: translating de
verbatra: de batch 1/1
verbatra: de: writing
verbatra: de done, 1 translated
verbatra: run finished, 1 locale processed
verbatra: waiting for changes...
```

These lines go to stderr, and `--quiet` drops them. See [Terminal output](/docs/cli/output#terminal-output).

## Examples

```bash
# watch and re-translate on each change
verbatra watch

# calmer in a busy editor: wait 1s after the last change, stream NDJSON
verbatra watch --debounce 1000 --json

# keep only German current while you work
verbatra watch --locales de
```

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | stopped cleanly by a single interrupt |
| `2` | could not start or stop: a config error, a startup or shutdown failure, or a usage error such as an invalid `--debounce` |
| `130` | force-stopped by a second interrupt |

A failed run during the session never changes the exit code. See [the exit-code contract](/docs/cli/output#exit-codes).
