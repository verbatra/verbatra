<AvailableFrom version="0.11.0" />

Run your app in a language that does not exist. `pseudo` builds a fake locale from your source strings: every value is accented, lengthened and wrapped in visible markers, so clipped buttons, concatenated sentences and unextracted labels stand out. It constructs no provider, reads no API key and makes no network request, so it works before any key exists.

## Synopsis

```bash
verbatra pseudo [flags]
```

## Flags

| Flag | Argument | Default | Effect |
| --- | --- | --- | --- |
| `--locale` | `<code>` | `en-XA` | the pseudolocale to generate; letters, digits and hyphens only (`INVALID_LOCALE` otherwise) |
| `--out` | `<path>` | `.verbatra-local/pseudo` | directory to write the pseudolocale under, relative to the working directory and inside it |

Also takes the [global flags](/docs/cli#global-flags) `--cwd`, `--config` and `--json`.

## Behavior

### What the transform does

| Step | What you see |
| --- | --- |
| Accent | every ASCII letter becomes an accented look-alike, so `Save` reads `Śáṽé` |
| Expand | the value grows by about a third of its translatable length, roughly what German needs over English |
| Mark | the value is wrapped in `[` and `]`, so a clipped or concatenated string is obvious |

`Hello {{name}}, you have {{count}} unread messages` becomes
`[Ĥéĺĺó {{name}}, ýóú ĥáṽé {{count}} úńŕéáḋ ṁéśśáġéś······]`.

Only translatable text changes. Placeholders survive in every syntax the [format adapters](/docs/formats) recognise, and inside an ICU message the argument names, `plural` and `select` keywords and branch selectors stay as written. vue-i18n pipe-separated plural forms are transformed one by one: `car | cars` becomes `[ćáŕ··] | [ćáŕś··]`. The transform is deterministic, so the file diffs cleanly.

### Nothing broken ever reaches the file

Every generated value passes the same integrity gate as a provider's translation: same placeholders as the source, valid message syntax, not degenerate, not blank. A value that would fail is copied from the source verbatim and named under `copied verbatim`; that is a report, not a failure.

### Where the output goes

The pseudolocale is written outside your real locale files, under `.verbatra-local/pseudo` by default, which [`verbatra init`](/docs/cli/init) adds to `.gitignore` (`pseudo` tops the entry up if it is missing). Your `files.pattern` is expanded inside that directory, so with `locales/{locale}.json` the default run writes `.verbatra-local/pseudo/locales/en-XA.json`. Point your dev server there, or pass `--out` to write where your build already serves.

`PSEUDO_OUTPUT_CONFLICT` refuses, before anything is read or written:

- a pseudolocale that names your source locale or a target locale,
- an `--out` that puts the file in the same directory as a configured locale file,
- an `--out` that is absolute, climbs out of the working directory, or, once symbolic links are resolved, lands outside the project, at its root, or on a file the project depends on.

Because the file sits outside `files.pattern`, [`translate`](/docs/cli/translate) never spends on it and [`check`](/docs/cli/check) and [`diff`](/docs/cli/diff) never report it.

### Formats written by patching an existing file

`xliff` and `apple-xcstrings` writers patch units already in the destination document, so the pseudolocale file is re-copied from your source file on every write, and a key added to the source later still arrives. A copied XLIFF has its `target-language` rewritten to the pseudolocale.

### JSON output

With `--json`, the [envelope](/docs/cli/output#json-output) carries `locale`, `path`, `entries` (source entries), `transformed` (pseudolocalized), `copied` (keys copied verbatim) and `written` (`false` when the file was already current).

### Terminal feedback

<AvailableFrom version="0.12.0" />

The result goes to stdout; the progress line and the next step go to stderr:

```text
verbatra: pseudolocalizing the source... done (0.1s)
verbatra pseudo
  en-XA: 118 of 120 entries pseudolocalized
    copied verbatim: legal.disclaimer, brand.name
  wrote .verbatra-local/pseudo/locales/en-XA.json
next: load .verbatra-local/pseudo/locales/en-XA.json as the en-XA locale in your dev server
```

A second run over an unchanged source reports `unchanged` instead of `wrote`. `--quiet` drops the stderr lines. See [Terminal output](/docs/cli/output#terminal-output).

## Examples

```bash
# generate en-XA under .verbatra-local/pseudo
verbatra pseudo

# generate a second pseudolocale alongside it
verbatra pseudo --locale en-XB

# write it where the dev server already serves static files
verbatra pseudo --out public/locales-pseudo

# machine-readable result for a script
verbatra pseudo --json
```

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | the pseudolocale was generated, whether or not the file changed; values copied verbatim do not change this |
| `2` | could not run: a usage error, a config or source problem, or a refused pseudolocale or output path |

See [the exit-code contract](/docs/cli/output#exit-codes).
