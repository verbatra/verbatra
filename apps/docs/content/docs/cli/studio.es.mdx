Arranca Verbatra Studio, un panel web local sobre tu proyecto de verbatra: estado de las traducciones, la cola de revisión, la actividad de las ejecuciones y tus ajustes resueltos, todo en vivo sobre los archivos en disco. Editar tus propios archivos de locale funciona de serie, igual que editar un glosario respaldado por archivo desde la página Settings; solo el gasto en el proveedor requiere activación explícita, detrás de `--allow-spend`. Antes de arrancar, `studio` carga `.env.local` y luego `.env` desde el directorio de trabajo y resuelve tu configuración una vez; un error de configuración sale con `2` antes de que arranque ningún servidor.

<AvailableFrom version="0.4.0" pkg="@verbatra/studio" />

## Sinopsis

```bash
verbatra studio [flags]
```

## Flags

| Flag | Argumento | Por defecto | Efecto |
| --- | --- | --- | --- |
| `--cwd` | `<path>` | directorio actual | resuelve la configuración y los archivos de locale desde este directorio |
| `--config` | `<path>` | busca uno | carga este archivo de configuración en lugar de buscar uno |
| `--port` | `<n>` | `5849` | escucha en este puerto; debe ser un entero de 1 a 65535 |
| `--allow-spend` | ninguno | desactivado | permite a Studio llamar a un proveedor de traducción (retraducir una clave, traducir los cambios pendientes) |
| `--expose-agent-tools` | ninguno | desactivado | registra las acciones de revisión de Studio como herramientas WebMCP para que un agente de IA del navegador pueda operarlas |

Cuando el flag `--allow-spend` está ausente, Studio lee en su lugar la variable de entorno `VERBATRA_STUDIO_ALLOW_SPEND`: `1`, `true`, `yes` u `on` (sin distinguir mayúsculas) cuenta como activado. El flag de la CLI siempre gana sobre la variable de entorno. Sin ninguno de los dos, Studio nunca contacta con un proveedor; la edición local no necesita ningún flag.

`--expose-agent-tools` se resuelve igual a partir de `VERBATRA_STUDIO_AGENT_TOOLS`, con el mismo conjunto de valores admitidos y la misma regla de que el flag de la CLI gana sobre la variable. Está desactivado por defecto. Para que un agente pueda gastar hacen falta este flag y `--allow-spend` a la vez; ninguno de los dos flags implica el otro. Consulta [Opera Studio con un agente del navegador](/docs/agent-tools-in-studio) para el catálogo de herramientas y el modelo de seguridad.

## La URL impresa

Studio solo escucha en `127.0.0.1`. En cuanto está escuchando, imprime una línea en stdout:

```
Verbatra Studio running at http://127.0.0.1:5849/?token=<token>
```

Abre esa URL exacta. El token solo se acepta como `?token=` en esa primera carga de página: el servidor lo comprueba, establece una cookie de sesión HttpOnly y redirige a `/`. Cada petición posterior se comprueba contra la cookie, y una sin cookie válida se rechaza. El token no es de un solo uso: volver a visitar la URL impresa, en otra pestaña o en otro navegador, vuelve a establecer la cookie, así que trata la URL como un secreto mientras Studio esté en ejecución. No se imprime nada antes de que el puerto quede enlazado con éxito, así que un arranque fallido nunca filtra una URL ni un token.

Un enlace fallido se notifica en stderr como `verbatra: error [<code>] <message>` con uno de dos códigos: `PORT_IN_USE` cuando otro proceso ya ocupa el puerto (elige otro con `--port`), o `BIND_FAILED` cuando el socket se abrió en una dirección distinta de `127.0.0.1`, en la que Studio se niega a servir.

## Instalación

`@verbatra/studio` es un paquete aparte, al que se llega mediante un import dinámico para que el resto de la CLI funcione sin él. Si no está instalado, `verbatra studio` sale con `2` con:

```
Verbatra Studio requires @verbatra/studio. Install it with: pnpm add -D @verbatra/studio
```

Ese comando de pnpm instala bien, pero sale con `1` y `ERR_PNPM_IGNORED_BUILDS`, y deja atrás un `pnpm-workspace.yaml` sin resolver que hace que los comandos pnpm posteriores fallen igual; la solución de una sola vez está en la [Solución de problemas](/docs/troubleshooting). npm y yarn instalan el paquete sin ese problema.

Studio se ejecuta a través de la CLI, así que instálalo junto con `@verbatra/cli`: `npm install --save-dev @verbatra/cli @verbatra/studio`, luego `npx verbatra studio`. Consulta [Instala e invoca](/docs/cli).

## Ejemplos

```bash
# start Verbatra Studio on the default port
verbatra studio

# enable the provider-calling actions, on a specific port
verbatra studio --allow-spend --port 6000
```

## Códigos de salida

| Código | Significado |
| --- | --- |
| `0` | detenido limpiamente por una sola interrupción (Ctrl-C, o SIGTERM) |
| `1` | la parada falló: cerrar el servidor lanzó un error durante el apagado |
| `2` | no se pudo arrancar: un error de configuración, `@verbatra/studio` no instalado, el puerto en uso, o un error de uso (un `--port` fuera de rango o no entero) |
| `130` | detenido a la fuerza por una segunda interrupción mientras el apagado estaba en curso |
