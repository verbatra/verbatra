Inicia Verbatra Studio, un panel web local sobre tu proyecto: el estado de las traducciones, la cola de revisión, la actividad de las ejecuciones y tu configuración resuelta, en vivo sobre los archivos en disco. Editar archivos de locale y un glosario basado en archivo funciona sin más; solo el gasto en el proveedor es opcional, detrás de `--allow-spend`.

<AvailableFrom version="0.4.0" pkg="@verbatra/studio" />

## Sinopsis

```bash
verbatra studio [flags]
```

## Flags

| Flag | Argumento | Por defecto | Efecto |
| --- | --- | --- | --- |
| `--port` | `<n>` | `5849` | escucha en este puerto; debe ser un entero de 1 a 65535 |
| `--allow-spend` | ninguno | desactivado, o `VERBATRA_STUDIO_ALLOW_SPEND` | permite que Studio llame a un proveedor de traducción (retraducir una clave, traducir los cambios pendientes) |
| `--expose-agent-tools` | ninguno | desactivado, o `VERBATRA_STUDIO_AGENT_TOOLS` | registra las acciones de revisión de Studio como herramientas WebMCP para que un agente de IA en el navegador las use |
| `--verbose` | ninguno | desactivado | imprime además una línea en stderr por petición, con el token de sesión enmascarado |

También acepta los [flags globales](/docs/cli#flags-globales) `--cwd` y `--config`.

## Comportamiento

### La URL impresa

Antes de arrancar, `studio` carga los [archivos de entorno](/docs/cli#archivos-de-entorno) y resuelve tu configuración una vez; un error de configuración sale con `2` antes de que arranque ningún servidor. Studio solo escucha en `127.0.0.1` y, en cuanto está escuchando, imprime una línea en stdout:

```
Verbatra Studio running at http://127.0.0.1:5849/?token=<token>
```

Abre exactamente esa URL. El token solo se acepta como `?token=` en la primera carga de la página: el servidor lo comprueba, fija una cookie de sesión HttpOnly y redirige a `/`. Cada petición posterior necesita esa cookie. El token no es de un solo uso, así que trata la URL como un secreto mientras Studio esté en marcha. No se imprime nada antes de ocupar el puerto, así que un arranque fallido nunca filtra un token.

Un fallo al ocupar el puerto se informa en stderr como `verbatra: error [<code>] <message>`: `PORT_IN_USE` cuando otro proceso tiene el puerto (pasa `--port <n>` o detén ese proceso), o `BIND_FAILED` cuando el socket quedó en una dirección distinta de `127.0.0.1`.

### Qué imprime en stderr

<AvailableFrom version="0.12.0" />

La línea de la URL es la única salida en stdout. Después, stderr dice qué capacidades están activas y cómo activar las que no:

```text output
verbatra: spend tools off (pass --allow-spend to retranslate from Studio)
verbatra: agent tools off (pass --expose-agent-tools to register them)
```

Con `--allow-spend` y el proveedor `none`, la primera línea dice `verbatra: spend tools off (provider none)`. En un terminal interactivo añade `verbatra: press Ctrl-C to stop`, e imprime `verbatra: Studio stopped` tras apagarse. `--verbose` reenvía una línea por petición (como `GET / 200`); la línea de arranque propia de Studio siempre se descarta. `--quiet` deja solo la línea de la URL. Una línea `verbatra: studio error: ...`, que aparece cuando una acción por lotes del panel se detiene por un error inesperado del servidor, sale siempre, incluso con `--quiet`. Consulta [Salida en el terminal](/docs/cli/output#salida-en-el-terminal).

### Gasto y herramientas de agente

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

Sin `--allow-spend`, Studio lee `VERBATRA_STUDIO_ALLOW_SPEND`; `--expose-agent-tools` recurre del mismo modo a `VERBATRA_STUDIO_AGENT_TOOLS`. En ambos casos, `1`, `true`, `yes` u `on` (sin distinguir mayúsculas e ignorando espacios alrededor) cuenta como activado, y el flag siempre gana a la variable. Sin ninguno de los dos, Studio nunca contacta con un proveedor.

El gasto desde un agente necesita los dos flags; ninguno implica el otro. Una configuración con `provider: { id: "none" }` desactiva la traducción automática por política, así que Studio retiene el gasto incluso con `--allow-spend`, y la página Settings lo indica. Consulta [Opera Studio con un agente de navegador](/docs/agent-tools-in-studio) para el catálogo de herramientas y el modelo de seguridad.

### Instalación

`@verbatra/studio` es un paquete propio que se carga con un import dinámico, para que el resto de la CLI funcione sin él. Instálalo junto a la CLI con `npm install --save-dev @verbatra/cli @verbatra/studio`. Si falta, `verbatra studio` sale con `2` y este mensaje:

```
Verbatra Studio requires @verbatra/studio. Install it alongside the CLI with: npm install --save-dev @verbatra/studio, or run both without installing with: npx -y -p @verbatra/cli -p @verbatra/studio verbatra studio
```

Con pnpm, esa instalación funciona pero sale con `1` y `ERR_PNPM_IGNORED_BUILDS`, y deja un `pnpm-workspace.yaml` sin responder; la solución, que se aplica una sola vez, está en [Solución de problemas](/docs/troubleshooting). npm y yarn no tienen ese problema.

## Ejemplos

```bash
# inicia Verbatra Studio en el puerto por defecto
verbatra studio

# activa las acciones que llaman al proveedor, en un puerto concreto
verbatra studio --allow-spend --port 6000

# deja que un agente de navegador use las acciones de revisión
verbatra studio --expose-agent-tools
```

## Códigos de salida

| Código | Significado |
| --- | --- |
| `0` | detenido limpiamente por una sola interrupción (Ctrl-C o SIGTERM) |
| `1` | falló la detención: cerrar el servidor lanzó un error durante el apagado |
| `2` | no pudo arrancar: un error de configuración, `@verbatra/studio` sin instalar, el puerto ocupado o un `--port` no válido (`INVALID_PORT`) |
| `130` | detenido a la fuerza por una segunda interrupción mientras se apagaba |

Consulta [Códigos de salida](/docs/cli/output#códigos-de-salida) para el contrato que sigue cada comando.
