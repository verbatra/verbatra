Starte Verbatra Studio, ein lokales Web-Dashboard über deinem Projekt: Übersetzungsstatus, die Review-Warteschlange, Lauf-Aktivität und deine aufgelösten Einstellungen, live über den Dateien auf der Platte. Locale-Dateien und ein dateibasiertes Glossar bearbeitest du ohne weiteres Flag; nur kostenpflichtige Provider-Aufrufe sind Opt-in, hinter `--allow-spend`.

<AvailableFrom version="0.4.0" pkg="@verbatra/studio" />

## Synopsis

```bash
verbatra studio [flags]
```

## Flags

| Flag | Argument | Standard | Wirkung |
| --- | --- | --- | --- |
| `--port` | `<n>` | `5849` | auf diesem Port lauschen; muss eine Ganzzahl von 1 bis 65535 sein |
| `--allow-spend` | keins | aus, oder `VERBATRA_STUDIO_ALLOW_SPEND` | Studio erlauben, einen Übersetzungs-Provider aufzurufen (einen Key neu übersetzen, ausstehende Änderungen übersetzen) |
| `--expose-agent-tools` | keins | aus, oder `VERBATRA_STUDIO_AGENT_TOOLS` | die Review-Aktionen von Studio als WebMCP-Tools registrieren, damit ein KI-Agent im Browser sie bedienen kann |
| `--verbose` | keins | aus | zusätzlich eine stderr-Zeile pro Anfrage ausgeben, mit maskiertem Sitzungstoken |

Außerdem nimmt `studio` die [globalen Flags](/docs/cli#globale-flags) `--cwd` und `--config`.

## Verhalten

### Die ausgegebene URL

Vor dem Start lädt `studio` `.env.local` und dann `.env` aus dem Arbeitsverzeichnis und löst deine Konfiguration einmal auf; ein Konfigurationsfehler endet mit `2`, bevor irgendein Server startet. Studio bindet sich nur an `127.0.0.1` und gibt, sobald es lauscht, eine Zeile auf stdout aus:

```
Verbatra Studio running at http://127.0.0.1:5849/?token=<token>
```

Öffne genau diese URL. Das Token wird nur als `?token=` beim ersten Seitenaufruf angenommen: Der Server prüft es, setzt ein HttpOnly-Sitzungscookie und leitet auf `/` weiter. Jede spätere Anfrage braucht dieses Cookie. Das Token ist nicht einmalig, behandle die URL also als Geheimnis, solange Studio läuft. Vor dem Binden des Ports wird nichts ausgegeben, ein fehlgeschlagener Start verrät also nie ein Token.

Ein fehlgeschlagenes Binden meldet Studio auf stderr als `verbatra: error [<code>] <message>`: `PORT_IN_USE`, wenn ein anderer Prozess den Port hält (gib `--port <n>` an oder beende diesen Prozess), oder `BIND_FAILED`, wenn der Socket auf einer anderen Adresse als `127.0.0.1` hochkam.

### Was es auf stderr ausgibt

<AvailableFrom version="0.12.0" />

Die URL-Zeile ist die einzige Ausgabe auf stdout. Danach sagt stderr, welche Fähigkeiten an sind und wie du die ausgeschalteten einschaltest:

```text output
verbatra: spend tools off (pass --allow-spend to retranslate from Studio)
verbatra: agent tools off (pass --expose-agent-tools to register them)
```

Mit `--allow-spend` unter dem Provider `none` lautet die erste Zeile `verbatra: spend tools off (provider none)`. In einem interaktiven Terminal kommt `verbatra: press Ctrl-C to stop` dazu, und nach dem Herunterfahren erscheint `verbatra: Studio stopped`. `--verbose` reicht eine Zeile pro Anfrage weiter (etwa `GET / 200`); die eigene Startzeile von Studio wird immer verworfen. `--quiet` behält nur die URL-Zeile. Eine Zeile `verbatra: studio error: ...`, die erscheint, wenn eine Stapelaktion im Dashboard an einem unerwarteten Serverfehler scheitert, kommt immer, auch unter `--quiet`. Siehe [Terminalausgabe](/docs/cli/output#terminalausgabe).

### Ausgaben und Agent-Tools

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

Ohne `--allow-spend` liest Studio `VERBATRA_STUDIO_ALLOW_SPEND`; `--expose-agent-tools` greift auf dieselbe Weise auf `VERBATRA_STUDIO_AGENT_TOOLS` zurück. Bei beiden zählt `1`, `true`, `yes` oder `on` (Groß- und Kleinschreibung egal) als an, und das Flag gewinnt immer gegen die Variable. Ohne beides kontaktiert Studio nie einen Provider.

Ausgaben durch einen Agenten brauchen beide Flags; keines impliziert das andere. Eine Konfiguration mit `provider: { id: "none" }` schaltet Maschinenübersetzung per Richtlinie ab, dann hält Studio Ausgaben auch mit `--allow-spend` zurück, und die Settings-Seite sagt das. Den Tool-Katalog und das Sicherheitsmodell findest du unter [Studio mit einem Browser-Agenten steuern](/docs/agent-tools-in-studio).

### Installation

`@verbatra/studio` ist ein eigenes Paket, das per dynamischem Import geladen wird, damit der Rest der CLI ohne es funktioniert. Installiere es neben der CLI mit `npm install --save-dev @verbatra/cli @verbatra/studio`. Fehlt es, endet `verbatra studio` mit `2` und dieser Meldung:

```
Verbatra Studio requires @verbatra/studio. Install it alongside the CLI with: npm install --save-dev @verbatra/studio, or run both without installing with: npx -y -p @verbatra/cli -p @verbatra/studio verbatra studio
```

Mit pnpm gelingt diese Installation, endet aber mit `1` und `ERR_PNPM_IGNORED_BUILDS` und hinterlässt eine unbeantwortete `pnpm-workspace.yaml`; die einmalige Lösung steht unter [Fehlerbehebung](/docs/troubleshooting). npm und yarn haben dieses Problem nicht.

## Beispiele

```bash
# Verbatra Studio auf dem Standardport starten
verbatra studio

# die Provider-Aktionen einschalten, auf einem bestimmten Port
verbatra studio --allow-spend --port 6000

# einen Browser-Agenten die Review-Aktionen bedienen lassen
verbatra studio --expose-agent-tools
```

## Exit-Codes

| Code | Bedeutung |
| --- | --- |
| `0` | sauber durch eine einzelne Unterbrechung beendet (Ctrl-C oder SIGTERM) |
| `1` | das Beenden ist fehlgeschlagen: das Schließen des Servers hat beim Herunterfahren einen Fehler geworfen |
| `2` | konnte nicht starten: ein Konfigurationsfehler, `@verbatra/studio` nicht installiert, der Port belegt oder ein ungültiges `--port` (`INVALID_PORT`) |
| `130` | durch eine zweite Unterbrechung während des Herunterfahrens hart beendet |

Den Vertrag, dem jeder Befehl folgt, findest du unter [Exit-Codes](/docs/cli/output#exit-codes).
