Starte Verbatra Studio, ein lokales Web-Dashboard über deinem verbatra-Projekt: Übersetzungsstatus, die Review-Warteschlange, Lauf-Aktivität und deine aufgelösten Einstellungen, alles live über den Dateien auf der Platte. Das Bearbeiten deiner eigenen Locale-Dateien funktioniert von Haus aus, ebenso das Bearbeiten eines dateibasierten Glossars auf der Seite Einstellungen; nur kostenpflichtige Provider-Aufrufe sind Opt-in, hinter `--allow-spend`. Vor dem Start lädt `studio` `.env.local` und dann `.env` aus dem Arbeitsverzeichnis und löst deine Konfiguration einmal auf; ein Konfigurationsfehler endet mit `2`, bevor irgendein Server startet.

<AvailableFrom version="0.4.0" pkg="@verbatra/studio" />

## Synopsis

```bash
verbatra studio [flags]
```

## Flags

| Flag | Argument | Standard | Wirkung |
| --- | --- | --- | --- |
| `--cwd` | `<path>` | aktuelles Verzeichnis | Konfiguration und Locale-Dateien von diesem Verzeichnis aus auflösen |
| `--config` | `<path>` | wird gesucht | diese Konfigurationsdatei laden, statt eine zu suchen |
| `--port` | `<n>` | `5849` | auf diesem Port lauschen; muss eine Ganzzahl von 1 bis 65535 sein |
| `--allow-spend` | keins | aus | Studio erlauben, einen Übersetzungs-Provider aufzurufen (einen Key neu übersetzen, ausstehende Änderungen übersetzen) |
| `--expose-agent-tools` | keins | aus | die Review-Aktionen von Studio als WebMCP-Tools registrieren, damit ein KI-Agent im Browser sie bedienen kann |
| `--verbose` | keins | aus | gibt zusätzlich eine stderr-Zeile pro Anfrage aus, mit maskiertem Sitzungstoken |

Wenn das Flag `--allow-spend` fehlt, liest Studio stattdessen die Umgebungsvariable `VERBATRA_STUDIO_ALLOW_SPEND`: `1`, `true`, `yes` oder `on` (Groß- und Kleinschreibung egal) zählt als an. Das CLI-Flag gewinnt immer über die Umgebungsvariable. Ohne beides kontaktiert Studio nie einen Provider; lokales Bearbeiten braucht kein Flag. Eine Konfiguration mit `provider: { id: "none" }` schaltet Maschinenübersetzung per Richtlinie ab, und dann hält Studio Provider-Ausgaben auch mit `--allow-spend` zurück: Die Settings-Seite sagt das, statt auf das Flag zu verweisen.

<AvailableFrom version="0.6.0" pkg="@verbatra/studio" />

`--expose-agent-tools` wird genauso aus `VERBATRA_STUDIO_AGENT_TOOLS` aufgelöst, mit derselben Menge gültiger Werte und derselben Regel, dass das CLI-Flag gegen die Variable gewinnt. Es ist standardmäßig aus. Ausgaben durch einen Agenten setzen sowohl dieses Flag als auch `--allow-spend` voraus; keines der Flags impliziert das andere. Den Tool-Katalog und das Sicherheitsmodell findest du unter [Studio mit einem Browser-Agenten bedienen](/docs/agent-tools-in-studio).

## Die ausgegebene URL

Studio bindet sich nur an `127.0.0.1`. Sobald es lauscht, gibt es eine Zeile auf stdout aus:

```
Verbatra Studio running at http://127.0.0.1:5849/?token=<token>
```

Öffne genau diese URL. Das Token wird nur als `?token=` beim ersten Laden der Seite akzeptiert: Der Server prüft es, setzt ein HttpOnly-Sitzungscookie und leitet auf `/` weiter. Jede spätere Anfrage wird gegen das Cookie geprüft, und eine ohne gültiges Cookie wird abgelehnt. Das Token ist nicht einmalig: Rufst du die ausgegebene URL erneut auf, in einem anderen Tab oder einem anderen Browser, wird das Cookie erneut gesetzt; behandle die URL also als Geheimnis, solange Studio läuft. Vor dem erfolgreichen Binden des Ports wird nichts ausgegeben; ein fehlgeschlagener Start gibt also nie eine URL oder ein Token preis.

Ein fehlgeschlagenes Binden wird auf stderr als `verbatra: error [<code>] <message>` mit einem von zwei Codes gemeldet: `PORT_IN_USE`, wenn ein anderer Prozess den Port bereits belegt (wähle mit `--port` einen anderen), oder `BIND_FAILED`, wenn der Socket auf einer anderen Adresse als `127.0.0.1` hochgekommen ist, auf der Studio den Dienst verweigert.

### Was es auf stderr ausgibt

<AvailableFrom version="0.12.0" />

Die URL-Zeile bleibt die einzige Ausgabe auf stdout. Danach sagt stderr, welche Fähigkeiten eingeschaltet sind und wie du die ausgeschalteten einschaltest:

```text
verbatra: spend tools off (pass --allow-spend to retranslate from Studio)
verbatra: agent tools off (pass --expose-agent-tools to register them)
```

In einem interaktiven Terminal kommt `verbatra: press Ctrl-C to stop` dazu, und sobald der Server heruntergefahren ist, erscheint `verbatra: Studio stopped`. Mit `--verbose` wird zusätzlich eine Zeile pro Anfrage (etwa `GET / 200`) auf stderr weitergereicht, mit maskiertem Sitzungstoken; die eigene Startzeile von Studio wird immer verworfen, weil stdout die URL schon enthält. `--quiet` behält nur die URL-Zeile. Eine Ausnahme ist eine Zeile `verbatra: studio error: ...`: Stoppt eine Sammelaktion im Dashboard an einem unerwarteten Serverfehler, nennt Studio den Eintrag und den Fehler auf stderr, mit oder ohne `--verbose` und auch unter `--quiet`.

## Installation

`@verbatra/studio` ist ein eigenes Paket, das über einen dynamischen Import erreicht wird, damit der Rest der CLI auch ohne es funktioniert. Ist es nicht installiert, endet `verbatra studio` mit `2` und gibt aus:

```
Verbatra Studio requires @verbatra/studio. Install it alongside the CLI with: npm install --save-dev @verbatra/studio, or run both without installing with: npx -y -p @verbatra/cli -p @verbatra/studio verbatra studio
```

Dieser pnpm-Befehl installiert korrekt, beendet sich aber mit `1` und `ERR_PNPM_IGNORED_BUILDS` und hinterlässt eine unbeantwortete `pnpm-workspace.yaml`, an der spätere pnpm-Befehle genauso scheitern; die einmalige Lösung steht in der [Fehlerbehebung](/docs/troubleshooting). npm und yarn installieren das Paket ohne dieses Problem.

Studio läuft über die CLI, installiere es also zusammen mit `@verbatra/cli`: `npm install --save-dev @verbatra/cli @verbatra/studio`, dann `npx verbatra studio`. Siehe [Installieren und aufrufen](/docs/cli).

## Beispiele

```bash
# start Verbatra Studio on the default port
verbatra studio

# enable the provider-calling actions, on a specific port
verbatra studio --allow-spend --port 6000
```

## Exit-Codes

| Code | Bedeutung |
| --- | --- |
| `0` | sauber gestoppt durch einen einzelnen Interrupt (Ctrl-C oder SIGTERM) |
| `1` | Stoppen fehlgeschlagen: das Schließen des Servers warf beim Herunterfahren einen Fehler |
| `2` | konnte nicht starten: ein Konfigurationsfehler, `@verbatra/studio` nicht installiert, der Port belegt oder ein Verwendungsfehler (ein `--port` außerhalb des Bereichs oder keine Ganzzahl) |
| `130` | zwangsbeendet durch einen zweiten Interrupt, während das Herunterfahren noch lief |
