`verbatra report provenance` lee `verbatra.provenance.json`, el archivo de bloqueo y los archivos de locale, e imprime por locale de destino cuántos valores escribió una máquina, cuántos revisó una persona y cuántos escribieron o importaron personas. No llama a ningún proveedor, no necesita clave de API y no escribe nada. El informe es una evidencia de apoyo, no asesoramiento legal.

## Sinopsis

```bash
verbatra report <report> [flags]
```

- `<report>`: el informe que se imprime. `provenance` es el único por ahora; cualquier otro nombre es un error de uso.

## Flags

| Flag | Argumento | Por defecto | Efecto |
| --- | --- | --- | --- |
| `--locales` | `<list>` | todos los destinos configurados | informa solo de este subconjunto separado por comas; un valor vacío o desconocido es un error de uso, salida `2` |

También acepta los [flags globales](/docs/cli#flags-globales) `--cwd`, `--config` y `--json`.

## Comportamiento

### Salida

```text output
verbatra report provenance (source en, verbatra 0.12.0, 2026-09-29T08:00:00.000Z)
  locale  machine, unreviewed  machine, reviewed  human  import  external  unrecorded  unknown  total
  de      12                   40                 3      85      1         0           0        141
Supporting evidence from verbatra.provenance.json, not legal advice. --json lists every key.
```

La primera línea nombra el locale de origen, la versión de verbatra y cuándo se generó el informe. Cada fila cuenta las claves que tienen valor tanto en el origen como en ese locale. [Evidencia de traducción automática](/docs/provenance-evidence#el-informe-de-procedencia) describe las categorías, lo que el informe puede y no puede mostrar, y el esquema JSON completo.

No hay `--out`: el informe va a stdout, como en `check` y `diff`, así que redirígelo si quieres guardarlo.

### Salida JSON

Esquema: [`report-envelope.json`](https://verbatra.kreitz-webdev.de/schema/v1/report-envelope.json) valida el envoltorio completo; [Esquemas](/docs/cli/output#esquemas) enumera los demás.

`--json` imprime un [envoltorio](/docs/cli/output#salida-json) cuyo `result` lista el origen, el estado de revisión, el proveedor, el modelo y el revisor de cada clave, para un archivo de auditoría. Si el archivo de procedencia no se puede leer, el resultado es `{ "available": false, "reason": "provenance-unreadable" }`.

### Procedencia ilegible

Un informe sin un archivo de procedencia legible listaría cada valor como `unrecorded`, lo que no es lo mismo que no tener registro. Por eso el comando falla de forma segura con la salida `1`, como [`check --require-reviewed`](/docs/cli/check), para que un job de CI no archive un archivo de auditoría vacío.

### Información en el terminal

El comando muestra una línea mientras lee los archivos. Cuando hay traducciones automáticas esperando revisión, sugiere Studio:

```text output
verbatra: reading the provenance record... done (0.1s)
next: verbatra studio (approve or reject the 12 machine translations no person has reviewed yet)
```

Estas líneas van a stderr, y `--quiet` las omite. Consulta [Salida en el terminal](/docs/cli/output#salida-en-el-terminal).

## Ejemplos

```bash
# contadores por locale: máquina sin revisar, máquina revisada, humana, importada y el resto
verbatra report provenance

# origen y estado de revisión de cada clave, para un archivo de auditoría
verbatra report provenance --json > provenance-report.json

# solo el locale alemán
verbatra report provenance --locales de
```

## Códigos de salida

| Código | Significado |
| --- | --- |
| `0` | se imprimió el informe |
| `1` | no hay informe: `verbatra.provenance.json` está dañado o lo escribió un verbatra más nuevo |
| `2` | no se pudo ejecutar: un error de configuración, un archivo de origen o de bloqueo ilegible, un valor `--locales` desconocido o vacío, o un nombre de informe desconocido |

Consulta [el contrato de códigos de salida](/docs/cli/output#códigos-de-salida).
