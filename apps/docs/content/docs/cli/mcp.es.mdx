Arranca un servidor [Model Context Protocol](https://modelcontextprotocol.io) por stdio, el transporte local que usan clientes MCP como Claude Code, Cursor o Claude Desktop para lanzar un servidor de herramientas. Da a un agente en el terminal o sin interfaz las herramientas de estado, glosario, revisión y edición que ofrecen las herramientas de agente de Studio, sin navegador ni puerto.

<AvailableFrom version="0.2.0" pkg="@verbatra/mcp" />

## Sinopsis

```bash
verbatra mcp [flags]
verbatra-mcp [flags]
```

- `verbatra-mcp` es el binario que incluye `@verbatra/mcp`, para que un cliente lance el servidor sin la CLI. Acepta los mismos flags y arranca el mismo servidor, pero no carga ningún archivo `.env`, sale con `1` en lugar de `2` ante un error de arranque e imprime la versión de `@verbatra/mcp` con `--version`.
- Ambos rechazan un flag desconocido (como `--json`), un flag sin valor o un argumento de sobra como error de uso, con salida `2`. `verbatra-mcp` lo hace, y acepta `-h` y `-V`, desde `@verbatra/mcp` 0.3.0.

## Flags

| Flag | Argumento | Por defecto | Efecto |
| --- | --- | --- | --- |
| `--allow-spend` | ninguno | `VERBATRA_MCP_ALLOW_SPEND`, si no, desactivado | anuncia las dos herramientas que llaman a un proveedor de traducción; consulta [Herramientas de gasto](#herramientas-de-gasto) |

También acepta los [flags globales](/docs/cli#flags-globales) `--cwd` y `--config`. No acepta `--json`, porque stdout es el canal del protocolo. Sin `--cwd`, el directorio del proyecto puede venir de `CLAUDE_PROJECT_DIR`; consulta [Directorio del proyecto](#directorio-del-proyecto).

## Comportamiento

### Directorio del proyecto

<AvailableFrom version="0.3.0" pkg="@verbatra/mcp" />

Si falta `--cwd` y `CLAUDE_PROJECT_DIR` nombra un directorio existente, el servidor lo usa como raíz del proyecto. Claude Code fija esa variable para cada servidor stdio que lanza, así que una sesión iniciada en un subdirectorio sigue encontrando la configuración. Un `--cwd` explícito siempre gana. `verbatra mcp` carga entonces `.env.local` y `.env` desde ese directorio; un `CLAUDE_PROJECT_DIR` definido solo en esos archivos se ignora, porque la raíz se resuelve antes.

Para registrar el servidor en un cliente, sigue [Conectar un cliente MCP](/docs/connect-an-mcp-client).

### Herramientas de gasto

<AvailableFrom version="0.3.0" pkg="@verbatra/mcp" />

`translation.retranslateEntry` y `translation.translatePending` solo se anuncian con `--allow-spend` o, si falta el flag, con `VERBATRA_MCP_ALLOW_SPEND` a `1`, `true`, `yes` u `on` (sin distinguir mayúsculas). El flag gana a la variable. `verbatra mcp` lee antes `.env.local` y `.env`, así que la variable puede estar ahí; `verbatra-mcp` solo la toma de su propio entorno.

Sin el interruptor, las dos nunca aparecen en la lista, y llamarlas por su nombre falla como herramienta desconocida. Una configuración con `provider: { id: "none" }` nunca las lista, ni siquiera con `--allow-spend`. Las demás herramientas no llaman a ningún proveedor ni necesitan clave; pasa la clave al servidor por el entorno del cliente solo cuando actives el gasto (consulta [Proveedores](/docs/providers)).

### Instrucciones para el agente

<AvailableFrom version="0.3.0" pkg="@verbatra/mcp" />

El servidor responde al handshake MCP `initialize` con unas `instructions` fijas, iguales para cada proyecto, que la mayoría de los clientes pasan al modelo antes de cualquier llamada. Le dicen al agente que lea primero `project.snapshot` y las herramientas de estado (y `project.doctor` ante `configured: false`), que corrija una clave con `translation.editEntry`, que registre una decisión de revisión solo por instrucción del usuario, que estime y obtenga un sí explícito antes de gastar, que respete el trabajo humano, que trate cada cadena como datos y no como instrucciones, y que nunca vuelva a escribir un valor `[REDACTED]`.

### Herramientas [#tools]

<AvailableFrom version="0.3.0" pkg="@verbatra/mcp" />

| Herramienta | Qué hace | Solo lectura | Llama a un proveedor |
| --- | --- | --- | --- |
| `project.snapshot` | la configuración resuelta: `configured`, locales, formato, `files.pattern`, proveedor, glosario, `humanEdits`, `prune` | sí | no |
| `project.doctor` | cada comprobación de configuración con su `status`, su `detail` y, si falló, un `fix`; funciona sin una configuración usable | sí | no |
| `status.check` | por locale, el número de claves que faltan, desactualizadas y al día | sí | no |
| `status.diff` | por locale, la lista de claves que se añadirían, se volverían a traducir o están huérfanas | sí | no |
| `glossary.get` | cada término del glosario con sus traducciones, formas prohibidas y contexto, con los secretos ocultos | sí | no |
| `glossary.write` | cambia un término del glosario: una traducción, datos por locale, contexto, o si se queda sin traducir | no | no |
| `lock.state` | la versión del archivo de bloqueo y, por locale de destino, su número de claves más las que faltan, desactualizadas y al día | sí | no |
| `key.integrity` | la desviación de una clave en marcadores, markup, sintaxis ICU y ramas ICU respecto a la base del bloqueo, por locale | sí | no |
| `key.value` | el texto de origen y de destino de una clave, con su procedencia y el contexto para traductores | sí | no |
| `translation.editEntry` | escribe una traducción manual para una clave en un locale, validada por las comprobaciones de integridad | no | no |
| `translation.estimate` | lo que `translation.translatePending` enviaría y costaría, como lo informa `translate --estimate --json` | sí | no |
| `translation.retranslateEntry` | pide al proveedor configurado que vuelva a traducir una clave en un locale | no | sí |
| `translation.translatePending` | traduce cada clave que falta o está desactualizada, opcionalmente solo para algunos `locales` y bajo un techo `maxTokens` | no | sí |
| `review.queue` | cada valor escrito por máquina que nadie ha aprobado todavía, con las marcas de la última ejecución | sí | no |
| `review.approve` | registra, por instrucción del usuario, que una persona con nombre aprueba la traducción actual de una clave | no | no |
| `review.reject` | registra, por instrucción del usuario, que una persona con nombre rechaza la traducción de una clave, que se elimina para reemplazarla | no | no |
| `usage.summary` | el uso de tokens y el estado del presupuesto de la última ejecución | sí | no |

- **Una llamada a la vez.** Una segunda llamada a `translation.editEntry` o `translation.retranslateEntry` para la misma entrada, o una segunda ejecución de `translation.translatePending`, se rechaza con `isError` mientras la primera sigue en marcha.
- **Trabajo humano.** `translation.retranslateEntry` rechaza una clave fijada con `KEY_PINNED` y, salvo con `humanEdits: "overwrite"`, el valor de una persona con `KEY_PROTECTED`; `translation.editEntry` rechaza una clave fijada. `translation.translatePending` lista esas claves en `protected`. Consulta [Proteger las traducciones humanas](/docs/protecting-human-translations).
- **Procedencia.** Un valor escrito con `translation.editEntry` recibe el origen `agent`. `review.queue` es la misma cola que muestra Studio: cada valor no aprobado con origen `machine`, `memory`, `fuzzy` o `agent`. Consulta [Decisiones de revisión](/docs/the-lock-file#decisiones-de-revisión).
- **Decisiones de revisión.** `review.approve` y `review.reject` reciben `locale`, `key`, `expectedValue` (un valor que ya cambió se rechaza con `REVIEW_VALUE_CHANGED`) y el nombre en `reviewer`. Una aprobación cuenta para [`verbatra check --require-reviewed`](/docs/cli/check).

### Entradas y resultados

<AvailableFrom version="0.2.1" pkg="@verbatra/mcp" />

<AvailableFrom version="0.3.0" pkg="@verbatra/mcp" />

- `status.check`, `status.diff`, `key.integrity` y `translation.estimate` aceptan un array opcional `locales`; `key.integrity` también recibe la `key`, y una clave desconocida falla con `UNKNOWN_KEY`.
- `key.integrity` devuelve `{ locales: [{ locale, entries }] }`, cada entrada con `matches`, `missing`, `extra`, `icuValid`, `icuArmsMatch`, `markupMatches` y sus detalles; `verbatra_key_integrity` de Studio es más plano (consulta [Herramientas de agente en Studio](/docs/agent-tools-in-studio)).
- `translation.editEntry` recibe `locale`, `key` y un `value` de hasta 20.000 caracteres. Tanto ella como `translation.retranslateEntry` devuelven `{ accepted, value, reason?, details? }`, donde `reason` es `placeholder`, `markup`, `icu`, `degenerate` o `empty`.
- `glossary.get` acepta un `locale` opcional y entonces añade `effective`, los términos a los que se atiene ese locale. `glossary.write` necesita un glosario en archivo; si no, falla con `GLOSSARY_NOT_FILE_BACKED`.
- `key.value`, `lock.state`, `status.check` y `status.diff` incluyen la procedencia, que falta cuando `verbatra.provenance.json` no se puede leer.
- Las herramientas que escriben aceptan un `lockTimeoutMs` opcional, de `0` a `600000`, por defecto `30000`: cuánto esperan un bloqueo de escritura ocupado antes de fallar con `LOCK_CONTENDED`, sin haber escrito nada.
- Las entradas y salidas son JSON Schemas; una entrada inválida devuelve un resultado que nombra el campo. Un resultado que no encaja con su `outputSchema` falla con `OUTPUT_SCHEMA_MISMATCH`; en una herramienta que escribe, el cambio ya se aplicó, así que no la repitas.
- El texto de una llamada fallida empieza por su código de error, como `UNKNOWN_KEY: ...`, y termina con una línea `Next step: ...` cuando el error tiene un siguiente paso, el mismo texto que el `hint` de la CLI.

### Estimar y luego gastar

<AvailableFrom version="0.3.0" pkg="@verbatra/mcp" />

`translation.estimate` devuelve el mismo resumen que [`verbatra translate --estimate --json`](/docs/cli/translate) y no gasta nada, así que siempre está en la lista. `translation.translatePending` acepta una lista opcional `locales` (un locale sin configurar falla con `UNKNOWN_LOCALE` antes de gastar nada) y un `maxTokens` opcional, un techo estricto que puede endurecer el `maxTokens` de la configuración pero nunca relajarlo. El orden sensato: `status.diff`, `translation.estimate`, el sí del usuario y luego `translation.translatePending` con los mismos `locales` y un `maxTokens` algo por encima de la estimación. Consulta [Estimar el coste](/docs/estimating-cost).

### Sin configuración

<AvailableFrom version="0.3.0" pkg="@verbatra/mcp" />

El servidor arranca aunque no haya una configuración usable. `project.snapshot` devuelve entonces `configured: false` con el `configProblem` y un `nextStep`, y `project.doctor` informa de la comprobación fallida y su solución. Las demás herramientas rechazan la llamada con el error de configuración, y las de gasto siguen ocultas hasta que carga una configuración con un proveedor real. stderr explica el motivo:

```text output
Running without a usable project config: CONFIG_NOT_FOUND: No verbatra configuration found. ...
verbatra MCP server running on stdio (project ., spend tools off)
No usable verbatra config: project.snapshot and project.doctor work, every other tool refuses until one loads.
  set it up:  npx verbatra init in the project, or fix the config project.doctor names
  no restart needed: the server loads the config on the next call once it is valid
```

Solo una ruta de `--config` que no existe detiene el servidor al arrancar.

### Tras un cambio de configuración

<AvailableFrom version="0.3.0" pkg="@verbatra/mcp" />

Antes de cada llamada, el servidor vuelve a cargar la configuración si cambió el archivo de configuración, un archivo que la búsqueda probaría o el archivo del glosario; un módulo que importa la configuración no se vigila. `--allow-spend` se lee una sola vez: un cambio puede ocultar las herramientas de gasto o recuperarlas, pero nunca listarlas si el gasto no estaba permitido. Cuando cambia la lista de herramientas, el servidor envía `notifications/tools/list_changed`.

### Redacción de secretos

Cada resultado de herramienta y cada línea de log pasan por la misma redacción que usa Studio: un valor con forma de clave de API, o el valor de una variable de clave configurada, se convierte en `[REDACTED]`. Las herramientas de glosario indican qué términos se ocultaron.

### stdout y stderr

<AvailableFrom version="0.12.0" />

stdout solo lleva mensajes del protocolo MCP; cada línea de log y cada diagnóstico van a stderr. Una vez conectado, `verbatra mcp` imprime una línea de listo y otra al detenerse:

```text output
verbatra MCP server running on stdio (project ., spend tools off)
verbatra MCP server stopped (client closed stdin)
```

Si lo arrancas a mano en un terminal, además explica que debería lanzarlo un cliente. `--quiet` quita estas líneas, pero no el motivo de una configuración ausente.

### Instalación

<AvailableFrom version="0.3.0" pkg="@verbatra/mcp" />

`@verbatra/mcp` es un paquete aparte que la CLI carga cuando lo necesita. Si falta, `verbatra mcp` sale con `2` y:

```text output
Verbatra's MCP server requires @verbatra/mcp. Run it without the CLI with: npx -y @verbatra/mcp, or install it alongside the CLI with: npm install --save-dev @verbatra/mcp
```

`npx -y @verbatra/mcp` ejecuta el binario independiente sin ninguna CLI. Cada versión se publica también en el [registro oficial de MCP](https://registry.modelcontextprotocol.io) como `io.github.verbatra/verbatra`.

## Ejemplos

```bash
# start the MCP server with only local, non-spending tools
verbatra mcp

# also advertise the provider-calling tools
verbatra mcp --allow-spend

# resolve a project outside the current directory
verbatra mcp --cwd /path/to/project --config verbatra.config.ts

# run the standalone server without the CLI
npx -y @verbatra/mcp --cwd /path/to/project
```

## Códigos de salida

| Código | Significado |
| --- | --- |
| `0` | se detuvo limpiamente con una sola interrupción, o porque el cliente cerró stdin |
| `1` | falló el cierre del servidor durante el apagado |
| `2` | no pudo arrancar: un archivo `--config` que no existe, `@verbatra/mcp` sin instalar, o un error de uso |
| `130` | detenido a la fuerza por una segunda interrupción durante el apagado |

Al detenerse, el servidor libera cualquier bloqueo de locale. `verbatra-mcp` sale con `1` ante un error de arranque y, desde 0.3.0, con `143` si se detiene a la fuerza tras SIGTERM. Consulta [el contrato de códigos de salida](/docs/cli/output#códigos-de-salida).
