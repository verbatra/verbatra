`@verbatra/cli` ships the `verbatra` binary, a thin wrapper over [`@verbatra/sdk`](/docs/sdk). These commands do the work:

<Cards>
  <Card title="init" href="/docs/cli/init">Create a verbatra config and `.env.example` for this project.</Card>
  <Card title="extract" href="/docs/cli/extract">Scan your application source for translation call sites and add the new keys to the source locale file.</Card>
  <Card title="translate" href="/docs/cli/translate">Translate every target locale once, then exit.</Card>
  <Card title="watch" href="/docs/cli/watch">Re-translate on every source change until interrupted.</Card>
  <Card title="check" href="/docs/cli/check">Report which keys are missing or stale per locale, read-only.</Card>
  <Card title="diff" href="/docs/cli/diff">List the exact keys that would be added, re-translated, or are orphaned per locale, read-only.</Card>
  <Card title="report" href="/docs/cli/report">Print a read-only report: `report provenance` lists which translations a machine wrote and which a person reviewed.</Card>
  <Card title="doctor" href="/docs/cli/doctor">Validate the project setup and report every problem at once, without calling a provider.</Card>
  <Card title="pseudo" href="/docs/cli/pseudo">Generate a pseudolocale from the source strings, without calling a provider.</Card>
  <Card title="types" href="/docs/cli/types">Generate TypeScript declarations for your catalog keys and their message arguments, without calling a provider.</Card>
  <Card title="export" href="/docs/cli/export">Export untranslated strings for a human translator, as an Excel workbook, one CSV or TSV file per locale, or one XLIFF file per locale for a CAT tool.</Card>
  <Card title="import" href="/docs/cli/import">Import a filled workbook or delimited file back into the locale files.</Card>
  <Card title="tmx" href="/docs/cli/tmx">Import a TMX translation memory from another tool into this project's memory, or export this project's memory as a TMX file.</Card>
  <Card title="studio" href="/docs/cli/studio">Start Verbatra Studio, the local translation dashboard.</Card>
  <Card title="mcp" href="/docs/cli/mcp">Start a stdio MCP server exposing verbatra's tools to an MCP client.</Card>
</Cards>

## Install and invoke

Install `@verbatra/cli` as a dev dependency, then run the binary through your package manager:

| Package manager | Install | Run |
| --- | --- | --- |
| npm | `npm install --save-dev @verbatra/cli` | `npx @verbatra/cli <command>` |
| pnpm | `pnpm add --save-dev @verbatra/cli` | `pnpm verbatra <command>` (or `pnpm exec verbatra <command>`) |
| yarn | `yarn add --dev @verbatra/cli` | `yarn verbatra <command>` |
| bun | `bun add --dev @verbatra/cli` | `bun run verbatra <command>` |

You need Node.js `>=22.14.0`.

Trying a command before installing? `npx @verbatra/cli <command>` (npm) or `pnpm dlx @verbatra/cli <command>` (pnpm) both work without a prior local install. Always use the scoped name: the unscoped name `verbatra` on npm does not belong to this project.

## Global flags

These flags mean the same on every command that takes them, so the command pages list only their own flags. The last column names the commands that do not take a flag.

| Flag | Argument | Default | Effect | Not accepted by |
| --- | --- | --- | --- | --- |
| `--cwd` | `<path>` | current directory | start the config search here and resolve the paths you pass against it; locale files resolve against the directory of the config the search found; `init` writes its files there | none |
| `--config` | `<path>` | search for one | load this config file instead of searching; see the [search order](/docs/config-file) | `init` |
| `--json` | none | off | print a machine-readable [envelope](/docs/cli/output#json-output) on stdout, one line per record; errors still go to stderr | `mcp`, `studio` |
| `-q`, `--quiet` | none | off | print only results, warnings and errors: no progress, hints or informational lines; works before or after the command name | none |
| `--no-color` | none | color on a terminal | never color the output; see [Terminal output](/docs/cli/output#terminal-output) | none |
| `-h`, `--help` | none | off | print the help of the program or the command and exit `0` | none |
| `-V`, `--version` | none | off | print the CLI version and exit `0` | none |

An unknown command or flag exits `2`, and so does a bare `verbatra` with no command: it prints the help to stderr and, when no config is found, suggests `verbatra init`. `mcp` never writes to stdout, since stdout is its protocol channel, so it refuses `--json` with `USAGE_ERROR`. From 0.12.0 a `--cwd` that names no existing directory exits `2` with [`INVALID_OPTION`](/docs/error-codes#invalid_option) on every command, before anything is read or written.

## Environment files

`translate`, `watch`, `doctor`, `studio`, and `mcp` load `.env.local` and then `.env` from the working directory before they run. When the config the search found sits in a parent directory, they then load the same two files from that directory too; with `--config` they read only the working directory. `doctor --literals` is the exception: it reads no API key, so it loads neither file. A variable already set in your real environment always wins, then the working directory's files, then the config directory's, and a value in `.env.local` wins over the same variable in `.env`. API keys are read only from the environment, never from the config file or a flag: see [Providers](/docs/providers). The read-only commands (`check`, `diff`, `report`), the handoff commands (`export`, `import`), `extract`, `init`, `pseudo`, `types`, and `tmx` never call a provider and load no `.env` files.
