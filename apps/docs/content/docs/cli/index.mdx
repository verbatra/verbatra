`@verbatra/cli` ships the `verbatra` binary, a thin wrapper over [`@verbatra/sdk`](/docs/sdk). These commands do the work:

| Command | What it does |
| --- | --- |
| [`init`](/docs/cli/init) | create a verbatra config and `.env.example` for this project |
| [`extract`](/docs/cli/extract) | scan your application source for translation call sites and add the new keys to the source locale file |
| [`translate`](/docs/cli/translate) | translate every target locale once, then exit |
| [`watch`](/docs/cli/watch) | re-translate on every source change until interrupted |
| [`check`](/docs/cli/check) | report which keys are missing or stale per locale, read-only |
| [`diff`](/docs/cli/diff) | list the exact keys that would be added, re-translated, or are orphaned per locale, read-only |
| [`report`](/docs/cli/report) | print a read-only report: `report provenance` lists which translations a machine wrote and which a person reviewed |
| [`doctor`](/docs/cli/doctor) | validate the project setup and report every problem at once, without calling a provider |
| [`pseudo`](/docs/cli/pseudo) | generate a pseudolocale from the source strings, without calling a provider |
| [`types`](/docs/cli/types) | generate TypeScript declarations for your catalog keys and their message arguments, without calling a provider |
| [`export`](/docs/cli/export) | export untranslated strings for a human translator, as an Excel workbook, one CSV or TSV file per locale, or one XLIFF file per locale for a CAT tool |
| [`import`](/docs/cli/import) | import a filled workbook or delimited file back into the locale files |
| [`tmx`](/docs/cli/tmx) | import a TMX translation memory from another tool into this project's memory, or export this project's memory as a TMX file |
| [`studio`](/docs/cli/studio) | start Verbatra Studio, the local translation dashboard |
| [`mcp`](/docs/cli/mcp) | start a stdio MCP server exposing verbatra's tools to an MCP client |

## Install and invoke

Install `@verbatra/cli` as a dev dependency, then run the binary through your package manager:

| Package manager | Install | Run |
| --- | --- | --- |
| npm | `npm install --save-dev @verbatra/cli` | `npx verbatra <command>` |
| pnpm | `pnpm add --save-dev @verbatra/cli` | `pnpm verbatra <command>` (or `pnpm exec verbatra <command>`) |
| yarn | `yarn add --dev @verbatra/cli` | `yarn verbatra <command>` |
| bun | `bun add --dev @verbatra/cli` | `bun run verbatra <command>` |

You need Node.js `>=22.14.0`.

Trying a command before installing? `npx @verbatra/cli <command>` (npm) or `pnpm dlx @verbatra/cli <command>` (pnpm) both work without a prior local install.

## Global flags

These flags mean the same on every command that takes them, so the command pages list only their own flags. The last column names the commands that do not take a flag.

| Flag | Argument | Default | Effect | Not accepted by |
| --- | --- | --- | --- | --- |
| `--cwd` | `<path>` | current directory | resolve the config and locale files from this directory; `init` writes its files there | none |
| `--config` | `<path>` | search for one | load this config file instead of searching; see the [search order](/docs/config-file) | `init` |
| `--json` | none | off | print a machine-readable [envelope](/docs/cli/output#json-output) on stdout, one line per record; errors still go to stderr | `mcp`, `studio` |
| `-q`, `--quiet` | none | off | print only results, warnings and errors: no progress, hints or informational lines; works before or after the command name | none |
| `--no-color` | none | color on a terminal | never color the output; see [Terminal output](/docs/cli/output#terminal-output) | none |
| `-h`, `--help` | none | off | print the help of the program or the command and exit `0` | none |
| `-V`, `--version` | none | off | print the CLI version and exit `0` | none |

An unknown command or flag exits `2`. `mcp` never writes to stdout, since stdout is its protocol channel, so it refuses `--json` with `USAGE_ERROR`.

## Environment files

`translate`, `watch`, `doctor`, `studio`, and `mcp` load `.env.local` and then `.env` from the working directory before they run. `doctor --literals` is the exception: it reads no API key, so it loads neither file. A variable already set in your real environment always wins. API keys are read only from the environment, never from the config file or a flag: see [Providers](/docs/providers). The read-only commands (`check`, `diff`, `report`), the handoff commands (`export`, `import`), `extract`, `pseudo`, `types`, and `tmx` never call a provider and load no `.env` files.
