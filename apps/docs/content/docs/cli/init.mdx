---
title: verbatra init
description: Create a verbatra config and .env example for this project, detected from your locale files, interactively or fully unattended.
---
Scaffold a project: `init` writes a `verbatra.config.ts` and a `.env.example` naming your provider's API key variable (never a key value), and makes sure `.gitignore` covers `.env`, `.env.local`, `.verbatra-local/`, and `verbatra.cache.json`. It looks at the locale files already in the project first, so in most projects the provider is the only thing you have to tell it.

## Synopsis

```bash
verbatra init [flags]
```

## Flags

| Flag | Argument | Default | Effect |
| --- | --- | --- | --- |
| `--cwd` | `<path>` | current directory | scan this directory and write the config and env files to it |
| `--provider` | `<id>` | none (required) | provider to scaffold: `anthropic`, `openai`, `gemini`, `deepl`, `google-translate`, `openai-compatible`, or `none` |
| `--format` | `<id>` | detected, else `i18next-json` | the locale file format, one of the ids on [Formats](/docs/formats) |
| `--source` | `<locale>` | detected, else `en` | the source locale your strings are written in |
| `--targets` | `<locales>` | detected, else `de` | comma-separated target locales to translate into |
| `--path` | `<pattern>` | detected, else `locales/{locale}.json` | locale file pattern; must contain the `{locale}` token |
| `--model` | `<name>` | the scaffold default | the model; required for `openai-compatible`, optional for `anthropic`, `openai`, and `gemini` |
| `--base-url` | `<url>` | none | the server URL; `openai-compatible` only, and required there |
| `--api-key-env-var` | `<name>` | `OPENAI_COMPATIBLE_API_KEY` | the environment variable `openai-compatible` reads its key from; `openai-compatible` only |
| `--yes` | none | off | never prompt, and take the default for anything neither passed nor detected |
| `--force` | none | off | overwrite an existing `verbatra.config.ts` whose content differs |
| `--json` | none | off | print one [JSON envelope](/docs/ci-and-exit-codes#json-output) describing what was written; never prompts |

A flag always wins. Anything you leave out is detected from the project, then prompted for when stdin is a terminal and neither `--yes` nor `--json` is given, and otherwise taken from its default only under `--yes`.

## Detection

`init` scans the directory for files a format adapter claims, skipping hidden directories, `node_modules`, and common build output, and finds the part of each path that spells a locale: a file name such as `de.json`, `messages_pt_BR.properties`, or `app_en.arb`, or a directory such as `locales/de/`, `de.lproj/`, or Android's `values-de/`. The file pattern covering the most locales wins, and it fills in:

- `format`: the one format whose adapter reads every matched file. Every JSON adapter reads `.json`, so for JSON files a single matching dependency in `package.json` (`i18next`, `vue-i18n`, `next-intl`, or `@ngx-translate/core`) decides.
- `files.pattern` and `files.localeStyle`: `posix` when the files spell `pt_BR`, `android` for `values-*` directories, `literal` otherwise.
- `sourceLocale`: the source language of an `.xcstrings` catalogue, else `en` or the single `en-*` locale found, else the only locale found.
- `targetLocales`: every other locale found.

A file next to the locale files that holds strings under no locale name, such as `messages.properties` beside `messages_de.properties`, `Strings.resx` beside `Strings.de.resx`, or a gettext `app.pot`, is reported as `unqualifiedSourceFile`. verbatra reads the source from the file its pattern names for the source locale and cannot point at such a file, so `init` does not guess the source locale then: pass `--source`, even with `--yes`, and the next steps tell you which file to rename or copy the base file to.

With no locale file at all, the dependencies alone decide the format. `--format`, `--path`, and `--source` narrow the detection instead of being overridden by it, so `--format yaml` only looks at YAML files.

`init` never guesses between equals. When several formats read the files (plain JSON with no i18n dependency, for example) it exits `2` with `FORMAT_AMBIGUOUS`, and when several file patterns tie (one file per namespace, such as `locales/{locale}/common.json` and `locales/{locale}/auth.json`) it exits `2` with `LAYOUT_AMBIGUOUS`. Both list the candidates; pass `--format` or `--path` to choose one. At a terminal it asks instead, suggesting the first candidate.

## Unattended runs

Without a terminal, or with `--json`, `init` never prompts. A value that is neither passed, detected, nor defaulted by `--yes` is an error: `init` exits `2` with `MISSING_OPTIONS` and names every missing flag at once. An error for an ambiguity or an invalid flag also lists the flags still missing, so one run tells an agent everything it has to pass. `--provider` has no default, and neither do `--base-url` and `--model` for `openai-compatible`, so those are always needed. This is the command an agent runs:

```bash
npx verbatra init --provider gemini --yes --json
```

With `--json`, stdout carries exactly one envelope. Its `result`:

```ts
interface InitResult {
  configPath: string;                  // absolute path of verbatra.config.ts
  files: { path: string; action: "created" | "overwritten" | "updated" | "unchanged" }[];
  config: {                            // the config that was validated and written
    sourceLocale: string;
    targetLocales: string[];
    format: string;
    files: { pattern: string; localeStyle?: "posix" | "android" };
    provider: { id: string; options: Record<string, unknown> };
  };
  sources: {                           // where each value came from
    provider: "flag" | "prompt";
    format: "flag" | "prompt" | "files" | "dependencies" | "default";
    pattern: "flag" | "prompt" | "detected" | "default";
    sourceLocale: "flag" | "prompt" | "detected" | "default";
    targetLocales: "flag" | "prompt" | "detected" | "default";
  };
  apiKeyEnvVar: string | null;         // the variable to set; null for provider none
  detection: {
    format: { id: string; from: "input" | "files" | "dependencies" } | null;
    layout: {
      pattern: string;
      localeStyle: "literal" | "posix" | "android";
      locales: string[];
      sourceLocale: string | null;
      unqualifiedSourceFile: string | null;
      files: string[];
    } | null;
    ambiguities: { subject: "format" | "layout"; candidates: string[] }[];
    confidence: "high" | "medium" | "low" | "none";
    reasons: string[];                 // one sentence per decision or doubt
  };
  nextSteps: { description: string; command: string | null }[];
}
```

`confidence` is `high` when the files alone decided everything, `medium` when a convention or a dependency filled a gap (such as taking `en` as the source), `low` when no locale file backed the format, and `none` when nothing was detected. A `default` in `sources` is the value to double-check. `nextSteps` ends with the exact commands to run next, such as `npx verbatra doctor`.

An error envelope for `FORMAT_AMBIGUOUS`, `LAYOUT_AMBIGUOUS`, `INVALID_PROVIDER`, or `INVALID_FORMAT` also carries a `candidates` array with the values to choose from. Every usage error that leaves flags unanswered also carries a `missing` array naming them, such as `"--source <locale>"`.

## Providers

`--provider none` scaffolds a [human-only](/docs/human-only-workflow) config with no `options` and writes no `.env.example`, since no API key is ever read.

`--provider openai-compatible` scaffolds a local or self-hosted server from `--base-url` and `--model`, with `maxOutputTokens: 4096`. Its key is optional: a server that needs none leaves `OPENAI_COMPATIBLE_API_KEY` unset, and `--api-key-env-var` names a different variable for one that does. `init` writes that variable's name into the config and `.env.example`, never a value, and refuses a base URL that carries credentials, a query string, or a fragment, such as `https://user:key@host` or `https://host/v1?api-key=...`, where a key could end up in the committed config. `--api-key-env-var` takes an upper-case name such as `LLM_API_KEY`, and a rejected value is never echoed back in case it was the key itself.

## Existing files

Running `init` again with the same answers changes nothing and succeeds, so it is safe to repeat. A `verbatra.config.ts` with different content is refused with `CONFIG_EXISTS` unless you pass `--force`. Another verbatra config in the same directory (a `.verbatrarc.json`, for example, or a `verbatra` property in `package.json`) is refused with `CONFIG_EXISTS` even under `--force`, because it would be read before `verbatra.config.ts`. Nothing is written when `init` refuses.

An existing `.env.example` is kept as it is; when it does not name the key variable yet, that one line is appended. `.gitignore` gets only the entries it is missing.

## Examples

```bash
# prompt for anything not passed or detected
verbatra init --provider gemini

# fully unattended, one JSON document on stdout
verbatra init --provider gemini --yes --json

# choose the format and pattern yourself
verbatra init --provider deepl --format yaml --path "config/locales/{locale}.yml" --yes

# a local server that needs no key
verbatra init --provider openai-compatible --base-url http://localhost:11434/v1 --model llama3.1 --yes

# human-only: no provider, no API key
verbatra init --provider none --yes
```

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | files written, or already up to date |
| `2` | a usage error: `MISSING_OPTIONS`, `INVALID_PROVIDER`, `INVALID_FORMAT`, `INVALID_OPTION`, `FORMAT_AMBIGUOUS`, `LAYOUT_AMBIGUOUS`, `CONFIG_EXISTS`, or `CONFIG_INVALID` when the answers would not make a valid config |
