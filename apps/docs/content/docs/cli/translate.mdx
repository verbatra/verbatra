---
title: verbatra translate
description: Translate every target locale once, then exit.

---
Run one translation pass over every target locale, then exit. `translate` diffs the source against [the lock file](/docs/the-lock-file), sends only new or changed strings to the provider, runs the [integrity checks](/docs/translation-safety), writes the locale files, and updates the lock. An unchanged string is never sent twice.

## Synopsis

```bash
verbatra translate [flags]
```

## Flags

| Flag | Argument | Default | Effect |
| --- | --- | --- | --- |
| `--locales` | `<list>` | every configured target locale | translate only this comma-separated subset; an unconfigured locale fails with `UNKNOWN_LOCALE`, an empty list exits `2` |
| `--dry-run` | none | off | report what a run would change without calling a provider or writing files; needs no API key |
| `--prune` | none | the config's `prune` option, otherwise off | remove orphaned keys (in a target file, absent from source) from the written file and the lock |
| `--lock-timeout` | `<seconds>` | `600` | wait this long for a held per-locale write lock; a whole number from `1` to `3600` |
| `--concurrency` | `<n>` | `1` | translate up to `n` target locales at once; a whole number from `1` to `100`, refused under a token budget |
| `--max-tokens` | `<n>` | the config's `maxTokens` | hard token ceiling for this run; the lower of this and the config's `maxTokens` applies |
| `--no-cache` | none | off (cache on) | bypass the [translation-memory cache](/docs/the-cache) (`verbatra.cache.json`) for this run |
| `--include-human` | none | off | also retranslate stale keys a person wrote or imported, for this run only; [pinned keys](/docs/protecting-human-translations#pinning-keys) stay untouched |
| `--estimate` | none | off | estimate what the run would send and cost, then exit; implies `--dry-run` |

Also takes the [global flags](/docs/cli#global-flags) `--cwd`, `--config` and `--json`. Before it runs, `translate` loads the [environment files](/docs/cli#environment-files).

## Behavior

### Dry run

`--dry-run` constructs no provider, so it needs no API key and cannot spend anything. It reads the source and target files, diffs them against the lock file, and reports exactly what a real run would change. It writes nothing (no locale file, no lock update, no run-status snapshot), neither reads nor writes the cache, and takes no write lock, so it never waits on a run in progress.

By default a run deletes nothing: orphaned keys are reported and left in place. `--prune` removes exactly those keys, and `--prune --dry-run` previews them.

### Cost estimate

<AvailableFrom version="0.12.0" />

`--estimate` adds a pre-run estimate to the dry run: how many keys would be sent, how many provider requests they would take, and the quantity the provider bills for (tokens for an LLM, source characters for DeepL or Google Cloud Translation, nothing for a self-hosted `openai-compatible` endpoint or a human-only project). A currency figure appears only when the config has a `rates` block covering the provider and model; otherwise the missing rate key is named instead of inventing `0.00`. See [Estimating cost](/docs/estimating-cost).

### A subset of locales

<AvailableFrom version="0.11.0" />

`--locales de,fr` narrows the run to part of the configured targets. The other locales keep their files, lock entries, and cache entries as they were. Use it on a rate-limited free tier to translate one locale at a time, or to re-run a single locale that came out partial. The run-status snapshot then describes that subset only.

### Write locks and interrupts

A locale waits up to `--lock-timeout` for a contended [write lock](/docs/the-lock-file#the-write-lock), then fails with `LOCK_CONTENDED` while the other locales still run. A lock left by a verbatra process that is no longer running on this machine is reclaimed at once. The timeout bounds only that wait before any provider call: recording a written file in the lock file always waits up to the ten-minute default, so a written file is never left unrecorded. Ctrl-C or SIGTERM releases the run's locks before the command exits.

### Token ceiling

<AvailableFrom version="0.12.0" />

`--max-tokens` is always a hard stop: a provider request that would pass the ceiling is withheld, whatever `budgetBehavior` says, and its keys are listed as `budgetWithheld`. It is counted like a configured [`maxTokens` budget](/docs/config-file#maxtokens-and-budgetbehavior) and can tighten that budget but never loosen it. A run the ceiling cut short exits `1`. Run `--estimate` first to pick a figure.

### Parallel locales

`--concurrency` is refused with exit `2` when a token budget applies (from `maxTokens` or `--max-tokens`), because which locale loses its remaining work would depend on how the locales interleave; a dry run is exempt. If a whole-run error, such as a corrupt lock file, surfaces while locales are running, no further locale starts, and the running ones finish and release their locks before the command exits `2`.

### Keys a person wrote

<AvailableFrom version="0.12.0" />

A stale key whose value a person wrote, imported, or changed outside verbatra is kept by default: it is listed as `protected`, not sent to the provider, and stays stale for `verbatra check`. A stderr line says how many were kept and points to `--include-human`, which retranslates them for one run (`humanEdits: "overwrite"`). Protected keys do not change the exit code, except in a human-only project. See [Protecting human translations](/docs/protecting-human-translations).

### Human-only projects

<AvailableFrom version="0.12.0" />

In a [human-only](/docs/human-only-workflow) project (`provider: { id: "none" }`) no provider is called. Keys the translation memory covers are written, and every other missing or changed key is listed as `unfilled` and exits `3`; a failed or partial locale still wins with `1`. A dry run reads the memory here, so its plan shows the same `cacheHits` and `unfilled` keys, and `--estimate` reports nothing billed. Hand the `unfilled` keys off with [`verbatra export`](/docs/cli/export).

### Failed and partial locales

<AvailableFrom version="0.9.0" />

One locale failing is not fatal: the run finishes and exits `1`. A **partial** locale exits `1` too: its file was written but keys are still missing, typically because a provider sub-batch failed or the integrity gate refused a translation. The human output lists every refused key under `integrity-withheld` with its reason (`placeholder`, `markup`, `icu`, `degenerate`, or `empty`); with `--json`, each locale carries them in `integrityRefusals`.

### Unsupported locales

<AvailableFrom version="0.12.0" />

A locale the configured DeepL or Google Cloud Translation provider does not support refuses the whole run with `LOCALE_UNSUPPORTED_BY_PROVIDER` and exit `2`, on a dry run and with `--estimate` too, before anything is spent. Leave it out with `--locales`, or see [Language support](/docs/language-support#checking-support-before-a-run). A glossary or tone the provider cannot apply only adds a notice (`GLOSSARY_UNSUPPORTED_BY_PROVIDER`, `FORMALITY_UNSUPPORTED_BY_PROVIDER`), as do `LOCALE_UNVERIFIED_BY_PROVIDER` and, for an LLM, `LOCALE_NOT_WELL_TESTED`.

### JSON output

With `--json`, stdout carries one [envelope](/docs/cli/output#json-output) whose `result` is a `RunSummary`:

```ts
interface RunSummary {
  dryRun: boolean;          // whether this was a dry run (no provider calls, no writes)
  locales: LocaleSummary[]; // one entry per target locale, in config order
  succeeded: string[];      // locales whose run succeeded
  partial: string[];        // locales written with keys still missing; these exit 1 too
  failed: string[];         // locales whose run failed
  usage?: UsageSummary;     // summed input/output tokens; absent when no call reported usage
  budget?: RunBudget;       // the token-budget outcome; present only when maxTokens is configured
  estimate?: RunEstimate;   // the pre-run cost estimate; present only when --estimate was passed
}
```

Each `LocaleSummary` carries the per-locale key lists (translated, unchanged, orphaned, withheld, flagged for review, and more); see [the SDK reference](/docs/sdk/run-summary) for the full anatomy.

### Terminal feedback

<AvailableFrom version="0.12.0" />

`translate` names the locales and provider before the run, and prints the elapsed time, tokens used, and the next command afterwards. On an interactive terminal the progress is one spinner line; when stderr is piped, every step is a plain line:

```text output
verbatra: translating 2 locales with gemini/gemini-2.5-flash
verbatra: translating de
verbatra: de batch 1/1
verbatra: de: writing
verbatra: de done, 12 translated
verbatra: translating fr
verbatra: fr batch 1/1
verbatra: fr: writing
verbatra: fr done, 12 translated
verbatra: run finished, 2 locales processed
[ok] done in 4.2s, 1830 tokens
next: verbatra check (confirm every locale is in sync)
```

A dry run or an estimate ends each locale with `would translate` instead. These lines go to stderr, and `--quiet` drops them. See [Terminal output](/docs/cli/output#terminal-output).

## Examples

```bash
# translate once using the config it finds
verbatra translate

# preview the keys that would be pruned, spending nothing
verbatra translate --prune --dry-run

# one locale at a time, which is what a rate-limited free tier needs
verbatra translate --locales de

# size and price the run without spending anything
verbatra translate --estimate

# stop before the run passes 50000 tokens
verbatra translate --max-tokens 50000

# also retranslate stale keys a person wrote
verbatra translate --include-human
```

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | every target locale came out complete |
| `1` | the run finished, but a locale failed or came out partial |
| `2` | could not run: a config, source, format, provider, unsupported-locale, or lock-file error, or a usage error |
| `3` | human-only project: the run finished cleanly, but keys are left for a human translation |
| `130` | interrupted with Ctrl-C (SIGINT) after releasing the write locks |
| `143` | stopped with SIGTERM after releasing the write locks |

On an interrupt, stderr ends with `verbatra: interrupted (SIGINT), released locks`, or under `--json` with the record `{"type":"interrupted","signal":"SIGINT","locksReleased":true}`. See [the exit-code contract](/docs/cli/output#exit-codes).
