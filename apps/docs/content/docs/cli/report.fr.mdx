`verbatra report provenance` lit `verbatra.provenance.json`, le fichier de verrouillage et les fichiers de locale, puis affiche par locale cible combien de valeurs une machine a écrites, combien une personne a relues et combien des personnes ont écrites ou importées. Il n'appelle aucun fournisseur, n'a besoin d'aucune clé d'API et n'écrit rien. Le rapport est une preuve d'appui, pas un conseil juridique.

## Synopsis

```bash
verbatra report <report> [flags]
```

- `<report>` : le rapport à afficher. `provenance` est le seul pour l'instant ; tout autre nom est une erreur d'utilisation.

## Exemples

```bash
# décomptes par locale : machine non relue, machine relue, humaine, importée et le reste
verbatra report provenance

# origine et état de relecture de chaque clé, pour un fichier d'audit
verbatra report provenance --json > provenance-report.json

# seulement la locale allemande
verbatra report provenance --locales de
```

## Options

| Option | Argument | Défaut | Effet |
| --- | --- | --- | --- |
| `--locales` | `<list>` | toutes les cibles configurées | rapporte seulement ce sous-ensemble séparé par des virgules ; une locale non configurée échoue avec `UNKNOWN_LOCALE` et une liste vide avec `INVALID_LOCALES`, les deux avec la sortie `2` |

Accepte aussi les [options globales](/fr/docs/cli#options-globales) `--cwd`, `--config` et `--json`.

## Comportement

### Sortie

```text output
verbatra report provenance (source en, verbatra 0.12.0, 2026-09-29T08:00:00.000Z)
  locale  machine, unreviewed  machine, reviewed  human  import  external  unrecorded  unknown  total
  de      12                   40                 3      85      1         0           0        141
Supporting evidence from verbatra.provenance.json, not legal advice. --json lists every key.
```

La première ligne nomme la locale source, la version de verbatra et le moment où le rapport a été fait. Chaque ligne compte les clés qui ont une valeur à la fois dans la source et dans cette locale. [Preuves de traduction automatique](/fr/docs/provenance-evidence#le-rapport-de-provenance) décrit les catégories, ce que le rapport peut montrer ou non, et le schéma JSON complet.

Il n'y a pas de `--out` : le rapport va sur stdout, comme pour `check` et `diff`, alors redirige-le si tu veux le garder.

### Sortie JSON

Schéma : [`report-envelope.json`](https://verbatra.kreitz-webdev.de/schema/v1/report-envelope.json) valide l'enveloppe entière ; [Schémas](/fr/docs/cli/output#schémas) liste les autres.

`--json` affiche une [enveloppe](/fr/docs/cli/output#sortie-json) dont le `result` liste l'origine, l'état de relecture, le fournisseur, le modèle et le relecteur de chaque clé, pour un fichier d'audit. Si le fichier de provenance est illisible, le résultat est `{ "available": false, "reason": "provenance-unreadable" }`.

### Provenance illisible

Un rapport sans fichier de provenance lisible listerait chaque valeur comme `unrecorded`, ce qui n'est pas la même chose que ne pas avoir d'enregistrement. La commande échoue donc prudemment avec la sortie `1`, comme [`check --require-reviewed`](/fr/docs/cli/check), pour qu'un job de CI n'archive pas un fichier d'audit vide.

### Retour dans le terminal

La commande affiche une ligne pendant qu'elle lit les fichiers. Quand des traductions automatiques attendent une relecture, elle suggère Studio :

```text output
verbatra: reading the provenance record... done (0.1s)
next: verbatra studio (approve or reject the 12 machine translations no person has reviewed yet)
```

Ces lignes vont sur stderr, et `--quiet` les supprime. Consulte [Sortie dans le terminal](/fr/docs/cli/output#sortie-dans-le-terminal).

## Codes de sortie

| Code | Signification |
| --- | --- |
| `0` | le rapport a été affiché |
| `1` | pas de rapport : `verbatra.provenance.json` est corrompu ou a été écrit par un verbatra plus récent |
| `2` | impossible de s'exécuter : une erreur de config, un fichier source ou de verrouillage illisible, une valeur `--locales` non configurée ou vide (`UNKNOWN_LOCALE`, `INVALID_LOCALES`), ou un nom de rapport inconnu |

Consulte [le contrat des codes de sortie](/fr/docs/cli/output#codes-de-sortie).
