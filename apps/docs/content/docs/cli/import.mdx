---
title: verbatra import
description: Import a filled workbook, CSV, TSV, or XLIFF handoff back into the locale files, running the same safety checks.
---
Read a handoff a translator filled in back into your locale files. Every value runs through the same integrity checks as an automated run: values that pass are written and [the lock file](/docs/the-lock-file) is updated, values that fail are withheld and reported, so a bad cell never lands in a locale file.

## Synopsis

```bash
verbatra import <workbook> [flags]
```

- `<workbook>`: the handoff [`verbatra export`](/docs/cli/export) wrote and the translator filled in. For `xlsx` it is the workbook file; for `csv`, `tsv`, `xliff2` and `xliff12` it is one `<locale>.csv`, `<locale>.tsv` or `<locale>.xlf` file, or the directory holding one file per locale.

## Flags

| Flag | Argument | Default | Effect |
| --- | --- | --- | --- |
| `--dry-run` | none | off | validate and report without writing locale files or updating the lock |
| `--format` | `<format>` | `xlsx`, or `xliff2` for a path ending in `.xlf` or `.xliff` | `xlsx`, `csv`, `tsv`, `xliff2` or `xliff12`; either XLIFF format reads both versions |
| `--reviewer` | `<name>` | none | name recorded on each XLIFF unit marked reviewed or final; at most 64 characters, stored in the committed provenance file |
| `--lock-timeout` | `<seconds>` | `600` | how long to wait for a held per-locale write lock; a whole number from `1` to `3600`, otherwise a usage error, exit `2` |

Also takes the [global flags](/docs/cli#global-flags) `--cwd`, `--config` and `--json`.

## Behavior

### Locale files and leftovers

With `csv` or `tsv` the locale comes from the file name, so keep every file named exactly as it was exported. A configured target locale with no file (or, in a workbook, no sheet) fails that locale with `WORKBOOK_SHEET_MISSING`; it is never silently skipped.

A file left over from an earlier export with a wider `--locales` selection is never applied. Import checks the directory against the manifest the most recent export wrote and fails such a locale with `HANDOFF_FILE_STALE`. Re-export that locale or delete the file. A directory with no readable manifest (assembled by hand, or stripped by an archive) is read as it is, and so is a single file you name directly.

### Write locks

<AvailableFrom version="0.12.0" />

`--lock-timeout` sets how long a locale waits for a contended [write lock](/docs/the-lock-file#the-write-lock) before it fails with `LOCK_CONTENDED`, exactly as on [`verbatra translate`](/docs/cli/translate). The wait happens before the locale's file is written, so a locale that times out stays untouched while the others still import, and the command exits `1`. Once a file is written, recording it in the lock file waits up to the ten-minute default whatever `--lock-timeout` says. A wait longer than a second prints a line naming the lock and its holder (a `lock-wait` record under `--json`). `--dry-run` takes no lock, so it never waits.

### XLIFF

<AvailableFrom version="0.12.0" />

An XLIFF file is read with the version it declares, and a single file whose name is not a configured locale is matched by the target language it declares. A unit whose target equals the current value changes nothing; any other target runs the integrity gate like a workbook row. A unit marked `reviewed` or `final` (in 1.2 also `signed-off` or `approved="yes"`) is recorded as approved, naming `--reviewer`, and reported with the `HANDOFF_REVIEWS_RECORDED` notice. A unit whose id names no source key is reported as a malformed row. See [Hand off to a translation agency](/docs/translation-agency).

### Blank and broken rows

A blank `Translation` cell never fails a locale: the row is skipped, its lock baseline is kept, and the key is reported as `unfilled` while it still needs a translation. Importing a handoff nobody has filled in yet therefore succeeds and lists every pending key.

A single unreadable row is reported as a malformed row, and the rest of the locale still imports. A handoff that is oversized or cannot be parsed at all (for example, not a readable xlsx container) is a whole-run `SOURCE_INVALID` error whose message says what was wrong.

### Terminal feedback

<AvailableFrom version="0.12.0" />

`import` shows one line while it reads and applies the file. After a clean import it suggests `verbatra check`, and after `--dry-run` the same import without the flag:

```text title="Output"
verbatra: importing verbatra-translations.xlsx... done (0.4s)
next: verbatra check (confirm every locale is in sync)
```

These lines go to stderr, and `--quiet` drops them. See [Terminal output](/docs/cli/output#terminal-output).

### JSON output

With `--json`, the [envelope](/docs/cli/output#json-output) carries one `RunSummary`, the same shape [`verbatra translate`](/docs/cli/translate) prints:

```ts
interface RunSummary {
  dryRun: boolean;          // whether this was a dry run (nothing written)
  locales: LocaleSummary[]; // one entry per target locale, in config order
  succeeded: string[];      // locales imported completely
  partial: string[];        // locales written with keys still missing; these exit 1 too
  failed: string[];         // locales whose import failed
}
```

Each `LocaleSummary` lists the per-locale keys (written, `unfilled`, withheld and more); see [the SDK reference](/docs/sdk/run-summary).

## Examples

```bash
# import the filled workbook
verbatra import verbatra-translations.xlsx

# validate and report, write nothing
verbatra import verbatra-translations.xlsx --dry-run

# import every locale file in a CSV handoff directory
verbatra import handoff --format csv

# import one XLIFF file back from a CAT tool, naming the reviewer
verbatra import handoff/de.xlf --reviewer "Agency GmbH"
```

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | every target locale came out complete |
| `1` | the run finished but one or more locales failed or came out partial |
| `2` | could not run: a whole-run error (config, handoff, format, or a corrupt lock file), or a usage error |
| `130` | interrupted with Ctrl-C (SIGINT) after releasing the run's write locks |
| `143` | stopped with SIGTERM after releasing the run's write locks |

<AvailableFrom version="0.9.0" />

The contract matches [`verbatra translate`](/docs/cli/translate), so a manual handoff branches the same way in CI: a partial locale exits `1`, and a lock file that is or turns corrupt stops the whole run with `2`, leaving the remaining locales untouched (locales applied before stay written). See [Exit codes](/docs/cli/output#exit-codes) for the contract every command follows.
