---
title: verbatra import
description: Import a filled workbook, CSV, TSV, or XLIFF handoff back into the locale files, running the same safety checks.
---
Read a workbook a translator filled in back into your locale files. Every value runs through the same integrity checks as an automated run: values that pass are written and [the lock file](/docs/the-lock-file) is updated; values that fail are withheld and reported instead of written, so a bad cell never lands in a locale file.

## Synopsis

```bash
verbatra import <workbook> [flags]
```

`<workbook>` is the path to the handoff produced by [`verbatra export`](/docs/cli/export) and filled in by the translator: the workbook file for `xlsx`, and for `csv`, `tsv`, `xliff2` and `xliff12` either one `<locale>.csv`, `<locale>.tsv` or `<locale>.xlf` file or the directory holding one file per locale.

## Flags

| Flag | Argument | Default | Effect |
| --- | --- | --- | --- |
| `--cwd` | `<path>` | current directory | resolve config and locale files from this directory |
| `--config` | `<path>` | search for one | load this config file instead of searching for one |
| `--dry-run` | none | off | validate and report without writing locale files or updating the lock |
| `--format` | `<format>` | `xlsx`, or `xliff2` for a path ending in `.xlf` or `.xliff` | read an Excel workbook (`xlsx`), delimited files (`csv`, `tsv`), or XLIFF files (`xliff2` and `xliff12` both read either version, from 0.12.0) |
| `--reviewer` | `<name>` | none | the name recorded on each XLIFF unit the handoff marks `reviewed` or `final` (1.2: `signed-off`, `final` or `approved="yes"`); at most 64 characters with no control characters, and stored in the committed provenance file (from 0.12.0) |
| `--lock-timeout` | `<seconds>` | `600` | how long to wait for a held per-locale write lock before failing; must be a bare positive integer of seconds no greater than `3600` (a value like `60s`, `0`, `-1`, or `7200` is a usage error, exit `2`) |
| `--json` | none | off | print one [JSON envelope](/docs/ci-and-exit-codes#json-output) on stdout carrying the run summary under `result` (the same [`RunSummary` shape](/docs/sdk) as `translate`), or the error code on a failed run; the human-readable error line still goes to stderr |

## Examples

```bash
# import the filled workbook
verbatra import verbatra-translations.xlsx

# validate and report, write nothing
verbatra import verbatra-translations.xlsx --dry-run

# import every locale file in a CSV handoff directory
verbatra import handoff --format csv

# import one XLIFF file back from a CAT tool, naming the reviewer
verbatra import handoff/de.xlf --reviewer "Agency GmbH"
```

With `csv` or `tsv` the locale comes from the file name, not from a sheet name, so keep every file named exactly as it was exported. A configured target locale with no file (or, in a workbook, no sheet) is reported as that locale's failure with `WORKBOOK_SHEET_MISSING`, never silently skipped.

A file left over from an earlier export with a wider `--locales` selection is never applied. Import reconciles the directory against the manifest the most recent export wrote there and reports such a locale as failed with `HANDOFF_FILE_STALE`, so an outdated translation cannot slip back in unnoticed. Re-export that locale to refresh its file, or delete the file. A directory with no readable manifest (one assembled by hand, or one that lost the hidden file on its way through an archive) is read as it always was, every present file is imported. Naming a single file directly is likewise taken at face value.

<AvailableFrom version="0.12.0" />

`--lock-timeout` tunes how long a locale waits for a contended [write lock](/docs/the-lock-file#the-write-lock) before that locale fails with `LOCK_CONTENDED`, exactly as on [`verbatra translate`](/docs/cli/translate). The wait happens before the locale's file is written, so a locale that times out is left untouched while the other locales still import, and the command exits `1`. Once a locale's file is written, recording it in the lock file waits up to the ten-minute default whatever `--lock-timeout` says. While a wait lasts longer than a second, a line on stderr names the lock file and its holder, or a `lock-wait` JSON record under `--json`. `--dry-run` takes no lock, so it never waits.

## XLIFF

<AvailableFrom version="0.12.0" />

An XLIFF file is read with the version it declares, and a single file whose name is not a configured locale is matched by the target language it declares. A unit whose target is exactly the current value changes nothing, any other target runs the integrity gate like a workbook row, and a unit marked `reviewed` or `final` is recorded as approved, naming `--reviewer`, and reported with the `HANDOFF_REVIEWS_RECORDED` notice. A unit whose id names no source key is reported as a malformed row rather than failing the locale. [Hand off to a translation agency](/docs/translation-agency) has the details.

## Terminal feedback

<AvailableFrom version="0.12.0" />

`import` shows one line while it reads and applies the file. After a clean import it suggests `verbatra check`, and after `--dry-run` it suggests the same import without the flag:

```text
verbatra: importing verbatra-translations.xlsx... done (0.4s)
next: verbatra check (confirm every locale is in sync)
```

These lines go to stderr, so stdout and `--json` output stay exactly as described above, and `--quiet` drops them. See [Terminal output](/docs/cli#terminal-output) for color, the spinner and the variables that control them.

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | every target locale came out complete |
| `1` | the run finished but one or more locales failed or came out partial |
| `2` | could not run: a whole-run error (config, workbook, format, or lock), or a usage error |
| `130` | interrupted with Ctrl-C (SIGINT); the run's write locks are released first and stderr ends with `verbatra: interrupted (SIGINT), released locks`, or under `--json` with the record `{"type":"interrupted","signal":"SIGINT","locksReleased":true}` |
| `143` | stopped with SIGTERM; the run's write locks are released first and stderr ends with `verbatra: interrupted (SIGTERM), released locks`, or under `--json` with the record `{"type":"interrupted","signal":"SIGTERM","locksReleased":true}` |

A handoff that is oversized or cannot be parsed at all (for example, a file that is not a readable xlsx container) is a whole-run `SOURCE_INVALID` error whose message says what was wrong with it. A single unreadable row is not: it is reported as a malformed row and the rest of the locale still imports.

<AvailableFrom version="0.9.0" />

The contract matches [`verbatra translate`](/docs/cli/translate), so a manual handoff branches the same way in CI. That includes partial locales: a locale written with keys still missing exits `1`, not `0`. It also includes the lock file: a lock file that is corrupt, or that turns corrupt while the import is running, stops the whole run with `2` instead of reporting one failed locale, so the locales still to come are left untouched. Locales applied before the abort stay written; fix the lock file and import again.

A blank `Translation` cell never fails a locale: the row is skipped, its prior lock baseline is kept, and the key is reported as `unfilled` whenever it still needs a translation, whether the row was exported as `new` or `changed`. Importing a workbook nobody has filled in yet therefore succeeds and returns the full inventory of pending keys.
