Démarre Verbatra Studio, un tableau de bord web local au-dessus de ton projet verbatra : l'état des traductions, la file de révision, l'activité des exécutions et tes paramètres résolus, le tout en direct sur les fichiers du disque. Modifier tes propres fichiers de locale fonctionne d'emblée, tout comme modifier un glossaire stocké dans un fichier depuis la page Paramètres ; seule la dépense chez un fournisseur demande une activation explicite, derrière `--allow-spend`. Avant de démarrer, `studio` charge `.env.local` puis `.env` depuis le répertoire de travail et résout ta config une fois ; une erreur de config sort avec le code `2` avant qu'un serveur ne démarre.

<AvailableFrom version="0.4.0" pkg="@verbatra/studio" />

## Synopsis

```bash
verbatra studio [flags]
```

## Options

| Option | Argument | Défaut | Effet |
| --- | --- | --- | --- |
| `--cwd` | `<path>` | répertoire courant | résout la config et les fichiers de locale depuis ce répertoire |
| `--config` | `<path>` | recherche automatique | charge ce fichier de config au lieu d'en chercher un |
| `--port` | `<n>` | `5849` | écoute sur ce port ; doit être un entier entre 1 et 65535 |
| `--allow-spend` | aucun | désactivé | autorise Studio à appeler un fournisseur de traduction (retraduire une clé, traduire les changements en attente) |
| `--expose-agent-tools` | aucun | désactivé | enregistre les actions de révision de Studio comme outils WebMCP pour qu'un agent IA de navigateur puisse les piloter |

Quand l'option `--allow-spend` est absente, Studio lit la variable d'environnement `VERBATRA_STUDIO_ALLOW_SPEND` à la place : `1`, `true`, `yes` ou `on` (insensible à la casse) compte comme activé. L'option CLI l'emporte toujours sur la variable d'environnement. Sans l'une ni l'autre, Studio ne contacte jamais de fournisseur ; la modification locale n'a besoin d'aucune option.

`--expose-agent-tools` se résout de la même façon à partir de `VERBATRA_STUDIO_AGENT_TOOLS`, avec le même ensemble de valeurs admises et la même règle : l'option CLI l'emporte sur la variable. Elle est désactivée par défaut. Pour qu'un agent puisse dépenser, il faut à la fois cette option et `--allow-spend` ; aucune des deux n'implique l'autre. Voir [Piloter Studio avec un agent de navigateur](/docs/agent-tools-in-studio) pour le catalogue d'outils et le modèle de sécurité.

## L'URL affichée

Studio n'écoute que sur `127.0.0.1`. Une fois à l'écoute, il affiche une ligne sur stdout :

```
Verbatra Studio running at http://127.0.0.1:5849/?token=<token>
```

Ouvre exactement cette URL. Le token n'est accepté que sous la forme `?token=` lors de ce premier chargement de page : le serveur le vérifie, pose un cookie de session HttpOnly et redirige vers `/`. Chaque requête suivante est vérifiée par rapport au cookie, et une requête sans cookie valide est rejetée. Le token n'est pas à usage unique : visiter à nouveau l'URL affichée, dans un autre onglet ou un autre navigateur, pose de nouveau le cookie, alors traite l'URL comme un secret tant que Studio tourne. Rien n'est affiché avant que le port soit lié avec succès, donc un démarrage échoué ne divulgue jamais d'URL ni de token.

Une liaison échouée est signalée sur stderr sous la forme `verbatra: error [<code>] <message>` avec l'un de deux codes : `PORT_IN_USE` quand un autre processus occupe déjà le port (choisis-en un autre avec `--port`), ou `BIND_FAILED` quand le socket s'est ouvert sur une autre adresse que `127.0.0.1`, sur laquelle Studio refuse de servir.

## Installation

`@verbatra/studio` est un paquet à part, atteint via un import dynamique pour que le reste de la CLI fonctionne sans lui. S'il n'est pas installé, `verbatra studio` sort avec le code `2` en affichant :

```
Verbatra Studio requires @verbatra/studio. Install it with: pnpm add -D @verbatra/studio
```

Cette commande pnpm installe correctement mais sort avec le code `1` et `ERR_PNPM_IGNORED_BUILDS`, et laisse derrière elle un `pnpm-workspace.yaml` resté sans réponse qui fait échouer de la même façon les commandes pnpm suivantes ; la correction, à faire une seule fois, est dans le [Dépannage](/docs/troubleshooting). npm et yarn installent le paquet sans ce problème.

Studio passe par la CLI, installe-le donc avec `@verbatra/cli` : `npm install --save-dev @verbatra/cli @verbatra/studio`, puis `npx verbatra studio`. Voir [Installation et invocation](/docs/cli).

## Exemples

```bash
# start Verbatra Studio on the default port
verbatra studio

# enable the provider-calling actions, on a specific port
verbatra studio --allow-spend --port 6000
```

## Codes de sortie

| Code | Signification |
| --- | --- |
| `0` | arrêté proprement par une seule interruption (Ctrl-C ou SIGTERM) |
| `1` | l'arrêt a échoué : la fermeture du serveur a levé une erreur pendant l'extinction |
| `2` | impossible de démarrer : une erreur de config, `@verbatra/studio` non installé, le port déjà utilisé, ou une erreur d'utilisation (un `--port` hors plage ou non entier) |
| `130` | arrêté de force par une seconde interruption pendant que l'extinction était en cours |
