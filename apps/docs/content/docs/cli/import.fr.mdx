---
title: verbatra import
description: Réimporte une remise remplie (classeur, CSV ou TSV) dans les fichiers de locale, avec les mêmes vérifications de sûreté.
---
Relis dans tes fichiers de locale un classeur rempli par un traducteur. Chaque valeur passe par les mêmes vérifications d'intégrité qu'une exécution automatisée : les valeurs qui passent sont écrites et [le fichier de verrouillage](/docs/the-lock-file) est mis à jour ; les valeurs qui échouent sont retenues et signalées au lieu d'être écrites, donc une cellule défectueuse n'atterrit jamais dans un fichier de locale.

## Synopsis

```bash
verbatra import <workbook> [flags]
```

`<workbook>` est le chemin de la remise produite par [`verbatra export`](/docs/cli/export) et remplie par le traducteur : le fichier du classeur avec `xlsx`, et avec `csv` et `tsv` soit un seul fichier `<locale>.csv`, soit le répertoire qui en contient un par locale.

## Options

| Option | Argument | Défaut | Effet |
| --- | --- | --- | --- |
| `--cwd` | `<path>` | répertoire courant | résout la config et les fichiers de locale depuis ce répertoire |
| `--config` | `<path>` | recherche automatique | charge ce fichier de config au lieu d'en chercher un |
| `--dry-run` | aucun | désactivé | valide et rapporte sans écrire les fichiers de locale ni mettre à jour le verrou |
| `--format` | `<format>` | `xlsx` | lit un classeur Excel (`xlsx`) ou des fichiers délimités (`csv`, `tsv`) |
| `--lock-timeout` | `<seconds>` | `600` | combien de temps attendre un verrou d'écriture de locale déjà détenu avant d'échouer ; doit être un entier positif en secondes, sans unité, d'au plus `3600` (une valeur comme `60s`, `0`, `-1` ou `7200` est une erreur d'utilisation, sortie `2`) |
| `--json` | aucun | désactivé | affiche une [enveloppe JSON](/docs/ci-and-exit-codes#sortie-json) sur stdout portant le résumé d'exécution sous `result` (la même [forme `RunSummary`](/docs/sdk) que `translate`), ou le code d'erreur si l'exécution échoue ; la ligne d'erreur lisible par un humain va toujours sur stderr |

## Exemples

```bash
# import the filled workbook
verbatra import verbatra-translations.xlsx

# validate and report, write nothing
verbatra import verbatra-translations.xlsx --dry-run

# import every locale file in a CSV handoff directory
verbatra import handoff --format csv
```

Avec `csv` ou `tsv`, la locale vient du nom du fichier et non d'un nom de feuille : garde donc chaque fichier nommé exactement comme il a été exporté. Une locale cible configurée sans fichier (ou, dans un classeur, sans feuille) est rapportée comme l'échec de cette locale avec `WORKBOOK_SHEET_MISSING`, jamais ignorée en silence.

Un fichier laissé par un export antérieur avec une sélection `--locales` plus large n'est jamais appliqué. L'import rapproche le répertoire du manifeste que l'export le plus récent y a écrit et rapporte une telle locale en échec avec `HANDOFF_FILE_STALE`, si bien qu'une traduction périmée ne peut pas se glisser à nouveau sans qu'on la voie. Réexporte cette locale pour rafraîchir son fichier, ou supprime le fichier. Un répertoire sans manifeste lisible (assemblé à la main, ou ayant perdu le fichier caché en passant par une archive) est lu comme il l'a toujours été, chaque fichier présent est importé. De même, un fichier unique nommé directement est pris tel quel.

<AvailableFrom version="0.12.0" />

`--lock-timeout` règle combien de temps une locale attend un [verrou d'écriture](/docs/the-lock-file#le-verrou-décriture) occupé avant d'échouer avec `LOCK_CONTENDED`, exactement comme pour [`verbatra translate`](/docs/cli/translate). L'attente a lieu avant l'écriture du fichier de la locale : une locale qui dépasse le délai reste intacte pendant que les autres locales s'importent quand même, et la commande sort avec `1`. Une fois le fichier d'une locale écrit, son enregistrement dans le fichier de verrouillage attend jusqu'au délai par défaut de dix minutes, quoi que dise `--lock-timeout`. Tant qu'une attente dure plus d'une seconde, une ligne sur stderr nomme le fichier de verrou et son détenteur, ou un enregistrement JSON `lock-wait` avec `--json`. `--dry-run` ne prend aucun verrou et n'attend donc jamais.

## Retour dans le terminal

<AvailableFrom version="0.12.0" />

`import` affiche une ligne pendant qu'il lit et applique le fichier. Après un import propre, il suggère `verbatra check`, et après `--dry-run` le même import sans le flag :

```text
verbatra: importing verbatra-translations.xlsx... done (0.4s)
next: verbatra check (confirm every locale is in sync)
```

Ces lignes vont sur stderr, donc stdout et la sortie `--json` restent exactement comme décrit plus haut, et `--quiet` les supprime. Vois [Sortie dans le terminal](/docs/cli#sortie-dans-le-terminal) pour la couleur, le spinner et les variables qui les contrôlent.

## Codes de sortie

| Code | Signification |
| --- | --- |
| `0` | chaque locale cible est ressortie complète |
| `1` | l'exécution est allée au bout mais une ou plusieurs locales ont échoué ou sont ressorties partielles |
| `2` | impossible de s'exécuter : une erreur globale (config, classeur, format ou verrou) ou une erreur d'utilisation |
| `130` | interrompu avec Ctrl-C (SIGINT) ; les verrous d'écriture de l'exécution sont libérés d'abord, et stderr se termine par `verbatra: interrupted (SIGINT), released locks`, ou sous `--json` par l'enregistrement `{"type":"interrupted","signal":"SIGINT","locksReleased":true}` |
| `143` | arrêté avec SIGTERM ; les verrous d'écriture de l'exécution sont libérés d'abord, et stderr se termine par `verbatra: interrupted (SIGTERM), released locks`, ou sous `--json` par l'enregistrement `{"type":"interrupted","signal":"SIGTERM","locksReleased":true}` |

Une remise surdimensionnée ou impossible à analyser (par exemple, un fichier qui n'est pas un conteneur xlsx lisible) est une erreur globale `SOURCE_INVALID` dont le message dit ce qui n'allait pas. Une seule ligne illisible, elle, ne l'est pas : elle est rapportée comme une ligne mal formée et le reste de la locale est tout de même importé.

<AvailableFrom version="0.9.0" />

Le contrat correspond à [`verbatra translate`](/docs/cli/translate), donc une remise manuelle se branche de la même façon en CI. Cela inclut les locales partielles : une locale écrite avec des clés toujours manquantes sort avec `1`, pas `0`. Cela inclut aussi le fichier de verrouillage : un fichier de verrouillage corrompu, ou qui le devient pendant l'import, interrompt toute l'exécution avec `2` au lieu de signaler une seule locale en échec, si bien que les locales encore à venir ne sont pas touchées. Les locales appliquées avant l'interruption restent écrites : répare le fichier de verrouillage puis relance l'import.

Une cellule `Translation` vide ne fait jamais échouer une locale : la ligne est sautée, la ligne de base antérieure de son verrou est conservée, et la clé est rapportée comme `unfilled` dès lors qu'elle a encore besoin d'une traduction, que la ligne ait été exportée comme `new` ou `changed`. Importer un classeur que personne n'a encore rempli réussit donc et renvoie l'inventaire complet des clés en attente.
