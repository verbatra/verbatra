---
title: verbatra import
description: Importiere eine ausgefüllte Übergabe als Arbeitsmappe, CSV oder TSV zurück in die Locale-Dateien, mit denselben Sicherheitsprüfungen.
---
Lies eine von einer Übersetzerin ausgefüllte Arbeitsmappe zurück in deine Locale-Dateien. Jeder Wert läuft durch dieselben Integritätsprüfungen wie ein automatischer Lauf: Werte, die bestehen, werden geschrieben, und die [Lock-Datei](/docs/the-lock-file) wird aktualisiert; Werte, die durchfallen, werden zurückgehalten und gemeldet statt geschrieben. Eine kaputte Zelle landet also nie in einer Locale-Datei.

## Synopsis

```bash
verbatra import <workbook> [flags]
```

`<workbook>` ist der Pfad zur Übergabe, die [`verbatra export`](/docs/cli/export) erzeugt und die Übersetzerin ausgefüllt hat: die Arbeitsmappen-Datei bei `xlsx`, und bei `csv` und `tsv` entweder eine einzelne `<locale>.csv`-Datei oder das Verzeichnis mit einer Datei pro Locale.

## Flags

| Flag | Argument | Standard | Wirkung |
| --- | --- | --- | --- |
| `--cwd` | `<path>` | aktuelles Verzeichnis | Konfiguration und Locale-Dateien von diesem Verzeichnis aus auflösen |
| `--config` | `<path>` | wird gesucht | diese Konfigurationsdatei laden, statt eine zu suchen |
| `--dry-run` | keins | aus | validieren und melden, ohne Locale-Dateien zu schreiben oder das Lock zu aktualisieren |
| `--format` | `<format>` | `xlsx` | eine Excel-Arbeitsmappe (`xlsx`) oder Dateien mit Trennzeichen (`csv`, `tsv`) lesen |
| `--json` | keins | aus | einen [JSON-Envelope](/docs/ci-and-exit-codes#json-ausgabe) auf stdout ausgeben, der die Lauf-Zusammenfassung unter `result` trägt (dieselbe [`RunSummary`-Form](/docs/sdk) wie bei `translate`), oder bei einem fehlgeschlagenen Lauf den Fehlercode; die menschenlesbare Fehlerzeile geht weiter auf stderr |

## Beispiele

```bash
# import the filled workbook
verbatra import verbatra-translations.xlsx

# validate and report, write nothing
verbatra import verbatra-translations.xlsx --dry-run

# import every locale file in a CSV handoff directory
verbatra import handoff --format csv
```

Bei `csv` und `tsv` kommt die Locale aus dem Dateinamen, nicht aus einem Blattnamen. Lass also jede Datei genau so heißen, wie sie exportiert wurde. Eine konfigurierte Ziel-Locale ohne Datei wird als Fehler dieser Locale gemeldet, nie stillschweigend übersprungen.

Eine Datei aus einem früheren Export mit einer breiteren `--locales`-Auswahl wird nie angewendet. Der Import gleicht das Verzeichnis mit dem Manifest ab, das der jüngste Export dorthin geschrieben hat, und meldet eine solche Locale als Fehler mit `HANDOFF_FILE_STALE`. So kann sich keine veraltete Übersetzung unbemerkt zurückschleichen. Exportiere die Locale neu, um ihre Datei aufzufrischen, oder lösche die Datei. Ein Verzeichnis ohne lesbares Manifest (von Hand zusammengestellt oder auf dem Weg durch ein Archiv um die versteckte Datei gebracht) wird wie bisher gelesen, jede vorhandene Datei wird importiert. Eine direkt benannte Einzeldatei wird ebenso beim Wort genommen.

## Exit-Codes

| Code | Bedeutung |
| --- | --- |
| `0` | jede Ziel-Locale kam vollständig durch |
| `1` | der Lauf lief durch, aber eine oder mehrere Locales schlugen fehl oder blieben unvollständig |
| `2` | konnte nicht laufen: ein Fehler des gesamten Laufs (Konfiguration, Arbeitsmappe, Format oder Lock) oder ein Verwendungsfehler |

<AvailableFrom version="0.9.0" />

Der Vertrag entspricht [`verbatra translate`](/docs/cli/translate); eine manuelle Übergabe verzweigt in CI also genauso. Das gilt auch für unvollständig gebliebene Locales: Eine Locale, die mit weiterhin fehlenden Keys geschrieben wurde, endet mit `1`, nicht mit `0`. Das gilt auch für die Lock-Datei: Eine Lock-Datei, die kaputt ist oder während des Imports kaputtgeht, bricht den gesamten Lauf mit `2` ab, statt eine einzelne fehlgeschlagene Locale zu melden; die noch ausstehenden Locales bleiben damit unberührt. Locales, die vor dem Abbruch angewendet wurden, bleiben geschrieben: Repariere die Lock-Datei und importiere erneut.

Eine leere `Translation`-Zelle lässt eine Locale nie fehlschlagen: Die Zeile wird übersprungen, ihre bisherige Lock-Baseline bleibt erhalten, und der Key wird als `unfilled` gemeldet, wann immer er weiterhin eine Übersetzung braucht, egal ob die Zeile als `new` oder als `changed` exportiert wurde. Der Import einer Arbeitsmappe, die noch niemand ausgefüllt hat, gelingt also und liefert den vollständigen Bestand ausstehender Keys zurück.
