---
title: verbatra import
description: Importiere eine ausgefüllte Übergabe als Arbeitsmappe, CSV, TSV oder XLIFF zurück in die Locale-Dateien, mit denselben Sicherheitsprüfungen.
---
Lies eine von einer Übersetzerin ausgefüllte Arbeitsmappe zurück in deine Locale-Dateien. Jeder Wert läuft durch dieselben Integritätsprüfungen wie ein automatischer Lauf: Werte, die bestehen, werden geschrieben, und die [Lock-Datei](/docs/the-lock-file) wird aktualisiert; Werte, die durchfallen, werden zurückgehalten und gemeldet statt geschrieben. Eine kaputte Zelle landet also nie in einer Locale-Datei.

## Synopsis

```bash
verbatra import <workbook> [flags]
```

`<workbook>` ist der Pfad zur Übergabe, die [`verbatra export`](/docs/cli/export) erzeugt und die Übersetzerin ausgefüllt hat: die Arbeitsmappen-Datei bei `xlsx`, und bei `csv`, `tsv`, `xliff2` und `xliff12` entweder eine einzelne `<locale>.csv`-, `<locale>.tsv`- oder `<locale>.xlf`-Datei oder das Verzeichnis mit einer Datei pro Locale.

## Flags

| Flag | Argument | Standard | Wirkung |
| --- | --- | --- | --- |
| `--cwd` | `<path>` | aktuelles Verzeichnis | Konfiguration und Locale-Dateien von diesem Verzeichnis aus auflösen |
| `--config` | `<path>` | wird gesucht | diese Konfigurationsdatei laden, statt eine zu suchen |
| `--dry-run` | keins | aus | validieren und melden, ohne Locale-Dateien zu schreiben oder das Lock zu aktualisieren |
| `--format` | `<format>` | `xlsx`, bei einem Pfad auf `.xlf` oder `.xliff` stattdessen `xliff2` | eine Excel-Arbeitsmappe (`xlsx`), Dateien mit Trennzeichen (`csv`, `tsv`) oder XLIFF-Dateien lesen (`xliff2` und `xliff12` lesen beide Versionen, ab 0.12.0) |
| `--reviewer` | `<name>` | keiner | der Name, der bei jeder XLIFF-Unit festgehalten wird, die die Übergabe als `reviewed` oder `final` markiert (1.2: `signed-off`, `final` oder `approved="yes"`); höchstens 64 Zeichen ohne Steuerzeichen, gespeichert in der eingecheckten Herkunftsdatei (ab 0.12.0) |
| `--lock-timeout` | `<seconds>` | `600` | wie lange auf eine gehaltene Schreibsperre einer Locale gewartet wird, bevor der Lauf scheitert; muss eine positive Ganzzahl an Sekunden ohne Einheit und höchstens `3600` sein (ein Wert wie `60s`, `0`, `-1` oder `7200` ist ein Verwendungsfehler, Exit `2`) |
| `--json` | keins | aus | einen [JSON-Envelope](/docs/ci-and-exit-codes#json-ausgabe) auf stdout ausgeben, der die Lauf-Zusammenfassung unter `result` trägt (dieselbe [`RunSummary`-Form](/docs/sdk) wie bei `translate`), oder bei einem fehlgeschlagenen Lauf den Fehlercode; die menschenlesbare Fehlerzeile geht weiter auf stderr |

## Beispiele

```bash
# import the filled workbook
verbatra import verbatra-translations.xlsx

# validate and report, write nothing
verbatra import verbatra-translations.xlsx --dry-run

# import every locale file in a CSV handoff directory
verbatra import handoff --format csv

# import one XLIFF file back from a CAT tool, naming the reviewer
verbatra import handoff/de.xlf --reviewer "Agency GmbH"
```

Bei `csv` und `tsv` kommt die Locale aus dem Dateinamen, nicht aus einem Blattnamen. Lass also jede Datei genau so heißen, wie sie exportiert wurde. Eine konfigurierte Ziel-Locale ohne Datei (oder, in einer Arbeitsmappe, ohne Blatt) wird als Fehler dieser Locale mit `WORKBOOK_SHEET_MISSING` gemeldet, nie stillschweigend übersprungen.

Eine Datei aus einem früheren Export mit einer breiteren `--locales`-Auswahl wird nie angewendet. Der Import gleicht das Verzeichnis mit dem Manifest ab, das der jüngste Export dorthin geschrieben hat, und meldet eine solche Locale als Fehler mit `HANDOFF_FILE_STALE`. So kann sich keine veraltete Übersetzung unbemerkt zurückschleichen. Exportiere die Locale neu, um ihre Datei aufzufrischen, oder lösche die Datei. Ein Verzeichnis ohne lesbares Manifest (von Hand zusammengestellt oder auf dem Weg durch ein Archiv um die versteckte Datei gebracht) wird wie bisher gelesen, jede vorhandene Datei wird importiert. Eine direkt benannte Einzeldatei wird ebenso beim Wort genommen.

<AvailableFrom version="0.12.0" />

`--lock-timeout` legt fest, wie lange eine Locale auf eine belegte [Schreibsperre](/docs/the-lock-file#die-schreibsperre) wartet, bevor sie mit `LOCK_CONTENDED` scheitert, genau wie bei [`verbatra translate`](/docs/cli/translate). Das Warten passiert, bevor die Datei der Locale geschrieben wird. Eine Locale, die in das Zeitlimit läuft, bleibt also unberührt, die anderen Locales werden trotzdem importiert, und der Befehl endet mit `1`. Ist die Datei einer Locale einmal geschrieben, wartet das Eintragen in die Lock-Datei bis zum Standard von zehn Minuten, egal was `--lock-timeout` sagt. Dauert ein Warten länger als eine Sekunde, nennt eine Zeile auf stderr die Sperrdatei und ihren Halter, unter `--json` ein `lock-wait`-JSON-Eintrag. `--dry-run` nimmt keine Sperre und wartet daher nie.

## XLIFF

<AvailableFrom version="0.12.0" />

Eine XLIFF-Datei wird in der Version gelesen, die sie angibt, und eine einzelne Datei, deren Name keine konfigurierte Locale ist, wird über die Zielsprache zugeordnet, die sie angibt. Eine Unit, deren Ziel genau dem aktuellen Wert entspricht, ändert nichts, jedes andere Ziel durchläuft das Integritäts-Gate wie eine Arbeitsmappen-Zeile, und eine als `reviewed` oder `final` markierte Unit wird als freigegeben festgehalten, mit `--reviewer` als Namen, und mit dem Hinweis `HANDOFF_REVIEWS_RECORDED` gemeldet. Eine Unit, deren ID keinen Quell-Key nennt, wird als fehlerhafte Zeile gemeldet, statt die Locale scheitern zu lassen. Details stehen unter [An eine Übersetzungsagentur übergeben](/docs/translation-agency).

## Rückmeldung im Terminal

<AvailableFrom version="0.12.0" />

`import` zeigt eine Zeile, während es die Datei liest und anwendet. Nach einem sauberen Import schlägt es `verbatra check` vor, nach `--dry-run` denselben Import ohne das Flag:

```text
verbatra: importing verbatra-translations.xlsx... done (0.4s)
next: verbatra check (confirm every locale is in sync)
```

Diese Zeilen gehen auf stderr, stdout und die `--json`-Ausgabe bleiben also genau wie oben beschrieben, und `--quiet` lässt sie weg. Farbe, Spinner und die Variablen dazu findest du unter [Terminalausgabe](/docs/cli#terminalausgabe).

## Exit-Codes

| Code | Bedeutung |
| --- | --- |
| `0` | jede Ziel-Locale kam vollständig durch |
| `1` | der Lauf lief durch, aber eine oder mehrere Locales schlugen fehl oder blieben unvollständig |
| `2` | konnte nicht laufen: ein Fehler des gesamten Laufs (Konfiguration, Arbeitsmappe, Format oder Lock) oder ein Verwendungsfehler |
| `130` | mit Ctrl-C (SIGINT) abgebrochen; die Schreibsperren des Laufs werden vorher freigegeben und stderr endet mit `verbatra: interrupted (SIGINT), released locks`, unter `--json` mit dem Datensatz `{"type":"interrupted","signal":"SIGINT","locksReleased":true}` |
| `143` | mit SIGTERM beendet; die Schreibsperren des Laufs werden vorher freigegeben und stderr endet mit `verbatra: interrupted (SIGTERM), released locks`, unter `--json` mit dem Datensatz `{"type":"interrupted","signal":"SIGTERM","locksReleased":true}` |

Eine Übergabe, die zu groß ist oder sich überhaupt nicht parsen lässt (zum Beispiel eine Datei, die kein lesbarer xlsx-Container ist), ist ein `SOURCE_INVALID`-Fehler des gesamten Laufs, dessen Meldung sagt, was mit ihr nicht stimmte. Eine einzelne unlesbare Zeile ist das nicht: Sie wird als fehlerhafte Zeile gemeldet, und der Rest der Locale wird trotzdem importiert.

<AvailableFrom version="0.9.0" />

Der Vertrag entspricht [`verbatra translate`](/docs/cli/translate); eine manuelle Übergabe verzweigt in CI also genauso. Das gilt auch für unvollständig gebliebene Locales: Eine Locale, die mit weiterhin fehlenden Keys geschrieben wurde, endet mit `1`, nicht mit `0`. Das gilt auch für die Lock-Datei: Eine Lock-Datei, die kaputt ist oder während des Imports kaputtgeht, bricht den gesamten Lauf mit `2` ab, statt eine einzelne fehlgeschlagene Locale zu melden; die noch ausstehenden Locales bleiben damit unberührt. Locales, die vor dem Abbruch angewendet wurden, bleiben geschrieben: Repariere die Lock-Datei und importiere erneut.

Eine leere `Translation`-Zelle lässt eine Locale nie fehlschlagen: Die Zeile wird übersprungen, ihre bisherige Lock-Baseline bleibt erhalten, und der Key wird als `unfilled` gemeldet, wann immer er weiterhin eine Übersetzung braucht, egal ob die Zeile als `new` oder als `changed` exportiert wurde. Der Import einer Arbeitsmappe, die noch niemand ausgefüllt hat, gelingt also und liefert den vollständigen Bestand ausstehender Keys zurück.
