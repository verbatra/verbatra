Lies eine von einer Übersetzerin ausgefüllte Übergabe zurück in deine Locale-Dateien. Jeder Wert läuft durch dieselben Integritätsprüfungen wie ein automatischer Lauf: Werte, die bestehen, werden geschrieben, und die [Lock-Datei](/docs/the-lock-file) wird aktualisiert; Werte, die durchfallen, werden zurückgehalten und gemeldet. Eine kaputte Zelle landet also nie in einer Locale-Datei.

## Synopsis

```bash
verbatra import <workbook> [flags]
```

- `<workbook>`: die Übergabe, die [`verbatra export`](/docs/cli/export) geschrieben und die Übersetzerin ausgefüllt hat. Bei `xlsx` ist das die Arbeitsmappen-Datei; bei `csv`, `tsv`, `xliff2` und `xliff12` eine einzelne `<locale>.csv`-, `<locale>.tsv`- oder `<locale>.xlf`-Datei oder das Verzeichnis mit einer Datei pro Locale.

## Flags

| Flag | Argument | Standard | Wirkung |
| --- | --- | --- | --- |
| `--dry-run` | keins | aus | validieren und melden, ohne Locale-Dateien zu schreiben oder das Lock zu aktualisieren |
| `--format` | `<format>` | aus der Endung des Pfads: `csv`, `tsv`, `xliff2` bei `.xlf` oder `.xliff`, sonst `xlsx` | `xlsx`, `csv`, `tsv`, `xliff2` oder `xliff12`; jedes der beiden XLIFF-Formate liest beide Versionen |
| `--reviewer` | `<name>` | keiner | Name, der bei jeder als reviewed oder final markierten XLIFF-Unit festgehalten wird; höchstens 64 Zeichen, gespeichert in der eingecheckten Herkunftsdatei |
| `--lock-timeout` | `<seconds>` | `600` | wie lange auf eine gehaltene Schreibsperre einer Locale gewartet wird; eine ganze Zahl von `1` bis `3600`, sonst ein Verwendungsfehler, Exit `2` |

Außerdem nimmt der Befehl die [globalen Flags](/docs/cli#globale-flags) `--cwd`, `--config` und `--json`.

## Verhalten

### Locale-Dateien und Überbleibsel

Bei `csv` und `tsv` kommt die Locale aus dem Dateinamen. Lass also jede Datei genau so heißen, wie sie exportiert wurde. Eine konfigurierte Ziel-Locale ohne Datei (oder, in einer Arbeitsmappe, ohne Blatt) scheitert mit `WORKBOOK_SHEET_MISSING`; sie wird nie stillschweigend übersprungen.

Eine Datei aus einem früheren Export mit breiterer `--locales`-Auswahl wird nie angewendet. Der Import gleicht das Verzeichnis mit dem Manifest des jüngsten Exports ab und lässt eine solche Locale mit `HANDOFF_FILE_STALE` scheitern. Exportiere die Locale neu oder lösche die Datei. Ein Verzeichnis ohne lesbares Manifest (von Hand zusammengestellt oder von einem Archiv beschnitten) wird so gelesen, wie es ist, ebenso eine Einzeldatei, die du direkt angibst.

### Schreibsperren

<AvailableFrom version="0.12.0" />

`--lock-timeout` legt fest, wie lange eine Locale auf eine belegte [Schreibsperre](/docs/the-lock-file#die-schreibsperre) wartet, bevor sie mit `LOCK_CONTENDED` scheitert, genau wie bei [`verbatra translate`](/docs/cli/translate). Das Warten passiert, bevor die Datei der Locale geschrieben wird: Eine Locale, die ins Zeitlimit läuft, bleibt unberührt, die anderen werden trotzdem importiert, und der Befehl endet mit `1`. Ist eine Datei einmal geschrieben, wartet das Eintragen in die Lock-Datei bis zum Standard von zehn Minuten, egal was `--lock-timeout` sagt. Ein Warten über eine Sekunde meldet eine Zeile mit der Sperre und ihrem Halter (unter `--json` ein `lock-wait`-Eintrag). `--dry-run` nimmt keine Sperre und wartet daher nie.

### XLIFF

<AvailableFrom version="0.12.0" />

Eine XLIFF-Datei wird in der Version gelesen, die sie angibt, und eine einzelne Datei, deren Name keine konfigurierte Locale ist, wird über ihre angegebene Zielsprache zugeordnet. Eine Unit, deren Ziel dem aktuellen Wert entspricht, ändert nichts; jedes andere Ziel durchläuft das Integritäts-Gate wie eine Arbeitsmappen-Zeile. Eine als `reviewed` oder `final` markierte Unit (in 1.2 auch `signed-off` oder `approved="yes"`) wird als freigegeben festgehalten, mit `--reviewer` als Namen, und mit dem Hinweis `HANDOFF_REVIEWS_RECORDED` gemeldet. Eine Unit, deren ID keinen Quell-Key nennt, wird als fehlerhafte Zeile gemeldet. Siehe [An eine Übersetzungsagentur übergeben](/docs/translation-agency).

### Leere und kaputte Zeilen

Eine leere `Translation`-Zelle lässt eine Locale nie scheitern: Die Zeile wird übersprungen, ihre Lock-Baseline bleibt erhalten, und der Key wird als `unfilled` gemeldet, solange er noch eine Übersetzung braucht. Der Import einer Übergabe, die noch niemand ausgefüllt hat, gelingt also und listet jeden ausstehenden Key.

Eine einzelne unlesbare Zeile wird als fehlerhafte Zeile gemeldet, und der Rest der Locale wird trotzdem importiert. Eine Übergabe, die zu groß ist oder sich gar nicht parsen lässt (etwa kein lesbarer xlsx-Container), ist ein `SOURCE_INVALID`-Fehler des gesamten Laufs, dessen Meldung sagt, was nicht stimmte.

### Rückmeldung im Terminal

<AvailableFrom version="0.12.0" />

`import` zeigt eine Zeile, während es die Datei liest und anwendet. Nach einem sauberen Import schlägt es `verbatra check` vor, nach `--dry-run` denselben Import ohne das Flag:

```text output
verbatra: importing verbatra-translations.xlsx... done (0.4s)
next: verbatra check (confirm every locale is in sync)
```

Diese Zeilen gehen auf stderr, und `--quiet` lässt sie weg. Siehe [Terminalausgabe](/docs/cli/output#terminalausgabe).

### JSON-Ausgabe

Mit `--json` trägt der [Envelope](/docs/cli/output#json-ausgabe) eine `RunSummary`, dieselbe Form, die [`verbatra translate`](/docs/cli/translate) ausgibt:

```ts
interface RunSummary {
  dryRun: boolean;          // whether this was a dry run (nothing written)
  locales: LocaleSummary[]; // one entry per target locale, in config order
  succeeded: string[];      // locales imported completely
  partial: string[];        // locales written with keys still missing; these exit 1 too
  failed: string[];         // locales whose import failed
}
```

Jede `LocaleSummary` listet die Keys pro Locale (geschrieben, `unfilled`, zurückgehalten und mehr); siehe [die SDK-Referenz](/docs/sdk/run-summary).

## Beispiele

```bash
# import the filled workbook
verbatra import verbatra-translations.xlsx

# validate and report, write nothing
verbatra import verbatra-translations.xlsx --dry-run

# import every locale file in a CSV handoff directory
verbatra import handoff --format csv

# import one XLIFF file back from a CAT tool, naming the reviewer
verbatra import handoff/de.xlf --reviewer "Agency GmbH"
```

## Exit-Codes

| Code | Bedeutung |
| --- | --- |
| `0` | jede Ziel-Locale kam vollständig durch |
| `1` | der Lauf lief durch, aber eine oder mehrere Locales schlugen fehl oder blieben unvollständig |
| `2` | konnte nicht laufen: ein Fehler des gesamten Laufs (Konfiguration, Übergabe, Format oder eine kaputte Lock-Datei) oder ein Verwendungsfehler |
| `130` | mit Ctrl-C (SIGINT) abgebrochen, nachdem die Schreibsperren des Laufs freigegeben wurden |
| `143` | mit SIGTERM beendet, nachdem die Schreibsperren des Laufs freigegeben wurden |

<AvailableFrom version="0.9.0" />

Der Vertrag entspricht [`verbatra translate`](/docs/cli/translate), eine manuelle Übergabe verzweigt in CI also genauso: Eine unvollständige Locale endet mit `1`, und eine Lock-Datei, die kaputt ist oder kaputtgeht, stoppt den gesamten Lauf mit `2` und lässt die übrigen Locales unberührt (bereits angewendete bleiben geschrieben). Den Vertrag, dem jeder Befehl folgt, findest du unter [Exit-Codes](/docs/cli/output#exit-codes).
