See which locale files changed in git, and what changed in each, with `localeGitStatus` and `localeGitDiff`.

- **What you get:** `localeGitStatus` lists the locale files, `verbatra.lock.json` and `verbatra.provenance.json` that differ from the last commit, each as `modified`, `added`, `deleted`, `untracked` or `conflicted`, plus the checked-out branch. `localeGitDiff` compares one locale at `HEAD` with the file on disk and lists the keys added, removed and changed, with their text, capped at 500 keys and 2000 characters per key and text. For `apple-strings` both read the `.stringsdict` file too.
- **Careful with the repository:** both take a locale, never a path, and run git without a shell, with a minimal environment, a timeout and an output cap, and with optional locks, `core.fsmonitor`, bare-repository discovery, lazy fetching from a partial clone's remote, submodule inspection and every content filter the repository configures switched off. That closes the usual ways a repository's own configuration can make git run a command; a project's `verbatra.config.ts` is still code verbatra runs. A repository that git refuses over ownership, a bare repository in the project folder, a missing git, a project outside a work tree and a `custom:` format come back as `available: false` with a reason instead of throwing.
- **Security fix in `localeHistory`:** it now runs git the same way. Git no longer inherits `GIT_*` variables (a `GIT_DIR` from a hook or a `.env` file could point it at another repository), never opens a bare repository planted in the project folder, never fetches missing objects from a promisor remote, and is killed outright on a timeout. Its reasons and result shape are unchanged, so a bare repository or a repository git refuses over ownership still reads as an empty history. A custom `execFile` you pass should drop inherited `GIT_*` variables as well.
